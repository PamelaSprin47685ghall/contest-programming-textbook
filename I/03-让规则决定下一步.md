# 03　让规则决定下一步

一台模型车每走一步，都要先回答几个问题：前面有没有障碍？电量还够不够？这条路要不要重复走几遍？程序里，这些规则靠“判断”和“重复”两种动作写出来。本章可以分几次读，每读到一题，就停下来做一做。

## 一个条件，只回答真或假

电量百分数存在 `battery` 里，`battery < 20` 就是在问“电量是不是小于 20”。条件成立，得到 `true`；不成立，得到 `false`。一个条件只回答真或假，没有第三种答案。

| 想问什么 | 写法 |
|---|---|
| 相等、不相等 | `==`、`!=` |
| 小于、不大于 | `<`、`<=` |
| 大于、不小于 | `>`、`>=` |

注意 `battery = 20` 是把变量改成 20，`battery == 20` 才是提问。混写时程序常常照样能编译，做的却是另一件事。

**停笔 1**　电量依次是 19、20、21，`battery < 20` 和 `battery <= 20` 各得到什么？找出两者答案不同的那一格。

## 只有一种情况成立时才做

**片段：** 输入 0 到 100 的电量，低于 20 输出 `CHARGE`，否则输出 `READY`。

```cpp
// 假设 int battery 已读入
if (battery < 20) {
    std::printf("CHARGE\n");
} else {
    std::printf("READY\n");
}
```

`if (条件)` 后面的大括号里是条件成立时要做的事，`else` 后面是条件不成立时要做的事。两个分支一次只走一边。如果不需要“否则”，整个 `else` 分支可以省掉。

读入也要检查。`scanf` 的返回值是它成功存入了几个值；要读一个整数却没返回 1，就结束程序，`return 1` 表示这次没有正常完成。不要在没读到数据时继续给出看似正常的答案。**片段：**

```cpp
// 位于 main 内
if (std::scanf("%d", &battery) != 1) {
    return 1;
}
```

后面查阅页会讲更完整的失败情况。

有的代码在分支只有一条语句时省略花括号。本书一直写上，免得以后加了一句，却忘了它其实不在分支里。排版整齐不等于含义正确，边界由括号决定。

**停笔 2**　把片段里的条件 `battery < 20` 改成 `battery = 20`，变量会发生什么变化？它还会按“低电量”判断吗？

## 条件可以组合，也会按顺序停止

模型车能出发，要同时满足：电量不少于 20，并且前方没有障碍。**片段，假设两个变量已有值：**

```cpp
bool can_move = battery >= 20 && !blocked;
```

`&&` 是“并且”，`||` 是“或者”，`!` 是“不是”。`!blocked` 读作“没有被挡住”。

`&&` 从左边开始算：左边为假，整体已经是假，右边就不再计算。`||` 的左边为真，整体已经是真，右边也不用算。这叫**短路**。

比如 `pieces != 0 && total / pieces > 5`，先排除 `pieces` 为零的情况，再做右边的除法。把两项一交换，零作除数的危险就回来了。

**停笔 3**　电量 60、前方有障碍时，`can_move` 是什么？`pieces` 为 0 时，上面的条件会做除法吗？为什么两项不能随便交换？

## 不用猜计算次序

常用运算符从先到后大致是：

```text
! → * / % → + - → < <= > >= → == != → && → ||
```

同一组里的优先级相同。比较复杂的表达式用括号写清楚，不必为了少一对括号考验读者。

要表达“温度在 10 到 30 之间，含两端”，写 `10 <= temperature && temperature <= 30`。不能照抄数学里的连写 `10 <= temperature <= 30`；那样会先得到真假，再拿 0 或 1 去和 30 比较。

`bool` 可以转成 0 或 1。检查两只开关“恰有一只打开”，可以直接比较 `(left_on != right_on)`，也可以数一数：

```cpp
int on_count = 0;
if (left_on) {
    ++on_count;
}
if (right_on) {
    ++on_count;
}
bool exactly_one = on_count == 1;
```

这是**片段**。一个办法直接问关系，另一个先保存数量；条件多起来以后，计数的办法更容易扩展。

**停笔 4**　两只开关都关、左开右关、左关右开、都开，分别写出 `on_count` 和 `exactly_one`。再写出“只要有一只开就亮灯”的条件，比较它与“恰好一只”有什么不同。

## 多种情况按哪一种处理

传感器温度高于 30 提醒降温，低于 10 提醒保温，其余情况正常。可以写成**片段**：

```cpp
if (temperature > 30) {
    std::printf("COOL\n");
} else if (temperature < 10) {
    std::printf("WARM\n");
} else {
    std::printf("NORMAL\n");
}
```

这一串从上往下检查，选第一个成立的分支，其余跳过。若两个条件可能同时成立，顺序就会改变结果；两个独立的 `if` 则可能都执行，不能随便拿来替换 `if ... else if`。

分支还可以放进另一个分支里面，例如先看电量够不够，够了再看路挡没挡。这叫**嵌套**。每层判断回答一个明确的问题，不要为了用嵌套而多绕一圈。

还有一条容易忽略的规则：变量只能在它所在的范围里使用。**片段：**

```cpp
int wait = 0;
if (blocked) {
    wait = 5;
}
std::printf("%d\n", wait);
```

后面要用 `wait`，就先在外面创建。若改成在分支里写 `int wait = 5;`，那是新建一个分支里的变量；走出大括号，那个名字就不能用了，外面的同名变量也没有被改动。

**停笔 5**　在纸上把片段里的 `wait` 换成分支内声明，解释为什么不对。“创建一个变量”和“修改已有变量”，差在哪个词？

分情况讨论时，先要把“按什么分”说清楚：按某头牛的位置分，还是按两个不同的目标分。分好以后，每一支用同一套办法验证一遍。下面两题都是这个形状。

**例题：挤奶顺序。** Farmer John 要给编号 1 到 N 的牛挤奶，顺序要同时满足两类要求：有 M 头牛按社会地位排好了次序，必须按这个次序出现，别的牛可以插在中间任意位置；另有 K 头牛点名要某个固定位置。题目保证这样的顺序一定存在。1 号牛病了，John 想让她尽量早被挤，问最早能排到第几个位置。这是 USACO 2018 年 3 月 Bronze 组第二题，叫“挤奶顺序”。

输入第一行是 `N M K`（$1 \le M < N$，$1 \le K < N$），第二行是 M 个按次序出现的牛号，接下来 K 行每行是“牛号 位置”；输出一个整数。样例：

```text
6 3 2
4 5 6
5 3
3 1
```

输出：

```text
4
```

思路按 1 号牛的身份分三支：她的位置已经固定，答案就是那个位置；她在阶层次序里，就把阶层牛尽量往前挤，让她占到一个早的位置；她只是普通牛，就把阶层牛尽量往后放，把前面的空位留给她。看样例：牛 3 占第 1 位、牛 5 占第 3 位，阶层要求 4 在 5 前，所以牛 4 只能到第 2 位；牛 6 排在 5 后面，放到靠后的位置，第 4 位就空出来给 1 号牛，答案是 4。三种身份对应三种处理，正是 `if ... else if ... else` 的形状。

**例题：困倦牛赶集。** 数轴上有 3 头牛，站在三个互不相同的整数位置。每次操作选两端的一头（最左或最右），把它移到另外两头之间任意一个空着的整数位置。当三头牛占住三个连续整数时结束。问最少和最多各要几步。这是 USACO 2019 年 2 月 Bronze 组第一题，叫“困倦牛赶集”。

输入一行三个整数（$1 \le a, b, c \le 10^9$）；输出两行，先最少后最多。样例：

```text
4 7 9
```

输出：

```text
1
2
```

先把位置从小到大排成 $p_0 < p_1 < p_2$，两个目标分开处理。求最少：本来就连着，0 步；某两个邻居之间恰好空一格（差 2），把外侧那头牛移进这个空，1 步；其余情况两步总能完成。求最多：每一步至少让外侧的一个间隙缩小 1 格，想拖得久就保住大的那个间隙，所以最多步数是两个间隙各减 1 后取较大者。样例 4、7、9 的间隙是 3 和 2：7 和 9 之间恰好空一格，最少 1 步；最多是 3−1 与 2−1 中较大的，2 步。同一个“移哪头牛”的决定，目标不同选择就不同——这正是分情况讨论的用处。

## 按编号选动作

当所有条件都是“这个整数等于几”，可以用 `switch`。**片段：** 输入 0 到 3 的模式号，0 停止，1 或 2 慢速，3 快速，其他整数输出 `UNKNOWN`。

```cpp
// 假设 int mode 已读入
switch (mode) {
    case 0:
        std::printf("STOP\n");
        break;
    case 1:
    case 2:
        std::printf("SLOW\n");
        break;
    case 3:
        std::printf("FAST\n");
        break;
    default:
        std::printf("UNKNOWN\n");
        break;
}
```

`case` 后面是固定的整数值，多个标号可以共用同一段动作。`break` 让执行离开这个 `switch`；漏写的话，程序会继续走进后面的分支，**不会**自动在下一个 `case` 停住。`default` 处理没有匹配项的情况。`switch` 不能直接比较 `std::string`，也不适合判断一个小数落在哪个范围。

如果只是从两个值里选一个，三元表达式更短：`battery < 20 ? 5 : 0`，条件成立取 5，否则取 0，例如 `int wait = battery < 20 ? 5 : 0;`。不要把很长的多层判断挤成一串问号。

## 从“判断一次”到“每次都判断”

`if` 判断一次就结束；`while` 每轮开始前再判断一次。**片段：** 倒数 3、2、1，然后输出 `GO`。

```cpp
// 位于 main 内
int left = 3;
while (left > 0) {
    std::printf("%d\n", left);
    --left;
}
std::printf("GO\n");
```

每轮先看 `left > 0`，成立才执行里面的两句，然后回到条件处。写循环一定要说清三件事：开始是什么值；什么情况下继续；每轮如何朝停止前进。

若忘记 `--left`，条件永远为真。程序不会因为“已经打印过 3 了”就替你减一。

**停笔 7**　把初值改成 0，循环体执行几次？删掉 `--left` 后为什么停不下来？不要真的运行不停输出的版本。

一轮一轮地判断，判的往往不是“这个数满足什么条件”，而是“下一个动作是什么”：要不要换行、要不要继续读。

**例题：文字处理器。** Bessie 用文字处理器给作文排版。作文有 N 个单词（不超过 100，每个 1 到 15 个字符），每行最多放 K 个字母（$K \le 80$），空格不算；当前行放得下，就把单词接在行尾，前面补一个空格；放不下，就另起一行。这是 USACO 2020 年 1 月 Bronze 组第一题，叫“文字处理器”。

输入第一行是 `N K`，第二行是 N 个单词；输出排版好的文章。样例：

```text
10 7
hello my name is Bessie and this is my essay
```

输出：

```text
hello my
name is
Bessie
and this
is my
essay
```

处理每个单词时只问一件事：当前行已有字母数加上这个单词的长度，超过 K 没有？没超就补空格接上去，超了就换行。每轮问一次、按答案决定动作，正是 `while` 循环体的形状。核心判断可以写成片段：

```cpp
// 位于循环内：每读到一个单词，就按这个判断决定动作
if (current + word_len <= K) {
    current += word_len;   // 放得下：接在当前行
} else {
    current = word_len;    // 放不下：另起一行
}
```

行首的单词前面不加空格，行尾不留多余空格，这两点由“补空格”和“换行”的时机保证。

## 先做一次，还是一次都可以不做

`do-while` 把判断放在后面，所以循环体至少执行一次。**片段：** 读入一次测量值，数值为负就再读；约定最终会有一个非负值。

```cpp
// 位于 main 内，约定最终会有一个非负值
int reading = 0;
do {
    if (std::scanf("%d", &reading) != 1) {
        return 1;
    }
} while (reading < 0);
std::printf("%d\n", reading);
```

注意末尾 `while (...)` 后面有分号。输入 `-2 -1 8` 时，输出 8；第一次读到 8，就只读一次。**第一次读取发生在什么时候**，正是这里不能只凭初值判断的原因。

如果确定要做若干次，常用三段式 `for`。**片段：**

```cpp
for (int step = 0; step < 4; ++step) {
    std::printf("step %d\n", step);
}
```

先创建 `step = 0`，每轮先看 `step < 4`，执行循环体，最后做 `++step`，再检查下一轮。打印的编号是 0、1、2、3，一共四次。`step` 这个名字在这个 `for` 结束后不能继续用。

**停笔 8**　这段 `for` 中，把条件改成 `step <= 4` 会多出哪一次？`while`、`do-while`、`for` 里，哪一个保证循环体至少执行一次？

## 核对

1. 19 时两者都为真；20 时只有 `<=` 为真；21 时都为假。20 正是区分两者的边界输入。
2. 电量被改成 20，赋值表达式的值也是 20，非零按真处理，总会输出 `CHARGE`。这不再是电量判断。
3. 不能出发；不会做除法。交换顺序后，会先做可能除零的计算。
4. `on_count` 依次为 0、1、1、2；`exactly_one` 依次为假、真、真、假；“至少一只”是 `left_on || right_on`，两只都开时也为真。
5. `int` 表示新建。应在外面创建，分支里只写 `wait = 5;`。同名不等于同一个变量。
6. 先输出 `SLOW`，再输出 `FAST`，到下一个 `break` 才离开。三元表达式条件为假时，取冒号后面的值。
7. 初值为 0 时执行零次。删掉 `--left` 后 `left` 始终是 3，条件永远为真。
8. 多出 `step == 4` 这一次。只有 `do-while` 保证至少执行一次；另外两种在开始时就可能不执行。
