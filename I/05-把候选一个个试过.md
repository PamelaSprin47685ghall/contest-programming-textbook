# 05　把候选一个个试过

循环替我们把同一件事反复做，可记录不会都乖乖排好队：有的这一轮用不上，有的写着“到此为止”，还有的才是真正要处理的。这一章先看循环里怎么跳过、怎么停住，再看一个更常用的动作——把候选一个个试过，也就是**枚举**。

## 有的记录跳过，有的让工作结束

设想一份成绩单：最多 6 个数，负数是不小心记下的无效记录，999 表示“后面没有了”，其余的数都在 0 到 100 之间，要加进总和。我们一边读一边加。下面片段在 main 里：

```cpp
// 位于 main 内，sum 已初始化为 0
for (int i = 0; i < 6; ++i) {
    int value = 0;
    if (std::scanf("%d", &value) != 1) {
        return 1;
    }
    if (value == 999) {
        break;      // 结束标记：立刻离开整个循环
    }
    if (value < 0) {
        continue;   // 无效记录：跳过本轮余下动作
    }
    sum += value;
}
std::printf("%d\n", sum);
```

`continue` 跳过本轮剩下的动作，直接开始下一轮；`break` 立刻离开最近的一层循环。有同学会把两个词记混：continue 是“这一轮不要了，下一轮照旧”，break 是“整个不干了”。

在三段式 `for` 里，`continue` 之后仍然执行末尾的更新 `++i`，再检查条件。`while` 就不同：更新若写在循环体末尾，被 `continue` 一跳过，就可能再也到不了停止的地方——这是 `while` 配 `continue` 容易踩的坑。

`break` 若写在 `switch` 里面，离开的是最近的 `switch`，不一定是外面的循环。它看的是实际嵌套位置，不是单词周围的排版。

**停笔 1**　输入 `8 -2 4 999 70 80`，输出多少？哪些数字根本不会被读入？若把遇到 999 的 `break` 换成 `continue`，结果会怎样？

## 把所有小方案逐一试过

有 3 种底色，编号 1 到 3；4 种图案，编号 1 到 4。要输出所有“编号和等于 5”的搭配。下面片段在 main 里：

```cpp
// 位于 main 内
for (int color = 1; color <= 3; ++color) {
    for (int pattern = 1; pattern <= 4; ++pattern) {
        if (color + pattern == 5) {
            std::printf("%d %d\n", color, pattern);
        }
    }
}
```

外层先定一种底色，内层把四种图案全部试一遍，再换下一种底色。一共检查 3 乘 4，也就是 12 次。这种把候选方案逐个试过的办法，叫**枚举**。

若只要每种底色找到第一个合适的图案，可以在输出后加 `break`——它只停内层，外层还会继续。若每种有 10000 个候选，两层就可能检查一亿次；程序再快，也不是可以无限做无用工作。

**停笔 2**　在纸上列出上面片段的输出。再把外层改成 2 种底色、内层改成 5 种图案，不运行就算出要检查多少次。

## 候选不止一种

枚举的候选，不止“底色配图案”这一种。它可能是一个位置、一条线、一种对应，也可能是一对牛。候选不多时，就照样逐一试过。

动笔之前先数一遍：一共有多少个候选？每个候选要检查几步？位数、线数、对数都数得清；数得清又算得完，就直接来。

### 候选是一条线

Farmer John 有 26 头奶牛，名字首字母是 A 到 Z。奶牛们玩一种多人井字棋：3 乘 3 的棋盘，每个格子填一个字母，表示占这格的牛。规则有两条：若一行、一列或一条对角线全是一个字母，这头牛单独获胜；若线上只有两种字母、而且两种都出现，这两头牛组队获胜。问：有多少头牛能单独获胜？有多少个两人组合能获胜（不分顺序）？

输入三行，每行三个大写字母。输出两行：第一行是单独获胜的牛数，第二行是组合数。

样例输入：

```text
COW
XXO
ABC
```

样例输出：

```text
0
2
```

中间一行 X-X-O 让 X 和 O 组队，对角线 C-X-C 让 C 和 X 组队；没有哪条线被一头牛独占。这是 USACO 2018 年 3 月 Bronze 组第一题，叫“团队井字棋”。

棋盘只有 9 个格子和 8 条可能的获胜线——3 行、3 列、2 条对角线。候选就是一条线，一共 8 个，逐一试过。对每条线数一数线上有几种字母：只有 1 种，这头牛单独获胜；正好 2 种，这两头牛组队。同一个组合可能从几条线冒出来（C 和 X 就出现在对角线），所以记组合时先把两个字母按字母序排好，C-X 和 X-C 只算一次。最后数一数：单独获胜的有几头牛，组合有几个。

### 候选是一种对应

你大概听说过“石头、剪刀、布”，奶牛玩的是“蹄子、纸、剪刀”：蹄子赢剪刀，剪刀赢纸，纸赢蹄子，手势相同则平局。约翰看着两头牛玩了 N 局，看得出三种手势都出现过，却分不清哪个编号代表哪个手势，于是把三种手势编号成 1、2、3。

输入第一行一个整数 N（1 到 100），之后 N 行，每行两个 1 到 3 的整数，表示一局里第一头牛和第二头牛出的编号。输出一个整数：在合适的编号与手势对应下，第一头牛最多能赢多少局。

样例输入：

```text
5
1 2
2 2
1 3
1 1
3 2
```

样例输出：

```text
2
```

一种对应是 1 代表剪刀、2 代表蹄子、3 代表纸，这样第一头牛在 1 对 3、3 对 2 两局获胜；别的对应最多也只有 2 局。这是 USACO 2017 年 1 月 Bronze 组第二题，叫“蹄子、纸、剪刀”。

候选是一种对应：三个手势排进三个编号，一共 3 乘 2 乘 1，6 种。每种对应都把 N 局按规则判一遍，数第一头牛赢几局，最后取最大的。6 种对应、每种最多 100 局，几百次判断，眨眼就算完。

### 候选是一对牛

N 头奶牛参加 K 次体操训练课，每次课后约翰按表现排名，从第 1 名到第 N 名，没有并列。若两头牛 A、B 在每一次训练里 A 都排在 B 前面，就说 (A, B) 是一对“稳定优胜对”。问一共有多少对。

输入第一行两个整数 K 和 N，之后 K 行，每行 N 个整数，是某次训练从第 1 名到第 N 名的牛编号。输出稳定优胜对的数量。

样例输入：

```text
3 4
4 1 2 3
4 1 3 2
4 2 1 3
```

样例输出：

```text
4
```

4 号牛三次都排第一，和 1、2、3 号各成一对；1 号牛在第三次训练被 2 号超过，所以 1 对 2 不算；1 号三次都在 3 号前面，又成一对。共 4 对。这是 USACO 2019 年 12 月 Bronze 组第一题，叫“奶牛体操”。

候选是一对牛。N 最多 20，对数最多约 190 对，每对再查 K 次训练（最多 10 次），一共两千次左右的比较。做法：先把 K 次训练的名次都记下来，再对每一对 (A, B) 把 K 次训练全看一遍——只要有一次 A 排在 B 后面，这一对就作废；全部通过才计入。

### 候选是一个位置

Bessie 正在学进制转换，可她总写错一位数字：写二进制会错一位，写三进制也会错一位。她不会多写或少写，所以写下的数可以有前导 0。给你两个字符串：N 的二进制表示（有一位错）和三进制表示（有一位错），求正确的 N（十进制）。N 不超过 10 亿，答案唯一。

输入两行：第一行是二进制串，第二行是三进制串。输出正确的 N。

样例输入：

```text
1010
212
```

样例输出：

```text
14
```

N 等于 14：二进制是 1110，三进制是 112。Bessie 把 1110 写成了 1010，把 112 写成了 212。这是 USACO 2011 年 11 月 Bronze 组第二题，叫“写错的数字”。

候选是一个位置——二进制串的哪一位写错了。二进制串最多约 30 位（2 的 30 次方已经超过 10 亿），候选最多 30 个。对每一位，把它翻转，把修正后的串按二进制转成十进制数，再把这个数转成三进制，和给的三进制串比一比，看是不是恰好差一位。是，就找到了；答案唯一，找到第一个就能停。

还有一道题，候选同样是“一个位置”。贝茜想把只含 M 和 O 的字符串变成 “MOO”，她有两种操作：把首字符或末字符换成相反的字符（M 换 O，O 换 M）；删掉首字符或末字符。给 Q 个字符串（Q 在 1 到 100 之间，每个长度 1 到 100），分别求最少操作次数；做不到就输出 -1。

输入第一行一个整数 Q，之后 Q 行每行一个字符串。对每个字符串输出一行答案。

样例输入：

```text
3
MOMMOM
MMO
MOO
```

样例输出：

```text
4
-1
0
```

这是 USACO 2023 年 1 月 Bronze 组第三题，叫“哞操作”。

操作只碰两端，所以最后留下的 3 个字符，一定是原串里挨在一起的 3 个——候选就是“保留哪三个连续字符”，也就是一个位置。其余字符都得删掉，一共删 len - 3 次（len 是原串长度）。替换也只碰两端，中间那个字符永远改不了，所以保留下来的三元组，中间必须是 O。枚举每个连续三元组：中间不是 O 的作废；中间是 O 的，首字符不是 M 就加 1 次替换，末字符不是 O 再加 1 次。总步数是删除数加替换数，取最小；一个三元组都挑不出来，就输出 -1。

### 候选是自己造出来的数

前面几道题，候选都摆在输入里。也有一种情况：候选不在输入里，得自己造。奶牛们坐车旅行，里程表从 X 英里走到 Y 英里，每当里程表显示一个“有趣”的数，奶牛们就哞叫一声（起点和终点也算）。一个数有趣，当且仅当去掉前导零后，各位数字里除了一个数字不同，其余全都相同：33323 有趣，110 有趣，9779 不有趣，55555 也不有趣。问一路上会哞叫多少次。

输入一行两个整数 X、Y（100 到 10 的 16 次方）。输出哞叫次数。

样例输入：

```text
110 133
```

样例输出：

```text
13
```

110、112、113、114、115、116、117、118、119、121、122、131、133，共 13 个。这是 USACO 2014 年 4 月 Bronze 组第一题，叫“里程表”。

有同学会说：从 X 到 Y 一个数一个数地检查不就行了？——Y 最大到 10 的 16 次方，数都数不完。换个方向：候选不是“每个里程数”，而是“有趣数本身”。先想清楚有趣数长什么样，再把它造出来。一个有趣数由四样东西决定：主数字 b（出现多次的那个）、唯一数字 j（只出现一次的那个）、数字的长度、以及 j 占的位置。枚举 b（0 到 9）、j（0 到 9，且不等于 b）、长度（3 到 17 位）、j 的位置，把数造出来，注意第一位不能是 0。造出来的数不会重复：主数字、唯一数字、长度和位置四个量定下来，数就唯一了。最后数一数哪些落在 X 到 Y 之间。候选一共大约 10 乘 9 乘 15 乘 17，两万多个，每个只花十几步，完全数得过来。

这一章枚举的候选，都是数得清又算得完的：线有 8 条，对应有 6 种，对有 190 对，位置有 30 个，连“有趣数”也能先数出两万多个再逐一造。数不清候选的时候，就先想清楚候选长什么样，再枚举决定它的那几个量——里程表就是这样。能数清候选、逐一试过，就可以读下一章了：下一章“把一排数据存起来”，数据要先存下来，才能回头慢慢查。
