# 08　把一排数据存起来

有的问题只要记住“目前最大的是谁”就够了；有的问题却要回头再找：先算出全班平均身高，再找出哪些人比平均高。输入只能读一遍，想回头，就得先把数据存下来。

## 一排同类型的位置

**片段：**

```cpp
int heights[4] = {142, 138, 145, 141};
```

这一行建出一个有 4 个 `int` 位置的**数组**。四个数在内存里挨着放，位置编号从 0 开始：0、1、2、3。这个编号叫**下标**。

`heights[0]` 是第一项，`heights[3]` 是第四项。`heights[4]` 已经出了这一排，不是“最后一项”。语言不会因为你只多写了 1 就帮你纠正：普通下标访问不检查边界。

下标越界属于未定义行为：有时表面正常，有时破坏别的数据，有时直接崩溃。一个程序没有崩溃，不能证明下标写对了。

**停笔 1**　画 4 个格子，格子上方写下标，下方写数据。第三个人的身高用哪个下标？题目说“第 k 个人”时，程序里的下标该写成什么？

## 创建以后，里面是什么

**对照片段：**

```cpp
int a[4] = {7, 2};
int b[4] = {};
int c[4];
```

`a` 的前两项是 7、2，剩下的自动补零；`b` 四项全是零。函数里面没给初值的局部数组 `c`，整数元素的值不确定，不能直接拿来算。先创建、再用循环逐项赋值也可以。

原生数组的长度建好就固定。C++14 里这个长度必须是编译时能确定的常量，比如 `int a[4];`。输入一个 `n` 再写 `int a[n];` 不是标准 C++14 的写法，某个编译器肯收，不代表到处能用。

**停笔 2**　分别写出 `a` 和 `b` 的四项。为什么不能对 `c` 写“应该也是零”？

## 运行时才知道有多少项

标准库的 `vector` 也能保存一排同类型的数据，长度还可以变。用它需要包含 `<vector>`。

**创建片段：**

```cpp
std::vector<int> empty;
std::vector<int> a(4);
std::vector<int> b(4, 7);
std::vector<int> c{4, 7};
std::vector<int> copy = c;
```

`empty` 没有元素；`a` 有四个零；`b` 有四个 7；`c` 只有两个元素 4 和 7。圆括号和花括号在这里意思不一样。`copy` 拷贝了 `c` 的内容，之后改 `copy[0]` 不会动 `c[0]`。

`vector<int> a(n)` 里的 `n` 可以来自输入。新建的 `int` 元素初值是零；别的类型按各自的初始化规则来，不能一概说成“什么类型都填零”。

**停笔 3**　`std::vector<int> x(3, 8);` 与 `std::vector<int> y{3, 8};` 各有几项、分别是什么？改 `copy` 为什么不该影响原来的序列？

### 大数组为什么要小心

很大的局部原生数组常被放在容量有限的调用栈区域，可能超出限制。放到函数外成为全局数组，会换一个存储位置，而且没显式初始化的全局整数数组自动为零；但它仍然受总内存限制，也会被多个函数共用。

`vector` 对象可以留在函数内，它的元素通常从动态存储区申请，适合长度由输入决定的数据。它也会耗尽内存，**不是大小不受限制**。知道要保存多少，就建合适的长度，别为了躲问题盲目开一个巨大的全局数组。

## 先统计，再回头找

**片段：**输入 `1 <= n <= 1000` 及 `n` 个 0 到 100 的读数，先求平均数，再输出严格高于平均数的读数位置，位置按 1 开始计；一个也没有时只输出换行。

```cpp
// 位于 main 内；假设 n 个读数已存入 readings[0..n-1]
int sum = 0;
for (int i = 0; i < n; ++i) {
    sum += readings[i];
}
for (int i = 0; i < n; ++i) {
    if (readings[i] * n > sum) {
        std::printf("%d ", i + 1);
    }
}
std::printf("\n");
```

读入部分就是前面学过的循环：先建 `std::vector<int> readings(n);`，再一项一项 `std::scanf("%d", &readings[i])` 填进去。平均数本来是 `sum / n`；为了不做小数除法，这里比较 `readings[i] * n > sum`——`n` 是正数，两边同乘 `n` 大小关系不变。按输入上限，乘积最多 100000，`int` 放得下。

读第一个数时还不知道总和，没法判断它是不是高于最终平均数。这就是要保存整排数据的原因，不是因为“数组看起来更高级”。

**停笔 4**　输入 `4` 和 `2 8 5 9`，圈出应输出的位置。若输入是 `5 5 5 5`，为什么不能随便输出一个最大值的位置？

先读一遍统计总量，再回头找哪几项满足条件——这是把数据存下来的第一个理由。下面三道题都是这个形状。

### 干草堆

2011 年 12 月铜组第一题叫“干草堆”。农夫约翰把 N 堆干草摆成一排，每堆原本一样高；奶牛把一些干草从一堆搬到另一堆，各堆高度就不一样了。给出每堆现在的高度，问最少搬动多少捆能让所有堆恢复一样高。总捆数不变，只是位置变了。

输入第一行是堆数 N（1 到 10000），接下来 N 行每行一堆的捆数（1 到 10000）。输出一个整数。

样例输入：

```text
4
2
10
7
1
```

样例输出：

```text
7
```

四堆是 2、10、7、1，平均 5。搬 7 捆：从第 2 堆搬 3 捆到第 1 堆、2 捆到第 4 堆，从第 3 堆搬 2 捆到第 4 堆，四堆都变 5。

总捆数不变，所以最后每堆一定等于平均值（题目保证能整除）。先扫一遍求和、算出平均，再回头扫一遍：每堆比平均多几捆，就把几捆加起来。多出来的总和就是最少搬动数——搬走的每一捆都来自偏高的堆，正好填平偏低的堆。这就是“先统计、再回头找”：第一遍只求和，第二遍才逐项比较。

### 奶牛慢跑

有时候要存数据，是因为要**换个方向**处理。2014 年 12 月铜组第三题“奶牛慢跑”：N 头奶牛在一条单车道跑道上慢跑，各自从不同位置出发、速度不同；快的追上慢的就得减速，和前面的合成一群。问最后剩下几群。

输入第一行 N（1 到 100000），接下来 N 行每行两个整数：出发位置和速度。位置是非负整数、速度是正整数，都不超过 10^9；位置互不相同，且输入按位置从小到大给出。输出一个整数。

样例输入：

```text
5
0 1
1 2
2 3
3 2
6 1
```

样例输出：

```text
2
```

位置已经按从小到大排好，能不能追上只取决于速度。从右往左看，维护“右边这群里最慢的速度”：当前这头牛的速度不大于它，就追不上，自己成为新的一群；否则它更快，迟早并进右边那群。数一数新群的数量。

读入时位置和速度一起进来，判断却要从右往左做——输入顺序正好相反。所以先把速度存进数组，再回头从最后一项往前扫。存数据，为的是处理顺序可以不是输入顺序。

### 晋级人数统计

2016 年 1 月铜组第一题“晋级人数统计”：比赛分铜、银、金、铂金四组，新选手从铜组开始，某场得满分就升到下一组，同一场比赛里甚至可能连升几次。给出每组赛前、赛后的人数，问铜升银、银升金、金升铂各有多少人。

输入共四行，每行两个整数：某组赛前和赛后的人数（0 到 1000000），依次是铜、银、金、铂金。输出三行，依次是铜升银、银升金、金升铂的人数。

样例输入：

```text
1 2
1 1
1 1
1 2
```

样例输出：

```text
1
1
1
```

晋级只往上走。看“银组及以上”的总人数，赛后比赛前多的部分只能来自铜组升上来的——这就是铜升银的人数。从最高组往下算：先算金升铂（金+铂金的前后差），再算银升金（银+金+铂金的前后差），最后算铜升银（四组总人数的前后差）。

这里要存的就是 8 个数：四组各存赛前、赛后。存下来以后，同一组的前后差、“某组及以上”的累加，都能反复取用。一排数据存好了，怎么切、怎么加，由后面要问的问题定。

## 核对

1. 下标依次是 0、1、2、3；第三个人用下标 2。第 k 个对应下标 k − 1，先确认 1 ≤ k ≤ 长度。
2. `a` 为 7、2、0、0；`b` 为四个零。局部 `c` 没有提供初值，不能假定为零。
3. `x` 三项都是 8；`y` 两项为 3、8。拷贝得到各自拥有内容的序列，不是两个名字共享一排元素。
4. 平均数为 6，输出位置 2、4。全部为 5 时没有严格高于平均数的项；“找最大”与题目不是一回事。

能分清“只留一个数”和“存下整排”两种场合，再读下一章——下一章要保存的不再是数字，而是一段文本。
