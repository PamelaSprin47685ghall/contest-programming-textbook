# 12　用记录表达一件事

打印任务里有名字、每份页数、份数。只用三排互不相干的变量，容易把一项名字和另一项数量配错。让属于同一件事的数据放在一起，能减少这类混乱。

## 一个任务，一份记录

**类型定义片段，需要 `<string>`：**

```cpp
struct PrintJob {
    std::string name;
    int pages;
    int copies;
};
```

`struct` 定义一种结构体类型。`name`、`pages`、`copies` 是它的成员。结尾 `};` 的分号不能漏；这个定义不是立刻执行一个打印任务，而是规定“每个这样的记录有哪些部分”。

有了类型，就能创建记录：

**使用片段，需要 `<string>`：**

```cpp
// 位于 main 内
PrintJob map{"map", 3, 5};
map.copies = 6;
```

花括号里的初值依定义顺序对应，分别是名称、页数、份数。点号 `.` 表示访问这个对象的成员。修改 `map.copies` 只改这份记录，不会改其他打印任务。

初学时要给每个成员明确的初值。`PrintJob job;` 里的整数成员不会因为旁边的字符串初始为空，就也自动有一个确定数值；`PrintJob job{};` 才会把整数成员初始化为零。

**停笔 1**　`PrintJob card{"card", 2, 7};` 含义是什么？若把 2 和 7 写反，总页数碰巧相同，记录是否仍然正确？

## 把自己的计算放在自己身上

每份页数乘份数，就是任务总页数。与其让每个使用者都重新记住这条规则，可以让记录自己提供一个动作。

**类型定义片段，需要 `<string>`：**

```cpp
struct PrintJob {
    std::string name;
    int pages;
    int copies;

    int total_pages() const {
        return pages * copies;
    }

    void print_label() const {
        std::printf("%s: %d\n", name.c_str(), total_pages());
    }
};
```

`total_pages` 和 `print_label` 是**成员函数**。`map.total_pages()` 算的是 `map` 的页数，不是 `card` 的页数。末尾的 `const` 表示这个成员函数不会通过当前对象的这条访问路径修改其普通成员，因此只读的 `PrintJob` 也可以调用它。

**调用片段，需要 `<cstdio>` 与 `<string>`：**

```cpp
// 位于 main 内
PrintJob map{"map", 3, 5};
PrintJob card{"card", 2, 7};
map.print_label();
card.print_label();
PrintJob{"notice", 1, 4}.print_label();
```

最后一行用的是临时对象：创建一份通知任务，调用它的成员函数，这条语句结束后临时对象就不再存在。不要把“能临时创建”误解成“它会一直留在内存里”。

**停笔 2**　写出上面三行输出。若 `print_label()` 需要读到总页数，是让它调用 `total_pages()`，还是在两个函数里各写一次乘法更容易保持一致？

### 成员函数怎样知道“自己”是谁

在普通的非静态成员函数里，`this` 是指向当前对象的指针。`return pages * copies;` 也可写为 `return this->pages * this->copies;`。箭头 `->` 是通过指针访问成员的符号，第 18 章再完整解释。

现在先知道：同一个函数定义被不同对象调用时，里面用的是相应对象的成员。它不需要把“当前任务”存到一个大家共用的全局变量里。`this->` 在这里可以省略，不必每次都写。

## 一排记录仍然可以用 `vector`

**片段，需要 `<vector>` 与 `<string>`：**

```cpp
// 位于 main 内
std::vector<PrintJob> jobs{
    {"map", 3, 5},
    {"card", 2, 7}
};
int pages = jobs[1].total_pages();
```

先用 `[1]` 选第二个记录，再用点号调用它的函数。`jobs[1]` 与 `jobs[0]` 各自有自己的成员，不必维护三排下标必须同步的数据。

## 把相关的两个答案一起交回来

上一章用两个引用参数接收小时和分钟。现在可以直接返回一份记录。

**类型定义片段：**

```cpp
struct TimeParts {
    int hours;
    int minutes;
};
```

**函数定义片段：**

```cpp
// 把 total_minutes 拆成小时和剩余分钟，作为一份记录返回
TimeParts split_time(int total_minutes) {
    return {total_minutes / 60, total_minutes % 60};
}
```

**调用片段：**

```cpp
// 位于 main 内
TimeParts result = split_time(135);
std::printf("%d %d\n", result.hours, result.minutes);
```

`split_time` 的返回类型现在是 `TimeParts`。调用者得到完整答案，不用先准备两个输出位置。结构体的价值不是“少写几行”，而是把“这两个数共同表示什么”说清楚。

不要为了用结构体，就把所有变量都塞进一个巨大的记录。只把属于同一个概念的数据和行为放在一起。之后排序、查找时，我们还会为这样的记录提供比较方式。

**停笔 4**　如果以后还要报告秒数，把结果作为结构体返回，与用三个互不相关的全局变量保存相比，哪一种更容易分清两次调用各自的答案？说明理由，不必写代码。

## 核对

1. 名称 `card`，每份两页，七份。写反后成了每份七页、两份；总页数相同不代表任务相同。
2. `map: 15`、`card: 14`、`notice: 4`。调用同一条规则更容易保持一致；规则改变只需改它自己的实现。
3. 第一项份数变成 10，总页数变成 30；第二项仍为 14，不受影响。
4. 返回结构体时，每次调用的结果可各存为一个对象；全局变量会被后来的调用覆盖，还要额外记住它当前属于哪次结果。

能把一件事的几样数据收进一份记录，再让记录自己算、自己报，就可以读下一章，把整排记录交给算法去排序和查找了。
