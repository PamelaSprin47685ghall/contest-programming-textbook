# 13　把一段数据交给算法

一排借阅编号要排序、去重，或者把前面几项移到后面。每次都从循环开始写，容易反复犯同一种错。标准库已经准备了这些算法；先告诉它“处理哪一段”，再告诉它必要的规则。

## 先指出这一段的两端

对 `vector`，`begin()` 标记开头，`end()` 标记最后一个元素**后面**的位置。这样的标记叫**迭代器**。

可以把 `[begin, end)` 读作“从 begin 开始，到 end 之前为止”。左端包含，右端不包含，叫**左闭右开区间**或半开区间。`end()` 不是最后一个元素，不能拿来读元素。

**片段：**

```cpp
std::vector<int> values{8, 3, 6};
auto position = values.begin();
int first = *position;
++position;
int second = *position;
```

`*position` 取得它所指的元素，`++position` 移到下一个位置。`auto` 让编译器由右边推导变量类型，不是“这个变量以后什么类型都能变”。这里推导出的是相应的迭代器类型。

**停笔 1**　画出三个元素和末尾后的位置。第一次、第二次取出的数是什么？空序列的 `begin()` 和 `end()` 应相同还是不同？

## 不必每次亲自移动标记

下面是**循环片段**：

```cpp
for (auto position = values.begin(); position != values.end(); ++position) {
    std::printf("%d\n", *position);
}
```

只是逐项看，也可以用范围 `for`：

```cpp
for (int value : values) {
    std::printf("%d\n", value);
}
```

这是**等价用途的片段**。`value` 是每项的副本。要直接修改元素，用 `int& value`；大型元素只读取，用 `const auto& value`。这里的 `&` 正是已经学过的引用，不是新的循环专用符号。

`vector` 的迭代器支持加减：`begin() + 2` 指到下标 2；`end() - begin()` 得到元素数量。不能越过合法范围，也不能把不同容器的迭代器相减。原生数组的指针也可以充当这类迭代器：`std::sort(a, a + n)` 处理前 `n` 个元素，条件是这段确实存在。不是所有容器的迭代器都支持 `+ 2`，后面的有序集合就不支持。

**停笔 2**　`for (int value : values) { value = 0; }` 能把原序列清零吗？应该只改哪里？若取前三项，末端应是 `begin() + 2` 还是 `begin() + 3`？

## 排序和去重不是同一件事

**片段（假设 `codes` 是 `std::vector<int>`，已有 `{7, 2, 7, 4, 2}`，位于 `main` 内）：**

```cpp
std::sort(codes.begin(), codes.end());
auto new_end = std::unique(codes.begin(), codes.end());
codes.erase(new_end, codes.end());
for (int code : codes) {
    std::printf("%d ", code);
}
std::printf("\n");
```

`sort` 排序。`unique` 只把**相邻**的重复项压到一起处理，把保留的内容放到前部，并返回新的逻辑末端。它没有改变 `vector` 的元素数量；新末端之后的元素值不要拿来当答案，最后用 `erase` 删去那一段。

若不先排序，`2,7,2` 的两个 2 不相邻，`unique` 不会把它们合成一项。先问题目是“合并相邻相同项”还是“只保留不同值”，再决定要不要排序；有时原来的顺序本身就是信息，不能随便打乱。

**停笔 3**　对 `3,3,1,3,1,1`，不排序直接 `unique`，前面保留的逻辑结果是什么？若先排序再去重呢？`unique` 之后马上看 `size()`，是否已经变短？

### ABC 的秘密

埃尔希心里想了三个正整数 A、B、C，满足 1 ≤ A ≤ B ≤ C。她没有直接告诉贝茜，而是把 A、B、C、A+B、B+C、C+A、A+B+C 这 7 个数打乱顺序交给贝茜，请她还原出 A、B、C。输入一行 7 个整数（范围 1 到 10 亿），输出一行三个整数 A、B、C。题目保证解是唯一的。

样例输入：

```text
2 2 11 4 9 7 9
```

样例输出：

```text
2 2 7
```

思路：把 7 个数排序。最小的两个一定是 A 和 B（A ≤ B ≤ C，而 A+B 至少比 B 大），最大的一个一定是三数之和 A+B+C。于是 C 等于“最大 − A − B”。样例排序后是 2、2、4、7、9、9、11，前两个是 A、B，最后一个是总和，C = 11 − 2 − 2 = 7。这是 USACO 2020 年 12 月 Bronze 组第一题，叫“ABC 的秘密”。

### 自动补全

贝茜买了一部新手机，喜欢发短信，但她的蹄子太大，在这么小的屏幕上打字总是出错。约翰答应帮她写一个自动补全程序：输入一个不完整的单词，程序给出补全建议。程序有一本 W 个单词的字典（小写字母，总字母数不超过 100 万），收到 N 个不完整单词，每个配一个整数 K。要找出：按字母顺序排列的所有以该不完整单词为前缀的补全中，第 K 个是哪个单词。输入第一行两个整数 W 和 N，接下来 W 行是字典单词，再接下来 N 行每行一个整数 K 后跟一个不完整单词。输出 N 行：第 i 行是第 K 个补全在字典里的原始编号（1 到 W）；以该前缀开头的单词不足 K 个，输出 −1。N 不超过 1000。

样例输入：

```text
10 3
dab
ba
ab
daa
aa
aaa
aab
abc
ac
dadba
4 a
2 da
4 da
```

样例输出：

```text
3
1
-1
```

思路：把字典按字母顺序排序，同时记住每个单词原来的编号。排序后，以同一个前缀开头的单词会连续地排在相邻位置——“把相同的项放到一起”，是排序之后最常接着做的一件事。对每个前缀，在这一段里数到第 K 个，再检查它是否确实以该前缀开头；不足 K 个就输出 −1。样例里以 a 开头的补全按字母序是 aa、aaa、aab、ab、abc、ac，第 4 个是 ab，它在字典第 3 行；以 da 开头的只有 3 个，没有第 4 个，输出 −1。这是 USACO 2014 年 2 月 Bronze 组第二题，叫“自动补全”。

### 拍照还原

约翰想给 N 头奶牛拍一张完美的合影，N 是偶数，不超过 20 万。奶牛分娟姗牛（G）和荷斯坦牛（H）。他希望尽可能多的 G 站在偶数编号的位置（第 1 个位置是奇数位，第 2 个是偶数位……）。他能做的只有一件事：反转任意一个偶数长度的前缀——选一个偶数 j，把第 1 头到第 j 头整个子段前后颠倒。问：要让偶数位置上的 G 最多，最少需要反转几次？输入第一行一个偶数 N，第二行一个长度 N 的字符串（由 G 和 H 组成），输出一个整数。

样例输入：

```text
14
GGGHGHHGHHHGHG
```

样例输出：

```text
1
```

思路：把序列按相邻两个位置两两分组：(1,2)、(3,4)、……。组内两个字符相同的（GG、HH），怎么反转都还是相同，对偶数位上的 G 没有影响，直接忽略；组内是 GH 的，G 站在奇数位，反转一次前缀就能把这组变成 HG，让 G 到偶数位；组内是 HG 的已经就位。这样问题变成一串“该不该翻”的状态：从后往前看，最后一个还没就位的组，只能靠“以它为右端的一次反转”来救（更短的前缀够不着它）。翻完它，它前面的组也会跟着变——不必真的去翻，记一个“已经翻过奇数次还是偶数次”的记号就行。倒着扫一遍，数出反转次数。样例里 14 个字符分成 7 组，从后往前遇到第一个 GH 组时翻一次前缀，答案就是 1。这是 USACO 2022 年 3 月 Bronze 组第一题，叫“拍照还原”。

能指出一段数据的两端、会排序去重，再读下一章，看同一段数据还能怎么转、怎么排。

## 核对

1. 第一次取 8，第二次取 3；空序列的 `begin()` 和 `end()` 相同，区间里没有可读元素。
2. 不能——`value` 是副本，改不到原序列。要改成 `int& value`；取前三项时末端是 `begin() + 3`，它本身不包含。
3. 不排序时 `unique` 保留 3、1、3、1；先排序保留 1、3。`erase` 之前 `size()` 还是原来的数量。
