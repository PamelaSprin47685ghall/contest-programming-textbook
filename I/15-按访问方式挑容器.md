# 15　按访问方式挑容器

图书排在架上，要随时取第几本；借书要排队，先来先办；画错一笔要撤销，先撤销最近的一步。同样是一批数据，拿取方式不同，合适的容器也不同。先看操作需要什么，不必先背一排英文名。

## 经常按编号取：`vector`

`vector` 把元素连续保存，按下标取一项很快。尾部添加通常也快：偶尔要换更大的存储空间、把全部元素搬过去，但平均到很多次添加上，代价仍然小。中间插入或删除，后面的元素通常要移动。

下面片段在 main 里：

```cpp
// 位于 main 内
std::vector<int> order{10, 30, 40};
order.insert(order.begin() + 1, 20);
order.erase(order.begin() + 2);
for (int value : order) {
    std::printf("%d ", value);
}
std::printf("\n");
std::printf("checked: %d\n", order.at(1));
```

`insert(位置, 值)` 在该位置**之前**插入；`erase(位置)` 删除该元素；`erase(起点, 末端)` 删除一段。

`at(i)` 也按下标访问，但会检查范围：越界时抛出异常，没有处理的话程序通常会终止。它不会自动把序列加长，也不是“越界就给零”。`[]` 不作这种检查，范围仍要自己保证。

## 提前准备空间，不等于已经有了元素

确定有 100 个元素，可以写 `std::vector<int> v(100);`，直接得到 100 项，再按下标填。

只知道“最多可能加 100 个”，就先创建空序列，再 `v.reserve(100)` 预留容量，然后逐项添加。`reserve` 不改变元素数量，这时的 `v[0]` 仍不存在；`resize(100)` 才把数量改成 100。

多开一批零元素再不断追加，会把本不想要的零也留在答案里。选 `resize` 还是 `reserve`，先看你要的是“已有多少项”，还是“为以后留多大空间”。

```cpp
// 位于 main 内
std::vector<int> v(100);   // 直接得到 100 项，按下标填
v[0] = 3;
```

```cpp
// 位于 main 内
std::vector<int> v;
v.reserve(100);            // 只预留容量，还没有元素
v.emplace_back(7);         // 现在才有第一项
```

交换两个同类型容器的内容，可以用 `a.swap(b)`，也可以用 `<utility>` 里的 `std::swap(a, b)`，不必逐项抄到第三个大容器里。本书使用的默认分配方式下，标准容器的这种交换通常不需复制全部元素。

## 旧位置不一定继续有效

添加元素可能让 `vector` 换存储空间，此前指向元素的迭代器、指针和引用会失效。即使没换空间，插入或删除位置及其后面的旧标记也可能失效；尾部添加还会改变末端标记。

先修改容器，再重新取得所需位置，比拿着旧标记继续用更安全。第 18 章会解释指针为何会“还记着旧位置”。这不是要求每次操作都把全部数据重新扫描一遍，而是先弄清手里的标记还能不能用。

## 两头都要加减：`deque`

`deque` 可以按下标取元素，也能在头尾快速添加、删除。它不保证全部元素在一段连续内存里，不能按原生连续数组来使用。

```cpp
// 位于 main 内
std::deque<int> line{20, 30};
line.emplace_front(10);
line.emplace_back(40);
line.pop_front();
line.pop_back();
for (int value : line) {
    std::printf("%d ", value);
}
std::printf("\n");
```

头部添加用 `emplace_front`，删除用 `pop_front`；尾部名称与 `vector` 类似。中间插入删除并不会因此变得一样便宜。`deque` 修改后的迭代器有效性也有自己的规则，不能以为“没整排搬家就什么标记都安全”。

## 只撤销最近一步：栈

书叠成一摞，新书放在上面，取时也先拿上面的。这种后进先出叫**栈**，英文 stack。

标准库 `stack` 是一个限制访问方式的适配器：只暴露需要的操作，默认由 `deque` 保存数据，但也可用其他合适的底层容器。它不是 `deque` 的子类，不提供任意下标访问。

```cpp
// 位于 main 内
std::stack<int> history;
history.emplace(2);
history.emplace(5);
history.emplace(9);
while (!history.empty()) {
    std::printf("%d\n", history.top());
    history.pop();
}
```

`emplace` 添一项，`top` 看栈顶，`pop` 删除栈顶但不返回它。要取得后删除，就先取值，再 `pop`。

需要“撤销最近一步”时，栈最贴切：边读边压，凑成完整的一段就弹出去，剩下的自然接上。

### 审查

约翰订了《好蹄子保养》杂志给奶牛们看，可最新一期有一篇教人煎牛排的文章，他不想让奶牛看到。他把杂志全文存成一个字符串 S（长度不超过 100 万），要删掉其中出现的子串 T（长度不超过 100）。删法是：找到 S 里第一次出现的 T，删掉它，再重复，直到再也没有 T；删掉一次之后，两边可能拼出新的 T。问最后剩下什么。

输入两行：第一行 S，第二行 T。S、T 都由小写字母组成，T 不长于 S；题目保证删除过程中 S 不会变成空串。输出删完后的字符串。

样例输入：

```text
whatthemomooofun
moo
```

样例输出：

```text
whatthefun
```

反复在整串里找 T 再删，每次都要重新扫描，删完还可能拼出新的 T，很慢。换个做法：把结果当栈用，从左往右一个字符一个字符地压进去；每压一个字符，就看看栈顶的 |T| 个字符是不是正好拼成了 T——是，就把这一段弹出。新字符总加在末尾，所以新的 T 只可能在末尾形成，每次只需检查末尾这一处。弹出之后，栈顶又露出旧字符，后面读进来的字符可能再和它拼成新的 T，下一轮检查时自然会撞上。样例里 `whatthemomooofun` 把 `moo` 弹掉，剩下 `whatthefun`。这正是栈的用法：边读边压，凑成完整的一段就弹出。这是 USACO 2015 年 2 月 Bronze 组第一题，叫“审查”。

## 先来先办：队列

队列 `queue` 先进先出：从尾部加入，从头部取走。

```cpp
// 位于 main 内
std::queue<int> waiting;
waiting.emplace(2);
waiting.emplace(5);
waiting.emplace(9);
while (!waiting.empty()) {
    std::printf("%d\n", waiting.front());
    waiting.pop();
}
```

队列用 `front()` 看队头，不叫 `top()`。它默认也由 `deque` 保存数据。栈和队列在空的时候，都不能取顶、取头或删除；所以循环先问 `empty()`。

## 不是按先后，而是每次取当前最急的

优先队列 `priority_queue` 每次提供优先级最高的一项。默认对整数来说，是数值最大的一项。它不保证你能随时从头到尾按顺序查看全部元素。

```cpp
// 位于 main 内；需要 <queue>
std::priority_queue<int> largest;
largest.emplace(4);
largest.emplace(9);
largest.emplace(6);
std::printf("%d\n", largest.top());   // 9
largest.pop();
std::printf("%d\n", largest.top());   // 6
```

第一次得到 9，删掉以后得到 6。第二种写法传入 `std::greater<int>`，让较小值出现在顶端：

```cpp
// 位于 main 内；需要 <queue>、<vector> 与 <functional>
std::priority_queue<int, std::vector<int>, std::greater<int>> smallest;
smallest.emplace(4);
smallest.emplace(9);
smallest.emplace(6);
std::printf("%d\n", smallest.top());  // 4
```

得到 4。先把这一行作为“每次取最小值”的配方查用，模板参数的细节不用一口气记完。

用自定义记录时，默认优先队列会根据 `<` 选最大的；也可以提供比较器。它和排序使用同样严格、一致的比较要求，但“比较规则下的最大者在顶端”不等于“排序后第一个在顶端”。不要照搬一个反向规则以后，还凭名称猜谁先出来。

添加和删除通常只需逐层调整，并不每次重排所有元素；看 `top()` 不会自动删除。已有元素参与比较的值也不应在容器外偷偷改变，否则内部安排可能不再正确。

## 选择前先问三句话

| 主要需要 | 先考虑 |
|---|---|
| 按下标取；主要在尾部加减 | `vector` |
| 两头频繁加减，也需要下标 | `deque` |
| 最近放进去的先取出 | `stack` |
| 最早放进去的先取出 | `queue` |
| 不断加入，每次取当前最大或最小 | `priority_queue` |

这不是速度排行榜。工具删去了你不需要的操作，反而能让意图更清楚。需要按名称查找时，还要换一种组织办法。
