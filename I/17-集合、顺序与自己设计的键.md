# 17　集合、顺序与自己设计的键

有些数据只问“出现过没有”，不必给每个键配一份值，用集合就够了；要按键的大小顺序走一遍、或者找旁边的键，用有序的版本；键也可以由自己设计。

## 只关心出现过没有：集合

上一章用映射记“键到值”：键是名字，值是对应的数据。可有时候，值是什么根本不重要，我们只想知道“这个键出现过没有”。比如登记今天哪些访客到过：north 来了，记一笔；south 来了，再记一笔；north 又来了，不用多记——它已经在名单上了。这时用 `unordered_set` 比用映射更直接。

```cpp
// 位于 main 内
std::unordered_set<std::string> visited;
visited.emplace("north");
visited.emplace("south");
visited.emplace("north");
std::printf("%zu\n", visited.size());
```

重复加入不会多存一份，集合里每个键最多一份。两个无序集合可以比相等：

```cpp
std::unordered_set<std::string> other{"south", "north"};
std::printf("%d\n", visited == other);
```

`==` 比较成员是否相同，不受遍历顺序影响；不能用 `<` 要求它按字典序比较整个无序集合。

如果要保留重复键，有 `unordered_multiset` 和 `unordered_multimap`。多重版本没有映射的方括号访问，`count` 可以大于 1，`emplace` 的返回形式也不同于单一键映射，不能直接照用 `.second` 判断插入成败。`erase(键)` 会删除所有匹配项；只想删一条，就先找出相应迭代器，再删该位置。

只关心“出现过没有”时，用集合比用映射更直接。下面四道题都靠这一手。

**猜动物游戏。** 埃尔希心里想好一种动物，贝茜一次问一个特征：“它有这个特征吗？”埃尔希只答“是”或“否”。候选动物一共 $N$ 种，每种带着自己的特征清单。只要还有不止一种动物符合已经听到的肯定回答，游戏就继续；只剩一种时，贝茜就猜中了。贝茜想让“是”尽量多，问最多能听到几次。输入：第一行 $N$（$2 \le N \le 100$），接下来 $N$ 行，每行是动物名、特征数 $K$、再跟着 $K$ 个特征字符串。输出一个整数。样例：

```text
4
bird 2 flies eatsworms
cow 4 eatsgrass isawesome makesmilk goesmoo
sheep 1 eatsgrass
goat 2 makesmilk eatsgrass
```

输出 3。怎么让“是”多？专挑两只动物都有的特征问：每问一个共同特征，两只都还在候选里，答“是”；把两只共有的特征问完，再问一个只有其中一只有的特征，答“是”，另一只被排除，游戏结束。所以答案是“任意两只动物共同特征数目的最大值再加 1”。把每只动物的特征放进集合，两两求交集、数共同元素就行。这是 USACO 2019 年 1 月 Bronze 组第三题，叫“猜动物游戏”。

**奶牛进化史。** 奶牛的演化史可以画成一棵树：根是没有特征的始祖，每分一次叉，要么全体后代获得一个新特征，要么一部分获得、另一部分没有；特征一旦产生就不再丢失。叶子是现在已知的各个亚种，每个亚种带着自己的特征集合。如果每个特征都只在树的一条边上出现一次，这棵树就是合法的。给定 $N$ 个亚种各自的特征，问能不能画出一棵合法的树。输入：第一行 $N$（$1 \le N \le 25$），接下来 $N$ 行，每行先是一个整数 $K$（$0 \le K \le 25$），然后是 $K$ 个特征字符串。输出 `yes` 或 `no`。样例：

```text
4
2 spots firebreathing
0
1 flying
2 telepathic flying
```

输出 `yes`。合法树里，拥有同一特征的牛构成一整棵子树。任取两个特征 A 和 B，它们的子树只可能一个套着另一个，或者互不相交；如果三种牛同时存在——同时有 A、B 的，只有 A 没有 B 的，只有 B 没有 A 的——两个特征就交叉了，画不出合法树。把每头牛的特征放进集合，枚举每一对特征检查有没有交叉。这是 USACO 2019 年 3 月 Bronze 组第三题，叫“奶牛进化史”。

**我在哪？** 约翰沿马路修了 $N$ 个邮箱，每个涂一种颜色（一个大写字母），连起来是一个长度 $N$ 的字符串。他方向感不好，站在某处就看他身边连续的 $K$ 个邮箱是什么颜色，想凭这个认出自己在哪。要保证无论站在哪一段连续的 $K$ 个邮箱前，看到的颜色组合在整条马路上只出现一次，$K$ 最小是多少？输入：第一行 $N$，第二行长度 $N$ 的大写字母串。输出最小正整数 $K$。样例：

```text
7
ABCDABC
```

输出 4：$K=3$ 时 `ABC` 出现两次，认不出位置；$K=4$ 时四个四连段各不重复。做法是从小到大试 $K$：把每个位置开始的长度 $K$ 子串放进集合，如果集合里子串的个数和子串总数一样多，说明没有重复，这个 $K$ 就够用了。这是 USACO 2019 年 12 月 Bronze 组第二题，叫“我在哪？”。

**哞叫时刻 II。** 给一个长度 $N$ 的整数数组。一个“moo 子序列”是三个下标 $i < j < k$，满足 $a_i \ne a_j$ 且 $a_j = a_k$，也就是形状 $x, y, y$ 而 $x \ne y$。问一共能形成多少种不同的 $(x, y)$ 数值组合。输入：第一行 $N$，第二行 $N$ 个整数（$1 \le a_i \le N \le 10^5$）。输出不同 $(x, y)$ 的对数。样例：

```text
6
1 2 3 4 4 4
```

输出 3：4 出现三次，倒数第二次在第五个位置，前面出现过 1、2、3、4 四种不同的数，去掉 4 自己，1、2、3 各能配一个，共 3 对。做法是边走边把见过的数放进集合，集合大小就是“前面出现过多少种不同的数”；对每个出现至少两次的数值 $y$，取它倒数第二次出现的位置，这个位置之前的不同数值个数减 1，就是 $y$ 能配出的 $x$ 数。这是 USACO 2025 年 1 月 Bronze 组第二题，叫“哞叫时刻 II”。

## 想按大小排好，再找旁边的键

集合只回答“在不在”。可有时还要按大小走一遍：柜号 10、20、40 都有人用，来了个 25，想找第一个不小于 25 的已有柜号，还要看看它前面一个柜号是谁。

```cpp
// 位于 main 内
std::set<int> lockers{10, 20, 40};
auto next = lockers.lower_bound(25);
if (next != lockers.end()) {
    std::printf("next: %d\n", *next);
}
if (next != lockers.begin()) {
    auto previous = next;
    --previous;
    std::printf("previous: %d\n", *previous);
}
```

`lower_bound(x)` 找第一个不小于 $x$ 的键；没有则返回 `end()`。要读迭代器，先确认不是末端；要往前走，先确认不在开头。空集合两端相同，以上两个分支都不进入。

`map` 和 `set` 会按键的比较规则保持有序。遍历得到的是按规则排列的顺序；可以通过迭代器 `++`、`--` 找前后邻居，但不能写迭代器 `+ 3`。有序映射 `map` 的 `find`、`emplace`、`[]` 等用法与单一键无序映射相似，但按序遍历。对应的有序多重版本是 `multimap`、`multiset`。

有同学一听“有序”就担心：是不是一定更慢？不一定。无序容器分布良好时，平均查找代价接近固定；分布很差时可能退化成逐项找。有序容器的查找、插入和删除通常只走逐层缩小的一条路径，最坏代价随层数增长。后面的课程会用更准确的记号描述这些代价。现在先按“需要顺序吗、需要邻居吗、键怎样比较”选择。

## 进一层：自己设计的键怎样分组

这一节可以另用一次阅读时间。前面两节的键都是现成的类型：字符串、整数。可有些东西没有现成的键——设备位置由“房间名”和“格号”共同决定：两个位置相同，必须房间和格号都相同，不能只比较格号。

无序容器还需要一个**哈希函数**，把键算成一个整数，再据此分组查找。像先按索引分区，再去相应区域找记录；分到同一区的不一定是同一个键，还要用判等规则核对。

最重要的一条是：**相等的键，哈希值必须相同。不同的键，可以出现相同哈希值。** 后一种叫碰撞，不是自动算错；碰撞过多会影响速度。哈希值不是“保证唯一的编号”，也不应拿来替代真正的键。

先定义键的类型和它的两条规则：

```cpp
struct Slot {
    std::string room;
    int number;

    bool operator==(const Slot& other) const {
        return room == other.room && number == other.number;
    }
};

struct SlotRules {
    std::size_t operator()(const Slot& slot) const {
        std::size_t room_hash = std::hash<std::string>{}(slot.room);
        std::size_t number_hash = std::hash<int>{}(slot.number);
        return room_hash ^ (number_hash << 1);
    }

    bool operator()(const Slot& a, const Slot& b) const {
        return a == b;
    }
};
```

`operator==` 给出判等。`SlotRules` 的一个参数版本是哈希工具；写了 `operator()`，对象就能像函数一样被调用。此处 `<< 1` 把无符号整数的位左移一位，`^` 逐位比较两个数，相异的位得到 1，用来混合两个哈希结果。现在不用发明自己的混合公式；这份简单写法能满足相等键哈希相同，但不是对所有数据都最佳的分布方案。

运算先在 `size_t` 这样的无符号类型里进行，避免用带符号 `int` 随意相乘而溢出。固定容器使用期间，同一键的哈希和判等结果要保持一致；不要求不同运行之间的库哈希值永远相同。

用起来：

```cpp
// 假设 Slot 与 SlotRules 已定义，位于 main 内
std::unordered_map<Slot, int, SlotRules> visits;
++visits[Slot{"blue", 2}];
++visits[Slot{"red", 2}];
++visits[Slot{"blue", 2}];
auto found = visits.find(Slot{"blue", 2});
std::printf("%zu %d\n", visits.size(), found->second);
```

有同学会问：两个不同房间碰巧算出同一个哈希值，会不会弄混？不会——哈希只负责分组，分到同一组还要用判等核对。示例默认通过 `operator==` 判等。也可把声明改为 `std::unordered_map<Slot, int, SlotRules, SlotRules>`，让同一个规则类型的两个参数版本负责判等。这是两种接法，不必把同一条判等逻辑复制两遍。

如果改成有序 `map` 或 `set`，不需要哈希，也不要求 `operator==`；需要 `<` 或指定的比较器。例如先比房间名，再比格号，形成一致的严格先后关系。有序容器按“彼此都不小于对方”判为同一键。若只比较房间，两个同房间、不同格号就会被当成同一个键，这通常不是你想要的。

**停笔 3**　上面片段最后有几个键？查 `blue,2` 得多少？若两个不同房间碰巧得到相同哈希值，容器该怎样分清？若判等认为两个键相等，哈希却不同，违反了哪条约定？

这两种用法都在“自己定义键”的范围里：一种把几个名字拼成一个键，一种把字符换成自己排的序号。

**记录整理。** 约翰记录奶牛进谷仓挤奶的情况：每个小时有一组 3 头牛进来，他记下三个名字。同一组牛可能多次进来，而且每次记名字的顺序不一定一样。问出现次数最多的那一组牛一共出现了几次。输入：第一行 $N$（$1 \le N \le 1000$），接下来 $N$ 行，每行三个名字（1 到 10 个大写字母）。输出一个整数。样例：

```text
5
BESSIE ELSIE MATILDA
FRAN BESSIE INGRID
BESSIE ELSIE MATILDA
MATILDA INGRID FRAN
ELSIE BESSIE MATILDA
```

输出 3：{BESSIE, ELSIE, MATILDA} 这一组出现了 3 次。同一组牛，名字顺序可能不同，所以先把三个名字排序，排序后的三个名字当作同一个键，用映射统计每组出现的次数，最后取最大值。这是 USACO 2013 年 12 月 Bronze 组第一题，叫“记录整理”。

**奶牛字母表。** 奶牛有自己的字母表，26 个小写字母全有，但顺序可能和普通的 `abcdefghijklmnopqrstuvwxyz` 不同。贝茜一遍又一遍从头唱整个奶牛字母表，约翰只听到其中一部分字母，记成一个字符串 $S$。问贝茜至少唱完了几遍，约翰才可能听到 $S$ 里的这些字母。输入：第一行 26 个互不相同的小写字母（奶牛字母表的顺序），第二行字符串 $S$（$1 \le |S| \le 1000$）。输出最少完整遍数。样例：

```text
abcdefghijklmnopqrstuvwxyz
mood
```

输出 3。先把 26 个字母换成奶牛字母表里的位置序号，得到一把自定义的键；然后看 $S$ 里相邻的两个字符，后一个的位置小于等于前一个时，就必须新开一遍。`mood` 里两个 o 不能在同一遍听到（一遍只有一个 o），d 又排在 o 前面，所以一共 3 遍。这是 USACO 2021 年 1 月 Bronze 组第一题，叫“奶牛字母表”。

## 这些动作合起来用

这一章的动作可以合起来用：先按对统计，再用计数决定最终次序。

**奶牛拍照。** 约翰想按某个顺序 $A$ 给 $N$ 头牛（编号 1 到 $N$）排队拍照。每次排好队、按下快门前，最多只有一头牛会离开原位插到别处。这个过程重复 5 次，得到 5 张照片；而且每头牛最多主动移动一次（别的牛动，它可能被动换位置）。给这 5 张照片里每头牛的位置，还原约翰最初想要的顺序 $A$。输入：第一行 $N$（$1 \le N \le 20000$），接下来 $5N$ 行，每 5 行一张照片，每行一个编号。输出 $N$ 行，每行一个编号。样例：

```text
5
1
2
3
4
5
2
1
3
4
5
3
1
2
4
5
4
1
2
3
5
5
1
2
3
4
```

输出：

```text
1
2
3
4
5
```

5 张照片里，分别是 1 到 5 号牛被挪到了最前面，其余保持 1、2、3、4、5 的相对顺序，所以原始顺序就是 1、2、3、4、5。为什么能还原？每张照片最多一头牛主动移动，所以任意两头牛 a、b，5 张照片里最多 2 张它们的相对顺序被破坏（a 动的那张、b 动的那张），至少 3 张保持真实顺序。于是：先记录每头牛在每张照片里的位置，对每一对牛数“谁在谁前面”的票数，真实顺序里靠前的那头至少赢 3 次，按多数票排序就是答案。集合、映射、计数、排序在这里合起来用。这是 USACO 2011 年 12 月 Bronze 组第二题，叫“奶牛拍照”。

## 核对

1. 两段片段依次输出 2、1。“是否到过”只关心不同成员，逐次记录要允许重复；多重版本的名字里含 `multi`。
2. `next: 40`、`previous: 20`。目标 5 时已在开头，前面没有元素；目标 50 时返回末端，但非空集合的末端可向前一步，得到 40。
3. 两个键，查询得 2；碰撞后用判等分清。相等键哈希不同违反了“相等必同哈希”，可能使本该同一项的数据被分到不同查找路径。

能分清“只要出现过没有”“要按顺序找邻居”“自己设计键”三种场合，就可以读下一章了——那里要问：手里只记着一个位置，位置上的对象还在吗？
