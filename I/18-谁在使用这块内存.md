# 18　谁在使用这块内存

这一章不必一次读完。每做完一小节，就在纸上画一画“哪个名字指向哪个对象”，再往下走。你已经会存一排数据了；这一章不是要你以后处处手动管理内存，而是回答一个问题：**手里只记着一个位置，那个位置上的对象还在吗？**

## 值和位置是两件事

变量 `level` 保存一个整数。`&level` 是它所在的位置；能保存这种位置的变量叫**指针**。指向 `int` 的指针，类型写成 `int*`。

**片段（位于 `main` 内，需要 `<cstdio>`）：**

```cpp
int level = 4;
int* position = &level;
std::printf("%d\n", *position);  // 输出 4
*position = 7;
std::printf("%d\n", level);      // 输出 7
```

`position` 保存的是地址；`*position` 访问那个地址上的整数，这一步叫**解引用**。所以先输出 4，再输出 7：改 `*position` 就是改 `level` 本身，不是改一份副本。

这里两种星号各管各的：声明里的 `int*` 说明类型；表达式里的 `*position` 表示“取所指的对象”。看代码时先看符号放在哪里，不要只凭单个符号猜意思。

## 指针能换位置，引用不能换主人

引用在创建时就绑定了对象，之后对引用赋值是修改那个对象；指针本身可以改成保存另一个地址。

**片段：**

```cpp
int left = 2;
int right = 9;
int* chosen = &left;
chosen = &right;
*chosen = 10;
```

最后 `left` 仍是 2，`right` 变成 10。指针还可以用 `nullptr` 表示“现在没有指向任何对象”；解引用 `nullptr` 没有意义，不能做。

声明多个变量时有一个常见的坑：`int *a = nullptr, b = 0;` 里，`a` 是指针，`b` 却是普通整数，并不是两个指针。本书一行只声明一个指针，省得猜语法。

旧代码里常用 `NULL` 表示空指针；C++14 写新代码时优先用 `nullptr`，意思更明确。

## 非空不等于还能用

地址不是一张让对象永远存在的通行证。局部变量走出自己的范围就结束生命；还记着它地址的指针可能依然非空，但不能再碰。

**危险片段，只用于辨认，不要解引用运行：**

```cpp
int* saved = nullptr;
{
    int temporary = 8;
    saved = &temporary;
}
```

走出大括号，`temporary` 已经不在了，`saved` 成为**悬垂指针**。不能因为 `saved != nullptr` 就去用 `*saved`；引用也可能悬垂，它同样没有自动检查寿命的能力。

函数不能返回指向自己普通局部变量的指针或引用。`vector` 重新分配空间，也会使指向旧元素的指针失效。解引用之前要同时知道：不是空；对象仍在；类型正确；位置有效；访问权限允许。

## 数组不是指针，但常能提供起点

**片段：**

```cpp
int values[4] = {3, 6, 9, 12};
int* first = values;
int third = *(first + 2);
```

这里数组名转换成了指向首元素的指针。`first + 2` 是往后移两个 `int` 元素的位置，取出 9；它不是“把地址往后移两个字节”。编译器按元素类型计算距离，不要自己再乘 `sizeof(int)`。

`values[2]` 与 `*(values + 2)` 访问同一个元素。同一数组内的两个合适指针相减，得到相隔几个元素，也不必再除以元素大小。

数组本身不等于指针：`sizeof(values)` 得到整个数组的字节数，`sizeof(first)` 只是指针本身的大小；数组还知道自己的固定容量，单个指针通常不携带长度。

指针运算只在同一数组对象的元素位置与末端后一个位置之间进行。`values + 4` 可以作为末端标记，但不能解引用；再越过这个末端继续加也不合法。不同数组的指针不能相减来“算距离”。

## 哪个部分不许改

给普通变量加 `const`，表示不能通过它修改值。指针有两件事可以受限制：指针本身能不能换位置，以及所指内容能不能通过这条路径修改。

**对照片段：**

```cpp
int a = 2;
int b = 5;
const int* view = &a;
int* const fixed = &a;
```

`view` 是“指向只读内容的指针”：可以改成 `view = &b`，但不能通过它写 `*view = 7`。原来的 `a` 并没有变成常量，仍然可以直接赋值。

`fixed` 是“指针本身固定”：不能改成 `fixed = &b`，但这里可以通过 `*fixed = 7` 修改 `a`。两个 `const` 也可以同时出现：`const int* const p = &a;`，两边都不许通过它改。

**停笔 5**　“指针不能换位置”和“不能通过指针修改内容”是同一件事吗？上面哪个指针允许换指向，哪个允许改内容？

## 自己申请，就要自己说清楚何时归还

`new` 在动态存储区创建对象，返回它的地址。对象不会因为保存地址的局部指针走出范围就自动删除；需要配对的释放。

**片段（位于 `main` 内，需要 `<cstdio>`）：**

```cpp
int* value = new int(12);
std::printf("%d\n", *value);   // 输出 12
delete value;
value = nullptr;

int* readings = new int[3]{};
readings[1] = 5;
std::printf("%d %d %d\n", readings[0], readings[1], readings[2]);  // 输出 0 5 0
delete[] readings;
readings = nullptr;
```

`new int(12)` 创建一个值为 12 的整数，用 `delete` 归还；`new int[3]{}` 创建三个初值为零的整数，用 `delete[]` 归还。这里的 `{}` 有用：`new int[3]` 不会把三个整数都初始化为零。

归还之后，不能再使用那个对象，也不能再次释放同一个对象。`delete nullptr` 是安全的，但这不等于“重复删除任何指针都安全”。`delete` 与 `delete[]` 不能混用，也不能拿来删除普通局部变量的地址。

**停笔 6**　上面的片段输出哪两行？删掉数组创建时的 `{}` 后，未赋值的第 0、2 项还能保证为零吗？若 `other = readings` 保存了同一地址，`readings = nullptr` 是否同时把 `other` 也变空？

### 一件东西只能有一份清楚的释放责任

只申请不归还，失去最后一个可用地址，就造成泄漏；两个指针都以为自己负责归还，又可能重复释放。提前 `return` 或抛出异常，还可能绕过原计划的 `delete`。

因此本书日常程序仍优先用局部对象、`vector`、`string`：由对象自己在生命周期结束时归还资源。需要单独动态拥有一个对象时，标准库还有 `unique_ptr` 等工具，它们同样遵守“明确的单一释放责任”。不必为了练习语法，把所有普通变量都改成 `new`。

这里只在短小、没有中途离开的示例里展示手动配对。写较复杂的程序时，不能靠“记住以后加一句 `delete`”保证每条路径都收尾。

## 通过指针使用一份记录

**片段（假设已有 `struct Box { std::string label; int cards; };`，位于 `main` 内）：**

```cpp
Box* box = new Box{"blue", 8};
(*box).cards += 2;
std::printf("%s %d\n", box->label.c_str(), box->cards);  // 输出 blue 10
delete box;
box = nullptr;
```

`box->cards` 是 `(*box).cards` 的简写：先找到对象，再访问成员。第 12 章的 `this->pages` 就是同一个箭头。普通对象用点，指针用箭头；不要因为看到结构体，就认定必须把它放进动态存储区。

释放结构体对象时，其中的 `string` 成员也会结束生命并处理自己的存储。这不意味着结构体里若保存一个普通裸指针，指向的另一个对象就会自动删除；仍要看谁真正拥有它。

## 核对

1. `*position = 7` 改格子内容；`position = &other` 改箭头指向，不改原格子里的值。
2. `right` 仍在；改指针不删除对象。不能解引用空指针。
3. 只排除“当前值是空指针”，不能排除对象已结束、位置越界等危险。`temporary` 应被划掉。
4. 指向 12；距离是三个元素，不是十二字节。末端后没有本数组可读的元素。
5. 不是同一件事。`view` 可换指向，但不可经它写内容；`fixed` 不可换指向，但可修改此处所指的可变整数。
6. 第一行 `12`，第二行 `0 5 0`。删掉 `{}` 后不能保证。赋空只改 `readings` 自己，另一个地址副本仍会悬垂。
7. `blue 10`。普通局部对象用点，走出范围自行结束，不手动删除。
