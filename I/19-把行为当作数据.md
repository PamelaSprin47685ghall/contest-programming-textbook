# 19　把行为当作数据

这一章分三次读也可以：先看短函数，再看捕获，最后看保存行为。排序时，我们不只交给工具一排数据，还交给它一条“谁排在前面”的规则；有时这条规则只用一次，写在旁边，比起一个远处的函数名更方便。

## 一小段可以调用的代码

**片段（位于 `main` 内，需要 `<cstdio>`）：**

```cpp
auto twice = [](int value) -> int {
    return value * 2;
};
std::printf("%d\n", twice(7));  // 输出 14
```

方括号开头的写法叫 **lambda 表达式**。它创建一个能被调用的对象。这里用变量 `twice` 保存，再像调用函数一样写 `twice(7)`。

把它分成四部分看：`[]` 是捕获表，暂时为空；`(int value)` 是参数；`-> int` 指定返回类型；花括号里是执行内容。末尾的分号属于“创建变量”这条语句，不是函数体里多出来的一句。

这里可以省略 `-> int`，编译器能从返回语句推导出来；没有返回值时也能推导成 `void`。若有多条返回语句，推导要保持类型一致。把返回类型写出来，有时更清楚。

`auto` 只是推导变量类型。每个 lambda 表达式都有编译器生成的类型，类型不是“叫 `auto` 的万能类型”。这让我们不必先写出那串类型名。

## 把短规则放在使用处

第 14 章用普通函数写排序规则；现在把只用一次的规则放到 `sort` 的第三个参数。

**片段（假设 `names` 是 `std::vector<std::string>`，位于 `main` 内）：**

```cpp
std::sort(names.begin(), names.end(),
          [](const std::string& a, const std::string& b) {
              if (a.size() != b.size()) {
                  return a.size() < b.size();
              }
              return a < b;
          });
```

这个例子里的名字限定为 ASCII，所以 `size()` 正好等于字母数。比较规则依然要满足严格、一致的先后关系；lambda 不会替你修复 `<=` 这种不合要求的比较。

把代码写在这里，不意味着 lambda 是一个普通命名函数声明。它是可作为值交给工具的对象；普通函数也可以作为这里的比较参数。选哪一种，取决于放在哪里更容易读。

## 想用外面的数，要说明怎样带进去

门票满减的门槛放在变量 `limit` 里；lambda 想用它，就在捕获表里写出名字。

**片段（位于 `main` 内，需要 `<cstdio>`）：**

```cpp
int limit = 10;
auto snapshot = [limit](int value) {
    return value >= limit;
};
auto current = [&limit](int value) {
    return value >= limit;
};
limit = 20;
std::printf("%d %d\n", snapshot(15), current(15));  // 输出 1 0
```

`[limit]` **按值捕获**：创建时保留一份 10，之后外面的 `limit` 变成 20，这份仍是 10。`[&limit]` **按引用捕获**：使用外面那个变量，现在看到 20。

`[&]` 表示把函数体中实际用到、需要捕获的外部局部变量按引用捕获；`[=]` 表示这类变量按值捕获。不是把整个程序里的所有变量无条件搬进来。初学时先显式写名字，更容易看出依赖谁。

按值捕获的普通副本，默认不能在 lambda 的调用中修改；本节只读取它。按引用捕获有修改权限，但仍要遵守原变量是否只读等限制。

## 行为还在，借用的变量可能已经不在

下面的**错误函数定义片段**（需要 `<functional>`）只用于辨认，不要运行：

```cpp
std::function<bool(int)> make_bad(int target) {
    return [&target](int value) {
        return value == target;
    };
}
```

参数 `target` 是这次调用的局部对象。函数返回后它就结束生命，但交出去的 lambda 仍借用它；下一次调用 lambda，就访问了已经不在的对象。

正确做法是保留需要的值，不是保留一个即将失效的位置。下面是**片段（需要 `<cstdio>` 与 `<functional>`）：**

```cpp
std::function<bool(int)> make_matcher(int target) {
    return [target](int value) {
        return value == target;
    };
}

// 位于 main 内：
auto is_five = make_matcher(5);
auto is_nine = make_matcher(9);
std::printf("%d %d %d\n", is_five(5), is_five(9), is_nine(9));  // 输出 1 0 1
```

两个匹配器各自保存自己的目标值，函数返回也不会失去它。这里按值捕获的是一个 `int`，复制就得到独立数值；如果按值捕获的是裸指针，只复制地址，不会自动复制或延长它指向对象的生命。

“只执行一次、就在当前函数内调用”的引用捕获，通常容易检查；要返回、保存或稍后执行，就必须重新检查所借用对象能否活得足够久。换个包装类型不会修复悬垂引用。

## 需要同一类盒子保存不同的行为

不同 lambda 有不同的实际类型。`std::function<返回类型(参数类型)>` 可以统一保存符合调用形式的行为，需要 `<functional>`。

**片段（位于 `main` 内）：**

```cpp
std::vector<std::function<int(int)>> rules;
rules.emplace_back([](int value) { return value + 3; });
rules.emplace_back([](int value) { return value * 2; });
for (const auto& rule : rules) {
    std::printf("%d\n", rule(10));  // 输出 13，再输出 20
}
```

`std::function<int(int)>` 读作“输入一个 `int`、返回一个 `int` 的可调用行为”。`std::function<int(bool, bool)>` 则是接收两个 `bool`、返回一个 `int`。

不必每个 lambda 都先包成 `function`。像前面那样直接保存或传给标准算法就够用；`function` 的统一包装可能有额外分配和间接调用开销，只有需要统一存储、明确接口等收益时再用。

默认创建的空 `function` 没有可调用目标，直接调用会抛出异常；不能把“没有规则”当成默认返回零。本书示例都先放入真实行为再调用。

## 核对

1. 结果 14；创建 lambda 没有执行函数体，调用才执行。一次简单运算可直接写；需要复用或交给别的工具时，保存行为更有用。
2. `Al`、`Bo`、`Mia`、`Zoe`。中文 UTF-8 文本按字节数比较，不自动按人眼看见的字数。
3. `1 0`。创建时的门槛用值捕获；跟随外部变量用引用捕获，后者还要保证外部变量活着。
4. `1 0 1`。包装不会延长被引用的局部参数寿命，错误仍在。
5. 分别输出 13、20：每次都把 10 交给一条规则。若要接着处理，由调用这两条规则的代码维护 `result`，依次写 `result = rule(result)`，最终得到 26。
