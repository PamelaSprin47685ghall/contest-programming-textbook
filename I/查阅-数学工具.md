# 查阅　数学工具

这页像工具箱，不是一节必须背完的课。会用四则运算，可以先读“取整”和“整数乘方”；后半页只是先认名字，等数学课学到相应概念再回来。数学函数需要正确的输入，也需要正确理解返回类型。工具帮你计算，不替你判断题目想要哪种答案。

## 小数取整有几种不同的方向

“只要有剩余就多开一页”与“取最近的整数”不是同一条规则；负数时差别更明显。下面以 `2.5` 和 `−2.5` 为例，看四个取整工具（都需 `<cmath>`）：

| 工具 | `2.5` 的结果 | `−2.5` 的结果 | 结果类型 |
|---|---|---|---|
| `std::floor(x)`：向较小方向取整 | 2 | −3 | 传 `double`，返回 `double` |
| `std::ceil(x)`：向较大方向取整 | 3 | −2 | `double` |
| `std::round(x)`：取最近整数，正好一半时远离零 | 3 | −3 | `double` |
| `std::llround(x)`：同样的舍入方向 | 3 | −3 | `long long` |

`floor` 的结果虽然没有小数部分，类型仍可能是 `double`。强制转换 `static_cast<int>(x)` 是截向 0，并不总等于 `floor(x)`，也不执行四舍五入。转换或 `llround` 之前，都要确认结果能装进目标整数类型。

**片段：**

```cpp
// 位于 main 内
double x = -2.5;
std::printf("%.0f %.0f %.0f %lld\n",
            std::floor(x), std::ceil(x), std::round(x), std::llround(x));
```

**停笔 1**　写出这段的输出。对 −2.5，向上取整是更接近零，还是更远离零？“向上”不是“把绝对值加大”。

## 精确整数乘方，不必绕进小数

`3` 的四次方是四个 3 相乘，也写作 $3^4$，结果是 81。注意 C++ 的 `^` **不是**乘方运算符，它是按位异或；不要写 `3 ^ 4` 来求这个答案。在很小的范围内算非负整数次方，可以自己写一个循环：

**片段：**

```cpp
// 约定 1 <= base <= 10、0 <= exponent <= 9，中间结果都放得下
long long integer_power(int base, int exponent) {
    long long result = 1;
    for (int i = 0; i < exponent; ++i) {
        result *= base;
    }
    return result;
}

// 位于 main 内
std::printf("%lld\n", integer_power(3, 4));
std::printf("%lld\n", integer_power(7, 0));
```

指数为 0 时不做乘法，得到 1。若扩大范围，必须重新检查每一步的乘积；换成 `long long` 并不意味着永不溢出。

`std::pow(base, exponent)` 是 `<cmath>` 里的乘方工具，这里常见用法返回小数近似值，也能处理合适范围的非整数指数。要做精确整数乘方，不要先拿它得到近似值再截断回整数。这不是说某个 `pow(10,6)` 在所有机器都会算错；有的整数结果能精确给出，但不能靠这个巧合制定整数算法。

**停笔 2**　片段里 `integer_power(3, 4)` 和 `integer_power(7, 0)` 分别是什么？若把 `result` 初值写成 0，为什么任何正指数都无法算对？只把返回类型改大，能自动改变之前每步的计算类型吗？

## 绝对值：离零有多远

`abs(-8)` 为 8，`abs(8)` 也为 8。整数和小数有同名重载：

- `<cstdlib>` 提供 `std::abs(int)`、`std::abs(long long)` 等整数版本。
- `<cmath>` 提供浮点版本，例如 `std::abs(double)`。

调用时让类型正确、包含相应头文件，需要两类就两个都包含。不是“名字叫 abs 就只适合小数”，也不是“把数先转成整数比较保险”。

有符号整数的最小值有特殊风险。例如本环境的 `int` 能表示 −2147483648，却不能表示 +2147483648，因此在 `int` 里取该最小值的绝对值会超范围。可以在**确认较宽类型能表示结果**后，先转换到较宽类型再取绝对值；不能先让窄类型发生溢出再补救。

**停笔 3**　一个测量值为 −2.75，误用整数版本得到 2，错在什么地方？为什么“绝对值总是正数，所以一定安全”不成立？

## 以下是以后会用到的名字

没有学过平方根、三角函数和对数时，先知道它们是不同工具，不要求现在做题。下表工具均在 `<cmath>`：

| 工具 | 做什么 | 使用前提或单位 |
|---|---|---|
| `std::sqrt(x)` | 求平方根，例如 9 的非负平方根为 3 | 普通实数计算要求 `x >= 0` |
| `std::sin(x)`、`std::cos(x)`、`std::tan(x)` | 三角函数 | 输入按弧度，不直接按“度”；正切有不定义的位置 |
| `std::asin(x)`、`std::acos(x)`、`std::atan(x)` | 反三角函数 | 前两者输入范围为 −1 到 1；返回角按弧度 |
| `std::exp(x)` | 以常数 e 为底的指数 | 结果过大可能超出浮点范围 |
| `std::log(x)`、`std::log10(x)` | 自然对数、以 10 为底的对数 | 普通有限实数结果要求 `x > 0` |
| `std::ilogb(x)` | 取浮点表示的指数，本环境以 2 为底 | 这里只考虑正的、有限且非零输入，返回 `int` |

上表除 `ilogb` 外，传 `double` 时这些函数返回 `double`。例如二进制环境里，`ilogb(8.0)` 为 3，`ilogb(12.0)` 也为 3，因为 12 落在 8 到 16 之间，不含 16。它不是返回一个小数的通用对数函数。

三角函数用到的“弧度”是另一种角度单位，180 度对应圆周率 π 弧度。C++14 不保证有名为 `M_PI` 的标准常量；以后需要时，可以用 `std::acos(-1.0)` 得到 π 的近似值。现在不必为记住这条而提前学完整套三角函数。

无效输入可能产生非数、无穷大或错误状态，并不是每次都会抛异常或停止程序；普通输入也可能有舍入误差。不要把“函数有返回值”当作“已经得到题目允许的有限答案”。

**停笔 4**　不用计算复杂函数，只分类：输入 −9 求普通实数平方根、输入 0 求有限自然对数、输入 9 求平方根，哪一个符合上表条件？如果题目要求整数，为什么不能一律调用小数函数再截断？

## 核对

1. 依次是 `-3 -2 -3 -3`。向上是往数轴较大的一边，对负数可以更接近零。
2. 依次是 `81`、`1`。乘法从零开始会一直是零；返回类型不反过来改变已经完成的计算类型。
3. 先发生了小数到整数的损失，已经不是原测量值的绝对值。类型有范围，绝对值结果也可能超范围；零的绝对值还是零而不是正数。
4. 只有输入 9 求平方根符合这些条件。整数题可能要求精确结果，近似加截断既可能损失信息，也可能超出目标类型范围。
