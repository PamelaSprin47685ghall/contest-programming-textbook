# 查阅　格式文本与文件

这页不是按顺序读的课文。你手头遇到哪种情况，就翻到哪一小节：读一个数、读一个字符、读一段有固定格式的文字、读文件，每节都能单独查。本页的 C 风格输入输出来自 `<cstdio>`。地址与指针的细节，第 18 章讲过；一时不熟，先用前面章节已经学过的写法。

## 一次读取为什么可能只做了一半

我们看一个常见的小要求：输入像 `12,7` 这样两个整数，中间一个逗号。格式字符串写成 `"%d,%d"`，逗号是普通字符，必须与输入里的逗号对上。

**片段：**

```cpp
// 位于 main 内
int row = 0;
int column = 0;
int matched = std::scanf("%d,%d", &row, &column);
std::printf("read: %d\n", matched);
if (matched != 2) {
    std::printf("BAD INPUT\n");
    return 1;
}
std::printf("%d %d\n", row, column);
```

输入 `12,7`，两个整数都写进变量，`scanf` 返回 2。输入 `12;7` 呢？先读到 12，接着格式要逗号，输入里却是分号，读取就停在这里，返回 1。不是“已经开始读，就一定把两个数都读完”；`column` 保持初值 0，不能当作有效数据。

## 按格式字符串从左向右读

格式里的普通字符要与输入匹配，一个对一个。格式里的空白则很特别：一个空格、多个空格或换行，都表示“跳过任意多个输入空白”，不是必须读到同一种、同样多的空白。

| 格式部分 | 它做什么 | 保存到哪里 |
|---|---|---|
| `%d` | 跳过前导空白，读整数 | `int*`，常写 `&x` |
| `%lld` | 跳过前导空白，读较宽整数 | `long long*` |
| `%lf` | 跳过前导空白，读小数 | `double*` |
| `%c` | 直接读一个字符，不自动跳空白 | `char*` |
| `%15s` | 跳过前导空白，最多读 15 个非空白字节，再补空字符 | 容量至少 16 的字符数组 |
| `%15[ABC]` | 最多读 15 个属于 A、B、C 的字节，再补空字符 | 同上，不自动跳前导空白 |
| `%15[^,]` | 最多读 15 个不是逗号的字节，再补空字符 | 同上，不自动跳前导空白 |
| `%%` | 匹配输入里的一个百分号 | 不接变量 |
| `%n` | 不取新字符，把这次调用已经消耗的字符数写入变量 | 默认接 `int*` |

`%[` 后面的集合叫扫描集。别把它当成一般的正则表达式；取反的 `^` 是说“不在这个集合里”，不是乘方。遇到第一个不匹配的字节，这一项就停止，那个字节通常留在输入里，等格式中后续的部分去处理。

字符串转换至少要读到一个匹配字符才算成功。`%[^,]` 不能自动把空字段识别成一个成功读入的空串：若第一个就是逗号，这一项匹配失败。

### 为什么别随手在最后加一个空格

`scanf("%d ", &x)` 读到整数后，还会继续跳过输入里的空白，直到遇到非空白或输入结束。交互输入时，你已经按了回车，它却可能还在等，看起来像卡住。

不需要后续格式时，读整数直接用 `"%d"`。`" %c"` 则是有意在字符前跳空白：要读一个非空白符号时适合；要研究空格或换行本身时，就不合适。

## 返回值在数“成功存入了几项”

一般情况下，返回值是成功赋值的项数。普通字符、格式里的空白、`%n` 以及被抑制的转换，都不计入这个数。

先看 `%d%d` 这种读数格式。还没有成功保存第一个数就遇到输入结束或读取错误，返回宏 `EOF`；已经成功读了一项再遇到文件结束，返回 1，而不是 `EOF`。`EOF` 是一个负值，常见为 −1；程序里用 `== EOF` 比较，不要把它永远写死成 −1。

本页常见的“全是实际要保存的数据”的格式，检查 `返回值 == 预期项数` 就能判断是否读全。加了 `%n`、跳过项等特殊项时，要按具体格式判断，不能机械地数百分号。

**片段：**

```cpp
// 位于 main 内
int a = 0;
int b = 0;
int matched = std::scanf("%d%d", &a, &b);
```

若输入文件只有一个 `8` 就结束，`matched` 为 1；空文件是 `EOF`；第一个字符是 `X`，整数匹配失败，返回 0。变量初始化为零，不代表读取成功，不能把缺失的输入偷偷补成零。

还有一个边界：`scanf` 的整数转换不能当“任意长度数字都能安全处理”的验证器。输入数值必须在目标类型能表示的范围内；超范围的转换没有普通匹配失败那样的安全保证。书里程序因此都说明数值范围。

## 有些字段只想越过，不保存

转换里的星号表示抑制赋值：`%*d` 仍读取整数，但不需要对应变量，也不增加返回的赋值项数。下面从 `ticket=42,blue,18` 中跳过编号，读取颜色和数量，再记录消耗的字符数。

**片段：**

```cpp
// 位于 main 内，line 是已经写好的 C 风格字符串
const char line[] = "ticket=42,blue,18";
char color[16] = {};
int amount = 0;
int consumed = -1;
int matched = std::sscanf(line, "ticket=%*d,%15[^,],%d%n",
                          color, &amount, &consumed);
if (matched != 2 || consumed < 0) {
    return 1;
}
std::printf("%s %d %d\n", color, amount, consumed);
```

`sscanf` 从一个有效的 C 风格字符串读取，不从键盘读取。颜色扫描到逗号之前，后面的普通逗号再把分隔符匹配掉。`%n` 写入已经消耗的 17 个字符，不消耗输入，也不增加返回值，所以成功项数是 2，不是 3。若输入格式要求完全到此结束，可以再用 `consumed` 检查后面是否还有内容；本例是固定字符串，不需要把这个动作伪装成额外的万能验证。

## 输出到文字里，也要给容量

`printf` 向标准输出写，`fprintf` 向文件写。向字符缓冲区写文字，优先用带容量参数的 `snprintf`，而不是没有容量限制的 `sprintf`。

**片段：**

```cpp
// 位于 main 内
char label[16] = {};
int needed = std::snprintf(label, sizeof label, "BOX-%d", 27);
if (needed < 0 || static_cast<std::size_t>(needed) >= sizeof label) {
    return 1;
}
std::printf("%s\n", label);
```

成功时返回本来需要的字符数，不包括末尾空字符。若这个数不小于缓冲区容量，说明内容被截断，不能把它当成完整标签。这里先检查负值再转换，避免把错误值当成很大的无符号数。

`sprintf(buffer, 格式, 参数...)` 与它用途相近，但不接容量，输出过长时可能越界。要会认旧代码里的名字，不必为了“学全接口”在新代码里用危险写法。`printf` 想输出一个百分号，格式里写 `%%`。

## 把输入来源换成文件

下面这段读取 `measurements.txt` 里的两个整数，把和写进 `total.txt`。约定两个数的绝对值都不超过 1000000。只把自己可覆盖的结果文件命名为 `total.txt`，因为 `"w"` 模式会清空已有内容。

**片段：**

```cpp
// 位于 main 内
std::FILE* in = std::fopen("measurements.txt", "r");
if (in == nullptr) {
    std::fprintf(stderr, "Cannot open input.\n");
    return 1;
}
int a = 0;
int b = 0;
bool read_ok = std::fscanf(in, "%d%d", &a, &b) == 2;
int input_close = std::fclose(in);
if (!read_ok || input_close != 0) {
    std::fprintf(stderr, "Cannot read input.\n");
    return 1;
}

// 输入确认有效后，再打开输出文件
std::FILE* out = std::fopen("total.txt", "w");
if (out == nullptr) {
    std::fprintf(stderr, "Cannot open output.\n");
    return 1;
}
bool write_ok = std::fprintf(out, "%d\n", a + b) >= 0;
int output_close = std::fclose(out);
if (!write_ok || output_close != 0) {
    std::fprintf(stderr, "Cannot finish output.\n");
    return 1;
}
```

这比前三行相加的程序长，是因为文件多了真实的失败情况，不是加法变复杂了。`fopen` 打开文件，失败返回空指针；`"r"` 读已有文件，`"w"` 创建或覆盖文件。相对文件名从程序当前工作目录寻找，不一定是源代码所在目录。`fscanf` 与 `scanf` 的读取规则一致，前面多一个文件参数；`fprintf` 对应输出；`fclose` 关闭。

检查输入成功后才打开输出，避免明明没有有效输入，却先清空旧结果。写入和关闭都要检查：输出可能先缓存在程序里，到关闭时才暴露错误。发生写入失败时，也不能宣称文件一点没改，它可能已有部分内容。`stderr` 是错误输出通道，提示文字不写进 `total.txt`。在这段短程序里，每条成功打开文件的路径都会关闭它，失败不会被包装成一次成功计算。

## 核对

1. 三种输入依次得到 2、1、0。后两种没读到的变量不算有效输入，程序报告失败。
2. 前者先读到换行本身，后者跳过空白后读到 `R`。要保留空白本身时，不能跳过。
3. 返回 0 或 1 也不是 `EOF`，但同样没读全。`X` 属于匹配失败，返回 0。
4. 补一个 `int` 变量，按格式顺序传它的地址；成功项数变成 3。17 是整次解析消耗的字符数，不是颜色长度。
5. 六个可见字符，至少七字节。容量为 6 时放不下完整内容和空字符，返回所需长度仍是 6，检查会发现截断并退出。编译器若提前发现必然放不下，也可能先给出警告；这不是可以忽略的普通提示。
6. 不应对空文件指针读取。推迟打开输出，避免无效输入先毁掉旧结果。关闭失败就没有“完整写好”的证据，必须报告失败。
