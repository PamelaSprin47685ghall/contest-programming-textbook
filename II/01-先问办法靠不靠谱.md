# 01　先问办法靠不靠谱

运动会报名截止，体育委员和班长各数了一遍人数。体育委员照报名表一行一行数，得 31；班长对着全班名单，数打了勾的同学，得 27。两个人都没有数错：有 4 位同学各报了两项，体育委员数的是“报名次数”，班长数的是“报了名的人”。

第一卷里，一道题做完，常常就是样例对上了。这一卷要多问几句：答案到底在数什么？这个办法凭什么不漏、不重？数据大到十万、一亿时，它还来得及吗？怎样留下一份能核对它的证据？这一章把四个问题各走一遍。后面每一章换一种工具，这四个问题都要再问。

## 答案究竟在数什么

动手写循环以前，先用一句话说出答案是什么，再问：它真正取决于输入里的哪些东西？这两句说清楚了，很多题就去掉了一半的难处。

### 驯服牛群

约翰在牛棚墙上挂了一个计数器，显示“距上次奶牛逃跑过了几天”：逃跑那天早上显示 0，第二天显示 1，以此类推，直到下一次逃跑又回到 0。约翰从一次逃跑的那天开始记，所以第 1 天一定是逃跑日。他记了 N 天（1 到 100），可是有些天的记录丢了。问：在和留下的记录不矛盾的各种情况里，逃跑最少几次、最多几次？

输入第一行 N，第二行 N 个整数：`-1` 表示那天的记录丢了，否则是那天的读数（0 到 100）。怎样都对不上记录时，输出 `-1`；否则输出最少和最多的次数，中间一个空格。

样例输入：

```text
4
-1 -1 -1 1
```

样例输出：

```text
2 3
```

第 4 天读数是 1，说明第 3 天逃跑过、第 4 天没有。第 1 天本来就是逃跑日。只有第 2 天说不准，所以是 2 到 3 次。这是 USACO 2018 年 2 月铜组第三题[“驯服牛群”](../USACO/铜组/2017_2018/2018.02/P3.md)。

先说清一个读数在说什么。第 i 天读数是 v，等于说了两件事：第 i − v 天逃跑过；从第 i − v + 1 天到第 i 天，都没有逃跑。于是第 i − v 天到第 i 天这一整段的读数都被它定下了：0、1、2、……、v。一条记录不只管自己那一天，它管住了往前的一段。

所以倒着走最方便。从最后一天往前，手里拿着“照已知的记录，这一天应该是几”。遇到一条记录，就从它开始往前倒数；倒数到 0 以前又碰到另一条记录，两条必须一致，不一致就矛盾。第 1 天若被推成不是 0，也矛盾。全部推完，读数被定为 0 的日子一定逃跑了，仍然不知道的日子可逃可不逃。最少次数是前一种日子的个数，最多次数再加上后一种。

**停笔 1**　输入 `3` 和 `0 2 -1`，应输出什么？说出哪一条记录在哪一天和谁冲突。

### 空想性错视

约翰看什么都像牛。对一个只含小写字母的字符串 s，记 B(s) 为：从 s 里删去一些字符（也可以一个不删），剩下的部分最多能读成几个连在一起的 `bessie`。例如 `bqessiyexbesszieb` 删去一些字母，能读成 `bessiebessie`，B 等于 2。给一个长度不超过 30 万的字符串 t，求 t 的所有连续子串的 B 值之和。

输入一行字符串 t，输出一个整数。

样例输入：

```text
bessiebessie
```

样例输出：

```text
14
```

12 个子串恰好能读出一个 `bessie`，整串能读出两个，12 + 2 = 14。这是 USACO 2023 年 3 月银组第三题[“空想性错视”](../USACO/银组/2022_2023/2023.03/P3.md)。

照字面去做：子串约有 n²/2 个，n 到 30 万时是 450 亿个，每个还要扫一遍，无论如何来不及。先换一句话说答案。

一个串的 B 可以这样求：从左往右找最早的 `b`，再在它后面找最早的 `e`，接着是 `s`、`s`、`i`、`e`；凑齐一份，再从下一个字符起凑下一份。每次取最早结束的那一份，后面留下的字符最多，不会比别的拼法少。

固定起点 i，这样一路凑下去，得到一串结束位置 e₁ < e₂ < ……（位置从 0 编号）。一个从 i 开始、在 j 之前结束的子串，它的 B 就是这串结束位置里有几个小于 j：更短的子串，这样凑走的是同一条路，只是停得早一些。所以，把起点为 i 的所有子串的 B 加起来，可以改成问：每个结束位置 e，被几个子串算了进去？右端可以是 e 本身，也可以更靠右，一共 n − e 种。

于是答案换了一种说法：每个起点各凑一遍，凑出的每一份 `bessie` 按它的结束位置 e 记 n − e，全部加起来。这一份记的数，叫作它对答案的**贡献**。我们没有多算也没有少算，只是把同一个总和换了加法的次序：原来先按子串分组，现在先按“凑出来的一份 `bessie`”分组。

拿样例核对，n = 12。起点 0 凑出两份，结束于 5 和 11，记 7 + 1；起点 1 到 6，第一个 `b` 都在位置 6，各凑出一份结束于 11，各记 1；起点 7 以后凑不齐。7 + 1 + 6 = 14。

剩下的麻烦是 n 个起点各走一遍，仍然太慢。可以让所有起点一起往右走：扫到一个字符，先放进一个新起点，再让所有“正在等这个字母”的起点前进一格。凑 `bessie` 只有 6 种进度，所以不必记住每个起点，只记每种进度上有几个起点。一个起点凑齐一份时，它在这个位置结束，按个数一次记上贡献，再回到进度 0 接着凑。

**停笔 2**　`bessie` 里 `s` 连着出现两次。扫到一个 `s` 时，若先把“等第一个 `s`”的起点推进一格，再处理“等第二个 `s`”的起点，会算错什么？应该按什么次序处理各种进度？

## 一份短小、可以相信的办法

[第一卷第 8 章](../I/08-把一排数据存起来.md)见过“奶牛慢跑”的铜组版：快的牛追上慢的就合成一群，问最后剩几群。银组版多了一个时间。

N 头奶牛（1 到 10 万）在一条无限长的单车道跑道上慢跑，各自从不同位置出发，速度可能不同。跑道上不能超车：快的追上前面的牛，就减速跟着，成为同一组。一共跑 T 分钟（1 到 10⁹），结束时站在同一位置的牛算同一组。问还剩几组。

输入第一行 N 和 T；之后 N 行，每行两个整数，是一头牛的出发位置和速度。位置是非负整数，速度是正整数，都不超过 10⁹；位置互不相同，按从小到大给出。输出组数。

样例输入：

```text
5 3
0 1
1 2
2 3
3 2
6 1
```

样例输出：

```text
3
```

要是没有谁挡着，五头牛 3 分钟后分别到 3、7、11、9、9。第 4、5 头都到 9，是一组；第 3 头本该到 11，被前面挡住，也停在 9；第 2 头停在 7，第 1 头停在 3，各成一组。共 3 组。这是 USACO 2014 年 12 月银组第三题[“奶牛慢跑”](../USACO/银组/2014_2015/2014.12/P3.md)。

一份办法值得相信，至少要说清下面几件事。

**答案是什么。** 跑完时，牛们一共停在几个不同的位置。

**手里记什么。** 先算每头牛没人挡时的终点，叫它 `free_end`。然后从最前面的牛往后看，手里记 `front_end`：已经看过的牛都在当前这头前面，它们实际停下的位置里，最靠后的一个。

**为什么记这一个就够。** 不能超车，所以一头牛的实际终点，是它自己的 `free_end` 和它前面所有牛的实际终点里最小的那个。前面那些位置里，能挡住它的只有最靠后的那个。

**每一步怎样改。** 看到一头新牛：它的 `free_end` 比 `front_end` 小，它就停在所有前面的牛后面，不和谁站在一处，组数加一，`front_end` 改成它的终点；否则它会被挡在 `front_end`，并进那一组，什么都不用改。正好相等也是并进去：结束时站在同一位置，题目算一组。

**数放不放得下。** 终点可以到 10⁹ + 10⁹ × 10⁹，超过 `int`，要用 `long long`。乘法 `speed * minutes` 的两边都是 `long long`，乘的时候就不会溢出。组数不超过 N，`int` 够用。

**会不会停。** 循环从倒数第二头走到第一头，每头只看一次。

下面是**完整程序 A**。

```cpp
#include <cstdio>
#include <vector>

int main() {
    int n = 0;
    long long minutes = 0;
    if (std::scanf("%d%lld", &n, &minutes) != 2) {
        return 1;
    }
    std::vector<long long> free_end(n);
    for (int i = 0; i < n; ++i) {
        long long position = 0;
        long long speed = 0;
        if (std::scanf("%lld%lld", &position, &speed) != 2) {
            return 1;
        }
        free_end[i] = position + speed * minutes;
    }
    // front_end：已经看过的牛都在当前这头前面，记它们实际终点里最靠后的一个
    long long front_end = free_end[n - 1];
    int groups = 1;
    for (int i = n - 2; i >= 0; --i) {
        if (free_end[i] < front_end) {
            ++groups;
            front_end = free_end[i];
        }
    }
    std::printf("%d\n", groups);
    return 0;
}
```

最前面那头牛没人挡，自己就是一组，所以 `groups` 从 1 开始，`front_end` 从它的终点开始。题目保证 N 至少是 1，`free_end[n - 1]` 一定存在。

**停笔 4**　如果输入的位置不是从小到大给出的，程序 A 哪一个想法不再成立？要先补做什么？

## 不是所有循环都同样贵

程序 A 每头牛只看一次。换一种写法：对每头牛，把它前面的牛全看一遍，取实际终点的最小值。这也对，可 N 是 10 万时要比较约 50 亿次。

评测用的机器一秒钟大约能做几亿次简单运算。这只是估数，不同机器、不同运算差得不少，但足够分出“来得及”和“差得远”。50 亿次差得远。

估工作量时，我们只问它跟着 N 怎样涨。工作量大约和 N 成正比，写作 O(N)；和 N² 成正比，写作 O(N²)。这个记号叫**时间复杂度**，它说的是数据翻一倍时工作量怎样变：O(N) 跟着翻一倍，O(N²) 变成四倍。它不管前面的常数，也不说具体几秒。

还有一种常见的增长：把 N 一次次对半分，分到 1 要几次？这个次数写作 log N。N 是 10⁵ 时约 17 次，10⁹ 时约 30 次，10¹⁸ 时约 60 次。O(N log N) 的工作量只比 O(N) 多一个不大的倍数。

| N | O(N) | O(N log N) | O(N²) |
|---|---|---|---|
| 10³ | 10³ | 约 10⁴ | 10⁶ |
| 10⁵ | 10⁵ | 约 1.7 × 10⁶ | 10¹⁰ |
| 10⁶ | 10⁶ | 约 2 × 10⁷ | 10¹² |

占用的内存也要数。一个 `int` 通常占 4 字节，一个 `long long` 占 8 字节。程序 A 存 10 万个 `long long`，约 800 KB。金组“空置栏位”有 300 万个栏位，内存只给 64 MB：每个栏位一个 `int`，约 12 MB，放得下；要是每个栏位存好几个 `long long`，或者顺手复制几份，就得先算一算。

**停笔 5**　N = 2 × 10⁵，时限 1 秒。O(N)、O(N log N)、O(N²) 三种办法，哪些大概来得及？各要做多少次运算？

### 循环里套着一个 while，不一定是平方

M 种麦片，每种只有一盒（M 到 10 万）。N 头牛（到 10 万）排成一队，每头牛有最爱的麦片和第二喜欢的麦片，两者不同。轮到一头牛时：最爱的还在，就拿走；否则第二喜欢的还在，就拿走；都没了，空手离开。对每个 i（0 到 N − 1），问：把队伍最前面的 i 头牛赶走以后，有几头牛能拿到麦片？

输入第一行 N 和 M，之后 N 行，第 i 行是第 i 头牛最爱和第二喜欢的麦片编号（1 到 M）。输出 N 行。

样例输入：

```text
4 2
1 2
1 2
1 2
1 2
```

样例输出：

```text
2
2
2
1
```

只要还剩至少两头牛，就恰好有两头拿到麦片。这是 USACO 2020 年 3 月银组第二题[“麦片”](../USACO/银组/2019_2020/2020.03/P2.md)。

每个 i 都从头模拟一遍，是 O(N²)。换个方向：先只有最后一头牛，再一头一头往队首加牛。新来的牛排在所有人前面，先挑。她拿走最爱的那盒；要是那盒原来在排在后面的某头牛手里，那头牛只好退一步，去试自己的第二志愿，又可能挤走另一头牛……一次加牛，可能引出一串让位。

下面是**片段**，位于 `main` 内。牛和麦片都从 1 编号，`holder[c]` 是拿着麦片 c 的牛，0 表示没人拿；编号小的牛排在前面。

```cpp
// 位于 main 内；favorite、second、holder、answer 都已建好，holder 全为 0
int count = 0;
for (int i = n; i >= 1; --i) {
    int cow = i;
    int cereal = favorite[i];
    while (true) {
        int other = holder[cereal];
        if (other == 0) {          // 这盒没人拿
            holder[cereal] = cow;
            ++count;
            break;
        }
        if (other < cow) {         // 拿着它的牛排在前面，抢不过
            break;
        }
        holder[cereal] = cow;      // 排在后面的 other 让出这盒
        if (cereal == second[other]) {
            break;                 // 这是 other 的第二志愿，other 空手
        }
        cow = other;
        cereal = second[other];
    }
    answer[i] = count;
}
```

`answer[i]` 是从第 i 头牛开始排队时的答案，赶走前 i 头牛，就是输出 `answer[i + 1]`。`count` 只在链条最后落到一盒没人拿的麦片上时加一：中间每让一次位，一头牛得到、一头牛失去，人数不变。

外层循环 N 次，里面的 `while` 看上去可能很长，一共是不是 O(N²)？别数一次最坏走几步，数整件事一共走了几步。`while` 每多转一圈，就有一头牛被挤走一次。一头牛被挤走，处境只会变坏：从拿着最爱的，变成拿着第二喜欢的；从拿着第二喜欢的，变成空手。往队首加牛，永远不会让后面的牛变好。所以每头牛一辈子最多被挤走两次，所有 `while` 加起来不超过 3N 圈，整个程序是 O(N + M)。

这种数法叫**均摊分析**：某一次可能很贵，但贵的次数被别的东西限制住了。第三卷第 27 章会把它讲得更细。

## 先留下能核对的答案

理由写在纸上，程序写在屏幕上，两者中间还隔着手误。最便宜的核对是：再写一个慢但直白的程序，造很多组小数据，让两份程序比答案。这种做法叫**对拍**。慢程序越直白越好，它应该照着题意写，不是照着快程序改。

“奶牛慢跑”的慢程序就用上一节嫌慢的办法：每头牛把前面的牛全看一遍，算出实际终点，再数有几个不同的终点。

**片段：**

```cpp
// 位于 main 内；free_end 已照程序 A 算好
std::vector<long long> actual(n);
for (int i = 0; i < n; ++i) {
    actual[i] = free_end[i];
    for (int j = i + 1; j < n; ++j) {
        if (free_end[j] < actual[i]) {
            actual[i] = free_end[j];
        }
    }
}
int groups = 1;
for (int i = 1; i < n; ++i) {
    if (actual[i] != actual[i - 1]) {
        ++groups;
    }
}
std::printf("%d\n", groups);
```

`actual[i]` 是第 i 头到最后一头的 `free_end` 里最小的，越往后，参加比较的牛越少，所以 `actual` 从前往后不会变小，相同的终点挨在一起，数相邻不同就是数不同终点。

再写一个造数据的**完整程序**。它读一个种子，用它造一组小输入：牛不超过 6 头，速度和时间都很小，这样终点容易撞在一起，等号上的错才有机会露出来。

```cpp
#include <cstdio>
#include <cstdlib>

int main() {
    unsigned seed = 0;
    if (std::scanf("%u", &seed) != 1) {
        return 1;
    }
    std::srand(seed);
    int n = 1 + std::rand() % 6;
    int minutes = 1 + std::rand() % 4;
    std::printf("%d %d\n", n, minutes);
    int position = std::rand() % 3;
    for (int i = 0; i < n; ++i) {
        int speed = 1 + std::rand() % 5;
        std::printf("%d %d\n", position, speed);
        position += 1 + std::rand() % 3;   // 至少加 1：位置互不相同，从小到大
    }
    return 0;
}
```

三份程序分别编译成 `gen`、`fast`、`slow`，在终端里让它们比 500 组：

```sh
for i in $(seq 1 500); do
    echo $i | ./gen > in.txt
    ./fast < in.txt > fast.txt
    ./slow < in.txt > slow.txt
    if ! cmp -s fast.txt slow.txt; then
        echo "第 $i 组不同"
        break
    fi
done
```

一组不同就停下，`in.txt` 里留着那组输入，可以拿到纸上一步步算。500 组都相同，也只说明这些小数据上两份程序一致。

还要看清两份程序共用了什么。它们都用了“实际终点等于自己和前面所有牛的终点里最小的那个”。对拍能抓住扫描方向、等号、`long long` 这一类错，抓不住这条事实本身的错；这条事实要靠上一节写下的理由。往后写慢程序，尽量少和快程序共用想法：能枚举全部方案就枚举，能一步步模拟就模拟。

**停笔 7**　把程序 A 的 `<` 改成 `<=` 再对拍。随机数据里出现什么情况，才能抓住这个错？如果生成器里速度能取到 10⁹，这种情况还容易出现吗？

这一章问了四件事：答案在数什么，办法凭什么对，要做多少工作、占多少地方，拿什么来核对。答案在数什么，有时换一种分组来数更快，像“空想性错视”；凭什么对，要说清手里每个数的意思和每一步的改法，像“奶牛慢跑”；工作量要数整件事，不只数一层循环，像“麦片”。能对一道新题把这四件事各说一两句，再读下一章。下一章的候选多到写不出几层循环，要让函数自己调用自己。

## 核对

1. 输出 `-1`。第 2 天读数 2，要求第 0 天逃跑，可是记录从第 1 天开始，而且第 1 天就是逃跑日，第 2 天只能是 1。
2. 同一个 `s` 会把同一批起点推进两格，一个字母被用了两次，凑出的 `bessie` 会多。要从进度大的往进度小的处理：先处理等第二个 `s` 的，再处理等第一个 `s` 的。`e` 也出现两次，但两次不挨着，推进一格后等的已是别的字母；一律从大往小处理，就不必逐个字母去想。
3. 输出 4。第 4、5 头牛终点都是 9，`<=` 让第 4 头又算了一组。
4. “倒着扫就是从最前面的牛往后看”不成立了。要先把（位置，速度）按位置从小到大排序，再照原样扫。
5. 2 × 10⁵ 次和约 3.5 × 10⁶ 次都来得及；O(N²) 要 4 × 10¹⁰ 次，来不及。
6. 新来的牛只会占走一盒麦片，或者引起一串让位，后面的牛能挑的盒子只少不多。
7. 要有两头牛的 `free_end` 相等，而且后一头的终点就是当时的 `front_end`。速度能取到 10⁹ 时，终点很少相等，这个错可能几千组都碰不上。所以对拍的数据不仅要小，值的范围也要小。
