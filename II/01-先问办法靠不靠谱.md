# 01　先问办法靠不靠谱

六张卡片写着一些整数。要找两张，使它们的和是 10。你一眼看见 4 和 6，却可能漏掉后面的另一张 4。程序需要的不是“看起来能找着”，而是一套不会漏、不会重复的安排。

## 答案究竟在数什么

这里数的是**位置对**。卡片为 `4 6 4` 时，第一张和第二张、第二张和第三张是两对。不能因为两张卡片都写着 4，就把它们合成一张。

把位置叫作 `i`、`j`，只检查 `i < j`。这样一对卡片不会先算 `(i,j)`，又算 `(j,i)`；也不会让卡片和自己配对。

**停笔 1**　卡片为 `5 5 5`，目标为 10，有几对？若允许 `i == j`，会多出哪些不合题意的方案？

## 一份短小、可以相信的办法

**完整程序：**输入 `0 <= n <= 200`、目标 `target`，再输入 `n` 个整数。目标及卡片值的绝对值不超过一百万。输出位置对的数量。后面的程序也会明确约定输入范围；读取失败就结束，不编造答案。

```cpp
#include <cstdio>
#include <vector>

int main() {
    int n = 0;
    int target = 0;
    if (std::scanf("%d%d", &n, &target) != 2 || n < 0 || n > 200) {
        return 1;
    }
    std::vector<int> cards(n);
    for (int& value : cards) {
        if (std::scanf("%d", &value) != 1) {
            return 1;
        }
    }
    int answer = 0;
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            if (cards[i] + cards[j] == target) {
                ++answer;
            }
        }
    }
    std::printf("%d\n", answer);
    return 0;
}
```

输入：

```text
3 10
4 6 4
```

输出：

```text
2
```

说明正确性时，分开回答：每个被数的方案合法吗？每个合法方案会出现吗？会出现几次？任意两张不同卡片都有一个较小位置和一个较大位置，恰好对应一轮检查。这就同时回答了后两个问题。

## 不是所有循环都同样贵

`n = 4` 时，内层分别检查 3、2、1、0 次，共 6 次。一般是 `n*(n-1)/2` 次。把 `n` 翻倍，检查次数大约变成四倍，不是两倍。

我们用 `O(n²)` 记录这种增长方式。`O` 读作“大 O”；它描述规模增大后的上界，忽略固定倍数，不是精确秒数。只扫一遍是 `O(n)`；始终只做几次操作是 `O(1)`。额外保存 `n` 个整数，需要 `O(n)` 空间。

以后还会遇到 `O(log n)`：每次剩下一半，从 1024 减到 1 只要 10 次。这里 `log` 先按以 2 为底理解；换一个固定底数，不改变大 O 分类。

**停笔 2**　`n = 200` 时检查多少对？`n = 200000` 呢？后一种规模还能不加思考地照搬这个程序吗？

## 先留下能核对的答案

小范围逐个试的办法叫**朴素算法**。它不因为慢就没有价值：以后写出快算法，可以让两个程序处理同一份小输入，对照答案，这叫**对拍**。

但两个程序抄同一段判断，可能一起错。朴素版应从题意独立出发。还要自己核对空输入、只有一项、全部相同、没有答案、恰好卡住边界这些情况。

编译警告和越界检查能发现部分实现问题，不能证明算法正确。测一万个样例也不能代替“为什么不漏”的解释。

**停笔 3**　有人把内层起点改成 `j = i`。找一个最短输入，使改动后的答案与题意不同。再解释为什么“随机试了很多次没问题”仍不足以宣布正确。

## 核对

1. 三对。允许同位置会多算三张卡片各自与自己的配对。
2. 19900 对；19999900000 对。后者已接近二百亿次检查，应先换办法，计数也要改用更宽的类型。
3. 一张值为 5 的卡片、目标 10 就够：应为零对，错误版算一对。随机数据不保证碰到造成错误的边界。

后面每个办法都沿用这三件事：先定清答案，说明为何正确，再估算需要多少工作。
