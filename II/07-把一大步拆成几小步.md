# 07　把一大步拆成几小步

走 13 步，不一定逐步登记。先准备走 1、2、4、8 步的结果，13 就是 8 加 4 加 1。这种“一份变两份”的准备，在许多问题中都用得到。

## 每次只解决一半

归并排序把两半都处理，所以每层仍要照看所有元素。二分查找只进入一半，所以总共只走一条链。都是“变小”，工作量却不同。

拆分时先说明：小问题是什么；答案怎样合起来；小到什么时候直接完成。递归栈会占空间，深度不受控制时还可能耗尽栈。不要把长链上十万层的递归当作安全默认值。

## 平方一次，等于准备两份相同的路

求 `base` 的 `exponent` 次方。若指数为偶数，先算一半的次方再平方；若为奇数，多乘一个 `base`。也可以从指数的二进制位出发，逐位决定要不要乘上当前这一份。

数很大时，只要余数。`(a*b) % modulus` 与先把 `a`、`b` 各取余再相乘取余，结果相同。这个规则来自把整数分成“整倍数加余数”。

**完整程序：**输入 `0 <= base <= 1000000000`、`0 <= exponent <= 10^18`、`1 <= modulus <= 1000000000`，输出次方的余数。本例把零次方定义为 1，包括 `base=0` 的情况。

```cpp
#include <cstdio>

int main() {
    long long base = 0;
    long long exponent = 0;
    long long modulus = 0;
    if (std::scanf("%lld%lld%lld", &base, &exponent, &modulus) != 3
        || base < 0 || base > 1000000000 || exponent < 0
        || exponent > 1000000000000000000LL || modulus < 1 || modulus > 1000000000) {
        return 1;
    }
    long long result = 1 % modulus;
    base %= modulus;
    while (exponent > 0) {
        if (exponent % 2 == 1) {
            result = result * base % modulus;
        }
        base = base * base % modulus;
        exponent /= 2;
    }
    std::printf("%lld\n", result);
    return 0;
}
```

输入：

```text
3 13 100
```

输出：

```text
23
```

这是**快速幂**，乘法次数为 `O(log exponent)`。零指数不进循环；模数为 1 时答案始终为 0。每次两个余数的乘积小于 `10^18`，本环境 `long long` 能装下；模数若扩大到接近类型上限，这份乘法就不再安全。

循环中始终保持：`result` 乘上“当前 base 的剩余 exponent 次方”，与原目标有相同余数。这叫**循环不变量**，描述每轮前后都没丢掉的事实。

## 连走很多次，也能提前准备

每个地点只有一个“下一站”。设 `jump[0][v]` 是从 `v` 走一步的位置，`jump[p+1][v] = jump[p][jump[p][v]]`，就准备好了走 `2^(p+1)` 步的位置。查询第 13 站时，按 8、4、1 步跳。这叫**倍增**。

准备 `O(n log K)` 时间和空间，每问 `O(log K)`，`K` 是最大步数。不是只能处理没有圈的路线；函数图有圈也能跳。缺少下一站时，要先约定是停留，还是用一个不会越界的空标记。

两排各有很多选择，枚举全部配对太贵时，还可以各自枚举一半方案，再把两半按和匹配，称为折半搜索。40 个选或不选从约一万亿份，变成两组各约一百万份；排序匹配还要另算工作量。

**停笔 3**　下一站是 `0→1→2→0`，从 0 走 5 步到哪里？为什么倍增的表能存在，不能说明最终位置一定不同于起点？

## 核对

1. 三层，八个单项段。二分只选择包含目标的一侧，不遍历所有单项。
2. 1、4、8 次方。乘法的起点应为 1，零会使结果一直为零。
3. 到 2。路线可以成圈，表保存的是确定步数后的结果，不保证产生新地点。
