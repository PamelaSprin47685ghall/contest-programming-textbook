# 08　给已经解决的小问题留个位置

做算术题的人都有过这种经历：草稿纸上算过一遍 17 × 23，十分钟后又要用，却想不起写在哪里，只好重算。要是一开始就在纸边留一栏，写上“17 × 23 = 391”，后面就只是抄一下。

[第 2 章](02-把选择走成一棵树.md)的搜索树里，同一个小问题常常在不同的分支上出现很多次。这一章的办法是：**先说清楚小问题是什么，给每个小问题在表里留一格，算一次，以后只查。**难的不是写循环，而是让表里每一格都有一句说得清的含义。

## 表格里每个数都要有一句含义

### 团队合作

农夫约翰的 N 头牛（N 到 10⁴）排成一排，第 i 头的技能值是 sᵢ（到 10⁵）。他要把它们分成若干队，每队是连续的一段，至多 K 头（K 到 10³）。比赛时，一队里每头牛的技能都变成这一队的最高值。怎样分队，能让所有牛的技能之和最大？

输入第一行 N 和 K，之后 N 行，每行一个技能值。输出最大的技能之和。

样例输入：

```text
7 3
1
15
7
9
2
5
10
```

样例输出：

```text
84
```

分成 {1, 15, 7}、{9}、{2, 5, 10}：15 × 3 + 9 + 10 × 3 = 84。这是 USACO 2018 年 12 月金组第三题[“团队合作”](../USACO/金组/2018_2019/2018.12/P3.md)。

搜索的话，相邻两头牛之间切或不切，有 2ᴺ⁻¹ 种分法。可是它们有大量相同的部分：只要前 4 头牛的分法已经定了，后面怎样分，和前 4 头具体怎样分无关，只和“前 4 头最多能得多少分”有关。

所以给每个前缀留一格：**`best[i]` 是只看前 i 头牛时，能得到的最大技能之和。**这句话要写得这样具体，才能接着问：`best[i]` 从哪里来？前 i 头牛里，最后一队一定是某一段 [i − len, i)，len 从 1 到 K。这一队的得分是 len 乘上这一段的最大值；它前面是前 i − len 头牛，按最好的方式分，就是 `best[i − len]`。把每个 len 都试一遍，取最大。

`best[0]` 是 0：没有牛，就没有分。答案是 `best[n]`。

下面是**完整程序 A**。

```cpp
#include <algorithm>
#include <cstdio>
#include <vector>

int main() {
    int n = 0;
    int k = 0;
    if (std::scanf("%d%d", &n, &k) != 2) {
        return 1;
    }
    std::vector<int> skill(n);
    for (int i = 0; i < n; ++i) {
        if (std::scanf("%d", &skill[i]) != 1) {
            return 1;
        }
    }
    // best[i]：只看前 i 头牛（第 0 到第 i - 1 头），把它们编好队，技能和最大是多少
    std::vector<int> best(n + 1, 0);
    for (int i = 1; i <= n; ++i) {
        int highest = 0;           // 最后一队 [i - len, i) 里最高的技能
        for (int len = 1; len <= k && len <= i; ++len) {
            highest = std::max(highest, skill[i - len]);
            best[i] = std::max(best[i], best[i - len] + len * highest);
        }
    }
    std::printf("%d\n", best[n]);
    return 0;
}
```

内层循环让 len 从 1 往上走，最后一队往左多包一头牛，`highest` 就和新进来的那头比一下，这样不用每次重新扫一遍这一段。一共 N × K 次，约 10⁷。技能之和至多 10⁴ × 10⁵ = 10⁹，`int` 放得下。

这种做法叫**动态规划**：把问题拆成一组小问题，每个小问题的答案存进表里的一格；这一格的含义叫**状态**，算一格时用到哪些已经算好的格子，叫**转移**。动态规划能用，靠的是两件事：算 `best[i]` 只需要更小的下标，所以按 i 从小到大算，用到的格子都已经填好；后面怎么分只需要知道 `best[i]` 这一个数，不需要知道前面具体怎样分。

我用切或不切的搜索，对 N 到 9 的四百组随机输入和程序 A 对拍，结果全部相同。

**停笔 1**　照程序 A 算样例，写出 `best[0]` 到 `best[7]`。

## 从“剩下什么”看，怎样才能合并

### 平衡的奶牛品种

给一个括号串，长度 N（N 到 1000）。每个括号都要指派给荷斯坦牛（H）或根西牛（G），要求只看 H 的那些括号是平衡的，只看 G 的那些括号也是平衡的。平衡的意思和平常一样：左右括号能一一配对，而且任何一个前缀里右括号都不比左括号多。问有几种指派方法，答案除以 2012 取余。

输入一行括号串，输出方法数。

样例输入：

```text
(())
```

样例输出：

```text
6
```

把串写成 1 2 3 4 号括号。四个全给 H 或全给 G，是 2 种；1、4 给 H，2、3 给 G，或者反过来，又是 2 种；1、3 给 H，2、4 给 G，或者反过来，也是 2 种。一共 6 种。这是 USACO 2012 年 11 月银组第三题[“平衡的奶牛品种”](../USACO/银组/2012_2013/2012.11/P3.md)。

从左往右指派。走到第 i 个括号时，以后能不能成功、有几种走法，只和两件事有关：H 现在多出几个左括号没配上（叫 H 的深度），G 现在多出几个。前面具体怎样指派，以后不再关心。所以状态可以写成“看过 i 个括号，H 深度 a，G 深度 g”。

还能再省。两个深度相加，就是整个前缀的深度：左括号数减右括号数，和怎样指派无关。所以 g 由 i 和 a 决定，状态只要记 i 和 a。这就是这一节的意思：先问“走到这里，剩下的局面还需要知道什么”；两条路剩下的局面一样，就合并成一格，方法数相加。

**片段：**

```cpp
// 位于 main 内；text 是读入的括号串，长度 n
const int MOD = 2012;
// ways[a]：已经看过的前缀里，H 的括号深度是 a、而且两种牛都没出过错的分法有几种。
// G 的深度不必另记：它等于整个前缀的深度减去 a
std::vector<int> ways(n + 2, 0);
ways[0] = 1;
int depth = 0;             // 整个前缀的深度
for (int i = 0; i < n; ++i) {
    std::vector<int> next(n + 2, 0);
    for (int a = 0; a <= depth; ++a) {
        if (ways[a] == 0) {
            continue;
        }
        int g = depth - a;
        if (text[i] == '(') {
            next[a + 1] = (next[a + 1] + ways[a]) % MOD;     // 给 H
            next[a] = (next[a] + ways[a]) % MOD;             // 给 G
        } else {
            if (a > 0) {
                next[a - 1] = (next[a - 1] + ways[a]) % MOD; // 给 H
            }
            if (g > 0) {
                next[a] = (next[a] + ways[a]) % MOD;         // 给 G
            }
        }
    }
    depth += (text[i] == '(') ? 1 : -1;
    if (depth < 0) {
        break;     // 整串有一个前缀右括号多了，两种牛不可能都平衡
    }
    ways = next;
}
std::printf("%d\n", depth == 0 ? ways[0] : 0);
```

遇到左括号，给 H 就是 a 加一，给 G 就是 g 加一、a 不变；遇到右括号，给谁就要谁的深度大于 0。整串的深度在某处变成负数，两种牛加起来右括号已经多了，不必再算。最后两种牛都要配完，也就是整串深度为 0、而且 a 为 0。

每读一个括号只用到上一格，所以只留一行 `ways`，再开一行 `next`。一共 N × N 次，约 10⁶。我用枚举 2ᴺ 种指派的程序，对 N 到 10 的三百个随机串检查了这段代码。

**停笔 2**　照片段算样例 `(())`，写出每读完一个括号后的 `ways`。

### 均分草捆

农夫约翰有 N 捆干草（N 到 20），第 i 捆重 sᵢ（到 100）。他要把每一捆都放进三个谷仓之一，让最重的那个谷仓尽量轻。输出最重的谷仓最少有多重。

输入第一行 N，之后 N 行，每行一捆的重量。

样例输入：

```text
8
14
2
5
15
8
9
20
4
```

样例输出：

```text
26
```

总重 77，三个谷仓至少有一个不轻于 77 / 3，也就是 26。分成 {14, 8, 4}、{15, 9, 2}、{20, 5}，重 26、26、25，正好做到。这是 USACO 2012 年 1 月银组第二题[“均分草捆”](../USACO/银组/2011_2012/2012.01/P2.md)。

每捆三种去向，搜索是 3²⁰ ≈ 3.5 × 10⁹ 种，太多。还是问：分完前几捆以后，剩下的事需要知道什么？只需要知道三个谷仓现在各重多少。三个重量之和是已分的总重，记两个就够：**`reach[a][b]` 是“分完已经看过的那些捆，1 号谷仓能不能恰好重 a、2 号恰好重 b”。**这一格存的不是数量，是能不能做到。

**片段：**

```cpp
// 位于 main 内；bale 已读入，共 n 捆，total 是总重
// reach[a][b]：已经分过的那些捆，能不能让 1 号谷仓重 a、2 号谷仓重 b
std::vector<std::vector<bool>> reach(total + 1, std::vector<bool>(total + 1, false));
reach[0][0] = true;
for (int i = 0; i < n; ++i) {
    int s = bale[i];
    // a、b 都从大往小走：用到的 reach[a - s][b]、reach[a][b - s] 还没算进这一捆
    for (int a = total; a >= 0; --a) {
        for (int b = total; b >= 0; --b) {
            if (a >= s && reach[a - s][b]) {
                reach[a][b] = true;
            }
            if (b >= s && reach[a][b - s]) {
                reach[a][b] = true;
            }
        }
    }
}
int best = total;
for (int a = 0; a <= total; ++a) {
    for (int b = 0; a + b <= total; ++b) {
        if (reach[a][b]) {
            best = std::min(best, std::max(std::max(a, b), total - a - b));
        }
    }
}
std::printf("%d\n", best);
```

每看一捆，就把表更新一遍：原来能做到 (a − s, b) 的，现在把这一捆放进 1 号，就能做到 (a, b)；放进 2 号同理；放进 3 号，a、b 都不变，原来是 `true` 的格子不用动。

要紧的是两重循环都从大往小走。表只有一张，更新是在原地做的。算 `reach[a][b]` 时要用的是“这一捆还没放”的旧值；a 从大往小走，`reach[a − s][b]` 的 a 更小，这一轮还没轮到它，仍是旧值；`reach[a][b − s]` 同理。要是从小往大走，`reach[a − s][b]` 可能刚刚因为这一捆变成 `true`，同一捆就被放了两次。这一节的题都有这种“每件只能拿一次”的约束，人们常把它叫作**背包**：一堆物品，每件拿或不拿（或者放进几个地方之一），按已经拿了多少来记状态。

总重至多 2000，表有约 4 × 10⁶ 格，每捆扫一遍，20 捆约 8 × 10⁷ 次。我用枚举 3ᴺ 种分法的程序，对 N 到 7 的三百组随机输入检查了这段代码。

## “不超过”与“恰好”不是同一张表

### 牛奶桶

农夫约翰有两只小桶，容量 X 和 Y（1 ≤ X < Y ≤ 1000），还有一只容量 M 的大桶（Y < M ≤ 1000）。他用小桶一次次装满牛奶倒进大桶，每只小桶用几次都可以，但大桶不能溢出。大桶最多能装多少牛奶？

输入一行 X、Y、M，输出最多的牛奶量。

样例输入：

```text
17 25 77
```

样例输出：

```text
76
```

三桶 17 加一桶 25 是 76。77 本身凑不出来：用 0、1、2、3 桶 25 以后，剩下 77、52、27、2，都不是 17 的倍数。这是 USACO 2016 年 2 月铜组第一题[“牛奶桶”](../USACO/铜组/2015_2016/2016.02/P1.md)。

这题有两种表，各说一句不同的话。第一种：**`exact[v]` 是“能不能恰好倒进 v 单位”。**最后倒进去的一桶是 X 或 Y，所以 `exact[v]` 看 `exact[v − X]` 和 `exact[v − Y]`。

**片段：**

```cpp
// 位于 main 内；x、y、m 已读入
// exact[v]：能不能恰好倒进 v 单位
std::vector<bool> exact(m + 1, false);
exact[0] = true;
for (int v = 1; v <= m; ++v) {
    exact[v] = (v >= x && exact[v - x]) || (v >= y && exact[v - y]);
}
int answer = 0;
for (int v = 0; v <= m; ++v) {
    if (exact[v]) {
        answer = v;
    }
}
```

开始只有 `exact[0]` 是 `true`：什么也不倒，恰好是 0。这张表回答的是“恰好”，题目问的却是“不超过 M 的最大值”，所以最后还要把整张表扫一遍，找最大的 `true`。

第二种：**`at_most[v]` 是“容量若是 v，最多能倒进多少”。**最后倒进去的一桶若是 X，前面倒的那些不超过 v − X，最多是 `at_most[v − X]`；什么也不倒也行，是 0。

**片段：**

```cpp
// 位于 main 内；x、y、m 已读入
// at_most[v]：桶的容量若是 v，最多能倒进多少
std::vector<int> at_most(m + 1, 0);
for (int v = 1; v <= m; ++v) {
    if (v >= x) {
        at_most[v] = std::max(at_most[v], at_most[v - x] + x);
    }
    if (v >= y) {
        at_most[v] = std::max(at_most[v], at_most[v - y] + y);
    }
}
```

这张表开始时每一格都是 0，因为空桶对任何容量都不超过；答案直接是 `at_most[m]`，不用再扫。两张表的初值、转移、读答案的地方都不同，混着写就会错。动手写表之前，先用一句话写出这一格的含义，初值和答案在哪一格就跟着定了。

这里的循环是从小往大走的，和“均分草捆”相反：小桶可以用很多次，`exact[v − X]` 刚刚用过 X，再用一次正是题目允许的。

我用枚举两种小桶各用几次的程序，对三百组随机的 X、Y、M 检查了两段代码，两张表给出的答案都和它相同。

## 答案由一段的两头决定

### 合成 248

一排 N 个正整数（N 到 248），每个在 1 到 40 之间。每一步可以选两个相邻、相等的数，把它们换成一个比原数大 1 的数。合并可以做任意多次，也可以不做。最后这一排里最大的数最大能是多少？

输入第一行 N，之后 N 行，每行一个数。输出能得到的最大的数。

样例输入：

```text
4
1
1
1
2
```

样例输出：

```text
3
```

先合并第 2、3 个 1，得到 1 2 2；再合并两个 2，得到 1 3。要是先合并前两个 1，得到 2 1 2，就卡住了。这是 USACO 2016 年 3 月金组第三题[“合成 248”](../USACO/金组/2015_2016/2016.03/P3.md)。

最后得到的那个最大的数，一定是由原来连续的一段合成的。所以小问题是：**`merged[i][j]` 是 [i, j) 这一段能不能合成一个数，能的话是几。**一段合成一个数，最后一步一定是左右两部分各自先合成一个数，而且两个数相等。分界点 mid 不知道，就每个都试。

一段合成出来的数只有一种可能：每次合并，两个 v 换成一个 v + 1，2ᵛ + 2ᵛ = 2ᵛ⁺¹，所以每个数 v 换成 2ᵛ 再加起来，这个和始终不变。一段最后若只剩一个数 w，2ʷ 就等于这一段原来的和，w 就定了。所以一格存一个数就够。

**片段：**

```cpp
// 位于 main 内；value 已读入，共 n 个
// merged[i][j]：[i, j) 这一段能合成一个数时，记那个数；不能时记 0
std::vector<std::vector<int>> merged(n + 1, std::vector<int>(n + 1, 0));
int answer = 0;
for (int i = 0; i < n; ++i) {
    merged[i][i + 1] = value[i];
    answer = std::max(answer, value[i]);
}
for (int len = 2; len <= n; ++len) {
    for (int i = 0; i + len <= n; ++i) {
        int j = i + len;
        // 最后一次合并，是左边 [i, mid) 合成的数和右边 [mid, j) 合成的数
        for (int mid = i + 1; mid < j; ++mid) {
            if (merged[i][mid] != 0 && merged[i][mid] == merged[mid][j]) {
                merged[i][j] = merged[i][mid] + 1;
            }
        }
        answer = std::max(answer, merged[i][j]);
    }
}
std::printf("%d\n", answer);
```

按长度从短到长算，算长度为 len 的一段时，它的左右两部分都更短，已经算好。这种状态是“一段 [i, j)”、按长度递推的写法，常叫**区间动态规划**。约 N³ / 6 ≈ 2.5 × 10⁶ 次。

我用枚举所有合并顺序的程序，对 N 到 7、数在 1 到 3 之间的三百组随机输入检查了这段代码。

1. `best` 依次是 0、1、30、45、54、63、72、84。比如 `best[5]`：最后一队是 {2} 时 54 + 2 = 56；是 {9, 2} 时 45 + 2 × 9 = 63；是 {7, 9, 2} 时 30 + 3 × 9 = 57；取 63。
2. 读第一个 `(` 后 `ways` 是 [1, 1]；第二个 `(` 后 [1, 2, 1]；第一个 `)` 后 [3, 3, 0]；第二个 `)` 后 `ways[0]` = 6，深度 0，输出 6。
3. `true`。a = 2 时 `reach[2][0]` 由 `reach[0][0]` 变成 `true`；a = 4 时 `reach[2][0]` 已经是新值，`reach[4][0]` 也变成 `true`。它说的是把这一捆在 1 号谷仓里放了两次，这不是一种分法。
