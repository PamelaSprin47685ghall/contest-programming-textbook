# 09　眼前的选择凭什么放心

活动室有几项预约，一次只能做一项。只想参加尽量多项，是先挑开始最早的，还是先挑时间最短的？听起来合理的规则，可能给出不同答案。

## 先试着推翻它

“开始最早”会被一项很长的活动困住：`[0,10)` 占满时间，而 `[1,2)`、`[2,3)` 能参加两项。

“时间最短”也不保证对：短活动 `[2,4)` 会挡住 `[0,3)` 和 `[3,6)` 两项。我们需要的不是另一个口号，而是可以证明的选择。

**停笔 1**　以上区间都左闭右开。为什么 `[0,3)` 与 `[3,6)` 可以一起选？如果题意要求两项之间至少休息一单位时间，判断要改哪里？

## 最早结束，给后面留最多机会

选结束最早的一项。设某份最优安排的第一项不是它，把第一项换成它：结束不会更晚，后面原能参加的项仍能参加，数量不减少。于是至少有一份最优安排以它开头。

剩下的也是同类问题，反复执行。这叫**交换论证**：并不是宣称所有最优解都长得一样，而是证明可以把一个最优解改成与当前选择一致的最优解。

**完整程序：**输入 `0 <= n <= 100000`，每项给 `0 <= start < finish <= 1000000000`。输出最多能参加的项数。

```cpp
#include <algorithm>
#include <cstdio>
#include <vector>

struct Activity {
    int start;
    int finish;
};

int main() {
    int n = 0;
    if (std::scanf("%d", &n) != 1 || n < 0 || n > 100000) {
        return 1;
    }
    std::vector<Activity> activities(n);
    for (Activity& activity : activities) {
        if (std::scanf("%d%d", &activity.start, &activity.finish) != 2
            || activity.start < 0 || activity.start >= activity.finish) {
            return 1;
        }
    }
    std::sort(activities.begin(), activities.end(),
              [](const Activity& a, const Activity& b) {
                  return a.finish < b.finish;
              });
    int answer = 0;
    int available = 0;
    for (const Activity& activity : activities) {
        if (activity.start >= available) {
            ++answer;
            available = activity.finish;
        }
    }
    std::printf("%d\n", answer);
    return 0;
}
```

输入：

```text
4
0 10
1 2
2 3
3 5
```

输出：

```text
3
```

排序 `O(n log n)`，扫描 `O(n)`。结束相同的两项任选一项都不减少后续机会，因此比较器只比结束时间也正确。

## 改一个要求，旧证明可能立刻失效

若每项有不同得分，最早结束可能先拿一分，挡住一百分。此时按结束时间排序，令 `best[i]` 为前 `i` 项最大总分；第 `i` 项不选，或选它并接上最后一个不冲突前缀，比较两者。用二分找那个前缀，就是贪心安排与 DP 的结合，但已不是原来的贪心规则。

合并几根绳子，每次代价等于两根长度之和，想使总代价最小，应反复合并最短两根。合并过程是一棵二叉树；最短两根可以交换到最深的一对兄弟叶子而不增加代价，缩成一个新叶子，再做同样的事。这是最优合并，也是哈夫曼树的核心。

贪心规则必须连同约束和目标一起记。能解决活动数量，不等于能解决活动得分；能解决两两合并，不等于任意多根合并都照搬同一程序。

**停笔 2**　活动 `[0,2)` 得 1 分，`[0,3)` 得 100 分。最早结束得到几分？绳长 `1,2,10`，先合并短的与先合并长的，总代价分别多少？

## 也可以用“相邻两项交换”找顺序

若相邻任务 A、B 的不同顺序会改变总代价，只比较 `AB` 与 `BA`，消掉共同部分，可能得到简单排序规则。但还要证明局部交换能把任意方案改成该顺序，并检查比较关系一致；局部更好不自动意味着全局最优。

**停笔 3**　有人说“这道题每次挑最大的一项，样例都过了，所以是贪心”。他缺少的是程序语法，还是排除反例的理由？你会先做哪项检查？

## 核对

1. 前项结束的时刻不再占用。若必须休息，改为下一项开始不早于上项结束加休息时长，并重新按新条件检查证明。
2. 仅 1 分，而最优 100 分。短的先合并为 `3+13=16`；先合并 2、10 则为 `12+13=25`。
3. 缺少正确性理由。先用小规模枚举寻找反例，再尝试交换论证；程序能运行不是规则成立的证据。
