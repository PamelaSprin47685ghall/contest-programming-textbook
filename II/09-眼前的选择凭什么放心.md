# 09　眼前的选择凭什么放心

排队买票，有人总挑最短的那一队。多数时候这没错；可是最短的那队前面若是一个要办十件事的人，挑它就亏了。“看上去最好”的一步，有时真是最好，有时只是看上去。

[第 8 章](08-给已经解决的小问题留个位置.md)把所有小问题的答案都留在表里，因为不知道哪一个会用上。这一章的题，每一步都只做眼前看上去最好的那个选择，不回头，也不留表。这种做法叫**贪心**。写贪心的代码往往只要几行，难的是回答：**凭什么这一步不会把以后的路堵死？**

## 先试着推翻它

### 笨拙的奶牛

给一个括号串，长度是偶数，到 10⁵。每次可以把一个字符翻过来：`(` 变 `)`，`)` 变 `(`。最少翻几个字符，能让它变成平衡的括号串？平衡的意思是左右括号一样多，而且任何前缀里右括号都不比左括号多。

输入一行括号串，输出最少的翻转次数。

样例输入：

```text
())(
```

样例输出：

```text
2
```

最后一个 `(` 后面再没有字符，必须翻成 `)`；第 3 个字符 `)` 前面的左括号已经配完，也要翻。翻完是 `()()`。这是 USACO 2012 年 11 月银组第一题[“笨拙的奶牛”](../USACO/银组/2012_2013/2012.11/P1.md)。

先猜一个办法：从左往右数深度（左括号比右括号多几个），深度要变成负数时，就把这个右括号翻成左括号；扫完以后还多出 d 个左括号，翻其中一半。

猜完别急着写，先找反例。`)(`：第一个字符就要翻，深度变 1；扫完深度 2，再翻一个，共 2 次，对。`))((`：翻第 1 个，深度 1，第 2 个配上，深度 0；后两个让深度到 2，再翻一个，共 2 次。再想不出反例，就该试着证明它。

第一处要翻的地方：深度第一次要变成 −1 时，这个前缀里右括号多了一个，不论以后怎样翻，这个前缀里总得把至少一个 `)` 翻成 `(`。翻其中哪一个，对后面每个前缀的作用都一样：深度多 2。区别只在前面：翻当前这个，前面那些已经合格的前缀不受影响。所以翻当前这个不会比翻别的差。最后剩下 d 个没配上的左括号：每翻一个左括号，深度少 2，至少要翻 d / 2 个；翻最靠右的那几个，前面的前缀都不受影响，恰好做到。

**片段：**

```cpp
// 位于 main 内；text 是读入的括号串
int depth = 0;      // 到目前为止，左括号比右括号多几个（已经算上翻过的）
int flips = 0;
for (char ch : text) {
    if (ch == '(') {
        ++depth;
    } else if (depth > 0) {
        --depth;
    } else {
        // 这个右括号前面没有左括号可配，不翻它，这个前缀就不平衡
        ++flips;
        depth = 1;
    }
}
// 剩下 depth 个左括号没配上，翻其中一半就能互相配好
flips += depth / 2;
std::printf("%d\n", flips);
```

一遍扫描，O(N)。我用枚举所有翻法的程序，对长度到 12 的三百个随机串检查了这段代码。

这一节的方法就是这个顺序：先猜，再找反例，找不到时把“为什么不会更差”说出来。说不出来，就还不能放心。

**停笔 1**　照片段算 `)))(((`，写出每个字符之后的 `depth` 和最后的 `flips`。

## 最早结束，给后面留最多机会

### 奶牛为什么要过马路

农场上有 C 只鸡（C 到 20000），第 i 只只在恰好时刻 Tᵢ 有空；还有 N 头牛（N 到 20000），第 j 头可以在时刻 Aⱼ 到 Bⱼ 之间（含两端）过马路。一头牛要一只鸡陪，条件是 Aⱼ ≤ Tᵢ ≤ Bⱼ；每只鸡至多陪一头牛。最多能配成几对？

输入第一行 C 和 N；之后 C 行，每行一个 Tᵢ；再之后 N 行，每行 Aⱼ 和 Bⱼ。所有时刻都是不超过 10⁹ 的非负整数，可以重复。输出最多的对数。

样例输入：

```text
5 4
7
8
6
2
9
2 5
4 9
0 3
8 13
```

样例输出：

```text
3
```

[0, 3] 的牛配 2，[4, 9] 的牛配 6，[8, 13] 的牛配 8，共 3 对。[2, 5] 的牛能用的只有 2，已经给了别人。这是 USACO 2017 年 2 月银组第一题[“奶牛为什么要过马路”](../USACO/银组/2016_2017/2017.02/P1.md)。

两个选择要定：哪头牛先挑，挑哪只鸡。先挑的应该是结束最早的牛：它能用的鸡，时刻都不超过它的 Bⱼ，别的牛结束得更晚，可能还有别的鸡可用。它挑它能用的鸡里时刻最早的那只：更晚的鸡，结束更晚的牛也许还用得上；更早的那只，以后的牛结束都不早于它，开始若也够早，就能用上任何一只更晚的。

把这句话写成证明。设 j 是结束最早的牛，c 是它能用的最早的鸡。拿任意一种最优配法来看：要是 j 没配上、c 也没配给别人，把 c 给 j，多一对，矛盾。要是 c 给了别的牛 k，而 j 配的是 c′ 或者没配：把 c 给 j，c′ 给 k（j 没配就让 k 不配，总数不变）。k 能用 c′ 吗？c′ ≥ c ≥ Aₖ，c′ ≤ Bⱼ ≤ Bₖ，能。要是 j 配的是 c′、c 没人用，直接把 j 换成 c。每种情况都得到一种同样多、而且 j 配 c 的最优配法。所以先做这一步不会把最优的路堵死；去掉 j 和 c，剩下的还是同一个问题。

**这种“拿一个最优解来，换几处，变成和贪心一样，而且不变差”的论证，叫交换论证。**

下面是**完整程序 A**。

```cpp
#include <algorithm>
#include <cstdio>
#include <set>
#include <vector>

struct Cow {
    int start = 0;
    int end = 0;
};

bool comes_before(const Cow& a, const Cow& b) {
    return a.end < b.end;
}

int main() {
    int c = 0;
    int n = 0;
    if (std::scanf("%d%d", &c, &n) != 2) {
        return 1;
    }
    std::multiset<int> chickens;   // 还没配对的鸡的时间，可能重复
    for (int i = 0; i < c; ++i) {
        int t = 0;
        if (std::scanf("%d", &t) != 1) {
            return 1;
        }
        chickens.insert(t);
    }
    std::vector<Cow> cows(n);
    for (int i = 0; i < n; ++i) {
        if (std::scanf("%d%d", &cows[i].start, &cows[i].end) != 2) {
            return 1;
        }
    }
    // 结束得早的牛先挑：它能用的鸡，后面的牛未必用得上
    std::sort(cows.begin(), cows.end(), comes_before);
    int pairs = 0;
    for (int i = 0; i < n; ++i) {
        // 它能用的鸡里挑时间最早的，晚一点的鸡留给结束更晚的牛
        auto it = chickens.lower_bound(cows[i].start);
        if (it != chickens.end() && *it <= cows[i].end) {
            chickens.erase(it);     // 只删这一只，不删同时间的其他鸡
            ++pairs;
        }
    }
    std::printf("%d\n", pairs);
    return 0;
}
```

鸡放在 `std::multiset` 里，因为时刻可以重复。`lower_bound` 找第一只不早于 `start` 的鸡；它若也不晚于 `end`，就配上。删除时传迭代器，只删这一只；要是写 `erase(*it)`，同一时刻的鸡会全被删掉。排序 O(N log N)，每头牛查一次、删一次，各 O(log C)。

我用一个把每头牛配每只可用的鸡都试一遍的递归程序（第 2 章的写法），对 C、N 到 7 的四百组随机输入和程序 A 对拍，结果全部相同。

**停笔 2**　要是改成按开始时刻排序，开始早的牛先挑，找一个两头牛、两只鸡的例子，让它少配一对。

## 改一个要求，旧证明可能立刻失效

### 录制哞运会

节目单上有 N 个节目（N 到 150），每个有开始和结束时刻（0 到 10⁹）。录像机有两个调谐器，可以同时录两个节目。一个节目结束的时刻另一个节目开始，不算冲突。最多能完整录下几个节目？

输入第一行 N，之后 N 行，每行一个节目的开始和结束时刻。输出最多的节目数。

样例输入：

```text
6
0 3
6 7
3 10
1 5
2 8
1 9
```

样例输出：

```text
4
```

一台录 0–3 和 3–10，另一台录 1–5 和 6–7。这是 USACO 2014 年 1 月银组第三题[“录制哞运会”](../USACO/银组/2013_2014/2014.01/P3.md)。

只有一台调谐器时，有一个熟悉的贪心：按结束时刻排序，能接上就录。它的交换论证和上一节一样：结束最早的节目放进最优解，不会挤掉更多。

两台时，很自然的想法是：先让第一台按这个办法录尽量多，剩下的节目再给第二台。这个想法的证明在哪里断了？单台的论证只保证第一台录得最多，没有保证它留给第二台的节目最好。第一台录得多，可能恰好把第二台需要的节目拿走了。

正确的贪心仍然按结束时刻处理节目，但要回答新的问题：两台都空着时，交给哪一台？交给空得晚的那台。两台都能接上这个节目，它结束的时刻一样；区别只在留下的那台什么时候空。空得早的那台留着，以后开始得早的节目还能用它。只有空得早的那台能接上，就交给它；两台都接不上，就不录。

**片段：**

```cpp
// 位于 main 内；shows 已按结束时间从早到晚排好
// free_at[0] <= free_at[1]：两台调谐器各自从什么时刻起空出来
int free_at[2] = {0, 0};
int recorded = 0;
for (const Show& show : shows) {
    if (show.start < free_at[0]) {
        continue;       // 空得早的那台都来不及，两台都录不了
    }
    if (show.start < free_at[1]) {
        free_at[0] = show.end;      // 只有空得早的那台来得及
    } else {
        free_at[1] = show.end;      // 两台都来得及：用空得晚的那台，空得早的留给以后
    }
    ++recorded;
    if (free_at[0] > free_at[1]) {
        std::swap(free_at[0], free_at[1]);
    }
}
std::printf("%d\n", recorded);
```

`free_at` 总保持前一个不大于后一个，所以“空得早的那台”永远是 `free_at[0]`。排序 O(N log N)，扫描 O(N)。我用把每个节目分给第一台、第二台或不录的 3ᴺ 种分法逐一检查的程序，对 N 到 8 的三百组随机输入检查了这段代码。同一批输入里也跑了“先录一台、再录一台”，它在其中几组上比最优少，停笔 3 就是从中挑出、平移过的一组。

**停笔 3**　四个节目 [0, 4)、[1, 2)、[2, 8)、[4, 7)。“先让一台录尽量多、剩下的给另一台”录了几个？最多能录几个？

**停笔 4**　照片段算样例，写出排好序的节目和每一步之后的 `free_at`。

## 也可以用“相邻两项交换”找顺序

### 爬山

N 头牛（N 到 25000）要上山再下山。第 i 头上山要 U(i) 时间，下山要 D(i) 时间（都在 1 到 50000 之间）。上山由约翰带队，下山由他的表弟带队，同一时刻至多一头牛在上山、至多一头在下山。牛到了山顶可以等；下山的顺序也可以和上山不同。所有牛走完，最少要多久？

输入第一行 N，之后 N 行，每行 U(i) 和 D(i)。输出最少的总时间。

样例输入：

```text
3
6 4
8 1
2 3
```

样例输出：

```text
17
```

上下山都按 3、1、2 号的顺序：3 号 2 时登顶，5 时下完；1 号 8 时登顶，12 时下完；2 号 16 时登顶，17 时下完。这是 USACO 2012 年 1 月银组第三题[“爬山”](../USACO/银组/2011_2012/2012.01/P3.md)。

先承认一件事：上下山用同一个顺序就够了，这在这类两道工序的问题里成立，这里不展开证明，后面的对拍会检查它。顺序定了，总时间是多少？第 k 头牛下山前，前 k 头都已上过山；它和它后面的牛还要一个个下山。所以总时间至少是 U(1) + … + U(k) + D(k) + … + D(N)，而且模拟一遍可以看出，总时间正好是这些和里最大的那个。

现在只交换相邻的两头牛 a、b（a 在前）。前面的上山时间之和记 P，后面的下山时间之和记 S。只有两项会变：a 在前时，这两项是 P + U(a) + D(a) + D(b) + S 和 P + U(a) + U(b) + D(b) + S，较大的那个等于 P + S + U(a) + U(b) + D(a) + D(b) − min(U(b), D(a))。b 在前时，减去的是 min(U(a), D(b))。所以 a 排在 b 前面不会更差，只要

min(U(a), D(b)) ≤ min(U(b), D(a))。

从这条式子能读出一个可以排序的规则：上山比下山快的牛排前面，它们之间上山快的先走；其余的牛排后面，它们之间下山慢的先走。

**片段：**

```cpp
// 下山的牛排在前面更好：上山快于下山的一组在前，组内上山时间短的先走；
// 其余的牛在后，组内下山时间长的先走
bool comes_before(const Cow& a, const Cow& b) {
    bool a_quick_up = a.up < a.down;
    bool b_quick_up = b.up < b.down;
    if (a_quick_up != b_quick_up) {
        return a_quick_up;
    }
    if (a_quick_up) {
        return a.up < b.up;
    }
    return a.down > b.down;
}
```

比如两头都是上山快的牛，U(a) ≤ U(b)：左边的 min(U(a), D(b)) 就是 U(a)，因为 U(a) ≤ U(b) < D(b)；右边两项 U(b) 和 D(a) 都不小于 U(a)。式子成立。

为什么只比较相邻两项就够？任何一种顺序，只要有相邻两头不合规则，就交换它们，总时间不会变长；一直换下去（就像冒泡排序），最后得到的是按规则排好的顺序。所以按规则排好的顺序，不比任何顺序差。

**片段：**

```cpp
// 位于 main 内；cows 已按 comes_before 排好，上山、下山都按这个顺序
long long at_top = 0;      // 这头牛到山顶的时刻
long long finished = 0;    // 到这头牛为止，最后一头下完山的时刻
for (const Cow& cow : cows) {
    at_top += cow.up;
    // 下山要等两件事：这头牛到了山顶，上一头已经下完
    finished = std::max(finished, at_top) + cow.down;
}
std::printf("%lld\n", finished);
```

我用把上山顺序和下山顺序各自的全部排列都试一遍的程序，对 N 到 5 的三百组随机输入检查了这两段代码，所以“上下山同序就够”这件事在这些输入上也检查过了。总时间到 25000 × 10⁵，超过 `int`，用 `long long`。

**停笔 5**　两头牛都是上山不比下山快，D(a) ≥ D(b)。说明 min(U(a), D(b)) ≤ min(U(b), D(a))。

## 核对

1. `depth` 依次是 1（翻）、0、1（翻）、2、3、4。`flips` 是 2 + 4 / 2 = 4。
2. 牛 [0, 10] 和 [1, 1]，鸡在 1 和 5。按开始排序，[0, 10] 先挑，拿走 1，[1, 1] 没有鸡，只配 1 对；先让 [1, 1] 拿 1，[0, 10] 拿 5，是 2 对。
3. 按结束排序是 [1, 2)、[0, 4)、[4, 7)、[2, 8)。第一台录 [1, 2) 和 [4, 7)；剩下 [0, 4) 和 [2, 8) 互相冲突，第二台只录一个，共 3 个。最多是 4 个：一台录 [1, 2) 和 [2, 8)，另一台录 [0, 4) 和 [4, 7)。
4. 排好序是 0–3、1–5、6–7、2–8、1–9、3–10。`free_at` 依次是 {0, 3}、{3, 5}、{3, 7}；2–8 和 1–9 开始都早于 3，不录；3–10 只有空得早的那台能接，变成 {7, 10}。录了 4 个。
5. U(a) ≥ D(a) ≥ D(b)，所以左边是 D(b)。右边的 U(b) ≥ D(b)，D(a) ≥ D(b)，所以右边不小于 D(b)。
