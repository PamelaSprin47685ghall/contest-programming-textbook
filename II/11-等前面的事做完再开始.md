# 11　等前面的事做完再开始

早上出门前要穿好几样东西：袜子得在鞋之前，裤子也得在鞋之前，衬衫得在外套之前。至于先穿袜子还是先穿衬衫，无所谓。没有人会把这些规矩背成一张固定的清单，只要每次挑一件“该等的都已经穿好”的穿上就行。

[第 10 章](10-把能到达的地方找出来.md)的边表示“能走过去”。这一章的边换一个意思：从 a 指向 b 的箭头，表示 **a 必须在 b 之前做完**。问题也换了：不是能到哪里，而是按什么顺序做，最早什么时候做完。

## 箭头表达“必须先于”

把上面的例子编号：0 袜子，1 裤子，2 鞋，3 衬衫，4 外套。箭头是 0 → 2、1 → 2、3 → 4。一件事前面有几个箭头指向它，就要等几件事；这个数常叫它的**入度**。入度为 0 的事随时可以做。做完一件，它指出去的箭头就满足了，箭头那头的事少等一件；少到 0，它也可以做了。

**片段：**

```cpp
// 位于 main 内；after[a] 里是必须排在 a 后面的事，need[b] 是 b 还要等几件事
std::queue<int> ready;          // 已经不用再等的事
for (int v = 0; v < n; ++v) {
    if (need[v] == 0) {
        ready.push(v);
    }
}
std::vector<int> order;
while (!ready.empty()) {
    int u = ready.front();
    ready.pop();
    order.push_back(u);
    for (int v : after[u]) {
        --need[v];              // u 做完了，v 少等一件
        if (need[v] == 0) {
            ready.push(v);
        }
    }
}
if (static_cast<int>(order.size()) < n) {
    std::printf("有圈，排不出顺序\n");     // 圈上的事互相等，谁的 need 都降不到 0
} else {
    for (int v : order) {
        std::printf("%d ", v);
    }
    std::printf("\n");
}
```

照这个例子，开始时 0、1、3 都不用等。0 做完，鞋还要等裤子；1 做完，鞋可以做了；3 做完，外套可以做了。输出是 `0 1 3 2 4`。这样排出来的顺序里，每个箭头都从前面指向后面，叫**拓扑序**。每件事进出 `ready` 一次，每个箭头看一次，O(N + M)。

拓扑序不一定只有一个：0 和 1 换一下也行。题目要字典序最小的那个时，把 `std::queue` 换成每次取出最小编号的 `std::priority_queue`（[第一卷第 15 章](../I/15-按访问方式挑容器.md)）：每一步都在当下能做的事里挑编号最小的。可是有时一个也没有。要是箭头连成一个圈，圈上的每件事都在等圈上的前一件，谁的 `need` 都降不到 0，它们永远不会进 `ready`，`order` 就少于 N 个。所以这段代码顺便回答了“这些要求能不能同时满足”：没有圈的有向图，叫**有向无环图**，它一定排得出拓扑序；有圈的一定排不出。

我用枚举全部排列的程序，对 N 到 8 的三百张随机有向图检查了这段代码：有拓扑序时，输出的顺序满足每个箭头；没有时，它报告有圈。

### 奶牛洗牌

N 头奶牛（N 到 10⁵）排成一列，位置 1 到 N。一次洗牌由 a₁ … a_N 描述：位置 i 上的牛移到位置 aᵢ，所有牛同时移动。aᵢ 可能有相同的，于是几头牛会走到一处，从此一起移动。有些位置不管洗多少次牌都一定有牛，数一数这样的位置有几个。

输入第一行 N，第二行 a₁ … a_N。输出这样的位置数。

样例输入：

```text
4
3 2 1 3
```

样例输出：

```text
3
```

没有哪个 aᵢ 等于 4，所以洗一次牌后位置 4 就空了，以后也不会再有牛。位置 1、2、3 互相送牛：1 → 3 → 1，2 → 2，一直有牛。这是 USACO 2017 年 12 月银组第三题[“奶牛洗牌”](../USACO/银组/2017_2018/2017.12/P3.md)。

这里的箭头不是“必须先于”，可是“等”的结构一样。一个位置以后有没有牛，取决于有没有还会有牛的位置把牛送过来。没有任何位置送牛来的位置，一次洗牌后就空了；它空了，就不再给 aᵢ 送牛，aᵢ 的来源少一个。和拓扑序一样，一层层把入度为 0 的点删掉。

**片段：**

```cpp
// 位于 main 内；to[i] 是位置 i 的牛洗一次牌后去的位置（从 0 编号）
std::vector<int> incoming(n, 0);   // 还可能有牛的位置里，有几个会把牛送到这里
for (int i = 0; i < n; ++i) {
    ++incoming[to[i]];
}
std::vector<int> empty_now;        // 确定以后永远空着、还没处理的位置
for (int i = 0; i < n; ++i) {
    if (incoming[i] == 0) {
        empty_now.push_back(i);
    }
}
int answer = n;
while (!empty_now.empty()) {
    int u = empty_now.back();
    empty_now.pop_back();
    --answer;
    // u 一空，它再也送不出牛，to[u] 少了一个来源
    --incoming[to[u]];
    if (incoming[to[u]] == 0) {
        empty_now.push_back(to[u]);
    }
}
std::printf("%d\n", answer);
```

删不动的位置，每个都还有一个“还会有牛的位置”送牛来。每个位置恰好送出一条箭头，顺着送来的方向往回走，走不到头，最后一定绕进一个圈，而圈上的位置一直有牛。所以剩下的正是圈上的位置。这里用 `std::vector` 当栈，删的先后不同，最后剩下的一样。

我用直接模拟 N + 1 次洗牌、看最后哪些位置还有牛的程序，对 N 到 9 的三百组随机输入检查了这段代码。

## 最早什么时候全部完成

### 挤奶调度

约翰有 N 头牛（N 到 10⁴），给第 i 头挤奶要 T(i) 时间（到 10⁵）。有 M 条要求（M 到 5 × 10⁴），每条说 A 必须挤完才能开始挤 B。帮工多到可以同时给任意多头牛挤奶。要求保证不成圈。挤完所有牛最少要多久？

输入第一行 N 和 M；之后 N 行，每行一个 T(i)；再之后 M 行，每行 A 和 B。输出最少的总时间。

样例输入：

```text
3 1
10
5
6
3 2
```

样例输出：

```text
11
```

牛 1 和牛 3 一开始同时挤；牛 3 在 6 时挤完，牛 2 接着挤，11 时挤完；牛 1 在 10 时挤完。全部挤完是 11。这是 USACO 2013 年 2 月银组第三题[“挤奶调度”](../USACO/银组/2012_2013/2013.02/P3.md)。

帮工无限，所以等待没有好处：一头牛的前面那些牛都挤完了，就马上开始。它最早的开始时刻，是所有必须先挤的牛里最晚挤完的那个时刻。这个数只依赖它前面的牛，所以按拓扑序算：轮到一头牛时，它前面的牛都已经算完。

下面是**完整程序 A**。

```cpp
#include <algorithm>
#include <cstdio>
#include <queue>
#include <vector>

int main() {
    int n = 0;
    int m = 0;
    if (std::scanf("%d%d", &n, &m) != 2) {
        return 1;
    }
    std::vector<int> milk_time(n, 0);
    for (int i = 0; i < n; ++i) {
        if (std::scanf("%d", &milk_time[i]) != 1) {
            return 1;
        }
    }
    std::vector<std::vector<int>> after(n);   // after[a]：要等 a 挤完才能开始的牛
    std::vector<int> need(n, 0);              // 还有几头必须先挤的牛没定下来
    for (int i = 0; i < m; ++i) {
        int a = 0;
        int b = 0;
        if (std::scanf("%d%d", &a, &b) != 2) {
            return 1;
        }
        after[a - 1].push_back(b - 1);
        ++need[b - 1];
    }
    // start[v]：v 最早什么时候能开始。帮工足够多，能开始就开始，不会更差
    std::vector<long long> start(n, 0);
    std::queue<int> ready;
    for (int v = 0; v < n; ++v) {
        if (need[v] == 0) {
            ready.push(v);
        }
    }
    long long all_done = 0;
    while (!ready.empty()) {
        int u = ready.front();
        ready.pop();
        // u 出队时，它前面的牛都已出队，start[u] 不会再变
        long long done = start[u] + milk_time[u];
        all_done = std::max(all_done, done);
        for (int v : after[u]) {
            start[v] = std::max(start[v], done);
            --need[v];
            if (need[v] == 0) {
                ready.push(v);
            }
        }
    }
    std::printf("%lld\n", all_done);
    return 0;
}
```

`start[v]` 每收到一个前面的牛挤完的消息就取一次最大值；`need[v]` 降到 0 时，所有消息都到齐了，`start[v]` 定下来，这时才让 v 进队。总时间至多是 10⁴ 头牛依次挤，10⁹，用 `long long` 留出余地。

总时间就是图里“挤奶时间之和最大的那条箭头链”：链上的牛只能一头接一头地挤，所以至少要这么久；按程序 A 的做法又正好做得到。

我写了一个检查程序，不排拓扑序，只是把每个箭头“完成时刻至少是前面的完成时刻加上自己的时间”反复更新 N 轮。对 N 到 8 的四百张随机无环图，它和程序 A 的答案全部相同。

### 同时到达

N 块田（N 到 100），1 号是谷仓，N 号是目的地。M 条路都是下坡路，只能从编号小的田走向编号大的田。同一条路，贝茜要走 C 时间，埃尔茜要走 D 时间（都在 1 到 100 之间）。两头牛同时从谷仓出发，路上不停留，要同时到达目的地。最少要多久？做不到就输出 `IMPOSSIBLE`。

输入第一行 N 和 M；之后 M 行，每行 A、B、C、D，表示从 A 到 B 的路（A < B）和两头牛各自的时间。

样例输入：

```text
3 3
1 3 1 2
1 2 1 2
2 3 1 2
```

样例输出：

```text
2
```

贝茜走 1 → 2 → 3，用 1 + 1 = 2；埃尔茜走 1 → 3，用 2。都在 2 时到达。这是 USACO 2015 年 1 月银组第三题[“同时到达”](../USACO/银组/2014_2015/2015.01/P3.md)。

只看各自最快的路线不够。样例里两人最快都是 2，碰巧相等；要是贝茜最快 2、埃尔茜最快 3，答案可能是更晚的某个时刻，那时两人都有一条路线恰好走完。中途不许停，所以贝茜不能“走快了等一等”。要知道的是每头牛能在哪些时刻到达目的地，而不只是最早的那个。路至多经过 99 条，每条至多 100，时刻不超过 9900。表的一格是：**`reach[v][t]` 是“能不能恰好用 t 的时间走到 v”。**

**片段：**

```cpp
// cost[a][b]：从 a 到 b 那条下坡路要走多久，没有路记 0。路只从小编号通向大编号。
// 返回 reach[v][t]：能不能从 0 号田出发，恰好用 t 的时间走到 v
std::vector<std::vector<bool>> exact_times(const std::vector<std::vector<int>>& cost, int limit) {
    int n = static_cast<int>(cost.size());
    std::vector<std::vector<bool>> reach(n, std::vector<bool>(limit + 1, false));
    reach[0][0] = true;
    // 按编号从小到大：轮到 v 时，通向 v 的路都从更小的编号出发，它们已经算完
    for (int v = 0; v < n; ++v) {
        for (int w = v + 1; w < n; ++w) {
            if (cost[v][w] == 0) {
                continue;
            }
            for (int t = 0; t + cost[v][w] <= limit; ++t) {
                if (reach[v][t]) {
                    reach[w][t + cost[v][w]] = true;
                }
            }
        }
    }
    return reach;
}
```

这是[第 8 章](08-给已经解决的小问题留个位置.md)的动态规划。那一章没有明说的一件事，在这里看得很清楚：算一格时用到的格子，必须先算好。把“这一格用到那一格”画成箭头，就是一张有向图；只要它没有圈，按拓扑序算就行。这题的箭头都是从编号小的田指向编号大的田，编号顺序本身就是拓扑序，不用再排。要是图里有圈，比如路可以上坡，`reach[v][t]` 就可能等着自己，这种表就不能这样一遍算完。

状态有 N × 9900 个，每条路扫一遍时刻，约 5000 × 10⁴ = 5 × 10⁷ 次。

我用把从 1 到 N 的每一条路径都走一遍、记下两人各自所有到达时刻的程序，对 N 到 6 的三百张随机图检查了这段代码。

## 核对

1. `order` 是 0、3、4。裤子在等鞋，鞋在等裤子和袜子，这两件永远等不到；`order` 只有 3 个，输出“有圈”。
2. 先删 5（没有位置送牛来），4 因此少了来源，也被删掉，接着是 3。剩下 1 和 2 互相送牛。答案是 2。
3. 牛 1：`start` 0，3 时挤完。牛 2：`start` 3，5 时挤完。牛 3：`start` 3，7 时挤完。牛 4：`start` = max(5, 7) = 7，8 时挤完。总时间 8。
4. 贝茜：1 号田 {0}，2 号田 {1}，3 号田 {1, 2}。埃尔茜：1 号田 {0}，2 号田 {2}，3 号田 {2, 4}。两人共同的最早时刻是 2。
5. `best[i]` 用到 `best[i − 1]` 到 `best[i − K]`（不小于 0 的那些）。每个箭头都从小下标指向大下标，所以按下标从小到大排，每个箭头都从前指向后，正是拓扑序。
