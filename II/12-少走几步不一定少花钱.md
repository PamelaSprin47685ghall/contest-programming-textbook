# 12　少走几步不一定少花钱

直达车票价 20，换乘两次只需 7。BFS 最先找到直达路线，却没有回答最便宜。现在每条边的权值才是要累计的代价。

## 已知路线只是一个上界

`distance[v]` 记录目前找到的最便宜路线。若从 `u` 走到 `v` 能更便宜，就更新：这一步叫**松弛**。从来没到过的点，不应假装距离为零。

所有边权非负时，每次挑尚未确定、暂定距离最小的点。别的路线若想绕路到它，绕路之前就已经不比当前距离小，后面又不能用负边降价，所以当前值可以确定。这是 Dijkstra 算法的理由。

用最小堆挑候选。一个点更新多次，堆里可能留着旧记录；弹出时发现记录不等于最新距离，就跳过，不把旧路线继续扩散。

**完整程序：**输入 `1 <= n <= 100000`、`0 <= m <= 200000` 及 `m` 条有向边 `u v cost`，其中 `0 <= cost <= 1000000`。求 0 到 `n-1` 最低代价，不可达输出 −1。

```cpp
#include <cstdio>
#include <functional>
#include <limits>
#include <queue>
#include <utility>
#include <vector>

struct Edge {
    int to;
    int cost;
};

int main() {
    int n = 0;
    int m = 0;
    if (std::scanf("%d%d", &n, &m) != 2 || n < 1 || n > 100000 || m < 0 || m > 200000) {
        return 1;
    }
    std::vector<std::vector<Edge>> graph(n);
    for (int i = 0; i < m; ++i) {
        int u = 0;
        int v = 0;
        int cost = 0;
        if (std::scanf("%d%d%d", &u, &v, &cost) != 3 || u < 0 || u >= n || v < 0 || v >= n
            || cost < 0 || cost > 1000000) {
            return 1;
        }
        graph[u].emplace_back(Edge{v, cost});
    }
    const long long infinity = std::numeric_limits<long long>::max() / 4;
    std::vector<long long> distance(n, infinity);
    using State = std::pair<long long, int>;
    std::priority_queue<State, std::vector<State>, std::greater<State>> waiting;
    distance[0] = 0;
    waiting.emplace(0, 0);
    while (!waiting.empty()) {
        State current = waiting.top();
        waiting.pop();
        int u = current.second;
        if (current.first != distance[u]) {
            continue;
        }
        for (const Edge& edge : graph[u]) {
            long long next = distance[u] + edge.cost;
            if (next < distance[edge.to]) {
                distance[edge.to] = next;
                waiting.emplace(next, edge.to);
            }
        }
    }
    std::printf("%lld\n", distance[n - 1] == infinity ? -1LL : distance[n - 1]);
    return 0;
}
```

输入：

```text
3 3
0 2 20
0 1 3
1 2 4
```

输出：

```text
7
```

这份懒删除堆实现的时间上界可写 `O((n+m) log(n+m))`，堆最坏保存 `O(m)` 条记录。不要误称堆始终只有 `n` 项。合法最短简单路代价不超过约 `10^11`，距离和哨兵之间有充足空间。

**停笔 1**　增加边 `0→1` 代价 10，为什么不能只因堆里还有 `(10,1)` 就再按它更新？增加零权边会破坏非负条件吗？

## 负边需要另一份理由

Bellman–Ford 反复扫描所有边。第 `k` 轮后，至少已经找到所有至多 `k` 条边路线的最优值。没有可达负环时，最短路可去掉非负圈，至多用 `n-1` 条边。再一轮仍能改进，说明有从起点可达的负环。

不可达点不参与加法。负环也不是“所有点的答案都坏了”：只有能从那个负环继续到达的目标才可能无限降低代价。队列优化常叫 SPFA，最坏仍可能很慢，不是必然线性。

若所有边权只有 0、1，可以用双端队列：零边更新放头，权 1 放尾，形成 0–1 BFS。若点数很少而需所有点对，Floyd 按中转点 `k` 外层枚举，尝试 `d[i][k]+d[k][j]`，时间 `O(n³)`、空间 `O(n²)`。外层顺序表达“允许哪些中转点”，不是三层循环可以任意交换。

**停笔 2**　有边 `0→1:2`、`0→2:5`、`2→1:-10`。在 1 暂定为 2 时就宣布最终确定，哪里错了？

**停笔 3**　一条最短路线若有一个代价为正的圈，删掉这个圈会怎样？为什么这能帮助解释“无负环时只需简单路”？

## 核对

1. 10 已不是点 1 的最新距离 3，应跳过旧记录。零仍非负，不破坏证明。
2. 后面经 2 可以得到 −5。非负证明的关键条件已经失效。
3. 路线更短且代价更低；零圈可删而不增加代价。不断去圈即可留下不重复点的路线。
