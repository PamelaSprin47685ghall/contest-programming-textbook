# 12　少走几步不一定少花钱

坐地铁去城另一头，换乘两次的路线常常比一趟直达快：直达那条绕了远路。路上经过几站，和花多少时间，是两回事。

[第 10 章](10-把能到达的地方找出来.md)的 BFS 数的是边的条数，每条边都当作一样长。这一章的边各有长短（时间、钱、要搬的草捆），要求的是总长最小的路线。办法换了，但思路相通：先有一个估计，再不断把它改小，直到能说清它为什么不会再小。

## 已知路线只是一个上界

### 路障

农场有 N 块田（N 到 250），M 条双向小路（M 到 25000），每条有长度（1 到 10⁶）。约翰从 1 号田走到 N 号田，总是走总长最短的路线。奶牛要挑恰好一条路，把它的长度翻倍，让约翰的最短路线尽量变长。最多能变长多少？

输入第一行 N 和 M，之后 M 行，每行一条路的两端和长度。输出最多增加的长度。

样例输入：

```text
5 7
2 1 5
1 3 1
3 2 8
3 5 7
3 4 3
2 4 7
4 5 2
```

样例输出：

```text
2
```

原来的最短路线是 1–3–4–5，长 6。把 3–4 翻倍成 6，最短的变成 1–3–5，长 8，多了 2。这是 USACO 2014 年 2 月银组第二题[“路障”](../USACO/银组/2013_2014/2014.02/P2.md)。

先要会求最短路线的长度，叫**最短路**。给每块田记一个数 `dist[v]`：目前找到的、从起点到 v 的最短路线有多长。它只是一个**上界**：真正的最短路不会比它长，可能更短。看到一条路 u–v，要是走到 u 再走这条路比 `dist[v]` 还短，就把 `dist[v]` 改小。这一步叫**松弛**。

按什么顺序松弛？所有边都不是负的时候，有一个好顺序：每次在还没处理的田里，挑 `dist` 最小的那块 u。它的 `dist` 已经是准确的了：任何别的路线，都得在某处第一次走到一块没处理的田 w。走到 w 之前的那块田已经处理过、松弛过它的边，所以这段路长不小于 `dist[w]`，而 `dist[w]` 不小于 `dist[u]`；后面的边又都不是负的，整条路线不会比 `dist[u]` 短。于是处理 u，用它松弛它的邻居，再挑下一个。这就是 **Dijkstra 算法**。“挑最小的”用[第一卷第 15 章](../I/15-按访问方式挑容器.md)的 `std::priority_queue`。

下面是**完整程序 A**。

```cpp
#include <algorithm>
#include <cstdio>
#include <queue>
#include <vector>

struct Road {
    int a = 0;
    int b = 0;
    long long length = 0;
};

struct Entry {
    long long dist = 0;
    int node = 0;
    // priority_queue 每次取“最大”的一项；这里把距离小的算作大，堆顶就是距离最小的
    bool operator<(const Entry& other) const {
        return dist > other.dist;
    }
};

// 从 0 号田到每块田的最短距离；via[v] 记下最后一次把 v 改小时用的那条路
std::vector<long long> shortest(const std::vector<Road>& roads,
                                const std::vector<std::vector<int>>& adj,
                                std::vector<int>& via) {
    int n = static_cast<int>(adj.size());
    const long long UNKNOWN = -1;
    std::vector<long long> dist(n, UNKNOWN);
    via.assign(n, -1);
    std::priority_queue<Entry> pending;
    dist[0] = 0;
    pending.push(Entry{0, 0});
    while (!pending.empty()) {
        Entry top = pending.top();
        pending.pop();
        if (top.dist > dist[top.node]) {
            continue;       // 这一项放进去以后，这块田又找到了更短的路，旧的作废
        }
        int u = top.node;
        for (int id : adj[u]) {
            int v = roads[id].a + roads[id].b - u;      // 这条路的另一头
            long long through_u = dist[u] + roads[id].length;
            if (dist[v] == UNKNOWN || through_u < dist[v]) {
                dist[v] = through_u;
                via[v] = id;
                pending.push(Entry{through_u, v});
            }
        }
    }
    return dist;
}

int main() {
    int n = 0;
    int m = 0;
    if (std::scanf("%d%d", &n, &m) != 2) {
        return 1;
    }
    std::vector<Road> roads(m);
    std::vector<std::vector<int>> adj(n);
    for (int i = 0; i < m; ++i) {
        if (std::scanf("%d%d%lld", &roads[i].a, &roads[i].b, &roads[i].length) != 3) {
            return 1;
        }
        --roads[i].a;
        --roads[i].b;
        adj[roads[i].a].push_back(i);
        adj[roads[i].b].push_back(i);
    }
    std::vector<int> via;
    long long original = shortest(roads, adj, via)[n - 1];

    // 不在这条最短路上的路翻倍，这条最短路原样还在，距离不会变长；只需试路上的边
    std::vector<int> on_path;
    for (int v = n - 1; v != 0; v = roads[via[v]].a + roads[via[v]].b - v) {
        on_path.push_back(via[v]);
    }
    long long worst = original;
    for (int id : on_path) {
        roads[id].length *= 2;
        std::vector<int> unused;
        worst = std::max(worst, shortest(roads, adj, unused)[n - 1]);
        roads[id].length /= 2;
    }
    std::printf("%lld\n", worst - original);
    return 0;
}
```

`Entry` 的 `operator<` 是反着写的：`std::priority_queue` 每次取最大的一项，把距离小的算作“大”，取出来的就是距离最小的。一块田的 `dist` 每改小一次，就放一项进堆；旧的项留在堆里，取出来时比 `dist` 大，直接跳过。每条路至多让一项进堆两次，一次 Dijkstra 是 O(M log M)。

为什么只试最短路线上的边？翻倍别的路，原来那条路线一点没变，最短距离不会变长。`via[v]` 记下最后一次把 v 改小时用的那条路，从 N 号田顺着 `via` 往回走，就是一条最短路线，至多 N − 1 条边。所以至多重跑 N − 1 次，约 250 × 25000 × 15 ≈ 10⁸ 次基本操作。

## 负边需要另一份理由

Dijkstra 的那句理由靠的是“后面的边都不是负的”。有负边时，它就不成立了。例如 4 个点，有向边 0 → 1 长 2，0 → 2 长 5，2 → 1 长 −4，1 → 3 长 1。从 0 出发，1 号点 `dist` 是 2，比 2 号点的 5 小，先处理；可是 0 → 2 → 1 只有 1。要是每个点只处理一次（很多写法这样做），3 号点就停在 3，真实是 2。程序 A 的写法会把 1 号点再处理一次，这个例子碰巧算对；但在有负边的图上，同一个点可能被处理很多次，O(M log M) 的保证就没了。

另一份理由是数边。没有总长为负的圈时，最短路线不会绕圈，至多 N − 1 条边。把所有边都松弛一遍，叫一轮。第 1 轮之后，所有“至多 1 条边”的路线都已考虑过；第 k 轮之后，`dist[v]` 不超过“至多 k 条边”的最短路线。做 N − 1 轮就够了。这是 **Bellman–Ford 算法**。

**片段：**

```cpp
// 位于 main 内；arcs 是 m 条有向边（from、to、length 可以为负），起点是 0
const long long INF = 1LL << 60;     // 还没找到路
std::vector<long long> dist(n, INF);
dist[0] = 0;
bool still_changing = false;
// 第 k 轮结束时，dist[v] 不超过“至多 k 条边”的路线里最短的那条
for (int round = 0; round < n; ++round) {
    still_changing = false;
    for (const Arc& arc : arcs) {
        if (dist[arc.from] != INF && dist[arc.from] + arc.length < dist[arc.to]) {
            dist[arc.to] = dist[arc.from] + arc.length;
            still_changing = true;
        }
    }
    if (!still_changing) {
        break;
    }
}
// 不绕圈的路至多 n - 1 条边。做到第 n 轮还在变小，说明能到一个总长为负的圈
if (still_changing) {
    std::printf("有负圈\n");
} else {
    for (int v = 0; v < n; ++v) {
        if (dist[v] == INF) {
            std::printf("%d 到不了\n", v);
        } else {
            std::printf("%d %lld\n", v, dist[v]);
        }
    }
}
```

一轮 O(M)，至多 N 轮，O(NM)，比 Dijkstra 慢，但不怕负边。多做的第 N 轮是检查：要是还有边能松弛，说明有一条路线绕着某个总长为负的**负圈**越走越短，最短路不存在。哪一轮都没有变化时可以提前停。

我用“最多走 N − 1 条边”和“最多走 3N + 3 条边”两种逐层递推互相比较的程序，对 N 到 5、边长 −3 到 8 的三百张随机有向图检查了这段代码：两种递推一样时，输出和它相同；不一样时（说明有负圈），片段报告负圈。

## 代价只有 0 和 1

### 拖拉机

拖拉机停在 (x, y)，田里放了 N 捆干草（N 到 50000），坐标都是 1 到 1000 的整数，拖拉机所在处没有草。拖拉机每次沿东西或南北走一格，不能开进有草的格子。要开到原点 (0, 0)，最少要搬走几捆草？

输入第一行 N、x、y，之后 N 行，每行一捆草的坐标。输出最少搬走的捆数。

样例输入：

```text
7 6 3
6 2
5 2
4 3
2 1
7 3
5 4
6 4
```

样例输出：

```text
1
```

拖拉机能开到的只有 (6, 3) 和 (5, 3)，四周是 (6, 2)、(7, 3)、(6, 4)、(5, 2)、(5, 4)、(4, 3)。搬走 (4, 3)，就能沿 y = 3 往西开到 (0, 3)，再往南到原点。这是 USACO 2012 年 3 月银组第一题[“拖拉机”](../USACO/银组/2011_2012/2012.03/P1.md)。

把每个格子当作点，走进一格的代价是：有草就是 1（搬走它），没草就是 0。草都在 1 到 1000 之内，所以坐标 0 到 1001 的网格就够：最外一圈没有草，绕得更远也不会更省。要求的是到原点的最短路。

可以用 Dijkstra，但边长只有 0 和 1 时有更简单的办法。Dijkstra 需要的只是“按距离从小到大取点”。这里队列里的距离至多两种：当前的 d 和 d + 1。代价 0 的邻居距离也是 d，放到队头，马上处理；代价 1 的邻居距离 d + 1，放到队尾。这样不用堆，一个 `std::deque` 就保持了从小到大的顺序。这叫 **0–1 BFS**。

**片段：**

```cpp
// 位于 main 内；has_bale[x][y] 已读入，网格坐标是 0 到 SIDE - 1，最外一圈没有草捆
const int SIDE = 1002;
const int UNKNOWN = -1;
std::vector<std::vector<int>> moved(SIDE, std::vector<int>(SIDE, UNKNOWN));
std::deque<int> pending;            // 格子写成 x × SIDE + y
moved[start_x][start_y] = 0;
pending.push_back(start_x * SIDE + start_y);
const int dx[4] = {-1, 1, 0, 0};
const int dy[4] = {0, 0, -1, 1};
while (!pending.empty()) {
    int cell = pending.front();
    pending.pop_front();
    int x = cell / SIDE;
    int y = cell % SIDE;
    for (int d = 0; d < 4; ++d) {
        int nx = x + dx[d];
        int ny = y + dy[d];
        if (nx < 0 || nx >= SIDE || ny < 0 || ny >= SIDE) {
            continue;
        }
        int cost = has_bale[nx][ny] ? 1 : 0;
        if (moved[nx][ny] == UNKNOWN || moved[x][y] + cost < moved[nx][ny]) {
            moved[nx][ny] = moved[x][y] + cost;
            // 代价 0 的放队头，和 (x, y) 同一层；代价 1 的放队尾，属于下一层
            if (cost == 0) {
                pending.push_front(nx * SIDE + ny);
            } else {
                pending.push_back(nx * SIDE + ny);
            }
        }
    }
}
std::printf("%d\n", moved[0][0]);
```

一个格子可能进队不止一次：第一次被碰到时，它的值至多是当前的 d + 1；以后的出队值都不小于 d，所以它至多再被改小一次，变成 d。每格至多进队两次，总共 O(格子数)，约 10⁶。

## 每两点之间都要知道距离

### 假期规划

N 个农场（N 到 200），前 K 个是枢纽（K 到 100）。有 M 条单向航班（M 到 10⁴），每条有票价（到 10⁶）。有 Q 个行程请求（Q 到 10⁴），每个从 a 到 b，可以坐任意多段航班，但必须至少经过一个枢纽（起点或终点是枢纽也算）。有的请求做不到。输出能做到的请求数，以及它们最低花费的总和。

输入第一行 N、M、K、Q；之后 M 行，每行一条航班的起点、终点、票价；再之后 Q 行，每行一个请求。

样例输入：

```text
3 3 1 3
3 1 10
1 3 10
1 2 7
3 2
2 3
1 2
```

样例输出：

```text
2
24
```

3 → 2 只能走 3 → 1 → 2，花 17；2 → 3 没有从 2 出发的航班，做不到；1 → 2 花 7。能做到 2 个，共 24。这是 USACO 2013 年 12 月银组第二题[“假期规划”](../USACO/银组/2013_2014/2013.12/P2.md)。

经过枢纽 h 的最便宜走法，是 a 到 h 的最短路加 h 到 b 的最短路。询问很多，起点和终点各不相同，最好把每两点之间的最短路都先算出来。N 只有 200，可以用一个三重循环。

想法是逐步放宽“中途可以经过哪些点”。开始时，中途不许经过任何点，`cost[i][j]` 就是直飞的票价。允许中途经过 0 号点以后，i 到 j 的最便宜走法，要么不经过 0，要么是 i 到 0、再 0 到 j。一般地，允许经过 0 到 via 号点时，最便宜的走法要么不经过 via，要么在 via 处分成两段，每段中途都只经过 0 到 via − 1。

**片段：**

```cpp
// 位于 main 内；cost[i][j] 已读入：i 到 j 最便宜的直飞票价，没有记 INF，cost[i][i] = 0
// 第 via 轮结束时，cost[i][j] 是“中途只经过 0 到 via 号农场”的最便宜走法
for (int via = 0; via < n; ++via) {
    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < n; ++j) {
            if (cost[i][via] != INF && cost[via][j] != INF
                && cost[i][via] + cost[via][j] < cost[i][j]) {
                cost[i][j] = cost[i][via] + cost[via][j];
            }
        }
    }
}
int answered = 0;
long long total = 0;
for (int i = 0; i < q; ++i) {
    int a = 0;
    int b = 0;
    if (std::scanf("%d%d", &a, &b) != 2) {
        return 1;
    }
    long long best = INF;
    for (int hub = 0; hub < k; ++hub) {     // 必须经过的那个枢纽是哪一个
        if (cost[a - 1][hub] != INF && cost[hub][b - 1] != INF) {
            best = std::min(best, cost[a - 1][hub] + cost[hub][b - 1]);
        }
    }
    if (best != INF) {
        ++answered;
        total += best;
    }
}
std::printf("%d\n%lld\n", answered, total);
```

这叫 **Floyd 算法**，O(N³)，200³ = 8 × 10⁶。`via` 必须是最外层：它是“允许经过哪些点”的那一步，里面两层只是对每对 (i, j) 用上这一步。表可以原地更新：这一轮里 `cost[i][via]` 和 `cost[via][j]` 自己不会变，因为经过 via 再回到 via 不会更便宜。之后每个询问只要试 K 个枢纽，O(QK)。一个请求的花费至多约 199 × 10⁶ ≈ 2 × 10⁸，总和到 2 × 10¹²，用 `long long`。

我用对每个起点跑 Dijkstra、再枚举枢纽的程序，对 N 到 6 的三百组随机输入检查了这段代码。

这一章的 `dist` 一开始都是上界，靠松弛改小。“路障”用 Dijkstra：边不为负时，最小的那个已经准确；再用“只有最短路上的边值得翻倍”把重跑的次数压到 N − 1。负边让这句理由失效，Bellman–Ford 改为数边，N − 1 轮够，第 N 轮还在变就有负圈。“拖拉机”的边长只有 0 和 1，双端队列代替了堆。“假期规划”一次求出每两点之间的距离，靠的是逐步放宽中途能经过的点。下一章问：要是只关心谁和谁连在一起、不关心怎么走，能记得多省。

## 核对

1. 依次取出 1、3、4、2、5 号田。`dist` 按 1 到 5 号田是 0、5、1、4、6。
2. 翻倍 1–3：1–3–4–5 长 7，最短是 7，多 1。翻倍 3–4：1–3–5 长 8，最短是 8，多 2。翻倍 4–5：1–3–4–5 和 1–3–5 都是 8，多 2。最大是 2。
3. 第 1 轮：0 → 1 让 `dist[1]` = 2，0 → 2 让 `dist[2]` = 5，2 → 1 让 `dist[1]` = 1，1 → 3 让 `dist[3]` = 2。第 2 轮没有变化，提前停。结果 0、1、5、2。
4. 从队头到队尾不减，而且至多两种值 d 和 d + 1，d 在前。出队的总是当前最小的距离，和 Dijkstra 每次取最小的一样；代价 0 的邻居距离仍是 d，放队头不破坏顺序，代价 1 的是 d + 1，放队尾也不破坏。
5. 第 1 行（从 1 号）：0、7、10。第 2 行（从 2 号）：INF、0、INF。第 3 行（从 3 号）：10、17、0。
