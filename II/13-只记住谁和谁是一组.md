# 13　只记住谁和谁是一组

体育课分组拔河，老师不点每个人的名，只问：“你跟谁一组？”甲说跟乙，乙说跟丙，丙说自己就是组长。于是甲、乙、丙都是丙那一组。谁站在谁旁边、谁先报的名，这时都不重要，要紧的只有一件事：两个人是不是同一组。

这一章只记这一件事。两个地点之间能不能走到，不问怎么走；两头牛是不是一伙，不问通过谁认识。只记“谁和谁是一组”，能换来很快的合并和查询。后两节用它去接通一张地图，并说明一种看上去很贪心的接法为什么不会后悔。

## 一组只需要一个代表

一组人里选一个人当**代表**。要问两个人是否同组，就各自找到自己的代表，看是不是同一个人。要把两组并成一组，就让一个代表改认另一个代表。

### 先在纸上做一次

六个人，编号 0 到 5。每人记一个数 `leader`：自己往上找一步该问谁。`leader[x] == x` 的人就是代表。开始时谁也不认识谁，每人都是自己的代表：

| x | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| leader | 0 | 1 | 2 | 3 | 4 | 5 |

先把 1 和 2 并起来：让 2 改认 1，`leader[2] = 1`。再并 3 和 4：`leader[4] = 3`。再并 2 和 4：2 的代表是 1，4 的代表是 3，让 3 改认 1，`leader[3] = 1`。现在问 4 和 2 是否同组：4 → 3 → 1，2 → 1，代表都是 1，同组。问 0 和 5：代表是 0 和 5，不同组。

这里每个人只记一个数，记的也不是“我组里有谁”，而是“往上该问谁”。合并时只改一个代表的 `leader`，组里其余的人一个也不用动。这样的结构叫**并查集**：它只做“并”和“查”两件事。

麻烦在于往上找的路可能很长。要是每次都把一个大组挂到一个单人下面，链会一层层变长，查一次要走很多步。两条办法合起来就够了。第一，合并时让人数少的组挂到人数多的组下面，这叫**按大小合并**：一个人每往下沉一层，他所在的组至少翻一倍，所以至多沉 log N 层。第二，查找时顺手把路缩短：每走一步，就让当前这个人改认他的“祖父”，下次再查就少走一半路，这叫**路径压缩**。两条都用上，查找的平均步数小到可以当作常数。

**停笔 1**　接着上面的表，再并 0 和 5，然后并 5 和 4。按“少的挂到多的下面”（一样多时，让第二个人的代表挂到第一个人的代表下面），写出每一步改了谁的 `leader`。并 5 和 4 时要先查 4 的代表，路径压缩顺手改了哪个数？

### 关闭农场

农场有 N 个谷仓、M 条双向道路（N、M 都在 1 到 3000）。约翰每次关闭一个谷仓，和它相连的道路也一起关掉。他想知道：一开始，以及每关一个谷仓之后，还开着的谷仓是否两两都能走到。农场一开始就可能不连通。

输入第一行 N 和 M；接下来 M 行，每行一条路的两个谷仓编号（1 到 N）；最后 N 行是 1 到 N 的一个排列，表示关闭的先后。输出 N 行 `YES` 或 `NO`：第一行说一开始，第 i + 1 行说关掉第 i 个谷仓以后。

样例输入：

```text
4 3
1 2
2 3
3 4
3
4
1
2
```

样例输出：

```text
YES
NO
YES
YES
```

四个谷仓连成一条线 1—2—3—4。一开始连通。关掉 3，剩下 {1, 2} 和 {4} 两块，`NO`。再关 4，只剩 1、2，连通。再关 1，只剩 2，一个谷仓也算连通。这是 USACO 2016 年 3 月银组第三题[“关闭农场”](../USACO/银组/2015_2016/2016.03/P3.md)。

每次关门以后都搜一遍全图，是 O(N × (N + M))，这一题来得及，数据再大就不行了。并查集会并不会拆：一条路关掉以后，没法把一组分回两组。那就倒过来看。从最后一个状态出发，那时所有谷仓都关了；倒着把谷仓一个个重新打开。打开一个谷仓，就把它和已经开着的邻居并成一组。拆变成了并。

手里再记一个数 `groups`：开着的谷仓一共分成几组。打开一个谷仓，它先自成一组，`groups` 加一；每成功并一次，两组变一组，`groups` 减一；两个谷仓本来就同组，合并不成功，不减。开着的谷仓全部连通，就是 `groups` 等于 1。

倒着打开到第 i 个（从 0 数），开着的恰好是关闭顺序里第 i 个以后的谷仓，也就是“关掉前 i 个以后”的样子。把这时的答案记在第 i 格，最后从第 0 格起正着输出。

拿样例走一遍。关闭顺序是 3、4、1、2，倒着打开：先开 2，`groups` 为 1，第 3 格记 `YES`；开 1，变 2，再和邻居 2 并成功，回到 1，第 2 格 `YES`；开 4，变 2，邻居 3 还关着，第 1 格 `NO`；开 3，变 3，和 2 并、和 4 并，回到 1，第 0 格 `YES`。正着输出，就是样例。

下面是**完整程序 A**。

```cpp
#include <cstdio>
#include <utility>
#include <vector>

std::vector<int> leader;      // leader[x]：x 往上该问谁；leader[x] == x 时 x 是代表
std::vector<int> group_size;  // 只对代表有意义：这一组有几个人

int find(int x) {
    while (leader[x] != x) {
        leader[x] = leader[leader[x]];  // 改认祖父，下次少走一半路
        x = leader[x];
    }
    return x;
}

// 并起 a、b 所在的组；本来就同组时返回 false
bool unite(int a, int b) {
    a = find(a);
    b = find(b);
    if (a == b) {
        return false;
    }
    if (group_size[a] < group_size[b]) {
        std::swap(a, b);
    }
    leader[b] = a;  // 人少的组挂到人多的组下面
    group_size[a] += group_size[b];
    return true;
}

int main() {
    int n = 0;
    int m = 0;
    if (std::scanf("%d%d", &n, &m) != 2) {
        return 1;
    }
    std::vector<std::vector<int>> roads(n + 1);
    for (int i = 0; i < m; ++i) {
        int a = 0;
        int b = 0;
        if (std::scanf("%d%d", &a, &b) != 2) {
            return 1;
        }
        roads[a].push_back(b);
        roads[b].push_back(a);
    }
    std::vector<int> order(n);
    for (int i = 0; i < n; ++i) {
        if (std::scanf("%d", &order[i]) != 1) {
            return 1;
        }
    }
    leader.resize(n + 1);
    group_size.assign(n + 1, 1);
    for (int x = 1; x <= n; ++x) {
        leader[x] = x;
    }
    std::vector<bool> open(n + 1, false);
    std::vector<bool> connected(n, false);
    int groups = 0;
    // 倒着打开：打开 order[i] 以后，开着的正是“关掉前 i 个以后”剩下的谷仓
    for (int i = n - 1; i >= 0; --i) {
        int barn = order[i];
        open[barn] = true;
        ++groups;
        for (int next : roads[barn]) {
            if (open[next] && unite(barn, next)) {
                --groups;
            }
        }
        connected[i] = (groups == 1);
    }
    for (int i = 0; i < n; ++i) {
        std::printf("%s\n", connected[i] ? "YES" : "NO");
    }
    return 0;
}
```

`leader` 和 `group_size` 写在 `main` 外面，是因为 `find`、`unite` 两个函数都要用它们；编号从 1 开始，所以都开 n + 1 格，0 号不用。每条路在两端各存一次，打开一个谷仓时只看它自己的邻居，所以每条路至多被看两次。整个程序是 O(N + M) 次合并和查找。

为什么 `group_size` 只对代表有意义？合并时只给新代表加上人数，被挂下去的那个代表的数不再更新。查人数一定要先 `find`。

### 哞 Tube

约翰有 N 个视频（到 10 万），用 N − 1 对比较把它们连成一棵树：任意两个视频之间恰好有一条由比较连成的路。每对比较有一个相关度。两个视频的相关度，是连接它们的那条路上最小的相关度。有 Q 个询问（到 10 万），每个给出 k 和 v，问和视频 v 的相关度至少为 k 的其他视频有几个。相关度和 k 都不超过 10⁹。

输入第一行 N 和 Q；接着 N − 1 行，每行 p、q、r，表示视频 p、q 的相关度为 r；再 Q 行，每行 k、v。按询问顺序输出答案，每行一个。

样例输入：

```text
4 3
1 2 3
2 3 2
2 4 4
1 2
4 1
3 1
```

样例输出：

```text
3
0
2
```

1 和 3 之间的路经过 1—2、2—3，相关度是 3 和 2 里小的那个，等于 2；1 和 4 是 3 和 4 里小的，等于 3。k = 4 时，视频 1 和谁都不够 4；k = 3 时，和 1 够格的是 2、4。这是 USACO 2018 年 1 月金组第一题[“哞 Tube”](../USACO/金组/2017_2018/2018.01/P1.md)。

“和 v 的相关度至少为 k”换一句话说：只留下相关度至少为 k 的比较，v 能走到谁。于是一个询问就是：只用相关度 ≥ k 的边时，v 所在的组有几个视频，再减去 v 自己。

每个询问各建一次组，太慢。注意 k 越小，能用的边越多，组只会变大、不会拆开。所以把询问按 k 从大到小排好，边也按相关度从大到小排好；处理一个询问以前，先把相关度不小于它的 k 的边全部并进去，再查 v 所在组的人数。边各并一次，询问各查一次，主要工作是两次排序，O((N + Q) log (N + Q))。

样例里，边按相关度从大到小是 2—4（4）、1—2（3）、2—3（2），询问按 k 从大到小是 (4, 1)、(3, 1)、(1, 2)。k = 4：并入 2—4，视频 1 那组只有它自己，答 0。k = 3：并入 1—2，1 那组是 {1, 2, 4}，答 2。k = 1：并入 2—3，全部一组，答 3。再按原来的顺序输出：3、0、2。

答案不是按读进来的顺序算出的，所以每个询问要带着自己原来的位置。先把全部询问读完、换一个好算的顺序回答、最后按原顺序输出，这种做法叫**离线**。上面的“关闭农场”把操作整个倒过来，也是离线。题目要是要求答完一个问题才给下一个，离线就不能用了。

## 用最少总长度接通全部地点

几个村子要通电，每两村之间架线有一个价钱，有的地方架不了。要让所有村子都通上电，总价最少是多少？村子之间不必直接相连，能转几站到达就行。

接通 N 个地点，至少要 N − 1 条边：每用一条边，组数至多减一。正好用 N − 1 条边、把全部地点连成一组的边集，中间一定没有圈：有圈的话拿掉圈上一条边仍然连通，边就少于 N − 1 了。这样连通而没有圈的一组边，叫**生成树**。总长度最小的生成树，叫**最小生成树**。

做法出奇地简单：把边从短到长排好，一条条看；一条边的两端还不在同一组，就选它，把两组并起来；已经同组，就跳过，选了只会添一个圈。选够 N − 1 条为止。这个做法叫 **Kruskal 算法**，它要的正是上一节的并查集。它凭什么对，下一节再说。

### 灌溉田地

约翰有 N 块田（1 到 2000），第 i 块在平面上的整点 (xᵢ, yᵢ)，0 ≤ xᵢ, yᵢ ≤ 1000，位置互不相同。在两块田之间铺管道，价钱是两点距离的平方 (xᵢ − xⱼ)² + (yᵢ − yⱼ)²。承包商不肯铺价钱小于 C 的管道（1 ≤ C ≤ 10⁶）。要让每块田的水都能流到其他所有田，最少花多少钱？做不到输出 −1。

输入第一行 N 和 C，接下来 N 行，每行一块田的坐标。输出一个整数。

样例输入：

```text
3 11
0 2
5 0
4 3
```

样例输出：

```text
46
```

三根可能的管道：(0, 2) 到 (5, 0) 是 25 + 4 = 29；(0, 2) 到 (4, 3) 是 16 + 1 = 17；(5, 0) 到 (4, 3) 是 1 + 9 = 10，小于 11，不能铺。剩下两根都得用，17 + 29 = 46。这是 USACO 2014 年 3 月银组第一题[“灌溉田地”](../USACO/银组/2013_2014/2014.03/P1.md)。

价钱小于 C 的管道直接当作不存在，其余就是最小生成树。2000 块田两两配对，约 200 万根管道，存得下，也排得完。下面是**片段**，`find`、`unite` 照搬程序 A，田从 0 编号；`Pipe` 是含 `cost`、`from`、`to` 三个 `int` 的记录。

```cpp
// 位于 main 内；x、y 存坐标，leader、group_size 已建好 n 格，每人自成一组
std::vector<Pipe> pipes;
for (int i = 0; i < n; ++i) {
    for (int j = i + 1; j < n; ++j) {
        int dx = x[i] - x[j];
        int dy = y[i] - y[j];
        int cost = dx * dx + dy * dy;
        if (cost >= min_cost) {
            pipes.push_back(Pipe{cost, i, j});
        }
    }
}
std::sort(pipes.begin(), pipes.end(), [](const Pipe& a, const Pipe& b) {
    return a.cost < b.cost;
});
long long total = 0;
int chosen = 0;
for (const Pipe& pipe : pipes) {
    if (unite(pipe.from, pipe.to)) {
        total += pipe.cost;
        ++chosen;
    }
}
if (chosen == n - 1) {
    std::printf("%lld\n", total);
} else {
    std::printf("-1\n");
}
```

一根管道最多 2 × 1000² = 2 × 10⁶，`int` 放得下；1999 根加起来约 4 × 10⁹，超过 `int`，`total` 用 `long long`。只有一块田时一根也不用选，`chosen` 和 n − 1 都是 0，输出 0。最后选不够 N − 1 根，说明能铺的管道接不通全部田，输出 −1。

200 万根管道，一根 12 字节，约 24 MB，排序约 4 × 10⁷ 次比较。边再多就该换一种不存边的办法：先让一块田自成“已接通的部分”，每轮在所有没接通的田里，挑离这一部分最近的一块接进来，再用它更新其余田到这一部分的距离。每轮扫一遍 N 块田，N 轮共 O(N²)，不必存下任何管道。这叫 **Prim 算法**。它和 Kruskal 选的边可能不同，总长度相同，理由也是下一节那一条。

## 为什么选便宜边不会后悔

Kruskal 每一步只看眼前最短的一条边，从不回头。有同学会担心：现在选了一条短边，会不会挡住以后一种更好的整体安排？下面说明不会。

设 Kruskal 刚要选边 e，e 连着两个还不同组的点 a、b。此前选的边，假定都能放进某一棵最小生成树 T 里。要是 T 本来就含 e，没什么可说。要是不含，把 e 加进 T，就出现一个圈：从 a 沿 T 走到 b，再沿 e 走回 a。a 在自己那一组里，b 不在，所以这条从 a 到 b 的路，一定有一条边 f 跨出 a 那一组。f 两端此刻不同组，Kruskal 没有跳过它；又因为比 e 短的边都已经看过了（要么选上，要么两端已经同组），f 不会比 e 短。从 T 里拿掉 f、放进 e，仍然是生成树，总长度不会变大，所以也是最小生成树，而且含有到 e 为止选过的全部边。一直这样做下去，Kruskal 选完的那 N − 1 条边，就是一棵最小生成树。

这个理由用的是[第 9 章](09-眼前的选择凭什么放心.md)《眼前的选择凭什么放心》里的老办法：拿一个最优答案，换掉一条边，证明不会变坏。它只用了一件事：f 跨出了 a 所在的那一组，而 e 是眼下跨组的边里最短的。Prim 每轮选的，也是跨出“已接通部分”的最短边，同一条理由照样成立。

要是 f 和 e 一样长，换完以后总长度不变：最小生成树可能不止一棵。下面这道题就在数有几棵。

### 简化农场

一张图有 N 个点（到 4 万）、M 条边（到 10 万），每条边有长度（1 到 10⁶）。题目保证同一个长度至多有 3 条边。求最小生成树的总长度，以及不同的最小生成树有几棵，后者除以 10⁹ + 7 取余数。

输入第一行 N 和 M，接下来 M 行，每行一条边的两端和长度。输出总长度和棵数，中间一个空格。

样例输入：

```text
4 5
1 2 1
3 4 1
1 3 2
1 4 2
2 3 2
```

样例输出：

```text
4 3
```

两条长度为 1 的边 1—2、3—4 一定要选。之后 {1, 2} 和 {3, 4} 两组，三条长度为 2 的边都连着这两组，选哪一条都行，只能选一条。总长 1 + 1 + 2 = 4，共 3 棵。这是 USACO 2011 年 12 月金组第二题[“简化农场”](../USACO/金组/2011_2012/2011.12/P2.md)。

把边按长度分批。一批里的边长度相同，上面的交换说明，选这一批里的哪几条，只要选出的边不成圈、而且把能并的组都并上，就都可以接着做成最小生成树。还有一件事：不管这一批怎样选，处理完以后的分组都一样，等于把这一批边全部加进去以后的连通情况。所以下一批面对的局面不受这一批的选法影响，各批的选法数可以相乘。

一批至多 3 条边，把每条边的两端换成它们此刻的代表，至多 6 个代表。3 条边的子集只有 8 个，逐个试：不成圈、而且合并次数等于这一批最多能做的合并次数，就算一种选法。样例的长度 2 那一批，三条边的两端都是代表 1 和代表 3，最多合并一次；单选一条的 3 个子集合格，选两条以上就成圈，选零条合并不够。乘积是 1 × 3 = 3。

**停笔 5**　把样例里的 `2 3 2` 改成 `2 3 3`，答案变成什么？要是不改它，而是再加一条 `2 4 1` 呢？

## 核对

1. 并 0 和 5：两组都只有一人，让 5 挂到 0 下，`leader[5] = 0`。并 5 和 4：5 的代表是 0（2 人）；查 4 时走 4 → 3 → 1，第一步就让 `leader[4]` 从 3 改成祖父 1。4 的代表 1 那组有 4 人，所以让 0 挂到 1 下，`leader[0] = 1`。
2. 输出 `NO`、`YES`、`YES`、`NO`，四行都错了位。记录时还没算上刚打开的谷仓，第 i 格记下的是打开 `order[i]` 以前的状态，也就是“关掉前 i + 1 个以后”的答案，整列往上挪了一格；最后一格记的是一个谷仓都没开时的 0 组。
3. 答 3。它排在 (3, 1) 和 (1, 2) 之间：处理它以前并入了相关度不小于 2 的全部边，四个视频都在一组，除去视频 3 自己，剩 3 个。
4. C = 30 时，29 和 17 都不能铺，只剩一根都没有，输出 −1。C = 17 时，17 和 29 都能铺，10 不能，仍是 46。
5. 改成 `2 3 3`：长度 2 那一批只剩 1—3、1—4 两条，任选一条，长度 3 的边用不上，输出 `4 2`。加 `2 4 1`：长度 1 有 1—2、3—4、2—4 三条，连成一条线 1—2—4—3，不成圈，全选，图已连通，长度 2 的边一条不用，输出 `3 1`。
