# 17　每次只请最合适的一项出来

医院的急诊室不按先来后到看病。护士给每位病人定一个轻重，医生空下来，就请最重的那一位进去。新病人随时会来，排在中间也好、最前也好，护士只要保证一件事：下一个被请进去的，是此刻最重的。至于第五重、第六重的是谁，没人关心。

[第一卷第 15 章](../I/15-按访问方式挑容器.md)用过 `priority_queue`：放进去一批数，每次取最大的。这一章看它里面是怎样排的，为什么只排到“够用”就停，以及什么样的题需要“每次只请最合适的一项出来”。

## 整排不用有序，只要每位家长不比孩子大

要随时取出最大的，最直接的办法是把整排排好序。可是新数不断加进来，每加一个都要挪动一大片。其实我们只需要最大的那个在最前面。

把数排成一棵树：每个位置有至多两个孩子，规矩只有一条，每位家长都不比自己的孩子小。这样，最上面那个一定是最大的：它不比孩子小，孩子不比孙子小，一路下去，它不比任何一个小。同一位家长的两个孩子谁大谁小，隔着几层的两个数谁大谁小，规矩都不管。

这棵树放在一个 `vector` 里，不用记谁是谁的孩子：下标 0 是最上面那个，下标 k 的两个孩子是 2k + 1 和 2k + 2，家长是 (k − 1) / 2。一层层从左往右填，中间不留空，N 个数就占下标 0 到 N − 1。

例如 `9 6 4 1 5 3 2 1`：下标 0 的 9 有孩子 6、4；下标 1 的 6 有孩子 1、5；下标 2 的 4 有孩子 3、2；下标 3 的 1 有孩子 1。每位家长都不比孩子小。可这一排并没有排好序：5 排在 1 后面，3 排在 5 后面。

满足这条规矩、这样存放的一排数，叫**堆**。最上面最大的，叫大根堆；规矩反过来、最上面最小的，叫小根堆。树一层比一层宽一倍，N 个数只有约 log N 层。

## 让堆自己维护自己的规矩

加一个数：先放在最末，规矩可能在它和家长之间被破坏。它比家长大，就和家长换位置，再和新家长比，直到不比家长大，或者到了最上面。这叫**上浮**。

取走最大的：把最末那个数挪到最上面，再把最末一格删掉。规矩可能在最上面被破坏。它比两个孩子中大的那个小，就和那个孩子换，再往下比，直到不比孩子小，或者没有孩子。这叫**下沉**。为什么要和大的那个孩子换？换上来的成了另一个孩子的家长，它得不比那个孩子小。

两件事都只沿一条从上到下的路走，至多 log N 步。下面是**片段**，放在 `main` 外面。

```cpp
std::vector<int> heap;  // 大根堆：heap[k] 不比 heap[2k + 1]、heap[2k + 2] 小

void push(int value) {
    heap.push_back(value);
    int k = heap.size() - 1;
    while (k > 0) {
        int up = (k - 1) / 2;
        if (heap[up] >= heap[k]) {
            break;
        }
        std::swap(heap[up], heap[k]);  // 比家长大：上浮一层
        k = up;
    }
}

// 删去最大的一个；调用前 heap 不能是空的
void pop() {
    heap[0] = heap.back();
    heap.pop_back();
    int size = heap.size();
    int k = 0;
    while (true) {
        int largest = k;
        int left = 2 * k + 1;
        int right = 2 * k + 2;
        if (left < size && heap[left] > heap[largest]) {
            largest = left;
        }
        if (right < size && heap[right] > heap[largest]) {
            largest = right;
        }
        if (largest == k) {
            break;
        }
        std::swap(heap[k], heap[largest]);  // 比大的孩子小：下沉一层
        k = largest;
    }
}
```

`pop` 里只剩一个数时，`heap[0] = heap.back()` 是自己赋给自己，再删掉，堆变空，`size` 是 0，循环第一轮就停。标准库的 `priority_queue` 做的是同样的事。往后的程序都直接用它，这个片段只是让我们知道它为什么快。

### 牛奶调度

N 头牛（1 到 1 万），挤一头牛要 1 个单位时间。第 i 头牛产 gᵢ 加仑（1 到 1000），但必须在时刻 dᵢ 以前挤完（1 到 1 万）。时间从 0 开始，所以时刻 x 以前至多挤 x 头牛。问最多能挤多少加仑。

输入第一行 N，接下来 N 行，每行 g 和 d。输出一个整数。

样例输入：

```text
4
10 3
7 5
8 1
2 1
```

样例输出：

```text
25
```

截止时刻是 1 的两头牛只能有一头在 0 到 1 之间挤，取产 8 的那头。另两头都来得及。8 + 10 + 7 = 25。这是 USACO 2013 年 12 月银组第一题[“牛奶调度”](../USACO/银组/2013_2014/2013.12/P1.md)。

把时间切成一个个时段：第 t 个时段是从 t − 1 到 t。能放进第 t 个时段的牛，是截止时刻不早于 t 的牛。越靠后的时段，能来的牛越少。所以从最后一个时段往前排：每个时段，从能来的、还没挤的牛里，请产奶最多的那头。

为什么不会后悔？看第 t 个时段，设能来的牛里产奶最多的是 c。拿任意一个最好的安排来比。c 要是没被挤，把第 t 个时段原来的牛换成 c，不会变少；c 要是被安排在更早的时段 s，就和第 t 个时段的牛对换：那头牛截止时刻不早于 t，当然也赶得上更早的 s。两种情况都说明，第 t 个时段请 c，总有一个最好的安排和它一致。

往前走一个时段，能来的牛只会多不会少：截止时刻正好是 t 的牛，从这一刻起加入。所以手里留一个大根堆，装“能来、还没挤”的牛的产奶量。每到一个时段，先把截止时刻恰好是它的牛加进去，再请出最大的。

下面是**完整程序 A**。

```cpp
#include <algorithm>
#include <cstdio>
#include <queue>
#include <vector>

int main() {
    int n = 0;
    if (std::scanf("%d", &n) != 1) {
        return 1;
    }
    const int max_time = 10000;
    std::vector<std::vector<int>> due(max_time + 1);  // due[t]：截止时刻恰好是 t 的牛的产奶量
    int last = 0;
    for (int i = 0; i < n; ++i) {
        int gallons = 0;
        int deadline = 0;
        if (std::scanf("%d%d", &gallons, &deadline) != 2) {
            return 1;
        }
        due[deadline].push_back(gallons);
        last = std::max(last, deadline);
    }
    std::priority_queue<int> waiting;  // 能放进当前时段、还没挤的牛
    int total = 0;
    for (int t = last; t >= 1; --t) {  // 第 t 个时段：从 t − 1 到 t
        for (int gallons : due[t]) {
            waiting.emplace(gallons);
        }
        if (!waiting.empty()) {
            total += waiting.top();
            waiting.pop();
        }
    }
    std::printf("%d\n", total);
    return 0;
}
```

总量至多 1 万 × 1000 = 10⁷，`int` 放得下。每头牛进堆一次、出堆至多一次，加上走过的 1 万个时段，是 O(N log N + 最大截止时刻)。

拿样例走一遍。最晚的截止时刻是 5。t = 5：产 7 的牛进堆，请出 7。t = 4：没有新牛，堆空。t = 3：产 10 的进堆，请出 10。t = 2：堆空。t = 1：8 和 2 进堆，请出 8；2 留在堆里，没有时段了。共 25。

慢办法不用这条贪心：试遍所有的牛的子集，对每个子集试遍挤奶的先后，看有没有一种先后让每头牛都赶得上。每组至多 6 头牛、截止时刻不超过 4，和程序 A 对拍 300 组，答案全部相同。

### 排队吃草

一小块草地一次只能让一头牛吃。N 头牛（到 10 万），第 i 头在时刻 aᵢ 到达（到 10⁹），轮到她就吃 tᵢ（到 10⁴）。草地空出来时，正在等的牛里资历最高的先吃；恰好在别人吃完那一刻到达的也算在等。牛按资历从高到低给出。问所有牛里，等得最久的等了多久。

输入第一行 N，接下来 N 行，每行 a 和 t。输出一个整数。

样例输入：

```text
5
25 3
105 30
20 50
10 17
100 10
```

样例输出：

```text
10
```

第 4 头牛时刻 10 先到，吃到 27。这期间第 1、3 头到了，第 1 头资历高，吃到 30，等了 2。第 3 头接着吃到 80，等了 10。80 以后草地空着，第 5 头时刻 100 到，吃到 110；第 2 头 105 到，等了 5。最久是 10。这是 USACO 2018 年 12 月银组第二题[“排队吃草”](../USACO/银组/2018_2019/2018.12/P2.md)。

这题按时间模拟。先把牛按到达时刻排好。手里两样东西：草地下次空出来的时刻 `free_at`；一个堆，装已经到了、还在等的牛，按资历排，资历最高的在最上面。每次草地空出来，先把到达时刻不晚于 `free_at` 的牛都放进堆，再请出资历最高的那头去吃，记下她等了多久，`free_at` 加上她吃的时间。堆是空的，说明草地会闲一阵，就直接跳到下一头牛到达的时刻。

用堆是因为“谁先吃”不按到达的先后，而按资历。只用一个按到达排好的队列，就会让先到的低资历牛插到高资历牛前面。资历高的编号小，所以堆里存编号，请出最小的那个，要用第一卷第 15 章那句 `std::greater<int>` 的写法。

**停笔 3**　样例里把第 5 头牛的到达时刻改成 50，答案变成几？说出时刻 80 草地空出来时堆里有谁。

## 建堆与排序不是一回事

手里已经有 N 个数，要建成一个堆。一个个 `push` 进去是 O(N log N)。还有更快的办法：先原样放进 `vector`，再从最后一位家长开始往前，每个位置做一次下沉。

拿 `3 1 4 1 5 9 2 6` 试，N = 8，最后一位家长是下标 3。下标 3 的 1 比孩子 6 小，换：`3 1 4 6 5 9 2 1`。下标 2 的 4 比大孩子 9 小，换：`3 1 9 6 5 4 2 1`。下标 1 的 1 和大孩子 6 换，再往下，比孩子 1 不小，停：`3 6 9 1 5 4 2 1`。下标 0 的 3 和 9 换，再和 4 换：`9 6 4 1 5 3 2 1`。这就是第一节那个堆。

为什么从后往前？做到位置 k 时，k 的两个孩子下面已经各是一个堆，k 只要下沉一次就把两个堆连同自己合成一个。工作量也比看上去小：一半的位置是叶子，根本不用沉；四分之一的位置至多沉一层；八分之一至多两层……加起来不超过 N 次交换，是 O(N)。

建好的堆并没有排好序。要排好序，得一次次请出最大的：每请一次 log N，N 次是 O(N log N)。建堆的 O(N) 省下的只是“建”，不是“排”。只靠比较大小，没有办法用 O(N) 把 N 个数排好；第三卷第 26 章会说明为什么。所以，一批数只要排一次、以后不再加新数，直接 `std::sort` 就好；数会不断进来、每次只要最大的那一个，才是堆的场合。

**停笔 4**　对 `2 7 1 8 2 8` 从后往前建大根堆，写出每做完一个位置后的整排。最后的结果是排好序的吗？

不必把整排排好，只要每位家长不比孩子大，就能随时请出最大的那一个。“牛奶调度”从后往前，每个时段请出能来的牛里最好的；“排队吃草”让资历决定谁先吃，而不是先来后到。能写出上浮、下沉每一步换了谁，能说清什么时候该排序、什么时候该用堆，再读下一章。下一章换到文字上：在一长串字里找一个词，失败一次以后，怎样不必退回开头重新比。
