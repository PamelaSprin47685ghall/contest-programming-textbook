# 20　让几种工具接成一件事

做一顿饭，要洗菜、切菜、烧水、炒菜。每一样都不难，难在先后：水没烧开，面就下不了锅；菜还没切，锅已经热得冒烟。会做饭的人，不是多会了一样手艺，而是知道这几样怎样接在一起，哪一样等哪一样。

这一卷讲了一样样工具：前缀和、二分、排序、搜索、DP、并查集、树状数组、堆……这最后一章不讲新工具，讲怎样把它们接成一件事：两个条件时先固定一个，每个部分只管好自己的那份账，程序错了怎样把出错的输入缩到最小，最后在离开本卷之前，独立做一道题。

## 原来是两项条件，可以先固定一项

一个点 (x₁, y₁) 能接在另一个点 (x₂, y₂) 后面，要求 x₂ ≤ x₁ 并且 y₂ ≤ y₁。两项条件同时要满足，一个个点对去试是 O(N²)。

办法是先让一项条件自己成立：把所有点按 x 排好，从小到大扫过去。扫到一个点时，已经扫过的点 x 都不比它大，第一项条件不用再管。剩下的只有 y：在已经扫过的点里，y 不超过它的那些，取最好的一个。这正是[第 15 章](15-修改以后还想马上查询.md)的树状数组能做的事：下标是 y 的名次，问一个前缀。

排序负责一项条件，数据结构负责另一项，这种接法在这一节的题里一再出现。

### 跳板

贝茜在方格纸上从 (0, 0) 走到 (N, N)（N 到 10⁹），只能往上或往右走。纸上有 P 块跳板（P 到 10⁵），第 i 块在 (x₁, y₁)，踩上去立刻落到 (x₂, y₂)，保证 x₁ ≤ x₂、y₁ ≤ y₂。所有起跳点和落点互不相同。问最少要走多远（跳的那一下不算路程）。

输入第一行 N 和 P，接下来 P 行，每行 x₁、y₁、x₂、y₂。输出一个整数。

样例输入：

```text
3 2
0 1 0 2
1 2 2 3
```

样例输出：

```text
3
```

从 (0, 0) 走 1 步到 (0, 1)，跳到 (0, 2)；走 1 步到 (1, 2)，跳到 (2, 3)；再走 1 步到 (3, 3)。共 3 步。这是 USACO 2020 年 1 月金组第三题[“跳板”](../USACO/金组/2019_2020/2020.01/P3.md)。

不用跳板，要走 2N 步。用了跳板，路程是 2N 减去各块跳板省下的。记 `cost[i]` 为走到第 i 块跳板起跳点最少要走多远。直接走过去是 x₁ + y₁；也可以先用别的跳板 j，从 j 的落点走过来，要 `cost[j]` + (x₁ − x₂ⱼ) + (y₁ − y₂ⱼ)，这时 j 的落点要满足 x₂ⱼ ≤ x₁、y₂ⱼ ≤ y₁。整理一下：

`cost[i]` = x₁ + y₁ + min(0, 所有能接上的 j 里 `cost[j]` − x₂ⱼ − y₂ⱼ 最小的那个)。

`cost[j]` − x₂ⱼ − y₂ⱼ 是负的时，说明用 j 比直接走省了路，省下的就是它的相反数。最后答案是 2N 加上所有跳板里这个数最小的那个（不比 0 大）。

这就是[第 8 章](08-给已经解决的小问题留个位置.md)的 DP，难处在“所有能接上的 j”是两项条件。照上面的办法，把起跳点和落点都当作事件，按 x、再按 y 排好扫过去。扫到一个落点，把它的那个数记进树状数组，下标是 y 的名次；扫到一个起跳点，问名次不超过它的前缀里最小的数。

两件事要核对。第一，`cost[j]` 要在用到之前算好：j 的起跳点 x、y 都不比它的落点大，又不是同一个点，所以排序后起跳点一定在落点前面。第二，树状数组要的是前缀最小值，第 15 章说过，最小值不能相减，只能在格子只改小、不改大的时候维护；这里每个落点只往里加一个数，取最小，正好只改小。

下面是**完整程序 A**。

```cpp
#include <algorithm>
#include <cstdio>
#include <vector>

// 按 y 的名次记前缀最小值。格子只会被改小，所以树状数组能维护它
struct PrefixMin {
    std::vector<long long> best;  // 开始全是 0：直接走过去，什么也不省

    void lower(int k, long long value) {
        int limit = best.size();
        while (k < limit) {
            best[k] = std::min(best[k], value);
            k += k & -k;
        }
    }

    // 名次 1 到 k 里最小的一个
    long long query(int k) const {
        long long result = 0;
        while (k > 0) {
            result = std::min(result, best[k]);
            k -= k & -k;
        }
        return result;
    }
};

struct Event {
    long long x;
    long long y;
    int board;
    bool landing;  // true 是落点，false 是起跳点
};

int main() {
    long long n = 0;
    int p = 0;
    if (std::scanf("%lld%d", &n, &p) != 2) {
        return 1;
    }
    std::vector<Event> events;
    std::vector<long long> ys;
    for (int i = 0; i < p; ++i) {
        long long x1 = 0;
        long long y1 = 0;
        long long x2 = 0;
        long long y2 = 0;
        if (std::scanf("%lld%lld%lld%lld", &x1, &y1, &x2, &y2) != 4) {
            return 1;
        }
        events.push_back(Event{x1, y1, i, false});
        events.push_back(Event{x2, y2, i, true});
        ys.push_back(y1);
        ys.push_back(y2);
    }
    std::sort(ys.begin(), ys.end());
    ys.erase(std::unique(ys.begin(), ys.end()), ys.end());
    // 先按 x、再按 y 排：能接在一个点前面的点，都排在它前面
    std::sort(events.begin(), events.end(), [](const Event& a, const Event& b) {
        if (a.x != b.x) {
            return a.x < b.x;
        }
        return a.y < b.y;
    });
    PrefixMin saved;
    saved.best.assign(ys.size() + 1, 0);
    std::vector<long long> cost(p, 0);  // cost[i]：走到跳板 i 的起跳点，最少走多远
    for (const Event& event : events) {
        int rank = std::lower_bound(ys.begin(), ys.end(), event.y) - ys.begin() + 1;
        if (event.landing) {
            saved.lower(rank, cost[event.board] - event.x - event.y);
        } else {
            cost[event.board] = event.x + event.y + saved.query(rank);
        }
    }
    std::printf("%lld\n", 2 * n + saved.query(ys.size()));
    return 0;
}
```

`saved` 里每格开始都是 0，表示“直接走过去，一点不省”，所以 `query` 从 0 起取最小，自然带上了公式里的 min(0, …)。坐标到 10⁹，`cost` 到 2 × 10⁹，都用 `long long`。`std::lower_bound` 在排好序的 `ys` 里找第一个不小于 `event.y` 的位置，意思和[第一卷第 17 章](../I/17-集合、顺序与自己设计的键.md)集合的 `lower_bound` 一样；`ys` 里一定有 `event.y`，所以找到的就是它，名次从 1 编号。

2P 个事件排一次序，每个事件做一次 `lower_bound` 和一次树状数组操作，是 O(P log P)。

慢办法不用这条 DP：把起点、终点和所有起跳点、落点都当作地点，能往右上走到的两点之间连一条“走路”的边，跳板连一条长度为 0 的边，反复松弛到不再变化。和程序 A 对拍 300 组，每组 N 不超过 6、至多 4 块跳板，答案全部相同。

## 每个对象只维护自己的账

程序 A 里有三样东西各管各的。`Event` 只是一份记录，不承诺什么。`PrefixMin` 承诺一件事：`query(k)` 等于“名次不超过 k、被 `lower` 记进来的所有数，再加上 0”里最小的那个。`main` 负责扫描的次序，它承诺：扫到一个起跳点时，能接上的落点都已经交给了 `PrefixMin`，不能接上的一个也没交。

分开写的好处，是每一份承诺可以单独核对。`PrefixMin` 可以拿一个普通数组来对拍：数组每格记最小值，`query` 就把前 k 格扫一遍。它对了，再去怀疑排序和 DP。[第 13 章](13-只记住谁和谁是一组.md)的并查集也是这样：`group_size` 这本账只记在代表身上，别的人的那一格不必对；调用的人只要守住“查人数先 `find`”，就不会读到旧账。

账要记在一处。要是 `main` 里另外留了一个“目前最省的数”，又在 `PrefixMin` 里记了一份，两份迟早会对不上。也要说清承诺的边界：`PrefixMin` 只在“格子只改小”时成立，谁要拿它去改大一个数，就超出了它的承诺，错了不能怪它。

**停笔 2**　有人想让 `PrefixMin` 也支持“撤回一个记进去的数”。`best` 里现在存的东西够不够？举一个例子说明撤回以后 `query` 会算错。

## 让失败的输入越来越小

程序错了，对拍会给出一组让两份程序答案不同的输入。这组输入往往比需要的大，满纸的数，看不出错在哪里。下一步不是盯着代码猜，而是把输入缩小：每次删去一点，删完还错，就留着删；删完不错了，就放回去，试着删别的。一直删到哪一点都删不动为止。

拿程序 A 做个试验。把 `lower` 里的 `best[k] = std::min(best[k], value);` 误写成 `best[k] = value;`，样例照样输出 3，看不出错。对拍到第 5 组就停了：

```text
5 3
5 2 5 5
3 1 4 5
0 4 1 4
```

错的程序输出 7，慢程序输出 5。试着删掉第三块跳板，还是 7 对 5，留着删。再删前两块里的任何一块，两份程序就一样了。最后剩下：

```text
5 2
5 2 5 5
3 1 4 5
```

两块跳板，可以在纸上走了。事件的次序是：(3, 1) 起跳，`cost` 为 4；(4, 5) 落下，记 4 − 9 = −5；(5, 2) 起跳，名次 2 以内最小是 0，`cost` 为 7；(5, 5) 落下，记 7 − 10 = −3。两个落点的 y 都是 5，记在同一格。第二次的 −3 把第一次的 −5 盖掉了，最后答案是 10 − 3 = 7。错在哪里一眼就看到：同一格被记了两次，后来的更差，却覆盖了先来的。

删的时候要守住输入的约定：这题要求所有点互不相同、x₁ ≤ x₂、y₁ ≤ y₂。删掉整块跳板不会破坏约定；要是把一个坐标改小，就得重新检查。一组不合约定的输入让程序出错，说明不了程序的问题。

删的办法可以交给一个小脚本，每次删一块、跑两份程序、比答案，不必手工一遍遍改文件。数值也可以照样缩：把坐标往小里换，只要还错就留着。最后留在纸上的，常常只有两三行。

**停笔 3**　再把坐标也往小里缩，能缩到 `2 2`、`0 0 0 2`、`1 0 2 0`：错的程序输出 3，应是 2。这一回两个落点的 y 一个是 2、一个是 0，并不在同一格，为什么还会被盖掉？

## 核对与离开本卷之前

### 先不翻书，试着独立做一次

教室里有 N 盏灯（1 到 10⁵），编号 1 到 N。电工一共接 M 根电线（0 到 2 × 10⁵），第 i 根在第 tᵢ 分钟接通，把灯 aᵢ 和灯 bᵢ 连起来；tᵢ 互不相同，都在 1 到 10⁹ 之间。连在一起的灯会同时亮。问最早在第几分钟，所有灯连成了一片。N = 1 时输出 0；接完也连不成一片，输出 −1。

先用纸笔做，不急着写程序。

输入第一行 N 和 M，接下来 M 行，每行 a、b、t。例如输入

```text
4 4
1 2 5
3 4 2
2 3 7
1 4 9
```

应输出

```text
7
```

先回答几个小问题：电线是按 t 的顺序给出的吗？需要按什么排序？“所有灯连成一片”用前面哪一章的工具判断最省事？还有没有第二种做法，可以拿来和第一种对拍？

做完再核对。电线不一定按时间给出，先按 t 从小到大排好。然后照第 13 章，一根根并起来，手里记“还剩几组”，从 N 开始，每成功并一次减一，减到 1 时的那根电线的 t 就是答案；全部并完还不到 1，输出 −1。样例排好后是 2、5、7、9：t = 2 并 3、4，剩 3 组；t = 5 并 1、2，剩 2 组；t = 7 并 2、3，剩 1 组，答案 7。N = 1 时一开始就只有 1 组，不用看电线，输出 0。排序 O(M log M)，合并几乎是 O(M)。

第二种做法：答案有单调性，第 t 分钟已经连成一片，以后也是一片。于是照[第 5 章](05-每次划掉一半候选.md)二分答案，每猜一个 t，只用 tᵢ ≤ t 的电线，照[第 10 章](10-把能到达的地方找出来.md)搜一遍看是否连通。它慢一些，O((N + M) log M)，但和并查集几乎不共用想法，正好拿来对拍。

**停笔 4**　给这道题找三个会让粗心的程序出错的输入：一个与 N = 1 有关，一个与“接完也连不成”有关，一个与电线的给出次序有关。各写出应有的输出。

### 回头看这一卷走过的路

[第 1 章](01-先问办法靠不靠谱.md)问了四件事：答案在数什么，办法凭什么对，要做多少工作，拿什么核对。以后每一章都在回答它们。

第 2 到第 9 章，学的是怎样少做重复的工作：把选择走成一棵树，再学会提前封住岔路；把重复的加法收进前缀和；排好序，让顺序替我们保存信息；每次划掉一半候选；让走过的路不白走；把一大步拆成几小步；给解决过的小问题留个位置；再问眼前的选择凭什么放心。

第 10 到第 14 章，换到地图上：先找出能到达的地方，再排出谁先谁后，再算最省的走法；只记谁和谁一组；没有圈的地图又多了根、子树和共同祖先。

第 15 到第 19 章，是几样随时修改、随时查询的工具，和文字、整数自带的线索：树状数组、线段树、堆、失败函数、前缀树、整除和余数。

这一章把它们接了起来。几十道银组、金组的题，没有一道是靠背出“这是哪一类题”做出来的。都是先说清答案在数什么，再问手里要记什么、每一步怎样改、为什么不漏不重。

### 下一步学什么

第三卷《把难题拆到能检查》接着往下走。它先练怎样摆出一个能检查的答案，换一张坐标纸看顺序；再把树上的路分段，换个顺序回答很多询问，给昨天留一份不会变的记录；然后是更省的 DP、只带着边界穿过下一格，地图上不能轻易断的地方，以及配对与网络。后面还有文字的结构、计数、余数、概率、博弈、几何，和“哪里不能靠蛮力过去”的道理。

那一卷的题更难，工具也更多，但读法不变。读不懂题，先用具体的数演一遍；程序出错，先把输入缩到最小。每次只换一个主要的想法，说得出它为什么有效，再往下走。

这一章没有新工具。“跳板”让排序管住一项条件、树状数组管住另一项；程序 A 的几个部分各守一份承诺，可以分开核对；一个看不出的错，靠把输入删到两行才露出来。能不翻书做出上面那道灯的题，并且用第二种办法核对它，就可以去读第三卷了。

## 核对

1. 答案仍是 3。新跳板从 (2, 0) 起跳，直接走过去要 2 步，名次在它以内的前缀里还没有记过数，`cost` 为 2；它的落点 (3, 2) 记 2 − 5 = −3。事件次序是 (0, 1) 起跳，`cost` 1；(0, 2) 落下，记 −1；(1, 2) 起跳，`cost` 3 − 1 = 2；(2, 0) 起跳，`cost` 2；(2, 3) 落下，记 −3；(3, 2) 落下，记 −3。最小仍是 −3，6 − 3 = 3：走到 (2, 0) 再跳、再走 1 步，和原来一样是 3 步。
2. 不够。`best[k]` 只存了几个数里最小的那一个，不知道第二小的是几。例如在名次 1 记进 −5 和 −3，`query(1)` 是 −5；撤回 −5 以后应是 −3，可是 `best` 里已经没有 −3 了。
3. 树状数组的一格管的是一段名次。y 的名次是 0 → 1、2 → 2，第 2 格管名次 1 到 2。先记的 −2 进了第 2 格；后记的 −1 从第 1 格往上走，也走到第 2 格，把 −2 盖成了 −1。最后 `query(2)` 读第 2 格，得 −1，答案 4 − 1 = 3。
4. N = 1、M = 0，应输出 0，不能因为没有电线就输出 −1。N = 3、只有一根 `1 2 4`，应输出 −1。N = 3，先给 `2 3 8` 再给 `1 2 4`，应输出 8；不排序就从头并的程序在第二根并完时连通，会输出 4。
