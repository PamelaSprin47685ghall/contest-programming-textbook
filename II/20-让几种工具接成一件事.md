# 20　让几种工具接成一件事

操场上放了许多标志牌，每块用横、纵坐标定位。老师不断问：“横坐标不超过 X、纵坐标不超过 Y 的牌有几块？”同位置可以有多块，都要计数。

先别挑模板。画三个点、两条查询边界，自己数一次，再决定每件工具负责什么。

## 原来是两项条件，可以先固定一项

把牌按横坐标排序，把问题也按 X 排序。依次回答问题时，将所有横坐标不超过 X 的牌加入记录。这样，记录里已经满足横坐标条件，只剩纵坐标条件要查。

纵坐标可能很大或为负，按出现值离散化。每放入一块牌，给对应排名加一；查询 Y 时，用 `upper_bound` 找有多少种坐标不大于 Y，再求那段前缀数量。

这叫**离线处理**：问题先全部收到，再改变处理顺序。输出时要恢复原问题顺序，所以每题保存编号。若下一题由上一题答案生成，就不能未经说明地这样排序。

**停笔 1**　牌在 `(1,4)`、`(3,2)`、`(3,5)`，查询 `(3,4)`，应先加入几块，再数出几块？同横坐标的牌是在查询前还是后加入？

## 每个对象只维护自己的账

排序后的扫描过程负责何时加入、何时查询；树状数组只负责计数与前缀和，不认识 X，也不认识“老师的问题”。我们没有让一个结构顺便偷偷安排另一个结构的工作。

**完整程序：**输入 `0 <= n,q <= 100000`，接着 `n` 行牌坐标、`q` 行查询 `X Y`，所有坐标绝对值不超过十亿。按输入顺序逐行输出数量。

```cpp
#include <algorithm>
#include <cstdio>
#include <vector>

class Counts {
    std::vector<int> tree;
public:
    explicit Counts(int n) : tree(n + 1, 0) {}
    void add(int index) {
        for (int i = index + 1; i < static_cast<int>(tree.size()); i += i & -i) {
            ++tree[i];
        }
    }
    int prefix(int count) const {
        int result = 0;
        for (int i = count; i > 0; i -= i & -i) {
            result += tree[i];
        }
        return result;
    }
};

struct Point {
    int x;
    int y;
};

struct Query {
    int x;
    int y;
    int id;
};

int main() {
    int n = 0;
    int q = 0;
    if (std::scanf("%d%d", &n, &q) != 2 || n < 0 || n > 100000 || q < 0 || q > 100000) {
        return 1;
    }
    std::vector<Point> points(n);
    std::vector<int> coordinates;
    coordinates.reserve(n);
    for (Point& point : points) {
        if (std::scanf("%d%d", &point.x, &point.y) != 2) {
            return 1;
        }
        coordinates.emplace_back(point.y);
    }
    std::vector<Query> queries(q);
    for (int i = 0; i < q; ++i) {
        if (std::scanf("%d%d", &queries[i].x, &queries[i].y) != 2) {
            return 1;
        }
        queries[i].id = i;
    }
    std::sort(coordinates.begin(), coordinates.end());
    coordinates.erase(std::unique(coordinates.begin(), coordinates.end()), coordinates.end());
    std::sort(points.begin(), points.end(), [](const Point& a, const Point& b) {
        return a.x < b.x;
    });
    std::sort(queries.begin(), queries.end(), [](const Query& a, const Query& b) {
        return a.x < b.x;
    });
    Counts counts(static_cast<int>(coordinates.size()));
    std::vector<int> answer(q);
    int inserted = 0;
    for (const Query& query : queries) {
        while (inserted < n && points[inserted].x <= query.x) {
            int index = static_cast<int>(std::lower_bound(coordinates.begin(), coordinates.end(),
                                                          points[inserted].y) - coordinates.begin());
            counts.add(index);
            ++inserted;
        }
        int end = static_cast<int>(std::upper_bound(coordinates.begin(), coordinates.end(), query.y)
                                   - coordinates.begin());
        answer[query.id] = counts.prefix(end);
    }
    for (int value : answer) {
        std::printf("%d\n", value);
    }
    return 0;
}
```

输入：

```text
3 3
1 4
3 2
3 5
2 4
3 4
0 100
```

输出：

```text
1
2
0
```

排序与树状数组总时间 `O((n+q) log(n+q+1))`，空间 `O(n+q)`。没有牌时坐标表为空，前缀查询仍为零；不能为了让答案“非空”虚构一块牌。

## 让失败的输入越来越小

朴素版每题扫描全部牌，为 `O(nq)`，但十分适合检查小数据。快慢程序答案不同，先删掉一半牌或一半查询，看差异是否仍在；保留仍会错的一半，继续缩小。最后可能只剩“同坐标的牌忘了先加入”这样一个清晰错误。

随机数据外，还要专门做：全部坐标相同；查询恰好落在边界；Y 在所有坐标外；查询顺序与 X 完全相反；没有点或没有查询。检查耗时、内存时另选大数据，不把小数据对拍当作性能证明。

**停笔 2**　若横坐标条件改成严格小于 X，程序哪一个比较要改？纵坐标改成严格小于 Y，又该换哪个查找工具？

**停笔 3**　把查询改成一个任意矩形，如何用至多四个“左下角无限延伸”的计数相加减？先定整数边界，不要让减一溢出。

## 核对与离开本卷之前

1. 三块都先加入，前缀数出两块。因为条件含等号，相同 X 必须先加入。
2. 插入条件改为 `< query.x`；Y 用 `lower_bound` 找严格小于的坐标数。
3. 对半开矩形 `[x1,x2)×[y1,y2)`，统一定义 `F(X,Y)` 数 `x<X,y<Y`，答案为 `F(x2,y2)-F(x1,y2)-F(x2,y1)+F(x1,y1)`。直接用严格边界，不必对最小整数减一。

能独立说明每份记录的含义，能找到一个会击穿错误方案的例子，再去第三卷。速度来自少做无用工作，不是把程序写得让别人看不懂。
