# 01　先摆一个能检查的答案

要把 1 到 7 排成一行，使相邻比较依次是“小、大、小、大”。你可以试遍排列，也可以直接摆成 `1 7 2 6 3 5 4`。这次先不求一个数，而是交出一份能被检查的作品。

## 从具体排列里找一条可重复规则

每次从剩余最小值、剩余最大值中轮流取一个。取最小时，下一个最大值一定更大；取最大值后，下一个最小值一定更小。直到只剩一项。这就说明所有相邻比较都符合要求，不是只验证了 7 这个样例。

这类题叫**构造**。交一份答案就够时，不必研究全部答案。却必须说明：有没有重复或遗漏；取值是否合法；每个相邻关系是否成立。

**完整程序：**输入 `1 <= n <= 100000`，输出 1 到 `n` 的一个排列，相邻关系从小于开始交替。`n=1` 时没有相邻关系，也符合约定。

```cpp
#include <cstdio>

int main() {
    int n = 0;
    if (std::scanf("%d", &n) != 1 || n < 1 || n > 100000) {
        return 1;
    }
    int left = 1;
    int right = n;
    for (int i = 0; i < n; ++i) {
        int value = (i % 2 == 0) ? left++ : right--;
        std::printf("%d%c", value, i + 1 == n ? '\n' : ' ');
    }
    return 0;
}
```

输入：

```text
7
```

输出：

```text
1 7 2 6 3 5 4
```

时间 `O(n)`，额外空间 `O(1)`。不同于判断“输出与某一行样例是否相同”，构造题的检查器应检查题目条件，别的合法排列也应通过。

**停笔 1**　对 `n=6` 写出程序的排列。若把第一步改取最大值，题目哪条要求会改变？

## 改一点，比较前后差了什么

两项任务的先后不好分析，就只交换相邻两项，比较总代价的变化。整个式子里大量共同部分会抵消，只剩与这两项相关的部分。这种增量分析，也可用于把所有方案都减去同一份基准方案。

例如一排灯最初全关，一次同时翻转两个相邻开关。每次亮灯数可能增减，但亮灯数的奇偶不变。所以“只亮一盏”不可能。这是**不变量**：动作改变了很多细节，却没改变某个特征。

证明过程结束，有时需要一个不断减少的非负整数，叫势能。例如每次交换一个相邻逆序对，逆序对数减一，最终必停。仅证明“不变量保持”不够证明会停；它也可能永远绕圈。

**停笔 2**　起初全关，要求只亮一盏，奇偶为何足以否定？如果操作改为翻转三盏，这个否定还成立吗？

## 先问局部，还是先看整体

平衡括号串，每个前缀里左括号不少于右括号，最终两者相等。这是把整体合法性拆成逐前缀检查。只看总数会接受 `)(`，只看相邻两个字符又看不到任意深的嵌套。

用栈匹配括号，可将每对括号看作树节点，包含关系是父子，外面加一个虚根便得到括号树。消去一对相邻可匹配符号，等于处理一个已经没有孩子的节点。由此，序列上的局部消除能变成树上的递归。

但“每个相邻位置都符合条件”不总能决定全局。三个点两两提出先后，可能组成圈。局部验证必须保存足够状态；计算理论里把程序运行拆成局部一致的格子，也是依靠这些格子共同编码完整状态，不是忽略全局。

遇到环，先选一个断口转成线；若答案依赖断口，就需要枚举、旋转表示或重复一份序列处理跨界区间。不能直接把跨尾首的一段丢掉。

**停笔 3**　`(()())` 对应的最外层括号有几个直接孩子？`())(` 总数相等，哪个前缀先失败？

## 核对

1. `1 6 2 5 3 4`。先取最大后，关系从大于开始，不再满足原先的方向。
2. 两次翻转使亮灯数改变偶数；从偶数到不了奇数。翻转三盏可改变奇偶，原不变量失效，须重新分析，而不是坚持旧结论。
3. 两个。`())` 处右括号首次多于左括号。
