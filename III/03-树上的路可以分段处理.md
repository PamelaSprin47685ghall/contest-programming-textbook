# 03　树上的路可以分段处理

城里的公交线路图，没人会把每两站之间怎么走都印出来。图上画的是几条线：从一个站到另一个站，先坐这条线，到换乘站下车，再坐另一条线。换乘不会太多，每条线上的一段又可以一口气坐完。

树上的路也可以这样管。这一章讲几种把树上的路拆成段的办法：把树分成几条长链，路就只换几次链；从孩子收答案，再把答案传回孩子；询问只涉及几个点时，只留下用得着的点；按路第一次经过哪个点来分账；以及把小的集合并进大的。树的基本说法，根、子树、重心、LCA、先序编号，照第二卷第 14 章《没有圈的地图多了什么》。

下面几节都用这棵 9 个点的树做例子，1 是根：

```text
1 的孩子：2、3
2 的孩子：4、5、6
3 的孩子：8
4 的孩子：7
8 的孩子：9
```

## 大孩子走同一条链

每个点的孩子里，子树最大的那个叫**重孩子**，连向它的边叫重边，别的叫轻边。一直沿重边往下走，得到的路叫一条**重链**。每个点恰好在一条重链上。

例子里，子树大小是：7、5、6、9 各 1，4 和 8 各 2，3 是 3，2 是 5，1 是 9。1 的重孩子是 2（5 比 3 大），2 的重孩子是 4（2 比 1 大），4 的是 7，3 的是 8，8 的是 9。重链有四条：1-2-4-7、3-8-9、5、6。

为什么这样分有用：从一个点往根走，每经过一条轻边，子树至少翻一倍。走过轻边从孩子 c 到父亲 p，p 还有一个重孩子，它的子树不比 c 的小，所以 p 的子树至少是 c 的两倍。n 个点的树里，子树大小翻不了 log₂ n 次以上，所以任意一点到根，至多经过 log₂ n 条轻边，也就至多碰到 log₂ n + 1 条重链。

再让重链在编号里挨在一起：求先序编号时，每个点先走重孩子，再走别的孩子。这样每条重链的编号是连续的一段，一条树上的路被拆成至多 O(log n) 段连续编号。每段交给第二卷第 16 章的线段树，“路上所有点加 1”“路上的最大值”这类问题，每次 O(log² n)。这种拆法叫**重链剖分**。

## 从孩子收答案，也能把答案传回孩子

第二卷第 14 章的树形 DP，从叶子往根收答案，最后得到根的答案。要是每个点都要当一次根，各做一遍是 O(n²)。办法是先算出根的答案，再看根从一个点挪到它的孩子时，答案怎样变，一路传下去。这叫**换根**。

### 目录遍历

一棵目录树有 N 个点（N 到 10⁵），1 号是根目录，叶子是文件，别的是目录。站在一个目录里，用相对路径写出一个文件：往上走一层写 `../`（3 个字符），往下进一个子目录写它的名字加一个斜杠，最后写文件名。问站在哪个目录里，到所有文件的相对路径长度之和最小，输出这个最小值。

输入第一行 N。接下来 N 行，第 i 行是第 i 个点的名字（不超过 16 个字符）和 m；m = 0 是文件，m > 0 是目录，后面跟着它里面 m 个点的编号。

样例输入：

```text
8
bessie 3 2 6 8
folder1 2 3 4
file1 0
folder2 1 5
file2 0
folder3 1 7
file3 0
file4 0
```

样例输出：

```text
42
```

站在 folder1 里，四条路径是 `file1`、`folder2/file2`、`../folder3/file3`、`../file4`，长 5、13、16、8，共 42。这是 USACO 2018 年 2 月金组第二题[“目录遍历”](../USACO/金组/2017_2018/2018.02/P2.md)。

先算站在根目录里的总长。每个文件的路径，是一路经过的目录名各加一个斜杠，再加上文件名。从根往下扫，记下“写到这个目录为止有多长”，每到一个文件把它加上。样例里是 13 + 21 + 13 + 5 = 52。

再看从目录 v 走进它的子目录 c，总长怎样变。c 里面的每个文件，路径开头少写了“c 的名字加一个斜杠”；c 外面的每个文件，路径开头多了一个 `../`。设 c 里面有 files 个文件，一共有 total 个文件，新的总长是

旧总长 − files × (c 的名字长度 + 1) + (total − files) × 3。

从根走进 folder1：52 − 2 × 8 + 2 × 3 = 42。

每个目录里有几个文件，是先序倒过来扫一遍收上来的；新总长只用到父亲的总长，所以照先序再扫一遍就能把每个目录都算出来。

下面是**完整程序 A**。

```cpp
#include <cstdio>
#include <cstring>
#include <vector>

int main() {
    int n = 0;
    if (std::scanf("%d", &n) != 1) {
        return 1;
    }
    std::vector<int> name_length(n, 0);
    std::vector<std::vector<int>> children(n);
    for (int i = 0; i < n; ++i) {
        char name[32] = {};
        int m = 0;
        if (std::scanf("%20s %d", name, &m) != 2) {
            return 1;
        }
        name_length[i] = static_cast<int>(std::strlen(name));
        for (int k = 0; k < m; ++k) {
            int child = 0;
            if (std::scanf("%d", &child) != 1) {
                return 1;
            }
            children[i].push_back(child - 1);
        }
    }

    // 先序：父亲排在孩子前面
    std::vector<int> order;
    order.push_back(0);
    for (int head = 0; head < static_cast<int>(order.size()); ++head) {
        for (int child : children[order[head]]) {
            order.push_back(child);
        }
    }

    // files[v]：v 里面（含更深层）有几个文件
    std::vector<long long> files(n, 0);
    for (int i = n - 1; i >= 0; --i) {
        int v = order[i];
        if (children[v].empty()) {
            files[v] = 1;
        }
        for (int child : children[v]) {
            files[v] += files[child];
        }
    }
    long long total_files = files[0];

    // 站在根目录：每个文件的路径长度 = 一路经过的目录名各加一个斜杠，再加文件名
    std::vector<long long> depth_length(n, 0);  // 从根写到 v 的前面一共多长
    long long root_sum = 0;
    for (int v : order) {
        for (int child : children[v]) {
            if (children[child].empty()) {
                root_sum += depth_length[v] + name_length[child];
            } else {
                depth_length[child] = depth_length[v] + name_length[child] + 1;
            }
        }
    }

    // 换根：从目录 v 走进它的子目录 child
    std::vector<long long> sum(n, 0);
    sum[0] = root_sum;
    long long best = root_sum;
    for (int v : order) {
        for (int child : children[v]) {
            if (children[child].empty()) {
                continue;
            }
            sum[child] = sum[v] - files[child] * (name_length[child] + 1) +
                         (total_files - files[child]) * 3;
            if (sum[child] < best) {
                best = sum[child];
            }
        }
    }
    std::printf("%lld\n", best);
    return 0;
}
```

树用第二卷第 14 章的办法遍历：`order` 里父亲总排在孩子前面，正着扫是从上往下，倒着扫是从下往上，不用递归，树是一条长链时也不怕。总长可能超过 32 位，都用 `long long`。三遍扫描各是 O(N)。

慢程序真的写出每一条路径：对每个目录、每个文件，先往上走到它们共同的祖先，再往下拼出名字，量字符串的长度。和程序 A 对拍 300 组，每组至多 12 个点、名字长 1 到 5，答案全部相同。

## 只留下这次真正用得着的点

有时一次询问只关心树上的 k 个点，比如“这 k 个点两两之间的路一共经过多少条边”。k 远小于 n 时，整棵树走一遍太浪费。办法是建一棵只含有用点的小树，叫**虚树**：留下这 k 个点和它们两两的 LCA，原树里一串没有分叉的点，在虚树里缩成一条边。

两两的 LCA 有 k² 对，不用都求。把 k 个点按先序编号排好，只求相邻两个的 LCA 就够了，得到的点不超过 2k − 1 个。

例子里先序编号（孩子按给出的次序）是 1、2、4、7、5、6、3、8、9。关键点取 5、7、9，按先序排是 7、5、9。相邻两对的 LCA：7 和 5 是 2，5 和 9 是 1。虚树的点是 1、2、5、7、9，边是 1-2、2-7、2-5、1-9，其中 2-7 代表原树的 2-4-7，1-9 代表 1-3-8-9。边上记下原树的长度，就能在小树上回答原来的问题。

## 把长路按“第一次经过哪里”分账

要数树上所有满足某个条件的路，比如“恰好 2 条边长的路有几条”。路有 n² 条，一条条看太多。换一个记账的办法：找到树的重心（第二卷第 14 章），所有的路分成两种，经过重心的，和完全落在去掉重心以后某一块里的。前一种在重心那里一起数；后一种交给每一块，在块里再找重心，照样分。

一条路在第一个碰到的重心那里被数到，只被数一次。去掉重心后，每一块至多是原来的一半，所以每个点至多落在 log₂ n 层里。每一层所有块加起来是 O(n) 的工作，总共 O(n log n)。这叫**点分治**。

在例子上数“恰好 2 条边长的路”。重心是 2：去掉它，剩下 {4, 7}、{5}、{6}、{1, 3, 8, 9}，最大一块 4 个，不超过 9 的一半。经过 2 的路有两类：2 是端点，另一端离 2 两步，有 7 和 3，2 条；2 在中间，两端是 2 的两个不同邻居，4 个邻居里挑 2 个，6 条。共 8 条。再进 {1, 3, 8, 9}，它是一条链 1-3-8-9，有 1-8、3-9 两条。其余的块里没有这么长的路。总共 10 条。

“两端在不同的块里”这一条不能丢：同一块里的两个点，路不经过重心，要留给那一块去数，否则会重复。

## 小的并进大的

几个集合不断两两合并，每次把一个集合里的东西全搬到另一个里。只要每次都把小的搬进大的，一个元素每被搬一次，它所在的集合至少大一倍，所以至多被搬 log₂ n 次。总的搬动量是 O(n log n)。第二卷第 13 章的按大小合并，说的是同一个道理；这里搬的不只是代表，而是集合里的全部东西。

### 最喜爱的颜色

N 头牛（N 到 2 × 10⁵），M 条“b 仰慕 a”的记录（M 到 2 × 10⁵，可以重复，也可以自己仰慕自己）。给每头牛一个颜色，要求：两头牛只要各自仰慕的牛里有颜色相同的，这两头牛的颜色也要相同。在颜色种数最多的安排里，输出字典序最小的那一个，也就是依次让 1 号、2 号……的颜色尽量小。

输入第一行 N、M，接下来 M 行，每行 a、b。输出 N 行，第 i 行是 i 号牛的颜色。

样例输入：

```text
9 12
1 2
4 2
5 8
4 6
6 9
2 9
8 7
8 3
7 1
9 4
3 5
3 4
```

样例输出：

```text
1
2
3
1
1
2
3
2
3
```

这是 USACO 2020 年 3 月金组第二题[“最喜爱的颜色”](../USACO/金组/2019_2020/2020.03/P2.md)。

先想哪些牛必须同色。2 和 6 都仰慕 4，所以 2、6 同色。同色的牛合成一组以后，这一组就像一头牛：仰慕组里任何一头的牛，也都必须同色。于是规则是：一组牛被两头牛仰慕，就把这两头牛所在的组并起来；并完后组变大，又可能触发新的合并。一直做到没有可并的为止。

最后剩下的每一组都能用一种独立的颜色：每组的仰慕者都在同一组里，条件成立。而每一次合并都是被迫的，所以组数已经最多。按编号从小到大，第一次碰到一个组就给它下一种新颜色，得到字典序最小的答案。

每一组记一份名单：仰慕组里成员的那些牛。名单里有两条记录，就把这两头牛的组并起来，再删掉一条。合并两组时，它们的名单也要合起来，这时把短的名单搬进长的。

下面是**片段**。`find` 是第二卷第 13 章带路径压缩的查找；这里谁当代表，看的是名单的长短，不是组的大小。

```cpp
// 位于 main 内；leader 与 find 是第二卷第 13 章的并查集，admirers[r] 是组 r 的名单
std::vector<int> pending;  // 名单里可能有两条以上记录的组
for (int v = 0; v < n; ++v) {
    if (admirers[v].size() > 1) {
        pending.push_back(v);
    }
}
auto merge = [&](int a, int b) {
    a = find(a);
    b = find(b);
    if (a == b) {
        return;
    }
    if (admirers[a].size() < admirers[b].size()) {
        std::swap(a, b);  // 让 b 是名单短的那一组
    }
    leader[b] = a;
    for (int cow : admirers[b]) {
        admirers[a].push_back(cow);
    }
    admirers[b].clear();
    pending.push_back(a);
};
while (!pending.empty()) {
    int group = pending.back();
    pending.pop_back();
    if (find(group) != group) {
        continue;  // 已经并进别的组，它的名单也搬走了
    }
    while (admirers[group].size() > 1) {
        int cow = admirers[group].back();
        admirers[group].pop_back();
        merge(cow, admirers[group].back());
        group = find(group);
    }
}
```

每处理一条记录就删掉一条，删掉的不再回来，所以 `while` 一共转不超过 M 次。搬名单时，搬的那份不比留下的长；若不删记录，一条记录每搬一次，它所在的名单至少翻倍。删记录会打乱“至少翻倍”这句话，但给每份名单记一笔与长度有关的账，仍能证明总搬动量是 O(M log M)，这里不展开。

慢程序反复扫所有记录对：两条记录仰慕的是同一组，就把两个仰慕者的组并起来，一直扫到不再变化。和片段对拍 300 组，每组至多 9 头牛、12 条记录，输出全部相同。
