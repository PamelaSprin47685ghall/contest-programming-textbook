# 06　别把每个旧答案都问一遍

开车去一个陌生城市，要在几十个加油站里挑一个。没人会把每个加油站都开过去看一眼。离得太远的不考虑，比前一个又贵又远的也不考虑，真正要比的往往只剩两三个。挑得快，不是因为比较得快，而是先说清楚了谁不可能赢。

第二卷第 8 章《给已经解决的小问题留个位置》里的 DP，算一个新状态时常常要把所有旧状态问一遍：dp[i] 是某些 dp[j] 加上一项代价里最小的那个。这一章讲怎样少问：把代价拆开，让旧状态变成一条条直线；代价不是直线时，看哪些旧状态可以一起比；再看什么时候干脆能让状态少一维。

## 先从算式里拆出只属于现在的部分

看一个小问题：一列正整数 a，切成若干段，每段的代价是“段和的平方加 c”，求最小总代价。记 sum[i] 为前 i 个数的和，

dp[i] = min（j < i）dp[j] + (sum[i] − sum[j])² + c。

直接算每个 i 都要问 i 个 j，O(n²)。把平方展开：

dp[i] = sum[i]² + c + min（j < i）(−2 · sum[j] · sum[i] + dp[j] + sum[j]²)。

括号里的东西，把 sum[i] 记作 x，对每个 j 都是 x 的一条直线：斜率 −2 · sum[j]，截距 dp[j] + sum[j]²。只属于“现在”的 sum[i]² + c 被拆到了外面。求 dp[i]，就是问这些直线在 x = sum[i] 处谁最低。

很多直线放在一起，最低的那部分是一条往上凸的折线，叫**下包络**。不在下包络上的直线，任何 x 处都不会最低，可以扔掉。这题还有两个方便的地方：j 越大，sum[j] 越大，新直线的斜率越来越小；问的 x = sum[i] 也越来越大。所以用一个双端队列：新直线从后面进，进之前把被它挡住的直线从后面弹掉；询问时，前面的直线要是已经不如第二条低，以后也不会再低，从前面弹掉。这叫**斜率优化**。

下面是**片段**。

```cpp
// 位于 main 内；sum[i] 是前 i 个数的和，严格增大；c 是每段的固定代价
std::vector<long long> best(n + 1, 0);
auto slope = [&](int j) { return -2 * sum[j]; };
auto intercept = [&](int j) { return best[j] + sum[j] * sum[j]; };
auto value = [&](int j, long long x) { return slope(j) * x + intercept(j); };
// 斜率依次变小的三条线 p、q、r：p 与 r 的交点不在 p 与 q 的交点右边，q 就没用了
auto useless = [&](int p, int q, int r) {
    return (intercept(r) - intercept(p)) * (slope(p) - slope(q)) <=
           (intercept(q) - intercept(p)) * (slope(p) - slope(r));
};
std::deque<int> lines;
lines.push_back(0);
for (int i = 1; i <= n; ++i) {
    long long x = sum[i];
    while (lines.size() >= 2 && value(lines[1], x) <= value(lines[0], x)) {
        lines.pop_front();
    }
    best[i] = value(lines.front(), x) + x * x + c;
    while (lines.size() >= 2 && useless(lines[lines.size() - 2], lines.back(), i)) {
        lines.pop_back();
    }
    lines.push_back(i);
}
```

`useless` 比的是两个交点的横坐标。斜率依次变小的 p、q、r，q 和 p 的交点在 (b_q − b_p) / (m_p − m_q)，r 和 p 的交点在 (b_r − b_p) / (m_p − m_r)，分母都是正的，交叉相乘就不用除法。要是 r 和 p 的交点不在 q 和 p 的交点右边，q 刚要变成最低时，r 已经比它低了，q 没用。

交叉相乘会把数变得很大。这里定的范围是 n ≤ 10⁵、1 ≤ aᵢ ≤ 10、c ≤ 10⁶：sum 至多 10⁶，截距至多约 2 × 10¹²，乘上斜率之差 2 × 10⁶，约 4 × 10¹⁸，`long long` 刚好放得下。范围再大，就要换一种不溢出的比较。

每条直线进队、出队各一次，O(n)。慢程序照原式把每个 j 都试一遍；n 不超过 30、c 从 0 取到 10⁶，对拍 300 组，答案全部相同。n = 10⁵、每个数都是 10、c = 10⁶ 的数据跑过 `-fsanitize=undefined`，没有溢出报告。

在 a = 1 2 3、c = 5 上跑一遍。sum 是 0、1、3、6。i = 1 时只有 j = 0，dp[1] = 1 + 5 = 6。i = 3 时，x = 6，三条直线在 6 处的值依次是 0、−5、−13，前两条都被弹掉，dp[3] = −13 + 36 + 5 = 28，对应切成 [1 2] 和 [3]。

## 不需要直线，也可能有更少决策

代价拆不成直线时，也不必问遍每个旧状态。要找的是一个理由，说明一大批旧状态可以只派一个代表。

### 书架

N 本书（N 到 10⁵）按编号顺序上架，第 i 本高 Hᵢ、宽 Wᵢ。一层放连续的若干本，总宽不超过 L，层高是这层最高的那本书。求所有层高之和的最小值。

输入第一行 N 和 L，接下来 N 行每行 H、W（1 ≤ H ≤ 10⁶，1 ≤ W ≤ L ≤ 10⁹）。输出一个整数。

样例输入：

```text
5 10
5 7
9 2
8 5
13 2
3 8
```

样例输出：

```text
21
```

三层是：第 1 本；第 2、3、4 本；第 5 本。高 5 + 13 + 3 = 21。这是 USACO 2012 年 4 月金组第二题[“书架”](../USACO/金组/2011_2012/2012.04/P2.md)。

记 best[i] 为放好前 i 本的最小总高度。最后一层从第 j 本放到第 i − 1 本（从 0 编号），

best[i] = min best[j] + max(H[j], …, H[i − 1])，j 满足这一层的宽度不超过 L。

能用的 j 是一段 [low, i)，宽度一超就把 low 往右挪，这是第二卷的双指针。难处在 max：它不是直线。

但它有另一种好用的形状。j 从右往左走，max 只会变大，而且是一段一段地变：几段 j 的 max 相同。同一段里，层高一样，只要 best[j] 最小的那个；best 随 j 不减（多放一本书，总高度不会变小），所以每段只派它最左边的 j 当代表。候选从 i 个变成了段数个，再把每段的“层高 + best[代表]”放进一个能随时取最小的集合。

新来一本书，它自己是一段。右边几段的层高要是不超过它，这几段的 max 都变成它的高度，并进它这一段，代表是最左的那一个。这和第二卷单调栈的做法一样：从右边弹，弹掉的不会再回来。宽度超了，最左一段的代表往右挪一格，这段空了就整个扔掉。

下面是**完整程序 A**。

```cpp
#include <cstdio>
#include <deque>
#include <set>
#include <vector>

// 一块：这一层从第 first 到第 last 本书开始时，层高都是 height
struct Block {
    int first;
    int last;
    long long height;
};

int main() {
    int n = 0;
    long long limit = 0;
    if (std::scanf("%d %lld", &n, &limit) != 2) {
        return 1;
    }
    std::vector<long long> h(n, 0);
    std::vector<long long> w(n, 0);
    for (int i = 0; i < n; ++i) {
        if (std::scanf("%lld %lld", &h[i], &w[i]) != 2) {
            return 1;
        }
    }

    // best[i]：放好前 i 本书的最小总高度
    std::vector<long long> best(n + 1, 0);
    std::deque<Block> blocks;           // 从左到右，层高从高到低
    std::multiset<long long> candidates;  // 每块一个候选：层高 + best[first]
    int low = 0;                        // 这一层最早能从第 low 本开始
    long long width = 0;                // 第 low 本到当前这本的总宽度
    for (int book = 0; book < n; ++book) {
        Block fresh = {book, book, h[book]};
        while (!blocks.empty() && blocks.back().height <= h[book]) {
            const Block& old = blocks.back();
            candidates.erase(candidates.find(old.height + best[old.first]));
            fresh.first = old.first;
            blocks.pop_back();
        }
        blocks.push_back(fresh);
        candidates.insert(fresh.height + best[fresh.first]);

        width += w[book];
        while (width > limit) {
            width -= w[low];
            Block& front = blocks.front();
            candidates.erase(candidates.find(front.height + best[front.first]));
            ++front.first;
            if (front.first > front.last) {
                blocks.pop_front();
            } else {
                candidates.insert(front.height + best[front.first]);
            }
            ++low;
        }
        best[book + 1] = *candidates.begin();
    }
    std::printf("%lld\n", best[n]);
    return 0;
}
```

`std::multiset` 是允许重复元素的 `std::set`，同样从小到大排着，`*candidates.begin()` 是最小的。几段可能算出一样的候选值，所以要允许重复；删的时候用 `find` 找到一个再删，只删一个。用 `erase(值)` 会把相同的全删掉。

每本书进栈一次、出栈一次，`low` 一共挪 N 次，每次动一下集合是 O(log N)，总共 O(N log N)。高度之和至多 10¹¹，用 `long long`。

在样例上看第 4 本书（高 13）来时：栈里是层高 9 的一段（代表 j = 1）和层高 8 的一段（代表 j = 2），都比 13 矮，并成层高 13 的一段，代表 j = 1，候选 13 + best[1] = 18，于是 best[4] = 18。第 5 本来时宽度超了两次，代表挪到 j = 3，候选是 13 + best[3] = 27；它自己那段的候选是 3 + best[4] = 21，答案 21。

慢程序照原式对每个 i 把能用的 j 都试一遍。N 不超过 12，对拍 300 组，答案全部相同。

## 让状态少一维，也有条件

有的 DP 状态有两维：第几个数，和它取什么值。看一个例子：把一列数 a 改成不减的序列 b，代价是 Σ|aᵢ − bᵢ|，求最小代价。

记 fᵢ(v) 为前 i 个数改好、bᵢ = v 时的最小代价。下一个数取 v，前一个只要不超过 v，于是 fᵢ₊₁(v) = min（u ≤ v）fᵢ(u) + |aᵢ₊₁ − v|。值域大时，把每个 v 都存下来太多。

可是 fᵢ 有一个好性质：它是凸的折线，越往右斜率越大。|a − v| 是凸的；凸函数取“前缀最小”，右边那段往上的部分被压平，仍是凸的；两个凸函数相加还是凸的。凸折线只要记下它在哪里拐弯，不必记每个 v 的值。这里只要记左半边的拐点，放进一个大根堆，堆顶是最右边的那个拐点，也就是折线最低处的右端。

加进 a：把 a 放进堆。要是堆顶比 a 大，说明最低处在 a 右边，b 取 a 要付出 堆顶 − a 的代价；把这个堆顶弹掉，再放一个 a 进去。

下面是**片段**。堆是第二卷第 17 章的 `std::priority_queue`。

```cpp
// 位于 main 内；a 是读入的一列数，cost 累计改动的总量
std::priority_queue<long long> turns;  // 折线在左边拐弯的位置
long long cost = 0;
for (int i = 0; i < n; ++i) {
    turns.push(a[i]);
    if (turns.top() > a[i]) {
        cost += turns.top() - a[i];
        turns.pop();
        turns.push(a[i]);
    }
}
```

在 3 1 2 上跑一遍。放 3，堆是 {3}。放 1，堆顶 3 比 1 大，代价加 2，弹掉 3，再放 1，堆是 {1, 1}。放 2，堆顶 2 不比 2 大，不动。总代价 2，例如改成 1 1 2。

慢程序真的按值做 DP：值只取 a 里出现过的那些，对每个 v 先取前缀最小再加 |a − v|。数在 −5 到 5 之间、至多 10 个，对拍 300 组，答案全部相同。

这样做是有条件的：每一步加上的代价要是凸的，取前缀最小这样的操作也要保持凸性。代价换成 min(|a − v|, 3) 这种“改多了也只付 3”的样子，折线就不凸了，只记拐点的办法也就不成立。

## 核对

1. dp[2] = 14。i = 2 时 x = 3，队列里是 j = 0 和 j = 1 两条直线，在 3 处的值是 0 和 −6 + 7 = 1，第二条不比第一条低，不弹。答案来自 j = 0：0 + 9 + 5 = 14，也就是 [1 2] 整段。
2. 两段算出同样的候选值时会出错。`erase(x)` 把所有等于 x 的都删了，另一段的候选也跟着没了，以后取最小就会漏掉它。拿改过的程序和慢程序对拍，第 23 组就不一样：N = 5、L = 2，书是 (3, 2)、(13, 2)、(3, 1)、(15, 1)、(3, 2)，几段的候选在中途撞成了同一个数。
3. 总代价 6。堆的变化：{5}；放 4，堆顶 5 比 4 大，付 1，堆成 {4, 4}；放 3，付 1，堆成 {4, 3, 3}；放 2，堆顶 4，付 2，堆成 {3, 3, 2, 2}；放 1，堆顶 3，付 2。共 1 + 1 + 2 + 2 = 6。改成的序列例如 3 3 3 3 3，代价 2 + 1 + 0 + 1 + 2 = 6。
