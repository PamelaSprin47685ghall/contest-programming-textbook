# 10　找不到搭档时让出一条路

体育课两人一组做练习。老师先让大家自己找，最后剩下一个人没有搭档。老师没有让他干等，而是去问一个已经配好的同学：“你能不能换个人？”那个同学的旧搭档又去找别人……一串人各让一步，最后多出一组，谁也没有落单。

这一章讲配对，也就是**匹配**：一张图里挑一些边，每个点至多在一条挑中的边上。先学“让出一条路”的办法，让匹配一对对变多；再看最大匹配背后的一份证据，它说明不可能更多；然后看配对有分数时，为什么不能只数对数；最后看一般的图里，奇数长的圈带来的麻烦。

## 沿着已配、未配交替走

先看点分成左右两边、边只连左右的图，叫**二分图**。左边 A、B、C 三个同学，右边 1、2、3 三个项目，能做的组合是 A-1、A-2、B-1、C-2、C-3。

按顺序贪心：A 配 1。轮到 B，B 只能做 1，可是 1 已经给了 A。这时不放弃，去问 A：能不能换一个？A 还能做 2，2 空着，于是 A 改配 2，把 1 让给 B。这一串是 B-1-A-2：B 到 1 是没配的边，1 到 A 是配着的边，A 到 2 又是没配的边，两头的 B 和 2 都还没有搭档。把这串边里配着的拆掉、没配的配上，匹配多了一对。

这样一条从没有搭档的点出发、配与不配交替、终点也没有搭档的路，叫**增广路**。找到一条，匹配就加一。反过来，匹配不是最大时一定存在增广路：把它和一个更大的匹配叠在一起，两边各出的边交替连成路和圈，更大的那一边多出来的边，一定落在某一条两头都没有搭档的路上。

于是算法是：左边的点一个个来，每个都用深搜找一条增广路。从左点 v 出发，试它的每个右邻 h：h 空着，直接配上；h 有搭档，就让这个搭档再去找别的右点。每一轮里每个右点只试一次。这叫匈牙利算法，左边 n 个点、m 条边时 O(nm)。

接着上面的例子轮到 C：C 先试 2，2 的搭档是 A；A 试 1，1 的搭档是 B；B 没有别的可做，失败；A 也没有别的了，失败。C 再试 3，3 空着，配上。最后是 A-2、B-1、C-3，三对。

## 匹配背后还有一份覆盖证据

怎样确定一个匹配已经最大？找一份证据：挑一些点，让每条边至少有一头被挑中，叫**点覆盖**。匹配里的每条边，覆盖都得挑它的一头，而匹配的边两两没有公共点，所以任何覆盖都不比任何匹配小。要是找到一个覆盖，点数正好等于匹配的对数，两者就都是最优的。

在二分图里，这样的覆盖总能找到，最大匹配的对数等于最小覆盖的点数，这叫 **König 定理**。做法是在匈牙利算法结束后，从左边每个没有搭档的点出发，沿着“没配的边从左到右、配着的边从右到左”走，记下走得到的点。覆盖取左边走不到的点和右边走得到的点。

在停笔 1 的那张图上做一遍：边是 A-1、A-2、B-1、C-2，匹配是 A-2、B-1，没有搭档的左点只有 C。从 C 沿没配的边到 2，从 2 沿配着的边回到 A，从 A 沿没配的边到 1，从 1 沿配着的边回到 B，B 没有别的没配的边了。走得到的点是 C、2、A、1、B。覆盖取左边走不到的（一个也没有）和右边走得到的 1、2，共两个点，正好等于两对。

为什么这样取出的点能盖住每条边，个数又恰好等于对数：一条边 u-h，u 在左边。u 走不到，u 就在覆盖里。u 走得到时，要是 u-h 没配，沿它就能走到 h；要是配着，u 本来就是从 h 走过来的；两种情况 h 都走得到，h 在覆盖里。再看个数：右边走得到的点 h 一定有搭档，否则从一个没搭档的左点走到没搭档的 h，就是一条增广路，匈牙利算法结束时不会有。左边走不到的点也一定有搭档，因为没有搭档的左点是出发点。而一对配好的点，要么右点走得到、左点也走得到（从右点回到左点），要么两个都走不到，所以每对恰好贡献覆盖里的一个点。

覆盖的反面也有用：没被挑中的点，两两之间一定没有边。一张图里两两不相连的一组点叫**独立集**，所以最大独立集的点数 = 总点数 − 最小覆盖 = 总点数 − 最大匹配。

### 奶牛越野障碍赛

N 条线段（N 到 250），每条平行于一个坐标轴，坐标在 1 到 10⁹ 之间。两条线段只要有一个公共点就算相交。保证任意两条横的不相交，任意两条竖的也不相交。最多能挑出几条线段，两两不相交？

输入第一行 N，接下来 N 行，每行 x1、y1、x2、y2。输出一个整数。

样例输入：

```text
3
4 5 10 5
6 2 6 12
8 3 8 5
```

样例输出：

```text
2
```

横线与两条竖线都相交，挑两条竖线。这是 USACO 2011 年 11 月金组第三题[“奶牛越野障碍赛”](../USACO/金组/2011_2012/2011.11/P3.md)。

相交的只可能是一横一竖。把横线放左边、竖线放右边，相交就连一条边，这是一张二分图。要挑的是两两不相交的线段，正是这张图的最大独立集，答案是 N 减去最大匹配。

下面是**完整程序 A**。

```cpp
#include <cstdio>
#include <utility>
#include <vector>

struct Matcher {
    std::vector<std::vector<int>> neighbors;  // 每条竖线和哪些横线相交
    std::vector<int> partner;                 // 每条横线的搭档竖线，−1 表示没有
    std::vector<bool> tried;                  // 这一轮已经试过的横线

    // 给竖线 v 找一条增广路：找到就沿路改配，返回真
    bool augment(int v) {
        for (int h : neighbors[v]) {
            if (tried[h]) {
                continue;
            }
            tried[h] = true;
            if (partner[h] == -1 || augment(partner[h])) {
                partner[h] = v;
                return true;
            }
        }
        return false;
    }
};

struct Segment {
    int x1;
    int y1;
    int x2;
    int y2;
};

int main() {
    int n = 0;
    if (std::scanf("%d", &n) != 1) {
        return 1;
    }
    std::vector<Segment> horizontal;
    std::vector<Segment> vertical;
    for (int i = 0; i < n; ++i) {
        Segment s = {0, 0, 0, 0};
        if (std::scanf("%d %d %d %d", &s.x1, &s.y1, &s.x2, &s.y2) != 4) {
            return 1;
        }
        if (s.x1 > s.x2) {
            std::swap(s.x1, s.x2);
        }
        if (s.y1 > s.y2) {
            std::swap(s.y1, s.y2);
        }
        if (s.y1 == s.y2) {
            horizontal.push_back(s);
        } else {
            vertical.push_back(s);
        }
    }

    int h_count = static_cast<int>(horizontal.size());
    int v_count = static_cast<int>(vertical.size());
    Matcher matcher;
    matcher.neighbors.assign(v_count, std::vector<int>());
    matcher.partner.assign(h_count, -1);
    for (int v = 0; v < v_count; ++v) {
        for (int h = 0; h < h_count; ++h) {
            const Segment& a = horizontal[h];
            const Segment& b = vertical[v];
            if (a.x1 <= b.x1 && b.x1 <= a.x2 && b.y1 <= a.y1 && a.y1 <= b.y2) {
                matcher.neighbors[v].push_back(h);
            }
        }
    }

    int matched = 0;
    for (int v = 0; v < v_count; ++v) {
        matcher.tried.assign(h_count, false);
        if (matcher.augment(v)) {
            ++matched;
        }
    }
    // 最多的不相交线段 = 总数 − 最大匹配
    std::printf("%d\n", n - matched);
    return 0;
}
```

`augment` 是递归的，深度不超过横线的条数，至多 250 层。`tried` 每一轮清空一次，同一轮里一条横线试过就不再试，否则会在一个圈里来回转。端点先换成从小到大，横线的 y1 等于 y2，判断相交只要看横线的 y 落在竖线的范围里、竖线的 x 落在横线的范围里。

建图看 N² 对线段，匹配 O(N · 边数)，N = 250 时都很快。

慢程序把 2ᴺ 个线段的子集都试一遍，挑出两两不相交的里最大的。N 不超过 10，随机生成时只保留横线互不相交、竖线互不相交的输入，端点还随机掉换顺序，对拍 300 组，答案全部相同。

答案只要一个数，用不着真的找出覆盖。但覆盖是这个答案的证据，写出来就能核对。接在程序 A 的匹配后面，照上一节的走法找出它：

下面是**片段**。

```cpp
// 位于 main 内；matcher 已做完匈牙利算法，左边是 v_count 条竖线，右边是 h_count 条横线
std::vector<bool> left_seen(v_count, false);
std::vector<bool> right_seen(h_count, false);
std::vector<bool> has_partner(v_count, false);
for (int h = 0; h < h_count; ++h) {
    if (matcher.partner[h] != -1) {
        has_partner[matcher.partner[h]] = true;
    }
}
std::vector<int> stack;
for (int v = 0; v < v_count; ++v) {
    if (!has_partner[v]) {
        left_seen[v] = true;
        stack.push_back(v);
    }
}
while (!stack.empty()) {
    int v = stack.back();
    stack.pop_back();
    for (int h : matcher.neighbors[v]) {
        if (right_seen[h] || matcher.partner[h] == v) {
            continue;  // 从左往右只走没配的边
        }
        right_seen[h] = true;
        int back = matcher.partner[h];  // 从右往左只走配着的边
        if (back != -1 && !left_seen[back]) {
            left_seen[back] = true;
            stack.push_back(back);
        }
    }
}
// 覆盖：左边没走到的点，加上右边走到的点
```

拿它另做了一项检查：在随机的小二分图上，覆盖的点数要等于匹配的对数，每条边都要被盖住，而对数要等于慢程序把所有边的子集试一遍得到的最大匹配。300 组全部通过。

## 有得分的配对，不能只数人数

配对要是有分数，要的就不再是对数最多，而是分数之和最大。对数最多的匹配不一定分数最高。

例子：A、B 两个人，1、2 两项工作。A 做 1 得 10 分，A 做 2 得 1 分，B 只能做 1，得 1 分。两对都配上是 A-2、B-1，2 分；只配 A-1 一对，10 分。

挑分数最高的边先配，也会出错。还是两个人两项工作，A-1 得 5 分，A-2 得 4 分，B-1 得 4 分，B-2 得 0 分。先拿最高的 A-1，剩下只能 B-2，共 5 分；A-2 加 B-1 是 8 分。

这时的增广要算清楚分数：沿一条增广路改配，有的边拆掉、有的边配上，分数的变化是配上的减去拆掉的，要挑变化最划算的那条路。拿上面的 5、4、4、0 来看。先只配 A-1，得 5 分。再给 B 找增广路：B-1-A-2，拆掉 A-1（−5），配上 B-1（+4）和 A-2（+4），分数变化是 +3，改配后是 8 分。另一条路是直接配 B-2，变化是 +0。挑 +3 的那条，就到了最优。每一步都挑“改配以后分数涨得最多”的增广路，最后得到的就是这个对数下分数最高的匹配；这样的路怎样找得快，要把分数当作边长来求最长路或最短路。

这正是[第 12 章](12-每次改配都算清代价.md)《每次改配都算清代价》的话题；人数和工作数都是 n、每人都要配上时，也有专门的 O(n³) 算法，叫 KM 算法。

## 奇圈使“左右”消失了

二分图里每个点都有固定的一边，一条交替路走到某个点，走了奇数步还是偶数步是定好的。一般的图里不是这样：有奇数长的圈，就能从两个方向走到同一个点，一次是奇数步，一次是偶数步。

例子：三角形 1-2-3，再有一条边 3-4。现在的匹配是 2-3，1 和 4 没有搭档。1-2-3-4 是一条增广路：1-2 没配，2-3 配着，3-4 没配。可是从 1 出发，要是先走 1-3 这条边，3 的搭档是 2，从 2 只能回到 1，就走不下去了；3 已经被“试过”，以后不再试，那条路就漏掉了。毛病出在 3：它从一个方向看是该“找搭档换”的一边，从另一个方向看是该“往外走”的一边。

所以二分图之所以好做，是因为每个点的一边可以事先定下来。拿到一张图，先照第二卷第 10 章的搜索给点交替涂两种颜色，涂得下去就是二分图，涂到某条边两头同色，就说明有奇圈。

Edmonds 的办法是：找到一个奇圈时，把整个圈缩成一个点。上面的 1、2、3 缩成一个点以后，它连着 4，而 4 没有搭档，增广路就找到了；再把圈展开，在圈里选对走法。这叫带花树算法，O(n³)。这里只讲到想法，具体的写法比较长。
