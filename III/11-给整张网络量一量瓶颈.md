# 11　给整张网络量一量瓶颈

学校水房有一根总管，几段水管接来接去，最后通到操场的饮水台。每段水管每分钟最多流过几升，写在管子上。总务老师想知道两件事：每分钟最多能有多少升水到达操场？要是想扩容，先换哪几段管子才有用？

第一问是一个“最多”，第二问是一个“卡在哪里”。这一章要说明：这两个问题其实是同一个问题，而且它的答案可以用一份证据核对，不用相信谁的感觉。

## 撤回不是新增一条真实管道

先把水管图说清楚。有一个出水的点，叫**源点** s；一个收水的点，叫**汇点** t；每条有向边 u → v 有一个非负整数 c(u, v)，叫它的**容量**。一份**流**给每条边一个数 f(u, v)，要求两件事：每条边 0 ≤ f ≤ c；除了 s 和 t，每个点流进来的总量等于流出去的总量。从 s 净流出的总量叫**流的值**。这样一张带容量的图，加上 s 和 t，叫一张**网络**。问最大的流值，就是**最大流**问题。

最自然的想法是：找一条从 s 到 t、每条边都还有余量的路，沿着它送满，再找下一条，直到找不到为止。看一个小网络，点 1 是 s，点 4 是 t，五条边的容量都是 1：

| 边 | 1→2 | 1→3 | 2→3 | 2→4 | 3→4 |
|---|---|---|---|---|---|
| 容量 | 1 | 1 | 1 | 1 | 1 |

要是第一次挑了 1→2→3→4，送 1 个单位，接下来 1→3 还有余量，3→4 却满了；1→2 也满了。再也找不到一条全有余量的路，手里只有 1。可是 1→2→4 和 1→3→4 各送 1，一共是 2。

第一次的选择不算错，只是走得不好。补救的办法是允许“撤回”：已经在 2→3 上送了 1，就等于多了一条 3 → 2 的余量 1。它不是一根真的从 3 流向 2 的管子，而是说“2→3 上已经送的那 1 个单位，可以退掉”。有了它，路 1→3→2→4 就能走：1→3 送 1，3→2 这一步把 2→3 上的 1 退回去，2→4 送 1。合起来看，2→3 上不再有水，1→2→4 与 1→3→4 各送 1，正是那份值为 2 的流。

把每条边的剩余容量 c − f 和可退的量 f（画成反方向的边）放在一起，得到的图叫**残量网络**。残量网络里一条从 s 到 t 的路，也叫增广路；[第 10 章](10-找不到搭档时让出一条路.md)匹配里的增广路是它的特例。沿它送的量是路上残量的最小值。

为什么找不到增广路时就一定最大？要一个能拿来比较的数。把点分成两组 S 和 T，s 在 S，t 在 T。从 S 指向 T 的边的容量之和，叫这个**割**的容量。任何一份流的值，都等于穿过这个割的净流量：从 S 到 T 的边上的流，减去从 T 到 S 的边上的流。前者不超过割的容量，后者不小于 0，所以**任何流的值 ≤ 任何割的容量**。

现在设残量网络里已经没有增广路。令 S 是从 s 在残量网络里能走到的点。t 不在 S 里。一条从 S 指向 T 的原边，要是还有余量，它的终点也能走到，矛盾，所以它是满的；一条从 T 指向 S 的原边，要是上面有流，反向的残量边就能把 S 接到它的起点，也矛盾，所以它上面是 0。于是流值恰好等于这个割的容量。一份流的值等于一个割的容量，而流值又不能超过任何割，这份流就是最大的，这个割也是最小的。这就是**最大流最小割定理**：最大流的值等于最小割的容量。

容量都是整数时，每次增广至少送 1，流值又不会超过 s 出发的边的容量之和，所以一定会停下来。停下时每条边上的流也都是整数。

## 只沿着本轮的层向前

随便找增广路可能很慢：一张图上两条容量很大的路中间夹一条容量 1 的边，增广路要是每次都绕经这条边来回撤回，送一个单位就算一次。改进是每轮只走“最短”的增广路，而且一轮里一次找完。

做法是：先在残量网络上从 s 做一次宽度优先搜索，记下每个点的层数 `level`（离 s 最少几步）。这一轮只许沿着 `level` 恰好加 1 的残量边走。在这张分层的图上反复找路、送流，直到 s 到 t 一条也找不到，这一轮结束，重新分层。这个办法叫 **Dinic 算法**。

每一轮结束时，所有长度等于当前最短距离的增广路都被堵死了；新出现的残量边都是反向边，它们从高一层指向低一层，走它们只会让路更长。所以下一轮 s 到 t 的最短距离严格变大。距离最多是点数 V，轮数不超过 V。一轮里每找到一条路，至少有一条边被送满、从分层图里消失，再配上下面说的 `next_arc`，一轮的工作是 O(V × E)。总共 O(V² × E)。这是一条上界，实际跑起来通常快得多；所有容量都是 1 时还能证得更好，[第 10 章](10-找不到搭档时让出一条路.md)《找不到搭档时让出一条路》的配对问题就是这种网络。

`next_arc[v]` 记着：这一轮在 v 处，前面那些边已经试过而且走不通了。走不通的边这一轮不会复活，因为本轮只会把边送满，不会给分层图里的边加余量。

输入第一行是点数 n 和边数 m，点从 1 编号，s 是 1，t 是 n；之后 m 行，每行 u、v、c，表示一条 u → v、容量 c 的边（可以有重边，c 不超过 10⁹）。输出最大流。程序里点改成从 0 编号。

样例输入：

```text
6 8
1 2 3
1 3 2
2 3 1
2 4 2
3 5 3
4 6 2
5 4 1
5 6 2
```

样例输出：

```text
4
```

第一轮分层：点 1 是 0 层，点 2、3 是 1 层，点 4、5 是 2 层，点 6 是 3 层。2→3、5→4 两端同层，本轮不用。先找到 1→2→4→6，送 2；1→2 还剩 1，可 2→4 满了，点 2 走不通；再找 1→3→5→6，送 2。第二轮从 1 出发只能走到 2、3、5、4，到不了 6，结束。S = {1, 2, 3, 4, 5}，割边是 4→6 和 5→6，容量 2 + 2 = 4，和流值相同。

下面是**完整程序 A**。

```cpp
#include <algorithm>
#include <cstdio>
#include <queue>
#include <vector>

struct Edge {
    int to;
    long long cap;   // 残量：这条边还能再送多少
};

const long long unlimited = 4000000000000000000LL;
std::vector<Edge> edges;            // 第 2k 条与第 2k + 1 条互为反向边
std::vector<std::vector<int>> out;  // out[v]：从 v 出发的边的编号
std::vector<int> level;
std::vector<std::size_t> next_arc;

int partner(int id) {
    return id % 2 == 0 ? id + 1 : id - 1;
}

void add_edge(int from, int to, long long cap) {
    out[from].push_back(static_cast<int>(edges.size()));
    edges.push_back(Edge{to, cap});
    out[to].push_back(static_cast<int>(edges.size()));
    edges.push_back(Edge{from, 0});
}

bool build_levels(int source, int sink) {
    level.assign(out.size(), -1);
    std::queue<int> waiting;
    level[source] = 0;
    waiting.push(source);
    while (!waiting.empty()) {
        int v = waiting.front();
        waiting.pop();
        for (int id : out[v]) {
            if (edges[id].cap > 0 && level[edges[id].to] < 0) {
                level[edges[id].to] = level[v] + 1;
                waiting.push(edges[id].to);
            }
        }
    }
    return level[sink] >= 0;
}

long long push(int v, int sink, long long limit) {
    if (v == sink) {
        return limit;
    }
    for (; next_arc[v] < out[v].size(); ++next_arc[v]) {
        int id = out[v][next_arc[v]];
        int to = edges[id].to;
        if (edges[id].cap > 0 && level[to] == level[v] + 1) {
            long long got = push(to, sink, std::min(limit, edges[id].cap));
            if (got > 0) {
                edges[id].cap -= got;
                edges[partner(id)].cap += got;
                return got;   // 这条边可能还有余量，下次仍从它试起
            }
        }
    }
    return 0;
}

long long max_flow(int source, int sink) {
    long long total = 0;
    while (build_levels(source, sink)) {
        next_arc.assign(out.size(), 0);
        while (true) {
            long long got = push(source, sink, unlimited);
            if (got == 0) {
                break;
            }
            total += got;
        }
    }
    return total;
}

int main() {
    int n = 0;
    int m = 0;
    if (std::scanf("%d%d", &n, &m) != 2) {
        return 1;
    }
    out.assign(n, std::vector<int>());
    for (int i = 0; i < m; ++i) {
        int u = 0;
        int v = 0;
        long long c = 0;
        if (std::scanf("%d%d%lld", &u, &v, &c) != 3) {
            return 1;
        }
        add_edge(u - 1, v - 1, c);
    }
    std::printf("%lld\n", max_flow(0, n - 1));
    return 0;
}
```

`push` 一次只找一条路，找到就沿原路返回，一路改残量。它找到路时不推进 `next_arc`，因为那条边可能还没满；找不到时才推进。递归最深是层数，不超过 n。流值最多是 m × 10⁹，`long long` 放得下。

算完以后，最后一次 `build_levels` 失败时留下的 `level`，正好标出了从 s 在残量网络里能到的点。下面是**片段**，打印最小割的 S 一侧。

```cpp
// 位于 main 内；max_flow 已经返回，level 是最后一次分层的结果
for (int v = 0; v < n; ++v) {
    if (level[v] >= 0) {
        std::printf("%d ", v + 1);
    }
}
std::printf("\n");
```

对样例，它输出 `1 2 3 4 5`。

## 边还要求至少送多少

有时一条边不但有上限，还有下限：这段水管必须至少流 l 升，否则会结冰。每条边的要求变成 l ≤ f ≤ c。这时连“有没有一份合法的流”都成了问题。

先看没有 s、t，只要求每个点都守恒的情形（这叫**循环流**）。办法是先硬塞：每条边先送满下限 l。这样容量只剩 c − l，可点上不再守恒。记 `excess[v]` 为“硬塞以后，v 多收了多少”：每条边 u → v 让 `excess[v]` 加 l、`excess[u]` 减 l。新建一个源点 S′ 和汇点 T′。`excess[v]` 为正，就从 S′ 连一条容量 `excess[v]` 的边到 v；为负，就从 v 连一条容量 −`excess[v]` 的边到 T′。剩下的流要把这些多出、欠下的量补平，这正是一份从 S′ 到 T′ 的流。合法的循环流存在，当且仅当 S′ 到 T′ 的最大流把 S′ 出发的边全部送满。

看一个三点的小例子：1→2 要求 [2, 3]，2→3 要求 [0, 1]，3→1 要求 [0, 4]，2→1 要求 [0, 5]。硬塞下限后，`excess[2]` = 2，`excess[1]` = −2。S′→2 容量 2，1→T′ 容量 2。2 上多出的 2 个单位可以走 2→1 直接回 1，也可以 2→3 走 1、再 3→1，另 1 个走 2→1。最大流是 2，送满了，所以有合法的循环流。

有 s 和 t 的情形，加一条 t → s、容量无限的边，就变回了循环流。

**片段：**

```cpp
// 用到程序 A 的 edges、out、add_edge、max_flow、unlimited
// low[i] <= f <= cap[i]；点从 0 编号
bool has_circulation(int n, const std::vector<int>& from, const std::vector<int>& to,
                     const std::vector<long long>& low, const std::vector<long long>& cap) {
    edges.clear();
    out.assign(n + 2, std::vector<int>());
    std::vector<long long> excess(n, 0);
    for (std::size_t i = 0; i < from.size(); ++i) {
        add_edge(from[i], to[i], cap[i] - low[i]);
        excess[to[i]] += low[i];
        excess[from[i]] -= low[i];
    }
    int extra_source = n;
    int extra_sink = n + 1;
    long long need = 0;
    for (int v = 0; v < n; ++v) {
        if (excess[v] > 0) {
            add_edge(extra_source, v, excess[v]);
            need += excess[v];
        } else if (excess[v] < 0) {
            add_edge(v, extra_sink, -excess[v]);
        }
    }
    return max_flow(extra_source, extra_sink) == need;
}
```

这里假定每条边都有 low ≤ cap；有一条不满足，直接无解。片段对拍时，慢办法把每条边的流量从 low 到 cap 全部枚举一遍，逐点检查守恒。

## 没有指定源汇的割

另一种问法：一张无向图，边上有权，删去一些边让图不再连通，删掉的总权最小是多少？这叫**全局最小割**。没有人告诉我们 s 和 t。

一个直接的办法：随便固定一个点当 s，比如点 0。最小割总要把点 0 和某个点分开，所以对其余每个点 t 各求一次 s–t 最小割，取最小，就是答案。这要 n − 1 次最大流。

还有一个不用流的办法，叫 **Stoer–Wagner 算法**。一轮里，从任意一点开始，一个个往集合 A 里加点，每次加“和 A 连接总权最大”的那个点。设最后两个加进来的是 prev 和 last。关键的事实是：只把 last 单独割出来，这个割的权（就是 last 加入时和 A 的连接总权）是所有分开 prev 和 last 的割里最小的。于是全局最小割要么分开了 prev 和 last，它不会比这一轮记下的数小；要么没有分开它们，把这两个点合成一个，答案不变。每轮合并两个点，n − 1 轮以后只剩一个点，记下的最小值就是答案。

那条关键事实的证明，要对加入顺序里的每个点比较“它和前面点的连接权”与“任一分开 prev、last 的割在前面那一段的权”，逐点归纳。这里只写出结论，证明可以照这句话自己补全。

**片段：**

```cpp
// weight[i][j]：点 i、j 之间的总边权，对称，对角线为 0；要求至少两个点
long long global_min_cut(std::vector<std::vector<long long>> weight) {
    int n = static_cast<int>(weight.size());
    std::vector<bool> merged(n, false);
    long long best = -1;
    for (int phase = 0; phase + 1 < n; ++phase) {
        std::vector<long long> attach(n, 0);   // 和集合 A 的连接总权
        std::vector<bool> in_a(n, false);
        int prev = -1;
        int last = -1;
        for (int step = 0; step < n - phase; ++step) {
            int pick = -1;
            for (int v = 0; v < n; ++v) {
                if (!merged[v] && !in_a[v] && (pick < 0 || attach[v] > attach[pick])) {
                    pick = v;
                }
            }
            in_a[pick] = true;
            prev = last;
            last = pick;
            for (int v = 0; v < n; ++v) {
                attach[v] += weight[pick][v];
            }
        }
        if (best < 0 || attach[last] < best) {
            best = attach[last];
        }
        for (int v = 0; v < n; ++v) {   // 把 last 并进 prev
            weight[prev][v] += weight[last][v];
            weight[v][prev] = weight[prev][v];
        }
        weight[prev][prev] = 0;
        merged[last] = true;
    }
    return best;
}
```

每轮 O(n²)，一共 O(n³)。`attach[last]` 在 last 加入以后又加了 `weight[last][last]`，它是 0，所以仍是 last 加入时的连接总权。

这一章从一个“最多送多少”出发，得到了一份能核对的证据：一个割。撤回让贪心找路不再一步定终身；分层让找路有了一个会变长的“时钟”，因而有界；下限可以先硬塞、再用一次流补平；没有源汇时，或者枚举汇点，或者每轮合并两个点。能对一张小网络同时写出最大流和一个最小割，并说清它们为什么相等，再读下一章。下一章的边除了容量还有单价，要在送得最多的前提下花得最少。

## 核对

1. S 有四种：{1} 容量 2，{1, 2} 容量 1→3、2→3、2→4 共 3，{1, 3} 容量 1→2、3→4 共 2，{1, 2, 3} 容量 2→4、3→4 共 2。最小是 2，和最大流相等；最小割不止一个。
2. 最大流变成 5。从 s 出发的两条边 1→2、1→3 容量 3 + 2 = 5，已经是割；而 1→2→4→6 送 2，1→3→5→6 送 2，1→2→3→5→4→6 再送 1，共 5。最小割是 {1→2, 1→3}。
3. 答案仍然对：停下的条件还是“残量网络里到不了 t”，停时的流仍然最大。不再成立的是“每轮以后最短距离严格变大”。那个网络里，第一轮送 1 以后，1→2 被跳过，这一轮结束；第二轮最短距离仍是 2，再送 1。轮数上界失去了依据，只是这里还看不出慢。
4. 不再有。2 多出的 2 个单位只能走 2→3（上限 1）再 3→1，最大流只有 1，小于需要的 2。
5. 答案是 3，两组是 {0, 1} 和 {2, 3}，割到 1–2、3–0、0–2。单点割的权依次是 5、4、5、4，{0, 2}|{1, 3} 是 8，{0, 3}|{1, 2} 是 7。固定点 0：和 1 分开最少 4（割出 {1}），和 2 分开最少 3，和 3 分开最少 3，取最小得 3。
