# 12　每次改配都算清代价

春游要租车。两家车行各有一辆车，两条路线各要一辆。甲车行跑东线要 1 百元、跑西线要 2 百元；乙车行跑东线要 2 百元、跑西线要 10 百元。班长先挑最便宜的一项：甲跑东线，1 百元。剩下只能让乙跑西线，10 百元，一共 11 百元。可是让甲跑西线、乙跑东线，只要 4 百元。

第一步挑得最便宜，最后却花得最多。上一章问的是“最多能送多少”，这一章的边上多了单价，要在送够的前提下花得最少。办法仍是一步一步改，但每一步都要把改动的代价算清：包括退掉以前的安排省回来的钱。

## 最便宜的下一步，不是原图最便宜的边

把上一章的网络加上一项：每条边 u → v 还有一个**费用** w(u, v)，送 1 个单位要付 w。一份流的费用是每条边上的流量乘以费用，再全部加起来。在流值最大的流里，求费用最小的一份，叫**最小费用最大流**。

残量网络照上一章建，只多一条规矩：反向边的费用是 −w。在 u → v 上撤回 1 个单位，就退回了 w。

租车的例子写成网络：s 连向甲、乙，甲、乙连向东线、西线，两条线连向 t，容量都是 1；甲、乙到两条线的边上标着单价，其余边费用 0。办法是：每次在残量网络里找一条**费用最小**的增广路，沿它送。

第一次，最便宜的路是 s → 甲 → 东 → t，费用 1。送完以后，残量网络里多了 东 → 甲、费用 −1 的反向边。第二次有两条路可走：s → 乙 → 西 → t，费用 10；s → 乙 → 东 → 甲 → 西 → t，费用 2 − 1 + 2 = 3。后一条更便宜。它的意思是：乙改去东线，甲从东线退出、改去西线。送完以后总费用 1 + 3 = 4，正是最好的安排。

这个“每次走最便宜的增广路”的办法叫**连续最短路**。它对，靠下面这条事实：一份流值为 k 的流，在同样流值的流里费用最小，当且仅当它的残量网络里没有费用为负的圈。直观地说，负圈就是一种“改配”：沿着它转一圈，每个点收支不变，流值不变，费用却降了。反过来，两份流值相同的流相减，差可以拆成残量网络里的若干个圈；没有负圈，就没有更便宜的那一份。

有了它，可以按流值归纳：流值为 k 的流已经最便宜，沿一条最便宜的增广路送 1 个单位，得到的流值为 k + 1 的流仍然没有负圈，所以也最便宜。证明的细节是：假如新残量网络里有负圈，它一定用到了刚送过的那条路上的反向边，把它和那条路拼在一起，会得到一条比“最便宜的增广路”还便宜的路，矛盾。

**停笔 1**　把乙跑西线的价格从 10 改成 3。照连续最短路的办法，第一次、第二次各走哪条路，各花多少？最后的总费用是不是最好的？

## 用势能让负边换一种表示

反向边的费用是负数，[第二卷第 12 章](../II/12-少走几步不一定少花钱.md)《少走几步不一定少花钱》里那种“每次定下一个最近的点”的最短路办法（Dijkstra 算法）就不能直接用。它要求每条边都不是负的。

补救的办法是给每个点 v 一个数 h(v)，叫**势能**，把边 u → v 的费用换成 w(u, v) + h(u) − h(v)。这叫**约化费用**。一条从 s 到 t 的路，换完以后的费用等于原费用加上 h(s) − h(t)，每条路加的是同一个数，所以哪条路最便宜不变。

要挑一组 h，让所有残量边的约化费用都不为负。取 h(v) 为上一轮从 s 到 v 的最短路长度。对上一轮已有的残量边，最短路的性质给出 h(v) ≤ h(u) + w(u, v)，约化费用不为负。上一轮沿最短路送流，新出现的反向边 v → u 都在那条最短路上，那里 h(v) = h(u) + w(u, v)，反向边的约化费用是 −w + h(v) − h(u) = 0，也不为负。

一开始还没有反向边。原图的费用都不为负时，h 全取 0 就行。每轮用约化费用跑一次 Dijkstra，得到的距离再加到 h 上，就是这一轮真正的最短路长度，留给下一轮用。

输入第一行是点数 n 和边数 m，点从 1 编号，s 是 1，t 是 n；之后 m 行，每行 u、v、容量、费用，容量不超过 10⁶，费用是 0 到 10⁶ 的整数。输出最大流和它的最小费用。

样例输入就是租车的网络：1 是 s，2、3 是甲、乙，4、5 是东线、西线，6 是 t。

```text
6 8
1 2 1 0
1 3 1 0
2 4 1 1
2 5 1 2
3 4 1 2
3 5 1 10
4 6 1 0
5 6 1 0
```

样例输出：

```text
2 4
```

下面是**完整程序 A**。

```cpp
#include <algorithm>
#include <cstdio>
#include <functional>
#include <queue>
#include <utility>
#include <vector>

struct Edge {
    int to;
    int cap;
    long long cost;
};

const long long unreachable = 4000000000000000000LL;
std::vector<Edge> edges;            // 第 2k 条与第 2k + 1 条互为反向边
std::vector<std::vector<int>> out;

int partner(int id) {
    return id % 2 == 0 ? id + 1 : id - 1;
}

void add_edge(int from, int to, int cap, long long cost) {
    out[from].push_back(static_cast<int>(edges.size()));
    edges.push_back(Edge{to, cap, cost});
    out[to].push_back(static_cast<int>(edges.size()));
    edges.push_back(Edge{from, 0, -cost});
}

int main() {
    int n = 0;
    int m = 0;
    if (std::scanf("%d%d", &n, &m) != 2) {
        return 1;
    }
    out.assign(n, std::vector<int>());
    for (int i = 0; i < m; ++i) {
        int u = 0;
        int v = 0;
        int cap = 0;
        long long cost = 0;
        if (std::scanf("%d%d%d%lld", &u, &v, &cap, &cost) != 4) {
            return 1;
        }
        add_edge(u - 1, v - 1, cap, cost);
    }
    int source = 0;
    int sink = n - 1;
    std::vector<long long> potential(n, 0);   // 原费用不为负，起初全取 0
    long long flow = 0;
    long long total_cost = 0;
    while (true) {
        std::vector<long long> dist(n, unreachable);
        std::vector<int> via(n, -1);          // 最短路上进入 v 的那条边
        typedef std::pair<long long, int> Item;
        std::priority_queue<Item, std::vector<Item>, std::greater<Item>> waiting;
        dist[source] = 0;
        waiting.push(Item(0, source));
        while (!waiting.empty()) {
            Item top = waiting.top();
            waiting.pop();
            int v = top.second;
            if (top.first != dist[v]) {
                continue;                     // 这是一条过期的记录
            }
            for (int id : out[v]) {
                const Edge& e = edges[id];
                if (e.cap == 0) {
                    continue;
                }
                long long reduced = e.cost + potential[v] - potential[e.to];
                if (dist[v] + reduced < dist[e.to]) {
                    dist[e.to] = dist[v] + reduced;
                    via[e.to] = id;
                    waiting.push(Item(dist[e.to], e.to));
                }
            }
        }
        if (dist[sink] == unreachable) {
            break;
        }
        for (int v = 0; v < n; ++v) {
            if (dist[v] != unreachable) {
                potential[v] += dist[v];
            }
        }
        int add = edges[via[sink]].cap;
        for (int v = sink; v != source; v = edges[partner(via[v])].to) {
            add = std::min(add, edges[via[v]].cap);
        }
        for (int v = sink; v != source; v = edges[partner(via[v])].to) {
            edges[via[v]].cap -= add;
            edges[partner(via[v])].cap += add;
            total_cost += static_cast<long long>(add) * edges[via[v]].cost;
        }
        flow += add;
    }
    std::printf("%lld %lld\n", flow, total_cost);
    return 0;
}
```

`typedef` 给 `std::pair<long long, int>` 起了一个短名字 `Item`，只为少写几遍；`std::greater<Item>` 让距离小的先出队，比较 `pair` 时先比第一项。同一个点可能先后进队几次，只有距离和 `dist` 相同的那一次才是新的，其余跳过。

到不了的点不改势能。它们以后也到不了：送流只改最短路上的边，而那条路上的点都到得了，新出现的反向边也只连接到得了的点。

每轮至少送 1 个单位，所以轮数不超过最大流的值，每轮一次 Dijkstra 是 O(m log m)。最大流很大时这个界并不好；这里不再展开，只说清它取决于流值，不只取决于 n 和 m。

**停笔 3**　如果原图里有一条费用为负的边（但没有负圈），程序 A 哪一句会失去依据？开始前应该先做什么，才能给出一组合格的势能？

对拍用了两种慢办法。一种把 Dijkstra 换成逐边松弛 n 轮的 Bellman–Ford，直接用带负数的费用找最短路；它和程序 A 共用“连续最短路是对的”这条事实，查的只是势能的写法。另一种只对“k 个人配 k 件事”的网络有效：把 k! 种配法全部列出来，取最便宜的。后一种完全不依赖本章的证明。

## 有时不必真的建整张网络

有些题的网络很特别，增广路长什么样一眼就能看出来。这时不必建图，只要把“撤回”这件事照样记账。

一种股票连续 n 天的价格依次给出。每天可以买进一股、卖出一股，或者什么都不做；手里股票数不能是负的，最后可以有剩余。问最多赚多少。

把每天看成一个点，“第 i 天买、第 j 天卖”赚 p_j − p_i。这是一个配对问题，可以建成费用流。但它的增广路只有两种：今天卖掉以前某天买的一股；或者把以前某次“第 i 天买、第 j 天卖”改成“第 i 天买、今天卖”，那第 j 天就空出来了。

后一种改配赚的是 (p_today − p_i) − (p_j − p_i) = p_today − p_j。它和“第 j 天买、今天卖”赚得一样多。所以卖过的那一天，可以当成一个价格为 p_j 的“买入机会”重新放回去，这就是撤回。

**片段：**

```cpp
// 位于 main 内；price 已读入，共 n 天
std::priority_queue<long long, std::vector<long long>, std::greater<long long>> offers;
long long profit = 0;
for (int i = 0; i < n; ++i) {
    if (!offers.empty() && offers.top() < price[i]) {
        profit += price[i] - offers.top();
        offers.pop();
        offers.push(price[i]);   // 今天的卖出以后可以改到更晚：这是撤回的机会
    }
    offers.push(price[i]);       // 今天本身也可以是一次买入
}
std::printf("%lld\n", profit);
```

价格 1、3、5：第 1 天放进 1；第 2 天 1 < 3，赚 2，放回两个 3；第 3 天最小的是 3 < 5，赚 2，一共 4。这 4 就是第 1 天买、第 3 天卖：第 2 天的“卖”被改配掉了，第 2 天什么都没做。

堆里每次只问最便宜的一项，正好代替了“找最便宜的增广路”。每天进堆至多两次，整件事 O(n log n)。对拍的慢办法按天数和手中股数做[第二卷第 8 章](../II/08-给已经解决的小问题留个位置.md)那样的表：记“第 i 天结束、手里 k 股时最多有多少钱”，它不知道堆，也不知道撤回。

**停笔 4**　价格依次是 4、2、6、1、3。逐天写出堆里有哪些数、`profit` 是多少。最后的答案对应哪几次买卖？

这一章换的是单价，没有换想法：残量网络仍然可以撤回，只是撤回要退钱。租车的例子说明，最便宜的下一步可能是一次改配；势能让带负号的反向边仍能交给 Dijkstra；股票的例子说明，增广路形状简单时，用一个堆记下“撤回的机会”就够了。[第二卷第 17 章](../II/17-每次只请最合适的一项出来.md)“奶牛优惠券”里“退券改付全价”的做法，可以照这个眼光再看一遍。能对一张小网络逐轮写出最便宜的增广路和它的费用，再读下一章。下一章换一个方向：有些图本身的形状，让难题变得容易。

## 核对

1. 第一次仍走 s → 甲 → 东 → t，花 1。第二次 s → 乙 → 西 → t 花 3，绕道 s → 乙 → 东 → 甲 → 西 → t 也花 2 − 1 + 2 = 3，两条一样便宜，任取一条，总费用都是 4。四种分法里最少就是 4。
2. 第一轮 s 到甲、乙、东、西的最短距离依次是 0、0、1、2，这就是新势能。“东 → 甲”的原费用是 −1，约化费用是 −1 + 1 − 0 = 0。
3. “h 全取 0 时所有约化费用不为负”失去依据，第一轮 Dijkstra 可能算错。先用 Bellman–Ford 从 s 求一次最短路，把距离当作初始势能。
4. 第 1 天：堆 {4}，0。第 2 天：{2, 4}，0。第 3 天：2 < 6，赚 4，堆 {4, 6, 6}，4。第 4 天：{1, 4, 6, 6}，4。第 5 天：1 < 3，赚 2，堆 {3, 3, 4, 6, 6}，6。答案 6：第 2 天买、第 3 天卖，第 4 天买、第 5 天卖。
