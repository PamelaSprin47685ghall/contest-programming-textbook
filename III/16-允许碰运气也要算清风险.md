# 16　允许碰运气也要算清风险

老师要检查全班四十份作业有没有抄答案。一份份逐题对，一晚上做不完。他每份随机抽三道题看。一个只抄了一道题的同学，多半能蒙混过关；一个整份照抄的同学，三道题都被抽到抄的部分，几乎跑不掉。“抽查”不是马虎，前提是老师心里有一本账：抄多少，被抓到的机会有多大。

程序也可以抽查、碰运气。这一章要分清两件事：程序可能**慢**的风险，和程序可能**错**的风险；还要说明，概率只有在我们自己掷骰子时才有意义。这里的概率、平均先按日常的意思理解，正式的定义在[第 22 章](22-平均要按机会大小来算.md)。最后两节离开随机，看两种“答案不一定最好，但差距有账可查”的办法。

## 错误概率与运行时间要分开

两种随机程序要分开说。

一种永远给出正确答案，只是花的时间看运气。快速排序随机选基准，就是这样：排出来一定对，平均比较约 2n ln n 次（n = 10⁶ 时约 2.8 × 10⁷ 次），比这多很多倍的机会极小。这种程序叫 **Las Vegas 型**。

另一种时间固定，答案有一个小概率是错的。例子：要检查两个 n × n 矩阵 A、B 的乘积是不是 C。直接乘要 n³ 次乘法，n = 1000 时是 10⁹。换一种问法：随机挑一列 0 或 1 组成的向量 x，比较 A(Bx) 和 Cx。这只要三次“矩阵乘向量”，约 3 × 10⁶ 次乘法。AB = C 时两边一定相等。AB ≠ C 时，可以证明两边相等的机会不超过一半：差 D = AB − C 有一个不为 0 的元素 D[i][j]，固定 x 的其余分量以后，Dx 的第 i 个分量是否为 0 只取决于 x[j]，x[j] 取 0 和取 1 两种情况里至多一种让它为 0。独立做 20 次，全部被骗过的机会不超过 2⁻²⁰，约一百万分之一。这种程序叫 **Monte Carlo 型**，它的“错”只朝一个方向：说“不相等”时一定对，说“相等”时可能错。

两种风险能互相换。Monte Carlo 型的程序，要是能便宜地验证答案，就可以“验证不过就重来”，变成 Las Vegas 型；Las Vegas 型的程序，规定一个时间上限，到了就交一个可能错的答案，变成 Monte Carlo 型。不管哪种，写出来时都要说清：时间的账是平均还是最坏，错误的账是多大的概率。

## 哈希怎样才有概率含义

比较两段文字是否相同，逐字比较要和长度成正比。把每段文字压成一个数，比较两个数，就快了。这个数就是[第一卷第 17 章](../I/17-集合、顺序与自己设计的键.md)说的哈希值。最常用的一种把字符看成数，算

H = c₀ × B^(L − 1) + c₁ × B^(L − 2) + …… + c_(L − 1)，再对一个大素数 p 取余。

两段不同的文字哈希值相同，叫**碰撞**。说“碰撞的概率很小”时，要问：概率是对什么而言的？要是 B 和 p 都是写死的，对一组固定的输入，结果是确定的：撞了就是撞了，没撞就是没撞，谈不上概率。有人可以照着你的 B 和 p 专门造两段会撞的文字；用 2⁶⁴ 自然溢出当作取余的写法，就有一类专门的串能让它出错。

概率要来自我们自己的随机选择：p 固定，B 在程序运行时从 1 到 p − 1 里随机挑，而输入在挑 B 之前就定了。这时两段长度为 L 的不同文字，它们哈希值之差是 B 的一个次数不超过 L − 1 的多项式，系数是两段文字对应字符之差，不全为 0；p 比字符的编号大，所以这些系数对 p 取余也不全为 0。在模素数 p 的世界里，这样的多项式至多有 L − 1 个根，所以撞上的机会不超过 (L − 1)/(p − 1)。

这只是**一次**比较的账。程序要做 q 次比较，至少错一次的机会不超过每次的机会之和（这叫**并集界**）。p 约 2 × 10⁹，L 和 q 都是 10⁵ 时，每次不超过约 5 × 10⁻⁵，乘以 10⁵ 次是 5，这条界什么也没保证。再加一个素数 10⁹ + 7，两个 B 各自独立地随机挑，两个哈希值同时相等才算相等。一次的界变成两个数相乘，约 5 × 10⁻⁵ × 10⁻⁴ = 5 × 10⁻⁹，十万次合起来不超过 5 × 10⁻⁴。下面的程序就这样做。

### 判断两段是否相同

输入第一行是一个小写字母串 s（长度 1 到 10⁵），第二行是询问数 q（1 到 10⁵），之后 q 行，每行 a、b、len，问从位置 a 开始和从位置 b 开始、各长 len 的两段是否相同（位置从 0 编号，保证不越界，len ≥ 1）。每个询问输出 `yes` 或 `no`。

样例输入：

```text
abcabcab
3
0 3 5
0 1 3
2 5 3
```

样例输出：

```text
yes
no
yes
```

`abcab` 与 `abcab` 相同；`abc` 与 `bca` 不同；`cab` 与 `cab` 相同。

随机数要用 `<random>` 里的工具，第一卷没有讲过。`std::random_device` 从系统取一个难以预测的种子；`std::mt19937` 是一台用这个种子出发、不断产生随机整数的“机器”；`std::uniform_int_distribution<long long> pick(1, p - 1)` 把机器的输出变成 1 到 p − 1 之间等可能的整数，`pick(engine)` 取一个。

下面是**完整程序 A**。

```cpp
#include <cstdio>
#include <random>
#include <string>
#include <vector>

char buffer[100001];

int main() {
    if (std::scanf("%100000s", buffer) != 1) {
        return 1;
    }
    std::string s = buffer;
    int n = static_cast<int>(s.size());
    const long long prime[2] = {2147483647LL, 1000000007LL};
    std::random_device device;
    std::mt19937 engine(device());
    std::vector<long long> prefix[2];   // prefix[h][i]：前 i 个字符的哈希值
    std::vector<long long> power[2];    // power[h][i]：底数的 i 次方
    for (int h = 0; h < 2; ++h) {
        std::uniform_int_distribution<long long> pick(1, prime[h] - 1);
        long long base = pick(engine);   // 先有输入，再掷骰子
        prefix[h].assign(n + 1, 0);
        power[h].assign(n + 1, 1);
        for (int i = 0; i < n; ++i) {
            prefix[h][i + 1] = (prefix[h][i] * base + (s[i] - 'a' + 1)) % prime[h];
            power[h][i + 1] = power[h][i] * base % prime[h];
        }
    }
    auto piece = [&](int h, int start, int len) {
        long long value = (prefix[h][start + len] - prefix[h][start] * power[h][len]) % prime[h];
        return value < 0 ? value + prime[h] : value;
    };
    int q = 0;
    if (std::scanf("%d", &q) != 1) {
        return 1;
    }
    for (int i = 0; i < q; ++i) {
        int a = 0;
        int b = 0;
        int len = 0;
        if (std::scanf("%d%d%d", &a, &b, &len) != 3) {
            return 1;
        }
        bool same = piece(0, a, len) == piece(0, b, len) && piece(1, a, len) == piece(1, b, len);
        std::printf("%s\n", same ? "yes" : "no");
    }
    return 0;
}
```

一段的哈希值由两个前缀相减得到：前 start + len 个字符的值，减去前 start 个字符的值乘以 B 的 len 次方。两个因数都小于 p，乘积小于 p² ≈ 4.6 × 10¹⁸，`long long` 放得下；相减可能是负数，所以取余以后再调回 0 到 p − 1。字符记成 1 到 26。本题两段一样长，从 0 记起也可以；要是以后比较不同长度的段，`a` 记成 0 会让 `a` 和 `aa` 的哈希值都是 0。

对拍的慢办法逐字比较。程序 A 每次运行挑的 B 都不同，对拍了几百次都对，说明的是这几百次没有碰撞，和上面那条界并不矛盾。

## 用平均值指导不随机的选择

随机也能拿来证明“存在”。把一张图的点分成两组，两端在不同组的边叫被**割到**的边。随便每个点掷一枚硬币决定去哪组，每条边被割到的机会是一半，所以平均割到 m/2 条边（m 是边数）。平均是 m/2，至少有一种分法割到不少于 m/2 条。

还能把硬币拿掉。按编号逐个放点：放点 v 时，看它已经放好的邻居，哪组少就去哪组。这样 v 和已放好的邻居之间的边，至少一半被割到。每条边在它较晚放下的那一端被算一次，所以割到的边至少 m/2。换一种说法：每一步都选“让剩下的点仍随机分时，平均割到的边数”不变小的那一边，平均值一步步变成确定的值。这种做法叫**条件期望法**。

**片段：**

```cpp
// 位于 main 内；neighbors[v] 是 v 的邻居表，点从 0 编号
std::vector<int> side(n, -1);   // -1 表示还没放
for (int v = 0; v < n; ++v) {
    int in_zero = 0;
    int in_one = 0;
    for (int u : neighbors[v]) {
        if (side[u] == 0) {
            ++in_zero;
        } else if (side[u] == 1) {
            ++in_one;
        }
    }
    side[v] = in_zero >= in_one ? 1 : 0;   // 去邻居少的那组
}
```

## 不求最优，也要给一条界

有的问题没有已知的快办法求最优。退一步，可以求一个不太差的答案，并且说清它离最优最多差多少。

在图里选一些点，让每条边至少有一个端点被选中，这是[第 10 章](10-找不到搭档时让出一条路.md)的点覆盖。求最少的点覆盖很难。下面的办法保证不超过最优的两倍：逐条看边，若两端都还没选，就把两端都选上。这样被“两端都选”的边彼此没有公共端点。任何一个点覆盖都得在每条这样的边上至少选一个点，而它们互不共用端点，所以最优至少是这些边的条数 k；我们选了 2k 个点，不超过最优的两倍。

这里的“两倍”不是猜的：答案和一个下界放在一起比。最优是多少我们不知道，但 k 一定不超过它。**近似比**说的就是这种有证明的倍数。

## 把数值缩粗，再修回误差账

背包问题：n 件物品，各有重量和价值，总重不超过 W，求最大总价值。[第二卷第 8 章](../II/08-给已经解决的小问题留个位置.md)用“价值和”做表的一维时，表的大小和价值的总和成正比；价值动辄 10⁹，表就放不下。

把价值缩粗：取一个数 K，每件物品的价值换成 v 除以 K 向下取整，用缩粗的价值做表，求出最优的一组物品。每件物品缩粗时丢掉不到 K，n 件加起来不到 n × K。所以这组物品的真实价值，和真正最优那组相比，差不到 n × K。取 K = ε × v_max / n（v_max 是单件最大价值，并假定每件都能单独装下，这时最优至少是 v_max），误差不到 ε × v_max ≤ ε × 最优。缩粗以后单件价值不超过 n / ε，表的大小只和 n、1/ε 有关。

例子：三件物品，价值 1000、1999、2001，重量 1、1、2，W = 2。取 ε = 0.5，n = 3，v_max = 2001，K = 0.5 × 2001 / 3 = 333.5。缩粗后的价值是 2、5、6：1000/333.5 约 2.998，向下取整成 2，丢掉了将近一个 K。误差的账是：丢掉的价值合起来不到 3 × 333.5 = 1000.5，所以表选出的那组，真实价值至少是最优减去 1000.5。

ε 越小，账越紧，表越大：缩粗后单件价值不超过 n/ε，表的价值一维约 n²/ε 格，每格对 n 件物品各看一次，总共约 n³/ε 步。这是一笔明码标价的交换：精度和时间，由我们自己挑。

**停笔 5**　在上面的例子里，缩粗后的表会选哪一组？真实价值和最优差多少？若 ε 改成 0.1，K 是几，三件物品缩粗后各是几？

这一章算了四本账。随机程序要分开记“慢”的账和“错”的账；哈希的概率来自运行时自己掷的骰子，次数一多，还要把每次的错误机会加起来；平均值不但说明好答案存在，还能一步步指引不随机的选择；近似答案和缩粗的数值，都要和一个下界或误差和放在一起比。能对一个随机程序说出它错的机会、对一个近似办法说出它差的倍数，再读下一章。下一章开始计数，先问：数清的到底是作品，还是做法？
