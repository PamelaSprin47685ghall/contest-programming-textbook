# 23　先知道轮到谁算赢

两人轮流拿石子，每次拿一颗或两颗，不能拿的人输。先手不总是赢；三颗时，无论拿几颗，都给对方留下能一步拿光的数量。

## 状态先分胜负

无合法动作是必败态；存在一步能走到必败态，就是必胜态；若所有下一步都是必胜态，当前必败。状态图必须没有无限进行的环，或者题目另有平局规则；否则这份递推未必涵盖所有结果。

只分胜负，在两堆游戏合起来时不够。两堆各自必胜，放一起可能必败。要保存更精细的信息。

## 最小没出现的数

mex 是最小未出现的非负整数。例如 `mex{0,2}=1`，空集的 mex 为 0。给状态 u 定义 `SG(u)=mex{SG(v):u能一步到v}`。

若多个无偏、正常规则的有限游戏独立合并，每次只动其中一个，总 SG 值是各 SG 的按位异或。异或为零必败；非零时可选一堆，把最高非零位消掉，并利用 mex 保证所需更小 SG 后继存在。这是 Sprague–Grundy 理论。

**完整程序：**输入堆数 `0 <= p <= 100000`、允许拿法数 `0 <= m <= 20`，再输入 m 个 1 到 100000 的拿法及 p 个 0 到 100000 的石子数。两人每步选一堆，拿允许数量，不能拿者输。输出 `WIN` 或 `LOSE`。

```cpp
#include <algorithm>
#include <cstdio>
#include <vector>

int main() {
    int p = 0;
    int m = 0;
    if (std::scanf("%d%d", &p, &m) != 2 || p < 0 || p > 100000 || m < 0 || m > 20) { return 1; }
    std::vector<int> moves(m), piles(p);
    for (int& move : moves) {
        if (std::scanf("%d", &move) != 1 || move < 1 || move > 100000) { return 1; }
    }
    int maximum = 0;
    for (int& pile : piles) {
        if (std::scanf("%d", &pile) != 1 || pile < 0 || pile > 100000) { return 1; }
        maximum = std::max(maximum, pile);
    }
    std::vector<int> sg(maximum + 1, 0), marked(m + 1, -1);
    for (int stones = 1; stones <= maximum; ++stones) {
        for (int move : moves) {
            if (move <= stones) { marked[sg[stones - move]] = stones; }
        }
        int value = 0;
        while (value <= m && marked[value] == stones) { ++value; }
        sg[stones] = value;
    }
    int combined = 0;
    for (int pile : piles) { combined ^= sg[pile]; }
    std::printf("%s\n", combined == 0 ? "LOSE" : "WIN");
    return 0;
}
```

输入：

```text
2 2
1 2
2 3
```

输出：

```text
WIN
```

每状态至多 m 个后继，mex 至多 m，标记表因此只需 `m+1` 项。时间 `O(maximum*m+p)`，空间 `O(maximum+m+p)`。时间戳 stones 避免每轮清空；m=0 时所有状态 SG 为零。

## Nim 的石子数恰好就是 SG

Nim 每步可从一堆拿任意正数。n 颗能去 0 到 n−1，所以 mex 为 n；因此所有堆异或即可。不能把这条简化直接搬到“只许拿 1、2”里，那里的 SG 呈 `0,1,2` 循环，不等于石子数。

反常规则“拿最后一颗者输”改变终止意义，普通 SG 合并定理不直接适用。双方动作不同的是有偏游戏；可用左右选择集合研究，但不再只用一个非负整数概括。

超现实数把某些有偏游戏的序关系扩展成数；nimber 的加法是游戏和对应的异或，而不是普通整数相加。它们有各自的乘法或序规则，不能因为都写成数字就混为一个四则运算系统。一般竞赛题先从可达状态、终止规则和对称性判断，不必引入超出实际问题的数系。

## 找规律以后，还要证明不会换样

减法游戏的小表常出现周期，可尝试记录最近 max(move) 个 SG 值。如果整段窗口完全重复，后面由同一递推确定，周期就会继续；只看到单个值相等远远不够。

**停笔 3**　若允许一条边从状态 A 回到 A，玩家可以无限拖延，普通“必胜或必败”分类遗漏了什么？

## 核对

1. `0,1,2,0,1,2,0`。两堆一颗异或为零，先手拿完一堆，后手拿最后一堆。
2. 是 `1 XOR 1=0`，不是 2。对手能用对应动作恢复平衡。
3. 可能出现无限局或平局，须依据题目规则另建分类，不能硬用有限无环递推。
