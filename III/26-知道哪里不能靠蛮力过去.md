# 26　知道哪里不能靠蛮力过去

“二十个问题”这个游戏，一个人心里想一样东西，另一个人只能问“是”或“不是”的问题。二十问以内猜中，听上去很难，可每个问题都能把候选砍掉一半的话，二十问能分开 2²⁰，一百万出头种东西。反过来，候选要是有一千万种，不论问题问得多聪明，二十问也不够。这一句“不够”，不是说我们还没想到好办法，而是说任何办法都不行。

这一章讲这种“任何办法都不行”的道理：先说清在什么机器上数步数，再证明比较排序至少要多少次比较，说明信息为什么压缩不了，最后看两种常用的说法：把一个问题变成另一个来比较难度，以及让步数依赖规模以外的参数。

## 先说清机器允许做什么

说“这个算法要 O(n log n) 步”，先要约定一步是什么。本书一直默认的是这样一台机器：内存是一排格子，每格放一个不太大的整数（64 位以内）；读写任何一格、两个数的加减乘除、比较、位运算，都算一步。这叫**字 RAM 模型**。按经验，竞赛机器一秒大约能做 10⁸ 到 10⁹ 次这样的简单操作。

模型说清楚了，下界才有意义。“排序至少要 n log n 步”这句话，在只允许比较的模型里成立；在字 RAM 上，要是数的范围不大，先数出每个值出现几次，再按值从小到大写回去，只要 O(n + 值域) 步，根本不做比较。下界和上界一样，都是对某个模型说的。

## 比较排序为什么绕不开那么多问句

只允许比较的排序算法，每次挑两个元素问“谁小”，根据回答决定下一次问什么，最后给出排列。把所有可能的提问过程画成一棵树：每个节点是一次比较，两个孩子是两种回答，叶子是给出的答案。这叫**决策树**。

n 个互不相同的数有 n! 种相对顺序，每种都要排对，而不同的顺序需要不同的整理方式，所以它们落在不同的叶子上，树至少有 n! 个叶子。一棵每个节点至多两个孩子、高度为 h 的树，至多有 2^h 个叶子。所以 2^h ≥ n!，最坏情况的比较次数 h ≥ log₂ n!。

log₂ n! 有多大？n! 的后一半因子都不小于 n/2，所以 n! ≥ (n/2)^(n/2)，log₂ n! ≥ (n/2) log₂(n/2)。它和 n log₂ n 是同一个量级。归并排序用了 O(n log n) 次比较，量级上已经不能再好。

下面的片段对小的 n 枚举全部排列，看插入排序最坏用几次比较，和下界放在一起。

**片段：**

```cpp
// 位于 main 内：对 0 到 n − 1 的所有排列做插入排序，记下最多用了几次比较
std::vector<int> perm(n, 0);
for (int i = 0; i < n; ++i) {
    perm[i] = i;
}
long long worst = 0;
do {
    std::vector<int> a = perm;
    long long compares = 0;
    for (int i = 1; i < n; ++i) {
        int j = i;
        while (j > 0) {
            ++compares;
            if (a[j - 1] < a[j]) {
                break;
            }
            std::swap(a[j - 1], a[j]);
            --j;
        }
    }
    if (compares > worst) {
        worst = compares;
    }
} while (std::next_permutation(perm.begin(), perm.end()));
// 下界：最小的 b，使 2 的 b 次方不小于 n!
long long factorial = 1;
for (int i = 2; i <= n; ++i) {
    factorial *= i;
}
int bound = 0;
while ((1LL << bound) < factorial) {
    ++bound;
}
std::printf("n = %d: 最多 %lld 次，下界 %d 次\n", n, worst, bound);
```

`std::next_permutation` 见[第一卷第 14 章](../I/14-旋转、比较规则与排列.md)，要 `#include <algorithm>`。n 从 1 到 9，插入排序最坏是 n(n − 1)/2 次，依次是 0、1、3、6、10、15、21、28、36；下界是 0、1、3、5、7、10、13、16、19。n ≤ 3 时两者相等；n 越大差得越远。

这种下界还可以用**对手论证**来想：对手不必事先定好输入，只要每次回答都和至少一半剩下的可能顺序一致。每问一次，剩下的可能至多减半，问不到 log₂ n! 次，剩下的就不止一种，算法分不清它们。

## 压缩的是信息，不是把名字改短

长 n 的 01 串有 2ⁿ 个，长度小于 n 的 01 串（含空串）一共只有 1 + 2 + …… + 2^(n−1) = 2ⁿ − 1 个。一个压缩程序要能还原，不同的输入必须压成不同的结果，所以不可能把每个长 n 的串都缩短：至少有一个变不短。同样地，能压到不超过 n − c 位的串，个数不到 2^(n−c+1)，只占不到 1/2^(c−1)。

这和比较排序的下界是同一个道理：要分开 N 种可能，就需要 log₂ N 位**信息**，用比较问也好，用 01 串写也好。压缩程序能把文本缩短，是因为真实的文本远不是均匀随机的；它利用的是规律，而不是把每个字换成更短的名字。

这条道理也能检查空间。要记住 1 到 n 的一个排列，至少要 log₂ n! 位，大约 n log₂ n 位；有人说“只用 O(n) 位存下任意排列”，就一定有地方说错了。

## 先把问题变成另一个，再谈难度

要说问题 A 不比问题 B 难，一个办法是把 A 的任何输入，用不多的步数改写成 B 的输入，使 B 的答案就是 A 的答案。这叫把 A **归约**到 B。B 有快办法，A 就有；反过来，A 被认为很难，B 也不会容易。

一张图里，两两不相邻的点组成**独立集**；让每条边至少有一端被选中的点集叫**点覆盖**。一个点集是独立集，当且仅当其余的点组成点覆盖：一条边两端都不在独立集里，就是至少一端在其余的点里。所以最大独立集的大小，等于点数减去最小点覆盖的大小，两个问题互相归约，步数只多 O(n)。

有一大类问题，答案“是”的时候能给出一份可以很快检查的证据，比如点覆盖给出那组点，这一类叫 **NP**。其中有些问题，NP 里每个问题都能归约到它，它叫 **NP 困难**的；本身又在 NP 里，就叫 **NP 完全**。点覆盖、独立集、给布尔式找一组让它为真的取值，都是 NP 完全的。至今没有人找到它们的多项式算法，也没有人证明不存在。在竞赛里，看出题目是这类问题的一般情形，就该回去找题目给的特殊条件：图是树、数很小、某个参数很小。

## 规模不是只能看一个 n

点覆盖在一般图上是 NP 完全的，可是要问“能不能用至多 k 个点覆盖所有边”，k 很小时有快办法。任取一条还没被覆盖的边 (u, v)，覆盖里一定有 u 或 v，分两支：选 u，或者选 v，每支都把 k 减 1。递归树的深度不超过 k，至多 2^k 个叶子，每个节点找一条未覆盖的边要 O(m) 步，总共 O(2^k × m)。

步数是 f(k) × 输入规模的多项式，f 只和参数 k 有关，这样的算法叫**固定参数可解**。点数 n 可以是几千，只要答案 k 不大，就算得动。

下面是**完整程序 A**。输入 n、m（n ≤ 1000，m ≤ 5000）和 m 条边，点从 1 编号，没有自环和重边；保证最小点覆盖不超过 12。输出最小点覆盖的大小。

```cpp
#include <cstdio>
#include <vector>

int m = 0;
std::vector<int> from;
std::vector<int> to;
std::vector<char> chosen;

// 还能再选 budget 个点时，能不能让每条边至少有一端被选中
bool can_cover(int budget) {
    int open_edge = -1;
    for (int i = 0; i < m; ++i) {
        if (chosen[from[i]] == 0 && chosen[to[i]] == 0) {
            open_edge = i;
            break;
        }
    }
    if (open_edge < 0) {
        return true;
    }
    if (budget == 0) {
        return false;
    }
    // 这条边的两端至少选一个：分两支试
    int ends[2] = {from[open_edge], to[open_edge]};
    for (int s = 0; s < 2; ++s) {
        chosen[ends[s]] = 1;
        bool ok = can_cover(budget - 1);
        chosen[ends[s]] = 0;
        if (ok) {
            return true;
        }
    }
    return false;
}

int main() {
    int n = 0;
    if (std::scanf("%d%d", &n, &m) != 2) {
        return 1;
    }
    from.assign(m, 0);
    to.assign(m, 0);
    chosen.assign(n + 1, 0);
    for (int i = 0; i < m; ++i) {
        if (std::scanf("%d%d", &from[i], &to[i]) != 2) {
            return 1;
        }
    }
    int k = 0;
    while (!can_cover(k)) {
        ++k;
    }
    std::printf("%d\n", k);
    return 0;
}
```

样例输入：

```text
5 5
1 2
2 3
3 4
4 5
5 1
```

样例输出：

```text
3
```

五个点连成一圈。2 个点至多盖住 4 条边，不够；选 1、3、4 就盖住了全部五条。程序从 k = 0 试起，k = 3 时第一次成功。k 从 0 试到答案 K，总步数约 (2⁰ + 2¹ + …… + 2^K) × m < 2^(K+1) × m，K = 12 时约 4 × 10⁷。对拍的慢程序枚举 2ⁿ 个点集。

还可以先做一步化简：一个点的度数超过剩下的预算，它就必须被选中，否则要选它的全部邻居，预算不够。反复这样做，剩下每个点的度数都不超过预算 k，k 个点至多盖住 k² 条边；剩下的边比 k² 多，就直接回答不能。这叫**核化**：先把输入缩到只和参数有关的大小，再搜索。

**片段：**

```cpp
// 位于 main 之前、can_cover 之后：先核化，再搜索
bool kernel_then_search(int budget) {
    int n = static_cast<int>(chosen.size()) - 1;
    std::vector<int> forced;            // 核化时被迫选中的点，最后要撤销
    bool answer = false;
    while (true) {
        std::vector<int> degree(n + 1, 0);
        int open_edges = 0;
        for (int i = 0; i < m; ++i) {
            if (chosen[from[i]] == 0 && chosen[to[i]] == 0) {
                ++degree[from[i]];
                ++degree[to[i]];
                ++open_edges;
            }
        }
        int big = -1;
        for (int v = 1; v <= n; ++v) {
            if (degree[v] > budget) {
                big = v;
                break;
            }
        }
        if (big < 0) {
            // 每个点至多盖住 budget 条边，budget 个点至多盖住 budget² 条
            answer = open_edges <= budget * budget && can_cover(budget);
            break;
        }
        if (budget == 0) {
            break;                      // 还有边没盖住，预算却用完了
        }
        chosen[big] = 1;
        forced.push_back(big);
        --budget;
    }
    for (int v : forced) {
        chosen[v] = 0;
    }
    return answer;
}
```

把程序 A 里的 `while (!can_cover(k))` 换成 `while (!kernel_then_search(k))`，答案不变。核化以后搜索面对的边不超过 k² 条，每个节点的 O(m) 变成 O(k²)，只是每次核化本身要扫一遍全部边。`for (int v : forced)` 依次取出 `forced` 里的每个点。

“度数超过预算就必须选”要求邻居各不相同，所以题目说没有重边。有重边时，一个点的度数可以很大，邻居却只有一个，这条规则就会选错。

**停笔 5**　一张星形图：中心 1 号点和 2 到 20 号点各连一条边。k = 1 时 `kernel_then_search` 做了什么？k = 0 时呢？

这一章说的都是“不能”。说不能之前先定模型；比较排序有 log₂ n! 的下界，信息量给出空间和压缩的下界；归约把难度从一个问题传到另一个；参数小的时候，难问题也可能算得动。能对一个想法先估一下“它至少要多少步、多少位”，并且知道遇到 NP 完全的一般情形该去找哪些特殊条件，再读下一章。下一章回到具体的数据结构：偶尔很贵的操作，平均下来能不能便宜。

## 核对

1. 里层执行 0 + 1 + …… + (n − 1) = n(n − 1)/2 次，n = 10⁵ 时约 5 × 10⁹ 次，按每秒 10⁹ 次要 5 秒左右，太慢了。
2. 5! = 120，2⁶ = 64 < 120 ≤ 128 = 2⁷，下界是 7 次。插入排序最坏是 5 × 4 ÷ 2 = 10 次（倒序输入）。
3. 长度 0 到 10 的 01 串共 2¹¹ − 1 = 2047 个，至多 2047 个长 20 的串能压到 10 位以下，占 2047 ÷ 2²⁰，约 0.2%。
4. 最小点覆盖是 {2, 4}，2 个点；最大独立集是 {1, 3, 5}，3 个点。2 + 3 = 5，正好是点数，两者互为补集。
5. k = 1：1 号点的度数是 19，大于 1，被迫选中，预算变成 0；再数一遍，没有未覆盖的边，所有点的度数都是 0，`open_edges` 是 0 ≤ 0，`can_cover(0)` 成立，回答能。k = 0：1 号点度数 19 > 0，找到 `big`，但预算已经是 0，直接回答不能。
