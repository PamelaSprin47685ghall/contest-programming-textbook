# 27　把一次大搬家拆进许多小动作

书架放满了，就去买一个两倍大的，把书全搬过去。搬一次很累，但不常搬：每次搬完，要再放进和原来一样多的书才会再满。算总账，每本书平均只被搬了不到两次。可要是哪天下午正好要找一本书，又正好赶上搬家，这个下午就全耽误了。这一章先学会算总账，再学会把大搬家拆成每天顺手做的一点。

## 均摊不是概率平均

一串操作中，个别操作很贵，但任何一段长 n 的操作总代价不超过 n × c，就说每个操作的**均摊代价**是 c。这里没有随机：不论操作怎样安排，总账都成立。[第 22 章](22-平均要按机会大小来算.md)的期望是对随机结果取平均，均摊是对一串操作取平均，两者不是一回事。

最常见的例子是二进制计数器加 1：末尾连续的 1 都变成 0，再把下一位变成 1。一次加 1 可能翻很多位，比如从 0111 1111 到 1000 0000 翻了 8 位。

**片段：**

```cpp
// 位于 main 内：二进制计数器从 0 加到 n，数一共翻了几位
std::vector<int> bit(32, 0);
long long flips = 0;
for (int step = 0; step < n; ++step) {
    int i = 0;
    while (bit[i] == 1) {          // 末尾的 1 都变成 0，这就是进位
        bit[i] = 0;
        ++flips;
        ++i;
    }
    bit[i] = 1;
    ++flips;
}
std::printf("%lld\n", flips);
```

从 0 加到 n，最低位每次都翻，第 2 位每两次翻一次，第 3 位每四次翻一次，总数不超过 n + n/2 + n/4 + …… < 2n。实际恰好是 2n 减去 n 的二进制里 1 的个数，n = 10⁹ 时是 1999999987。

另一种算法叫**势能法**：给数据结构的每个状态定一个非负的数 Φ，叫势能，一开始是 0。一次操作的均摊代价定义为实际代价加上 Φ 的变化。把一串操作的均摊代价加起来，Φ 的变化前后抵消，只剩最后的 Φ，它不小于 0，所以实际总代价不超过均摊代价之和。计数器取 Φ = 二进制里 1 的个数：一次加 1 把 t 个 1 变成 0、一个 0 变成 1，实际代价 t + 1，Φ 变化 1 − t，均摊代价恰好是 2。

## 提前开始搬，才有时间分期付款

均摊只管总账。有些场合每一步都要快，比如交互题每问都有时限，或者程序要实时响应。把均摊变成每一步的保证，叫**去均摊**。

书架的例子：容量 s 的数组放满时，不一次搬完，而是申请容量 2s 的新数组，以后每放进一个新元素，就顺手从旧数组搬 2 个过去。新数组还能再放 s 个，搬完 s 个旧元素只需要 s/2 次，新数组远没满时旧的就搬完了，旧数组可以扔掉。读第 i 个元素时，看它已经搬过去没有，去对应的数组里拿。每一步都只多做常数件事。

这里的关键是开始得早、每步搬得够多：搬完以前，新数组不能再满。算法设计里常说，去均摊就是“给每笔大开销定一个时钟，钟走完以前必须做完”。

## 队列重构也有自己的时钟

队列可以用两个栈做：新来的压进 `in`，出队时从 `out` 弹；`out` 空了，就把 `in` 整个倒进 `out`，顺序正好翻过来，最早来的在栈顶。

**片段：**

```cpp
// 位于 main 之前：用两个栈做成的队列
struct TwoStackQueue {
    std::vector<int> in;           // 新来的压在这里
    std::vector<int> out;          // 出队从这里弹，栈顶是最早来的

    void push(int v) {
        in.push_back(v);
    }

    bool empty() const {
        return in.empty() && out.empty();
    }

    int pop() {                    // 调用前要保证队列非空
        if (out.empty()) {
            while (!in.empty()) {
                out.push_back(in.back());
                in.pop_back();
            }
        }
        int v = out.back();
        out.pop_back();
        return v;
    }
};
```

一次出队可能要倒 k 个元素，但每个元素一生只被倒一次。用势能法，取 Φ = 2 × `in` 的大小：入队实际代价 1，Φ 加 2；倒 k 个元素再弹一个，实际代价 2k + 1（每个元素弹出、压入各一次），Φ 减 2k；两种操作的均摊代价都是常数。我们拿它和 `std::queue` 对拍，300 组随机的入队、出队序列结果一致。

要去均摊，就得在 `out` 还没空时提前开始倒。思路是：`out` 剩下的元素个数就是时钟，在它弹完之前，每次操作顺手搬几个，把 `in` 里的元素准备成新的 `out`。难点在于一边准备，旧的 `out` 还在被弹，新来的又进 `in`，要同时维护好几份栈，细节比两个栈多得多。实际写程序时，均摊 O(1) 通常就够了；只有题目真的要求每一步都快时，才值得这样做。

## 二进制分组的进位也可以排班

有的结构不支持插入，只能一次建好，比如第 24 章的凸包要先排序。要支持一个个加点，可以把所有点分成若干组，每组的大小是互不相同的 2 的幂，就像二进制写法：13 个点分成 8、4、1 三组。来一个新点，它自成一组；和已有的某组一样大，就合并重建，继续往前进位。每个点每次被重建，所在的组都变大一倍，所以一个点至多参与 log₂ n 次重建。这叫**二进制分组**。查询时每组各问一次，至多 log₂ n 组。

### 例题　围住牛群

一开始有 N 头牛，各在一个整点上，接着有 Q 次操作（N、Q ≤ 10⁵）。`1 x y` 是在 (x, y) 加一头牛；`2 A B C` 问直线 Ax + By = C 能不能当围栏：所有牛都严格在它的同一侧才行，有牛在线上也不行。坐标绝对值不超过 10⁹，A、B 的绝对值不超过 10⁹ 且不同时为 0，C 的绝对值不超过 10¹⁸。每次询问输出一行 `YES` 或 `NO`。

样例输入：

```text
3 4
0 0
0 1
1 0
2 2 2 3
1 1 1
2 2 2 3
2 0 1 1
```

样例输出：

```text
YES
NO
NO
```

记 f(x, y) = Ax + By。第一问三头牛的 f 是 0、2、2，都小于 3，可用。加入 (1, 1) 后它的 f 是 4，在另一侧，不可用。第三问直线 y = 1 上有牛 (0, 1)，也不可用。

这是 USACO 2015 年 2 月金组第三题[“围住牛群”](../USACO/金组/2014_2015/2015.02/P3.md)。

可用，就是全体牛的 f 的最大值小于 C，或者最小值大于 C。把直线整个乘 −1，答案不变，所以可以让 B > 0（B = 0 时让 A > 0）。B > 0 时，f 的最大值一定在上链上取到，最小值在下链上。沿上链从左往右，边的斜率越来越小，相邻两点 f 的差 = A × dx + B × dy 先正后负，最大值在第一次不再增大的地方，可以二分。下链反过来。B = 0 时 f = Ax，只看最左和最右的点。

每组存按 x 排好的点和两条链。合并两组时，两份排好的点用 `std::merge` 归并成一份，再从左往右重建两条链，不必重新排序。

下面是**完整程序 A**。

```cpp
#include <algorithm>
#include <cstdio>
#include <vector>

struct Point {
    long long x;
    long long y;
};

bool left_lower(const Point& a, const Point& b) {
    if (a.x != b.x) {
        return a.x < b.x;
    }
    return a.y < b.y;
}

long long cross(const Point& o, const Point& a, const Point& b) {
    return (a.x - o.x) * (b.y - o.y) - (a.y - o.y) * (b.x - o.x);
}

// 一组点：按 x 排好的全部点，以及它们的下链、上链
struct Group {
    std::vector<Point> points;
    std::vector<Point> lower;
    std::vector<Point> upper;
};

void build_chains(Group& g) {
    g.lower.clear();
    g.upper.clear();
    for (const Point& q : g.points) {
        while (g.lower.size() >= 2 &&
               cross(g.lower[g.lower.size() - 2], g.lower.back(), q) <= 0) {
            g.lower.pop_back();
        }
        g.lower.push_back(q);
        while (g.upper.size() >= 2 &&
               cross(g.upper[g.upper.size() - 2], g.upper.back(), q) >= 0) {
            g.upper.pop_back();
        }
        g.upper.push_back(q);
    }
}

long long value(long long a, long long b, const Point& p) {
    return a * p.x + b * p.y;
}

// b > 0 时链上的 value 先增后减（上链）或先减后增（下链）；
// want_max 为真时在上链找最大，否则在下链找最小
long long extreme(const std::vector<Point>& chain, long long a, long long b, bool want_max) {
    int lo = 0;
    int hi = static_cast<int>(chain.size()) - 1;
    while (lo < hi) {
        int mid = (lo + hi) / 2;
        long long step = value(a, b, chain[mid + 1]) - value(a, b, chain[mid]);
        bool turned = want_max ? step <= 0 : step >= 0;
        if (turned) {
            hi = mid;
        } else {
            lo = mid + 1;
        }
    }
    return value(a, b, chain[lo]);
}

int main() {
    int n = 0;
    int q = 0;
    if (std::scanf("%d%d", &n, &q) != 2) {
        return 1;
    }
    std::vector<Group> groups;          // 大小是互不相同的 2 的幂，从大到小
    int total = n + q;
    for (int i = 0; i < total; ++i) {
        int kind = 1;
        if (i >= n && std::scanf("%d", &kind) != 1) {
            return 1;
        }
        if (kind == 1) {
            Group g;
            Point p = {0, 0};
            if (std::scanf("%lld%lld", &p.x, &p.y) != 2) {
                return 1;
            }
            g.points.push_back(p);
            // 像二进制加 1：末尾和它一样大的组，合并成一组，继续进位
            while (!groups.empty() && groups.back().points.size() == g.points.size()) {
                std::vector<Point> merged(g.points.size() * 2);
                std::merge(g.points.begin(), g.points.end(),
                           groups.back().points.begin(), groups.back().points.end(),
                           merged.begin(), left_lower);
                g.points.swap(merged);
                groups.pop_back();
            }
            build_chains(g);
            groups.push_back(g);
            continue;
        }
        long long a = 0;
        long long b = 0;
        long long c = 0;
        if (std::scanf("%lld%lld%lld", &a, &b, &c) != 3) {
            return 1;
        }
        if (b < 0 || (b == 0 && a < 0)) {   // 整条直线乘 −1，可用与否不变
            a = -a;
            b = -b;
            c = -c;
        }
        bool all_below = true;
        bool all_above = true;
        for (const Group& g : groups) {
            long long high = 0;
            long long low = 0;
            if (b == 0) {                   // 此时 a > 0，只看最左、最右
                high = value(a, b, g.points.back());
                low = value(a, b, g.points.front());
            } else {
                high = extreme(g.upper, a, b, true);
                low = extreme(g.lower, a, b, false);
            }
            if (high >= c) {
                all_below = false;
            }
            if (low <= c) {
                all_above = false;
            }
        }
        std::printf("%s\n", (all_below || all_above) ? "YES" : "NO");
    }
    return 0;
}
```

`std::merge` 把两段排好的数据归并到 `merged`，比较规则和排序时相同。`g.points.swap(merged)` 交换两个数组的内容，不复制元素。a × x 和 b × y 都不超过 10¹⁸，和不超过 2 × 10¹⁸；`step` 是两个这样的数之差，不超过 4 × 10¹⁸；`long long` 的上限约 9.2 × 10¹⁸，都放得下。

每个点至多参与 log₂ n 次归并和重建，加点的总代价是 O(n log n)；每次询问有至多 log₂ n 组，每组二分 O(log n) 步，共 O(log² n)。

这里的重建仍是均摊的：第 2^k 个点到来时，要把 2^k 个点一次重建。和书架一样，也可以排班：给每次将来的进位预先安排时钟，平时每加一个点就顺手做一点合并的工作，让每次加点都只花 O(log n) 步。我们不写这个版本，只要知道均摊的结构多半都能这样改。

对拍的慢程序每次询问都直接算出全部牛的 f。

## 不要把常数优化当新算法证明

写完程序嫌慢，常见的改法有：读入改快一点，数组换个摆法让内存访问连续，循环的里外层换个顺序，把除法换成乘法。这些都可能快上几倍，叫**常数优化**。

常数优化值得做，但要分清它和算法的不同。第一，它不改变量级：O(n²) 的程序优化得再好，n 大十倍还是慢一百倍。第二，它的效果要靠测量，不能靠推理：同样的改动，换一台机器、换一个编译器，可能就不快了；要在同一份数据上前后各量几次。第三，它不能拿来证明正确：快了，不说明对了；对拍和证明一样都不能省。

一个具体的例子是矩阵乘法 c[i][j] += a[i][k] × b[k][j]。三层循环按 i、j、k 的顺序写，最里层沿着 b 的一列跳着读；换成 i、k、j，最里层沿着 b 和 c 的一行连着读，在常见的机器上能快好几倍。可它仍是 n³ 次乘法，[第 19 章](19-把很多关系放进一张数表.md)里矩阵快速幂的量级，和这个顺序无关。

**停笔 5**　有人说：“我把输入换成更快的读法，O(n²) 的程序在 n = 10⁵ 时只跑了 0.8 秒，所以这个算法其实是 O(n log n)。”这句话错在哪里？

这一章的大开销都被拆开算了。均摊对一串操作算总账，势能法让总账好记；去均摊给每笔大开销定一个时钟，提前开始，分期做完；两个栈的队列、二进制分组都是这样的结构。“围住牛群”把不支持插入的凸包按二进制分组，每组在链上二分。常数优化只是让同一个算法跑得快些。能对一个偶尔很贵的操作，说出它的均摊代价，并说清要不要、怎样把它拆进平时，再读下一章。下一章看一排数：它的大小关系里，藏着一棵树。

## 核对

1. 从 0111 1111 加 1 要翻 8 位，变成 1000 0000；再减 1 又翻 8 位，回到 0111 1111。到达以后，n 次操作翻 8n 位。一般地，先用 n/2 次加 1 走到 2^(b−1) − 1，b 约为 log₂ n，剩下 n/2 次在两数之间来回，每次翻 b 位，总共约 (n/2) × log₂ n 位，均摊代价是 log n 量级，不再是常数。势能法的证明里，加 1 时 Φ 下降，减 1 时 Φ 却上升，抵消不了。
2. 每次搬 1 个：新数组还能放 s 个，正好在它放满的那一刻搬完 s 个旧元素，不留余地，而且下一次扩容又要立刻开始，勉强可行但没有余量；每次搬 2 个就从容得多。只申请 s + 1：再放 1 个就满，s 个旧元素来不及搬，一放满又要扩容，每次都得一次搬完，退化回整次搬家。
3. 第一次出队：`out` 空，把 `in` 里的 3、2、1 倒过去，`out` 栈顶是 1，弹出 1；此时 `in` 空，`out` 剩 2、3（栈顶是 2）。入队 4 进 `in`。第二次出队弹出 2，第三次弹出 3。第四次出队时 `out` 空，把 `in` 里的 4 倒过去再弹出。一共倒了两次，3 个和 1 个，共 4 个元素。
4. 7 个点依次是：1；2；2、1；4；4、1；4、2；4、2、1。第 8 个点自成一组，和大小 1 的组合并得 2，再和大小 2 的组合并得 4，再和大小 4 的组合并得 8：合并 3 次，最后重建的组有 8 个点。
5. 跑得快不改变量级。0.8 秒只说明这一个 n 在这台机器上常数小；n 变成 10⁶，O(n²) 的时间会变成约 100 倍，而 O(n log n) 只变成十几倍。量级要靠数步数来证明，不能靠一次计时。
