# 把难题拆到能检查

这是《循序渐进编程竞赛》的第三卷，写给读完[第二卷《让办法站得住》](../II/README.md)的你：会用前缀和、二分、动态规划、贪心、图上搜索、最短路、并查集、树、树状数组、线段树和堆，习惯先问“办法凭什么对”，也会写慢程序和自己的程序对拍。

第二卷的想法够用时，难处多在把它用对。这一卷的题，难处常常在前面一步：要先换一个看法，才看得出该用什么。有时要先摆出一个能逐条检查的答案；有时要换一张坐标纸、换一个回答顺序；有时要承认一个问题没有捷径，并说清楚为什么。每章讲一组工具，配一份完整程序 A，并把“为什么对”“为什么够快”写成能一句句检查的理由。没有合适真题的章，就用数据小到能手算的例子来讲。

读到“停笔”，先遮住后文，用纸笔把小例子算完，或者先写出自己的理由，再看章末“核对”。这一卷的证明比前两卷长，一天读一节、甚至半节都可以；读不懂的证明先跳过，做完后面的停笔再回来，常常就通了。

## 本卷怎么写代码

示例使用 **C++14**，约定与前两卷相同：写出 `std::` 前缀，不写 `using namespace std;`；输入输出用 `<cstdio>`；变量在声明时给初值；`if`、`for`、`while` 一律带花括号；区间从 0 开始，写作 `[left, right)`。

每章一份“**完整程序 A**”，可以直接编译运行；其余是**片段**，第一行注释交代它放在 `main` 内还是 `main` 外、哪些量已经算好。取模的题把模数写成常量，乘法前先想清楚会不会溢出 `long long`；用到浮点数的地方（例如第 8、22、24 章）会说明误差从哪里来、比较时留多少余地。第 29 章的交互程序每次输出后都要 `std::fflush(stdout)`，并配一份本地裁判，让你在自己的电脑上模拟另一方。

这一卷每章都写了对拍：慢程序通常是第二卷的直接办法，甚至是把所有可能都试一遍；用它在小数据上核对快程序，再说清快程序为什么在大数据上也对。

## 给带读者：怎样使用，检查到了哪里

这一卷不必按顺序读完。第 1 到 7 章最贴近比赛里常见的金组、白金组题，可以先读；第 8 到 13 章的图论、第 16 到 23 章的数学可以按需要挑着读；第 26 到 29 章讲算法本身，适合在做过一些题以后再读。第 8、11、12、30 章没有 USACO 题作主插入点，正文用能手算的小例子讲，同样有停笔和核对。表格里的白金组题都标了“带读”，建议大人陪着读题解，只要求说清关键的一步。

本卷有 30 章正文、1 份查阅页、1 份插入点目录和本导读。正文共 131 组“停笔”练习，查阅页另有 5 组，均附核对答案；30 份完整程序 A，每章一份；共 78 个代码块（查阅页 2 个）；30 章都写了对拍。各节表格一共登记 USACO 题 132 道：铜组 1、银组 16、金组 50、白金组 65，其中 65 道白金组题标为“带读”；另有 3 处“可以接着看”提到主插入点在别处的题。

代码核对使用 GCC 14.2.0，以 `-std=c++14 -Wall -Wextra -Werror -pedantic` 编译。78 个代码块全部重新从正文抽出编译：完整程序直接编译；片段放进补全了上下文的测试程序里编译，测试程序都包含片段的原文。完整程序 A 另用 `-fsanitize=undefined,address` 跑过样例，并和慢程序在随机小数据上对拍。正文里的 201 个相对链接已逐一核对能打开，全卷没有外部网址。

## 全卷的题从哪来

书里的竞赛题都来自 USACO（USA Computing Olympiad，美国计算机奥林匹克）的月赛。链接指向仓库里 `USACO/` 目录下的题面与题解，例如 `USACO/白金组/2019_2020/2020.02/P2.md` 是 2020 年 2 月白金组第二题。正文用自己的话重述题意，样例照原样给出。

四组一共 719 题。只用第二卷的想法说不清为什么对、为什么够快的 132 题登记在本卷，按章、节排在[插入点目录 III](插入点目录III.md)里；519 题见[插入点目录 II](../II/插入点目录II.md)；铜组另有 68 题已在第一卷正文里当例题讲过。每题只登记一次。
