# USACO 题解宪法

本目录重写根目录 USACO 的题解，目标：给后来者一份能读懂、能照着学的解题代码。
代码只使用 I 册 13 章正文与两份查阅页讲过的语法，避免过度设计。

本文件是根目录 `AGENTS.md` 的子宪法：继承根 AXIOM/LEMMA/SPEC 体系，只补充本目录的代码风格约束。

# AXIOM

1. [读者] 代码的第一读者是还没学会这些技巧的人，不是作者自己。任何一行都要能被一个学过本册 13 章的人读懂并复述。
   - 理由：语料的目的是"打通 USACO、启发后来者"，可读性就是验收标准。

2. [读者] 只使用教科书讲过的语法。教科书没讲的写法换成教科书里的等价写法。教科书没有等价写法时，宁可用更直白但稍长的写法。
   - 理由：读者只会这些；用了没讲的语法，读者就卡住。

3. [读者] 避免过度设计。抽象只在消除真实重复、且读者能一眼验证时使用；不为想象中的第二个使用方预建框架。
   - 理由：根 LEMMA 4。抽象要能指出当下的收益，指不出就删。

4. [读者] 输入按竞赛约定保证有效：代码不检查读取失败、不防御越界输入。这是竞赛与工业的明确分界。
   - 理由：检查会淹没解题主体；读者学的是算法，不是防御式 IO。教科书在竞赛语境同样省略。

5. [读者] 代码遵循 Mise-en-place 和 Polya 解题学组织，不抽走读者的脚手架。
   - 理由：让读者看到"怎么想到的"，而不是只看到"答案"。

6. [读者] 凡是一行代码的正确性需要读者逆向推导才能验证的地方，都要重写。
   - 理由：读者共享的是教科书，不是作者的心智模型。

7. [作者] 代码尽量不同函数间解耦，细粒度拆分语法单元。今后读者可以把一个代码在任何地方拆成前后两部分，然后前半部分自己写，后半部分用给定代码，依然可以编译执行成功。
   - 理由：读者可以用类似二分查找的方法，找出自己的编程失误。

# LEMMA

1. [AXIOM: 3] 每个结构体、每个辅助函数都要能说出它消除了什么真实重复、或隔离了什么真实职责。说不出就删掉。
   - 推理：根 LEMMA 4 要求抽象指出收益。

3. [AXIOM: 1, 5] 命名表达含义，不表达类型或实现。变量用题目里的词（cow、distance、milk），函数用动作（read、solve、print）。不写 `a0`/`i0`/`X0` 这类只有下标区分的名字，除非题目本身如此。
   - 推理：AXIOM 1 要求读者能复述，含义名好复述。

4. [AXIOM: 1, 6] 注释写"为什么"，不写"是什么"。`// 把 X 离散化` 是废话；`// 相等键哈希必须相同，所以用 (x,y) 一起算` 是解释。注释也不复述教科书已讲的语法。
   - 推理：AXIOM 6 只要求解释不显然处；复述基础语法是噪声。

5. [AXIOM: 2, 3] 一个概念只保留一种写法。读入、遍历、去重、最值、方向移动，各选一种教科书惯用写法，全库统一。
   - 推理：多种写法让读者多猜一次，AXIOM 1 要求少让读者猜。根 LEMMA 5 的例外清单精神：统一写法，不并存两套。

6. [AXIOM: 2] 除非性能受损，否则不用位运算、不用 `s += s` 这类聪明写法。确需时加注释。
   - 推理：AXIOM 2 禁止没讲的语法；这些写法对读者是黑箱。

# SPEC

1. [AXIOM: 2] 每个文件只使用本册 13 章正文与两份查阅页出现过的语法与标准库函数。出现新语法即违规。
   - 证明：198 个题解文件全部通过 `g++ -std=c++14 -O2 -Wall -Wextra -Werror` 编译（零警告），

   - 证明：重写时逐题删除了旧代码中无使用方的抽象（如 `make_unique` 包装、模板化的

     职责（读入、状态、搜索、输出），并以 oracle 对照验证删除后行为不变。

3. [AXIOM: 1, 6] 每个文件里，凡是一行代码的正确性不显然（需要推导）的地方都有注释；注释不解释教科书已讲的语法。
   - 证明：抽查各年度代表文件（含最复杂的 Dijkstra、并查集、Trie、LCA、位压缩状态），

# 01　先让一件小事做对

学校的图书角要贴一张小标签。你可以手写，也可以让程序输出。我们先不做复杂计算，只把这件小事做好。

## 先说清楚要得到什么

我们希望屏幕上出现两行：

```text
BOOK CORNER
12 books
```

下面是**完整程序 A**。先不用记住全部符号，找到里面的两句文字就好。

```cpp
#include <cstdio>

int main() {
    std::printf("BOOK CORNER\n");
    std::printf("12 books\n");
    return 0;
}
```

`std::printf` 是输出工具。双引号圈住要输出的文字；`\n` 不是要显示的两个普通字符，而是“换到下一行”。一条输出语句结束后，程序不会自动换行，所以要自己写它。

**停笔 1**　如果把第一句中的 `\n` 删掉，屏幕上会出现什么？把空格也写清楚。

### 有电脑时怎么试

把代码保存为 `main.cpp`，交给支持 C++14 的编译器。编译器先检查并把源代码变成可执行程序，再由你启动程序。使用带“编译运行”按钮的编辑器时，这两步可能合成一个按钮。

在装有 `g++` 的 Linux 或 macOS 终端，也可以输入：

```sh
g++ -std=c++14 -Wall -Wextra main.cpp -o main
./main
```

`.cpp` 文件是你写的文字，`main` 是编译得到的程序。改完文字后要重新编译；不然运行的可能还是旧版本。

## 暂时只认这几个位置

第一行 `#include <cstdio>` 准备本页要用的输入输出工具。`main` 是程序开始执行的函数；函数是有名字、能被调用的一段代码，后面再专门学。

`{` 和 `}` 圈出 `main` 里面的内容。执行从上往下走。两句 `printf` 完成后，`return 0;` 结束 `main`，把“正常结束”的状态交给运行程序的环境。这个 `0` 不会被显示出来。

代码中可以写 `//` 注释：从 `//` 到本行结束都是给人看的说明，不参与执行。输出语句和 `return` 语句后有分号；`#include` 后不加分号，函数最后的右花括号后也不用加。

书写代码的标点要用英文半角，例如 `;`，不能换成中文的 `；`。但注释和双引号里的文字可以包含中文，只要编辑器和显示环境支持相应编码。

**停笔 2**　朋友说：“程序输出完以后，还会把 `return 0` 的零打印出来。”你用上面哪一行代码反驳他？如果真的想多输出一个零，应增加什么？

## 把会变的数单独记下来

现在图书角有多少本书，经常要改。我们不把数量藏在文字里，而是给它一个名字。

下面是**片段**，可以替换程序 A 中的两句输出：

```cpp
int books = 12;
std::printf("%d books\n", books);
```

`int books = 12;` 创建一个用来保存整数的变量，名字叫 `books`，初始值是 `12`。`%d` 是格式中的一个位置：输出时，用后面的整数填进去。`%d` 不会原样显示。

变量名可以用字母、数字和下划线，但数字不能放在开头。语言还允许下划线开头，初学时先不用那类名字，避免碰到系统保留的名称。我们选字母开头、有含义的名字，例如 `book_count`。`books` 和 `Books` 大小写不同，是两个名字；`int` 这类语言已经占用的词不能再做变量名。

先有变量，才能使用。`int books;` 只创建变量，没有给这个局部整数初值；不能把里面“不知道是什么”的内容拿去算。写成 `int books = 0;` 则确定是零。

**停笔 3**　`books2`、`2books`、`book_count`、`int`，哪些可以做变量名？`int books = 0;` 和 `int books;` 有什么不同？

## 等号不是一道方程

数学里写“左边等于右边”；程序里的 `=` 是一项动作：先算右边，再把结果保存到左边。

**片段：**

```cpp
int books = 12;
books = books + 5;
books = books - 2;
std::printf("%d\n", books);
```

第二句不是问“12 是否等于 17”，而是取出现在的 `books`，加 5，再存回去。之后提到 `books`，用的就是新值。再次赋值时不再写 `int`；写 `int` 表示创建，而不是更新。

**停笔 4**　在纸上画一列 `books`。上面每执行完一条会改变它的语句，就写下一个值。最后输出多少？

## 让数量从输入进来

如果每次数量变化都要改代码，仍然不方便。让程序运行时接收数据。

下面是**完整程序 B**，输入两本书架的数量，输出总数。约定每个数量都是 0 到 1000 的整数，输入一定符合约定。学过判断后，我们还会检查是否真的读到了数据。

```cpp
#include <cstdio>

int main() {
    int upper = 0;
    int lower = 0;
    std::scanf("%d%d", &upper, &lower);
    int total = upper + lower;
    std::printf("Total: %d\n", total);
    return 0;
}
```

输入 `8 13`，输出 `Total: 21`。两个数也可以分在两行。`scanf` 读整数时，会跳过它前面的空格和换行。

这里的两个 `%d` 按顺序对应 `upper` 和 `lower`。输出时给 `printf` **值**；输入时给 `scanf` **保存位置**。`&upper` 表示“变量 `upper` 所在的位置”。如果只给现在的数值，读取工具就不知道把新值放在哪里。这也是输入中要写 `&` 的原因。

**停笔 5**　不运行，把程序 B 改成：输入“总书数”和“借出数”，输出剩下多少本。输入 `23 7` 时应输出什么？只改变量名够吗？

## 一张临时纸片的用处

两张标签写反了，需要交换两个变量的值。假设 `left` 是 4，`right` 是 9。

**片段：**

```cpp
int saved = left;
left = right;
right = saved;
```

先把旧的 `left` 暂存起来。若直接写 `left = right; right = left;`，第一步以后两个变量都是 9，旧的 4 已经没有地方找了。

标准库也提供 `std::swap(left, right)`；在程序开头加 `#include <utility>` 就可以用。这是“交换”这个动作，不是把一个数复制到另一个数。

**停笔 6**　依次执行三句交换代码，写出每步的 `left`、`right`、`saved`。再给那两句错误代码也做一遍。

## 核对与下一步

1. 没有换行也没有额外空格，所以输出一行 `BOOK CORNER12 books`，随后才换行。
2. `return` 不负责显示。可以增加 `std::printf("0\n");`。屏幕只会显示输出工具明确写出的内容。
3. `books2`、`book_count` 可以；数字不能打头，`int` 已有用途。带 `= 0` 的变量有确定初值，另一种不能直接拿来读。
4. 依次是 12、17、15，最后输出 15。
5. 还要把加法改成减法。输入 `23 7`，剩 16 本。变量可取名 `total`、`borrowed`、`remaining`，使每个名字和实际用途一致。
6. 正确三步依次得到 `(4,9,4)`、`(9,9,4)`、`(9,4,4)`。错误两步只会得到 `(9,9)`、`(9,9)`。

能区分“创建变量”“改变变量”“显示变量”，再读下一章。不必现在背出每个符号的正式名称。

# 02　数字也有使用条件

23 张贴纸，每页放 6 张。要几页？最后一页有几张？同一组数字，问题不同，算法也不同。本章先把这类计算说清楚，再看计算机为什么有时会算出意料外的结果。

## 分完得到多少，剩下多少

C++ 用 `+ - * /` 表示加、减、乘、除。两个整数做 `/`，只留下整数商；`%` 得到余数。

**片段：**

```cpp
int full_pages = 23 / 6;
int last_count = 23 % 6;
```

于是装满 3 页，剩下 5 张。要把全部贴纸装下，还要为这 5 张再开一页，一共 4 页。

若 `a` 是不小于 0 的整数，`b` 是正整数，总页数可以写成：

```cpp
int pages = a / b;
if (a % b != 0) {
    ++pages;
}
```

这是**片段**，`if` 表示“如果”，`!=` 表示“不等于”，`++pages` 表示给页数加 1，下一章会细讲。也常见 `(a + b - 1) / b`，但它要求 `a + b - 1` 没有超出整数范围。前一种写法不必先做这次加法。

除数不能是 0，`%` 也一样。`%` 只用于整数，不能拿来求两个 `double` 的余数。

**停笔 1**　把 0、6、7、23 张贴纸分别装入每页 6 张的册子。写出完整页数、余数、需要的总页数。零张贴纸需要几页？

### 以后遇到负数时

负数可以表示欠款或零度以下的温度。C++14 的整数除法会向 0 截去小数部分：`-8 / 3` 是 `-2`，不是 `-3`；`-8 % 3` 是 `-2`。可以用 `-8 = (-2) * 3 + (-2)` 核对。

余数为 0 或与被除数同号。因此判断奇数用 `x % 2 != 0`，不要只认 `x % 2 == 1`，负奇数的余数可能是 −1。最小的有符号整数除以 −1 还有结果超范围的问题，并不是每一组整数除法都安全。

## 需要小数时，先改变参加计算的数

`5 / 2` 的结果是 2。把这个结果放进 `double`，只是把已经算好的 2 保存成小数类型，丢掉的部分不会回来。

**完整程序 A：**

```cpp
#include <cstdio>

int main() {
    double first = 5 / 2;
    double second = 5.0 / 2;
    std::printf("%.1f %.1f\n", first, second);
    return 0;
}
```

输出 `2.0 2.5`。`%.1f` 表示按小数形式输出，保留小数点后一位。小数位数只影响显示，不会让内部计算变得更精确。

**停笔 2**　预测 `7 / 4`、`7.0 / 4`、`(7 / 4) * 1.0`。最后一个为什么不是 1.75？

## 机器不是用纸来记数字

计算机里，一个只能表示 0 或 1 的位置叫**位**，英文是 bit。常见计算机把 8 位合成一个**字节**，英文是 byte。

一位有 2 种状态，两位有 4 种，三位有 8 种；每加一位，组合数就翻一倍。8 位有 256 种组合。写成数学记号是 $2^8$，这里的 8 表示把八个 2 相乘，不是 2 乘 8。

同样一组位可以按不同规则解释。一个字节能用来表示 0 到 255，但不代表 C++ 的每个 `char` 都一定按这个范围解释。**类型**既说明使用方式，也限制能表示的值。

本书的运行环境使用 8 位字节、4 字节 `int`、8 字节 `long long` 和 `double`。C++ 不保证所有机器的 `int` 都是 4 字节；换环境时，可用 `sizeof(int)` 查字节数，用 `<limits>` 查范围。

| 类型 | 这里用来保存什么 | 必须知道的限制 |
|---|---|---|
| `int` | 一般整数，如本数、下标 | 本环境是 −2147483648 到 2147483647 |
| `long long` | 比 `int` 范围大的整数 | 本环境约在正负 9220000000000000000 之间，仍不是无限大 |
| `double` | 带小数的近似值 | 很多十进制小数无法精确保存 |
| `char` | 一个字节，也常用来保存 ASCII 字符 | `sizeof(char)` 总为 1；普通 `char` 是否带符号由环境决定 |
| `bool` | 是或否 | 两个值为 `true` 和 `false` |

**停笔 3**　学校有 800 本书、某次距离测量为 2.75 米、一个结果表示“是否借出”、单个英文字母。分别先选哪种类型？不要只因为一个类型范围大，就让所有数据都用它。

## 结果放得下，还要看计算时放不放得下

60000 乘 60000 是 3600000000，超过了本环境 `int` 的最大值。

下面是**对照片段**，第一行不应执行来“试试会得到几”：

```cpp
long long wrong = 60000 * 60000;
long long right = 1LL * 60000 * 60000;
```

第一行先用两个 `int` 相乘，已经超范围，然后才准备存入 `long long`。后面换大容器来不及了。有符号整数计算超范围是**未定义行为**，语言不保证它会变负、绕回、报错或崩溃中的哪一种。

`1LL` 是 `long long` 类型的整数 1。第二行从第一次乘法起就用较宽的类型计算。若 `a`、`b` 是 `int` 变量，也可写 `static_cast<long long>(a) * b`；这一长串表示“先把 `a` 转成 `long long`”。别处常见的 `(long long)a` 也有转换含义，本书使用前一种写法。

只考虑本章这些类型时：有 `double` 参加就按小数计算；否则有 `long long` 就按 `long long` 计算；`char`、`bool` 等小整数通常先提升为 `int`。后面遇到无符号整数时，不能只套这一张简化规则。

**停笔 4**　`long long result = a * b;` 一定安全吗？如果 `a` 和 `b` 都是 60000，应怎样改？如果它们更大，`long long` 是否永远够用？

## 小数不是小数点后想存多少位就存多少位

`double` 只有有限的存储位置，很多值只能存一个很接近的数。例如 `0.1 + 0.2` 与写出的 `0.3` 不一定得到完全相同的内部值。

**完整程序 B：**

```cpp
#include <cstdio>

int main() {
    std::printf("%.17f\n", 0.1 + 0.2);
    std::printf("%.17f\n", 0.3);
    return 0;
}
```

在常见的双精度环境里，两行末尾会有差异。少显示几位可能看不出差异，却不表示误差消失了。钱款若以“分”为单位就能准确表达，可以先用整数保存；测量值则常需要小数。不要无条件把所有小数换成整数，也不要指望提高输出位数能修好计算。

## 是与否，以及常见格式

`bool ready = true;` 表示“已准备好”。整数转成 `bool` 时，0 为假，任何非零值都为真；`bool` 转成整数时，假为 0，真为 1。

字符写成单引号，例如 `'R'`；一段文字用双引号，例如 `"READY"`。它们不是同一种东西。常见 ASCII 编码里 `'0'` 对应整数 48，`'a'` 对应 97；字符 `'7'` 也不等于整数 7。文本章再解释编码。

把常用格式放在一起查，不必背一大页：

| 数据 | `printf` 输出 | `scanf` 输入 |
|---|---|---|
| `int` | `%d` | `%d`，后接 `&变量` |
| `long long` | `%lld` | `%lld`，后接 `&变量` |
| `double` | `%f`，如 `%.2f` | `%lf`，后接 `&变量` |
| `char` | `%c` | `%c`，后接 `&变量` |

输出 `double` 时 `%f`、`%lf` 在 C++14 中都可用；输入则必须区分 `%f` 读 `float` 和 `%lf` 读 `double`。占位符与变量类型配错不是“自动帮你转换”。

**停笔 5**　`bool a = -3; bool b = 0;` 中谁真谁假？输入 `long long distance` 时能用 `%d` 吗？

## 把“改变自己”写短一点

**片段：**

```cpp
count += 3;
count -= 2;
count *= 4;
count /= 2;
count %= 5;
```

当左边是普通变量时，可以分别理解为 `count = count + 3` 等五种更新。`++count` 和 `count++` 都让它加 1，`--count` 和 `count--` 都让它减 1。

如果还要使用这个表达式的值，前后就不同：

```cpp
int count = 4;
int old = count++;
int next = ++count;
```

第二句把旧值 4 给 `old`，再让 `count` 变成 5；第三句先把 `count` 变成 6，再把 6 给 `next`。一条语句里不要把同一个变量的多次自增和其他读取挤在一起。分别写出来，容易检查，也避开求值次序的陷阱。

**停笔 6**　从 `int x = 10;` 开始，依次执行 `x -= 3; x *= 2; x %= 5;`。每步是什么？再分别解释“加一”和“用旧值后加一”的差别。

## 核对

1. 完整页数分别是 0、1、1、3；余数是 0、0、1、5；总页数是 0、1、2、4。没有贴纸不需要开空白页。
2. 分别是 1、1.75、1.0。最后一个先做了整数除法，只剩 1。
3. 依次选 `int`、`double`、`bool`、`char`。
4. 不安全。可写 `1LL * a * b` 或先转换一个操作数。还须确认乘积不超过 `long long` 范围；没有一种固定宽度类型能保存所有整数。
5. `a` 为真，`b` 为假；`long long` 输入用 `%lld`。
6. 依次是 7、14、4。单独成句时两种加一都一样；放在表达式里，后置使用旧值，前置使用新值。

# 03　让规则决定下一步

一台模型车每走一步都要决定：前方有障碍吗？电量够不够？重复走几次？程序用“判断”和“重复”把这些规则写出来。本章可以分几次读，每次读到一题就停下来做。

## 一个条件，只回答真或假

电量百分数记在 `battery` 里，`battery < 20` 问的是“电量是否小于 20”。条件成立得到 `true`，不成立得到 `false`。

| 想问什么 | 写法 |
|---|---|
| 相等、不相等 | `==`、`!=` |
| 小于、不大于 | `<`、`<=` |
| 大于、不小于 | `>`、`>=` |

`battery = 20` 会把变量改成 20；`battery == 20` 才是在提问。混写时，程序可能仍能编译，却做了完全不同的事。

**停笔 1**　电量依次是 19、20、21 时，`battery < 20` 与 `battery <= 20` 各得到什么？找出两者答案不同的那一格。

## 只有一种情况成立时才做

**完整程序 A：**输入 0 到 100 的电量，低于 20 输出 `CHARGE`，否则输出 `READY`。

```cpp
#include <cstdio>

int main() {
    int battery = 0;
    if (std::scanf("%d", &battery) != 1) {
        return 1;
    }
    if (battery < 20) {
        std::printf("CHARGE\n");
    } else {
        std::printf("READY\n");
    }
    return 0;
}
```

`if (条件)` 后的大括号里是条件成立时的动作，`else` 后是否则要做的动作。一次只选一边。如果不需要“否则”，可以把整个 `else` 分支省掉。

这里也开始检查输入。`scanf` 返回成功存入了几个值；要读一个整数，却没有返回 1，就结束程序，`return 1` 表示没有正常完成。不要在没读到数据时继续给出看似正常的答案。后面查阅页会讲更完整的失败情况。

有些代码会在分支只有一条语句时省略花括号。本书一直写上，避免后来加了一句，却忘了它其实不在分支里。程序排版整齐不等于含义正确，边界由括号决定。

**停笔 2**　如果把程序中的第二个 `if` 改成 `if (battery = 20)`，变量发生什么变化？它还会按“低电量”判断吗？

## 条件可以组合，也会按顺序停止

模型车能出发，需要电量不少于 20 **并且**前方没有障碍：

**片段，假设两个变量已有值：**

```cpp
bool can_move = battery >= 20 && !blocked;
```

`&&` 是“并且”，`||` 是“或者”，`!` 是“不是”。`!blocked` 表示“没有被挡住”。

`&&` 从左边开始：左边为假，整体已经是假，右边不再计算。`||` 的左边为真，整体已经是真，也不用算右边。这叫**短路**。

例如 `pieces != 0 && total / pieces > 5`，先排除 `pieces` 为零的情况，才做右边的除法。若把两边交换，零作除数的危险就回来了。

**停笔 3**　电量 60、前方有障碍，`can_move` 是什么？`pieces` 为 0 时，以上条件会做除法吗？为什么不能把两项随便交换？

### 不用猜计算次序

常用运算符中，从先到后大致是：

```text
! → * / % → + - → < <= > >= → == != → && → ||
```

同一组在这张表里优先级相同。比较复杂时用括号写清楚，不用为了少一对括号考验读者。

要表达“温度在 10 到 30 之间，含两端”，写 `10 <= temperature && temperature <= 30`。不能照抄数学里的连写形式 `10 <= temperature <= 30`；那会先得到真假，再拿 0 或 1 与 30 比较。

`bool` 还能转成 0 或 1。检查两只开关“恰有一只打开”，可以比较 `(left_on != right_on)`，也可以数一数：

```cpp
int on_count = 0;
if (left_on) {
    ++on_count;
}
if (right_on) {
    ++on_count;
}
bool exactly_one = on_count == 1;
```

这是**片段**。一个办法直接问关系，另一个保存数量；以后条件多起来，计数的办法更容易扩展。

**停笔 4**　两只开关都关、左开右关、左关右开、都开，分别列出 `on_count` 和 `exactly_one`。再写出“只要有一只开就亮灯”的条件，比较它与“恰好一只”有什么不同。

## 多种情况按哪一种处理

传感器温度高于 30 提醒降温，低于 10 提醒保温，其余正常。可以写成**片段**：

```cpp
if (temperature > 30) {
    std::printf("COOL\n");
} else if (temperature < 10) {
    std::printf("WARM\n");
} else {
    std::printf("NORMAL\n");
}
```

这一串从上往下检查，选第一个成立的分支，其余跳过。若两个条件可能同时成立，顺序就会改变结果。两个独立的 `if` 则可能都执行，不能随便拿来替换 `if ... else if`。

分支也可以放在另一个分支里面。例如先看电量是否足够，够了以后再看路是否被挡住。这叫**嵌套**。每层判断回答一个明确的问题，不要为了用嵌套而多绕一圈。

还有一条容易忽略的规则：变量只能在它所在的范围里使用。**片段：**

```cpp
int wait = 0;
if (blocked) {
    wait = 5;
}
std::printf("%d\n", wait);
```

需要在后面用 `wait`，就先在外面创建。若改成在分支里写 `int wait = 5;`，那是新建一个里面的变量；走出大括号，那个名字就不能用了，也没有改外面的同名变量。

**停笔 5**　在纸上把程序里的 `wait` 换成分支内声明，解释为什么不对。“创建一个变量”和“修改已有变量”，差在哪个词？

## 按编号选动作

当条件都是“这个整数等于几”，可用 `switch`。

**完整程序 B：**输入 0 到 3 的模式号，0 停止，1 或 2 慢速，3 快速；其他整数输出 `UNKNOWN`。

```cpp
#include <cstdio>

int main() {
    int mode = 0;
    if (std::scanf("%d", &mode) != 1) {
        return 1;
    }
    switch (mode) {
        case 0:
            std::printf("STOP\n");
            break;
        case 1:
        case 2:
            std::printf("SLOW\n");
            break;
        case 3:
            std::printf("FAST\n");
            break;
        default:
            std::printf("UNKNOWN\n");
            break;
    }
    return 0;
}
```

`case` 后是固定的整数值，多个标号可共用动作。`break` 让执行离开这个 `switch`。如果漏写，程序可能继续走进后面的分支，**不会**自动在下一个 `case` 停住。`default` 处理没有匹配项的情况。`switch` 不用于直接比较 `std::string` 或判断一个小数落在哪个范围。

如果只是从两个值里选一个，三元表达式更短：`battery < 20 ? 5 : 0`，条件成立取 5，否则取 0。比如 `int wait = battery < 20 ? 5 : 0;`。不要把很长的多层判断挤成一串问号。

**停笔 6**　输入 1，删掉 `SLOW` 后面的 `break`，输出会怎样？三元表达式里的条件为假时，取问号后面还是冒号后面的值？

## 从“判断一次”到“每次都判断”

`if` 判断一次，`while` 每轮开始前再判断。下面**完整程序 C**倒数 3、2、1，然后输出 `GO`。

```cpp
#include <cstdio>

int main() {
    int left = 3;
    while (left > 0) {
        std::printf("%d\n", left);
        --left;
    }
    std::printf("GO\n");
    return 0;
}
```

每轮先看 `left > 0`，成立才执行里面的两句，然后回到条件处。一定要说清三件事：开始是什么值；什么情况下继续；每轮如何朝停止前进。

若忘记 `--left`，条件永远为真。程序不会看见“打印过 3 了”就替你减一。

**停笔 7**　把初值改成 0，循环体执行几次？把 `--left` 删掉后为什么停不下来？不要真的运行不停输出的版本。

## 先做一次，还是一次都可以不做

`do-while` 把判断放在后面，所以至少执行一次。下面是**完整程序 D**，读入一次测量值，数值为负就再读；约定最终会有一个非负值。

```cpp
#include <cstdio>

int main() {
    int reading = 0;
    do {
        if (std::scanf("%d", &reading) != 1) {
            return 1;
        }
    } while (reading < 0);
    std::printf("%d\n", reading);
    return 0;
}
```

注意末尾 `while (...)` 后有分号。输入 `-2 -1 8` 时，输出 8；第一次读到 8，则只读一次。**什么时候第一次读取**，正是这里不能只看初值是否为负的原因。

如果确定要做若干次，常用三段式 `for`。**片段：**

```cpp
for (int step = 0; step < 4; ++step) {
    std::printf("step %d\n", step);
}
```

先创建 `step = 0`，每轮先看 `step < 4`，执行循环体，最后做 `++step`，再检查下一轮。打印的编号为 0、1、2、3，一共四次。`step` 的名字在这个 `for` 结束后不能继续用。

**停笔 8**　这段 `for` 中，把条件改成 `step <= 4` 会多出哪一次？`while`、`do-while`、`for` 中，哪一个保证循环体至少执行一次？

2. 电量被改成 20，赋值表达式的值也是 20，非零当作真，总会输出 `CHARGE`。这不是电量判断。
3. 不能出发；不会做除法。换顺序后，会先做可能除零的计算。
4. 数量依次为 0、1、1、2；“恰好一只”依次为假、真、真、假；“至少一只”是 `left_on || right_on`，两只都开时也成立。
5. `int` 表示新建。应在外面创建，在里面只写 `wait = 5;`。同名不等于同一个变量。
6. 先输出 `SLOW`，再输出 `FAST`，到下一个 `break` 才离开。三元条件为假取冒号后面的值。
7. 初值为 0 时执行零次。删掉更新后 `left` 始终为 3，条件永远为真。
8. 多出 `step == 4`。只有 `do-while` 保证至少一次；另外两种开始时就可能不执行。

# 04　一次只看一个数

运动会上，老师依次报出每次跳远的距离。你手里只有一张小纸片，不想抄下全部记录。要找最远的一次，需要记住什么？如果还要知道它出现几次呢？

这一章练的不是更多循环写法，而是：**每看一个新数，怎样改好手里的记录。**

## 暂时领先的答案

依次读到 132、145、139、145。先把 132 记为“目前最远”。读到 145，更新；读到 139，不动；最后又读到 145，最远距离没变。

“目前最远”不是猜测，而是已经看过的那些数中的最大值。看完全部数据，它就成了最终最大值。每轮前后都能说清它的含义，程序就容易检查。

**停笔 1**　依次读到 −7、−12、−3。如果开始把“目前最大”设成 0，会得到什么错答案？为什么从第一条记录开始更合适？

## 最大值与出现次数一起维护

遇到更大的值，旧纪录的次数就没有用了，改成 1；遇到相同值，次数加 1；更小则两者都不变。

**完整程序 A：**先输入 `n`，再输入 `n` 个整数。约定 `1 <= n <= 10000`，每个整数在 `int` 范围内。输出最大值及其次数。

```cpp
#include <cstdio>

int main() {
    int n = 0;
    if (std::scanf("%d", &n) != 1 || n < 1 || n > 10000) {
        return 1;
    }
    int best = 0;
    if (std::scanf("%d", &best) != 1) {
        return 1;
    }
    int times = 1;
    for (int i = 1; i < n; ++i) {
        int value = 0;
        if (std::scanf("%d", &value) != 1) {
            return 1;
        }
        if (value > best) {
            best = value;
            times = 1;
        } else if (value == best) {
            ++times;
        }
    }
    std::printf("%d %d\n", best, times);
    return 0;
}
```

第一条记录已经在循环前读过，所以循环从 `i = 1` 开始，再读 `n - 1` 条。只读一个数时，循环一次也不执行，次数仍是 1。

**停笔 2**　输入为 `5` 和 `8 8 5 10 10`。每次读完后，写下 `best` 与 `times`。若遇到新纪录时忘了把次数改成 1，最后会错成多少？

### 想查类型的边界怎么办

有时程序不是从第一条记录开始，可用 `<limits>` 查类型范围。**查阅片段：**

```cpp
std::numeric_limits<int>::lowest();
std::numeric_limits<int>::max();
```

前者是最小可表示值，后者是最大可表示值。需要先 `#include <limits>`。对整数，`min()` 与 `lowest()` 相同；对 `double`，`min()` 却是最小的正的正规值，不是“最负的数”。要找最小值边界，用 `lowest()` 更不容易混淆。

边界值也是合法数据，不能随便把它当成“不存在”。空数据没有最大值，应另行说明“没有数据”，而不是输出一个类型边界假装是答案。

## 第二个位置到底允许什么

“第二大”有两种常见意思。记录是 9、9、4，按从大到小排好后取第二个，得到 9；要求“比最大值小的最大值”，则是 4。先说明题意，代码才能有对错。

下面采用**允许相同数值占两个位置**的意思。已读过前两个数，并整理好 `first >= second` 后，每个新数这样处理：

**片段：**

```cpp
if (value > first) {
    second = first;
    first = value;
} else if (value > second) {
    second = value;
}
```

新数成为第一名时，要先把旧第一名放到第二名。如果先覆盖 `first`，旧值就丢了。

**完整程序 B：**输入 `2 <= n <= 10000` 及 `n` 个 `int`，输出排在前两个位置的数。

```cpp
#include <cstdio>
#include <utility>

int main() {
    int n = 0;
    if (std::scanf("%d", &n) != 1 || n < 2 || n > 10000) {
        return 1;
    }
    int first = 0;
    int second = 0;
    if (std::scanf("%d%d", &first, &second) != 2) {
        return 1;
    }
    if (first < second) {
        std::swap(first, second);
    }
    for (int i = 2; i < n; ++i) {
        int value = 0;
        if (std::scanf("%d", &value) != 1) {
            return 1;
        }
        if (value > first) {
            second = first;
            first = value;
        } else if (value > second) {
            second = value;
        }
    }
    std::printf("%d %d\n", first, second);
    return 0;
}
```

**停笔 3**　对 6、2、8、8 逐步更新两名。若题目改成“两个不同的数值”，哪一步不应照原样处理？全部数都相同时，还存在第二个不同数值吗？

## 每轮拿走一点，问题就变小一点

整数 406 的最后一位是 `406 % 10`，去掉最后一位是 `406 / 10`。重复这两个动作，可以从右向左读出十进制各位。

**完整程序 C：**输入 0 到 1000000000 的整数，输出各位数字之和。

```cpp
#include <cstdio>

int main() {
    int remaining = 0;
    if (std::scanf("%d", &remaining) != 1 || remaining < 0 || remaining > 1000000000) {
        return 1;
    }
    int sum = 0;
    do {
        int digit = remaining % 10;
        sum += digit;
        remaining /= 10;
    } while (remaining != 0);
    std::printf("%d\n", sum);
    return 0;
}
```

这里用 `do-while`，让输入 0 也按一个数字处理一次。`remaining` 表示还没处理的部分，`sum` 表示已经处理的那些数字之和。每轮少掉一位，最终会停。

**停笔 4**　处理 406 时，按轮写出 `digit`、更新后的 `remaining` 和 `sum`。最后一位是 0 时，程序会不会误以为整件事已经做完？

重复更新不限于取数位。比如把待分发的 25 份材料每轮分走一半，剩下不足一半时也要写清规则。下面**片段**规定每轮留下整数商 `waiting / 2`：

```cpp
int waiting = 25;
while (waiting > 0) {
    std::printf("%d\n", waiting);
    int next = waiting / 2;
    waiting = next;
}
```

先根据旧状态算 `next`，再整体更新。若下一个状态依赖几个旧变量，别在旧值还没用完时就覆盖它。循环能否结束，要按自己的更新规则检查，不能只凭“总会越来越小吧”。

## 有的记录跳过，有的让工作结束

`continue` 跳过本轮余下动作；`break` 立刻离开最近的一层循环。

下面是**完整程序 D**。最多读 6 个数；负数是无效记录，跳过；999 表示提前结束；其余约定在 0 到 100 之间，计入总和。

```cpp
#include <cstdio>

int main() {
    int sum = 0;
    for (int i = 0; i < 6; ++i) {
        int value = 0;
        if (std::scanf("%d", &value) != 1) {
            return 1;
        }
        if (value == 999) {
            break;
        }
        if (value < 0) {
            continue;
        }
        sum += value;
    }
    std::printf("%d\n", sum);
    return 0;
}
```

在三段式 `for` 里，`continue` 后仍会执行末尾更新 `++i`，再检查条件。`while` 的更新若写在循环体末尾，却被 `continue` 跳过，可能再也到不了停止处。

`break` 若写在 `switch` 里面，离开的是最近的 `switch`，不一定是外面的循环。看的是实际嵌套位置，而不是单词周围的排版。

## 把所有小方案逐一试过

有 3 种底色、4 种图案，底色编号 1 到 3，图案编号 1 到 4。下面是**完整程序 E**，输出所有编号和为 5 的搭配。

```cpp
#include <cstdio>

int main() {
    for (int color = 1; color <= 3; ++color) {
        for (int pattern = 1; pattern <= 4; ++pattern) {
            if (color + pattern == 5) {
                std::printf("%d %d\n", color, pattern);
            }
        }
    }
    return 0;
}
```

外层选一种底色，内层把四种图案全部试过，再换底色。一共检查 3 乘 4，也就是 12 次。这种逐个尝试候选方案的办法叫**枚举**。

若只要每种底色找到第一个合适图案，可以在输出后加 `break`，只停内层，外层还会继续。若每种有 10000 个候选，两层就可能检查一亿次；程序快，也不是可以无限做无用工作。

# 05　把一排数据存起来

有些问题只要记住“目前最大值”。有些却要回头看：先算全班平均身高，再找出哪些人高于平均值。如果输入只能读一次，就得先把数据保存下来。

## 一排同类型的位置

下面是**片段**：

```cpp
int heights[4] = {142, 138, 145, 141};
```

这创建一个有 4 个 `int` 元素的**数组**。元素在内存中连续排列。它们的位置编号从 **0** 开始，依次是 0、1、2、3；编号也叫**下标**。

`heights[0]` 是第一项，`heights[3]` 是第四项。`heights[4]` 已经出了这一排，不是“最后一项”。语言不会因为你只多写了 1 就替你纠正，普通下标访问不自动检查边界。

越界属于未定义行为：可能表面正常，可能破坏别的数据，也可能崩溃。一个程序没有崩溃，不能证明下标写对了。

**停笔 1**　画 4 个格子，格子上方写下标，下方写数据。第三个人的身高用哪个下标？若题目说“第 k 个人”，程序下标应怎样换算？

## 创建以后，里面是什么

**对照片段：**

```cpp
int a[4] = {7, 2};
int b[4] = {};
int c[4];
```

`a` 的前两项是 7、2，其余补零；`b` 全是零；函数里面没有初始化的局部数组 `c`，其整数元素的值不确定，不能直接读来计算。先创建再通过循环逐项赋值也可以。

原生数组的长度在创建后固定。标准 C++14 的这种数组长度要是编译时确定的常量，例如 `int a[4];`。输入一个 `n` 再写 `int a[n];` 不是标准 C++14 的做法，有些编译器接受也不代表到处能用。

**停笔 2**　分别写出 `a` 和 `b` 的四项。对 `c` 写“应该也是零”为什么不可靠？

## 运行时才知道有多少项

标准库的 `vector` 也能保存一排同类型的数据，而且长度可以变化。

**创建片段，需要 `<vector>`：**

```cpp
std::vector<int> empty;
std::vector<int> a(4);
std::vector<int> b(4, 7);
std::vector<int> c{4, 7};
std::vector<int> copy = c;
```

`empty` 没有元素；`a` 有四个零；`b` 有四个 7；`c` 只有两个元素 4 和 7。圆括号与花括号在这里意思不同。`copy` 拷贝了 `c` 的内容，之后改 `copy[0]` 不会改 `c[0]`。

`vector<int> a(n)` 中 `n` 可以来自输入。对 `int`，新建的这些元素初值为零；其他类型按各自初始化规则来，不能概括成“一切类型都填数字零”。

**停笔 3**　`std::vector<int> x(3, 8);` 与 `std::vector<int> y{3, 8};` 各有几项？分别是什么？修改 `copy` 为什么不应影响原来的序列？

### 大数组为什么要小心

很大的局部原生数组常被放在容量有限的调用栈区域，可能超出限制。放到函数外成为全局数组，会换一种存储位置，而且未显式初始化的全局整数数组会初始化为零；但它仍然受总内存限制，也会被多个函数共同使用。

`vector` 对象可以留在函数内，它的元素通常从动态存储区申请，适合长度由输入决定的数据。它也会耗尽内存，**不是大小不受限制**。知道要保存多少，就创建合适的长度，不要为了避开问题盲目开一个巨大的全局数组。

## 先统计，再回头找

**完整程序 A：**输入 `1 <= n <= 1000` 及 `n` 个 0 到 100 的读数。先求平均数，再输出严格高于平均数的读数位置，位置按 1 开始计。一个也没有时只输出换行。

```cpp
#include <cstdio>
#include <vector>

int main() {
    int n = 0;
    if (std::scanf("%d", &n) != 1 || n < 1 || n > 1000) {
        return 1;
    }
    std::vector<int> readings(n);
    int sum = 0;
    for (int i = 0; i < n; ++i) {
        if (std::scanf("%d", &readings[i]) != 1) {
            return 1;
        }
        sum += readings[i];
    }
    for (int i = 0; i < n; ++i) {
        if (readings[i] * n > sum) {
            std::printf("%d ", i + 1);
        }
    }
    std::printf("\n");
    return 0;
}
```

平均数是 `sum / n`。为了不先做小数除法，这里比较 `readings[i] * n > sum`；`n` 为正，比较两边同乘 `n` 后，大小方向不变。按输入上限，乘积最多 100000，`int` 放得下。

读第一个数时还不知道总和，不能确定它是否高于最终平均数。这就是需要保存整排数据的原因，不是因为“数组看起来更高级”。

**停笔 4**　输入 `4` 和 `2 8 5 9`，圈出应输出的位置。若输入是 `5 5 5 5`，为什么不能随便输出一个最大值的位置？

## 长度可以变，但不是随便访问

下面是**操作片段**，从空 `vector<int> v` 开始看：

```cpp
v.emplace_back(6);
v.emplace_back(9);
v.pop_back();
v.resize(4);
v.resize(2);
v.clear();
```

尾部添加叫 `emplace_back`；`pop_back` 删掉末项但不返回它；`resize` 改元素数量，增加的 `int` 元素补零，缩短就删去后面的元素；`clear` 删掉全部元素。

用 `v.size()` 查元素数量，用 `v.empty()` 问是否为空。`v.back()` 访问最后一项，但空序列没有最后一项，不能调用它；空序列也不能 `pop_back()`。`v[i]` 与原生数组一样，要求下标有效。

**停笔 5**　每执行完上面一句，写出 `v` 的内容。哪一步之后不能调用 `back()`？最后两项“消失”和“变成零”是一回事吗？

### 长度减一，不一定会变成 −1

`size()` 返回无符号整数类型，常用名称是 `std::size_t`。无符号数没有负值。空序列的 `v.size() - 1` 不会是 −1，而会绕成一个很大的正数。

不要这样写反向循环：

```cpp
for (int i = v.size() - 1; i >= 0; --i) {
    std::printf("%d\n", v[i]);
}
```

这是**有风险的片段**，问题在于“先做了无符号减法”。在本书长度最多 1000、能放进 `int` 的题目里，先转换，再减一：

```cpp
int length = static_cast<int>(v.size());
for (int i = length - 1; i >= 0; --i) {
    std::printf("%d\n", v[i]);
}
```

这是**替换片段**。若实际长度可能超过 `int` 范围，不能不检查就转换。只想看每一个元素、根本不需要下标时，后面会学更简单的范围 `for`。

`vector<bool>` 比较特殊，元素按位压缩，访问得到的也不是普通的 `bool&`。不能简单认定它一定更快或更慢。初学时要保存一排小标记，可选 `vector<char>`，每项一个字节，0 表示否、1 表示是。

**停笔 6**　空 `vector` 下，`length` 是多少？`length - 1` 是多少？循环体会执行吗？为什么必须先转换再减一？

## 不只是按顺序记，也可以反着查

4 台设备各拿到一个储物柜，柜号恰好是 1 到 4 的一个排列。按设备顺序输入柜号为 `3 1 4 2`。我们想按柜号知道是谁在用。

**完整程序 B：**

```cpp
#include <cstdio>
#include <vector>

int main() {
    int n = 0;
    if (std::scanf("%d", &n) != 1 || n < 1 || n > 1000) {
        return 1;
    }
    std::vector<int> owner(n + 1);
    for (int device = 1; device <= n; ++device) {
        int locker = 0;
        if (std::scanf("%d", &locker) != 1 || locker < 1 || locker > n) {
            return 1;
        }
        owner[locker] = device;
    }
    for (int locker = 1; locker <= n; ++locker) {
        std::printf("%d\n", owner[locker]);
    }
    return 0;
}
```

题目保证柜号不重复，不是让程序解决多人抢同一个柜子的情况。这里故意多开一个位置，0 号不用，让柜号可直接作下标；因此长度是 `n + 1`，最大下标才到 `n`。

数组表示的不是“输入的原样复印”，而是“每个柜子的使用者”。数据放在哪个位置，由以后要问的问题决定。

**停笔 7**　为示例画出 `owner[1]` 到 `owner[4]`。若少开一个位置，只写 `owner(n)`，哪个柜号会越界？

2. `a` 为 7、2、0、0；`b` 为四个零。局部 `c` 没有提供初值，不能假定为零。
3. `x` 三项都是 8；`y` 两项为 3、8。拷贝得到各自拥有内容的序列，不是两个名字共享一排元素。
4. 平均数为 6，输出位置 2、4。全部为 5 时没有严格高于平均数的项；“找最大”与题目不是一回事。
5. 依次为 `[6]`、`[6,9]`、`[6]`、`[6,0,0,0]`、`[6,0]`、`[]`。最后为空，不能取末项。缩短删掉了元素，不是把原位置保留为零。
6. 长度为 0，减一为 −1，循环体执行零次。转换放在后面，先发生的无符号减法就无法被撤销。
7. 依次为 2、4、1、3。柜号 `n` 会访问 `owner[n]`，长度为 `n` 时该位置不存在。

# 06　文本是一种数据

现在不只保存“12 本书”，还要保存一本书的名称。名称不是一个整数，也不一定只有一个字。先把“一个字节”“一个字符”和“一段文字”分开，后面的操作就不会混在一起。

## `'7'` 不等于 `7`

ASCII 是一套把字符与整数对应起来的编码，包含 128 个编码值。常见的英文字母、数字和符号在里面各有编号：`'A'` 是 65，`'a'` 是 97，`'0'` 是 48。

**片段：**

```cpp
char mark = '7';
int digit = mark - '0';
```

ASCII 的十个数字字符连续排列，`'7' - '0'` 得到数字 7。前提是已经知道 `mark` 在 `'0'` 到 `'9'` 之间，不能把任意一个字节都这样转换。

单引号表示一个字符字面量，例如 `'R'`；双引号表示字符串字面量，例如 `"ROBOT"`。在普通 `char` 中放一个英文字母很方便，但不能把一个 UTF-8 汉字硬装进一个 `char`。

**停笔 1**　ASCII 中 `'3'` 的编号是多少？`'3' + 1` 作为一个整数是多少？这个编号又对应哪个数字字符？

## 为什么中文不能一个字节装一个字

ASCII 够表示常见英文符号，不够表示世界上的文字。Unicode 给许多文字和符号规定统一的编码点；UTF-8 则规定把这些编码点怎样写成字节。

不必现在记住编码细节，先认识长度不同：

| UTF-8 文本中的例子 | 占用字节数 |
|---|---|
| `A` | 1 |
| `é` | 2 |
| `中` | 3 |
| `𠀀` | 4 |

很多常用汉字是三个字节，但不是所有汉字都恰好三个字节。一个看起来完整的文字单位还可能涉及多个编码点。因此“字节数”“编码点数”“屏幕上看见几个字”也不能总画等号。

本书文件使用 UTF-8。按字节拿出中文的一小段，可能截断一个字。后面 `string` 的下标、长度和子串，都是按它保存的 `char` 元素操作，不会自动替你识别完整汉字。

**停笔 2**　按 UTF-8 保存 `A中B`，一共几个字节？只取最前面的两个字节，是否能得到一段完整的 `A中`？

## 先用适合保存文字的盒子

`std::string` 保存可变长度的字符串，需要 `<string>`。下面是**创建与操作片段**：

```cpp
std::string title;
std::string code = "R2";
std::string copy = code;
std::string label = code + " ready";
```

`title` 初始为空串，长度为零，不是一串可随意读取的零字符。`copy` 有自己的内容；`+` 把字符串连接起来，只要表达式中有适合的 `string` 操作数即可。两个字符串字面量不能直接靠 `+` 相加，例如 `"R" + "2"` 不是这里的拼接写法。

`code.size()` 查 `char` 元素个数，UTF-8 文本中就是字节数。`code[0]` 访问第一项；`code.empty()` 判断是否为空；`code.clear()` 清空。长度可变也不意味着 `code[code.size()]` 是一个能任意修改的额外字符位置。

**停笔 3**　`code` 是 `"R2"`，执行 `copy = code; copy[0] = 'B';` 后，两个字符串分别是什么？空串可以直接改 `title[0]` 吗？

## 一次读一个词，还是读整行

**完整程序 A：**读入一个不含空白的英文编号，再读下一整行说明，输出二者。输入示例为两行：第一行 `R2`，第二行 `turn left slowly`。

```cpp
#include <iostream>
#include <limits>
#include <string>

int main() {
    std::string code;
    std::string note;
    if (!(std::cin >> code)) {
        return 1;
    }
    std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
    if (!std::getline(std::cin, note)) {
        return 1;
    }
    std::cout << code << ": " << note << '\n';
    return 0;
}
```

`std::cin >> code` 跳过前导空白，读取一个词，遇到空白就停；`std::getline` 读到换行，保留行内空格，换行本身不存入字符串。

读完编号时，行末换行还在输入里。这里的 `ignore` 丢弃该行余下部分，直到并包括换行，再从下一行读说明。它不是所有程序都要照抄的咒语：如果一开始就要读整行，直接 `getline`；如果同一行余下内容也是数据，就不能随便丢弃。

`std::cout` 是这里的输出工具，用 `<<` 依次接上要输出的内容；`std::cin` 用 `>>` 接上要保存到的变量。这套工具知道 `string` 怎样读写，不用为字符串指定一个固定缓冲区。

**停笔 4**　删掉 `ignore`，通常会读到怎样的 `note`？若直接用 `cin >> note`，能否读到 `turn left slowly` 的全部？

## 取一小段，或比较先后

**片段：**

```cpp
std::string code = "BOX-314";
std::string number = code.substr(4, 3);
```

`substr(起点, 数量)` 从下标 4 开始取三项，得到 `"314"`。第二个参数是数量，不是结束下标。省略数量会取到末尾；数量超过剩余长度时，只取剩下的部分。起点等于长度会得到空串，超过长度则抛出异常，不能当成普通越界读取。

两个 `string` 可以用 `==` 判断相同，用 `<` 等按**字典序**比较：从左到右找第一处不同，比较那里的字符；若一直相同直到一边结束，短的排前面。在本书的 ASCII 例子里，按 ASCII 编码值比较，不按长度、数值或中文拼音比较。

例如 `"B12"` 排在 `"B3"` 前面，因为 `'1' < '3'`；这不是把 12 与 3 当成整数。`vector` 的关系比较也采用同样的逐项思路，只是比较的元素不一定是字符。

**停笔 5**　比较 `"AB"` 和 `"ABA"`、`"R10"` 和 `"R2"`。对 `"BOX-314"`，`substr(4, 2)` 取到什么？

## 看懂旧接口：末尾放一个“到这里结束”

另一种文本表示方法是字符数组，最后以空字符 `\0` 结束，叫 **C 风格字符串**。空字符的值为 0，不是字符 `'0'`，也不是空格。

**片段：**

```cpp
char word[4] = "CAT";
```

四个位置依次保存 `'C'`、`'A'`、`'T'`、`'\0'`。这不是四个可见字母。`strlen` 从开头数到第一个空字符之前，需要 `<cstring>`；数组的容量则包括那个空字符所占的位置。

**完整程序 B：**从一个词里统计字节数，约定输入词最多 15 个字节。

```cpp
#include <cstdio>
#include <cstring>
#include <string>

int main() {
    char buffer[16] = {};
    if (std::scanf("%15s", buffer) != 1) {
        return 1;
    }
    std::size_t length = 0;
    while (buffer[length] != '\0') {
        ++length;
    }
    std::string word = buffer;
    std::printf("%zu %zu %s\n", length, std::strlen(buffer), word.c_str());
    return 0;
}
```

`%15s` 最多存 15 个非空白字节，再补一个空字符，所以数组至少要有 16 个位置。没有宽度的 `%s` 可能把长输入写出数组外。宽度只防止写爆数组，不负责判断输入是否被截断；约定之外的长词还会留下未读取的部分。

这里不写 `&buffer`：在这个调用中，数组名会提供首元素的地址，读取工具已经能找到保存位置。它与前面给单个整数写 `&value` 的目的相同。

`string` 可以由有效的 C 风格字符串创建，也可赋值。反过来，用 `word.c_str()` 得到只读的、以空字符结尾的表示，可交给 `printf("%s", ...)`。不能把 `std::string` 对象直接交给 `%s`；也不要通过 `c_str()` 返回的指针去改字符串。

两个字符数组不能靠 `==` 或 `<` 实现内容比较；那样没有在逐个比较文本。先转成 `string`，或使用合适的 C 字符串比较函数。用字符串关系运算时，至少让一边成为 `string`。

**停笔 6**　`char name[6]` 用 `%s` 输入，最大安全宽度是多少？`"CAT"` 的数组容量与文字长度分别是多少？没有空字符的字符数组可以直接交给 `strlen` 吗？

## 只在适用的文字范围里转换大小写

`<cctype>` 提供这些工具。它们的分类结果为零或非零，不保证“真”恰好是 1。

| 工具 | 用途 |
|---|---|
| `std::islower`、`std::isupper` | 是否小写、是否大写 |
| `std::isalpha`、`std::isdigit`、`std::isalnum` | 是否字母、数字、字母或数字 |
| `std::tolower`、`std::toupper` | 转为小写、转为大写，其他字符通常保持原样 |

下面是**完整程序 C**：读取一个 ASCII 编号，把字母变大写，数字不变。

```cpp
#include <cctype>
#include <iostream>
#include <string>

int main() {
    std::string code;
    if (!(std::cin >> code)) {
        return 1;
    }
    for (std::size_t i = 0; i < code.size(); ++i) {
        unsigned char byte = static_cast<unsigned char>(code[i]);
        code[i] = static_cast<char>(std::toupper(byte));
    }
    std::cout << code << '\n';
    return 0;
}
```

那次 `unsigned char` 转换有实际用处：这些函数要求输入为 EOF 或可表示成 `unsigned char` 的值；普通 `char` 可能为负，直接传入会违反要求。`toupper` 返回 `int`，这里再转换回 `char` 保存。

这套按字节分类的工具不是 UTF-8 中文处理工具，也不是任意语言的大小写转换器。先在约定的 ASCII 编号上使用，别把拆开的中文三个字节逐个“转大写”。

# 07　把规则交给函数

一个程序里，有时好几处都要做同一件事。比如把步数换成行走时间。与其在每处重新写一遍，不如给这条规则起名字：你告诉它数据，它交回答案。

## 先约定输入，再约定答案

**完整程序 A：**每步需要 3 秒，先后计算 12 步和 7 步的时间。

```cpp
#include <cstdio>

int walk_seconds(int steps, int seconds_per_step) {
    return steps * seconds_per_step;
}

int main() {
    int first = walk_seconds(12, 3);
    int second = walk_seconds(7, 3);
    std::printf("%d %d\n", first, second);
    return 0;
}
```

`walk_seconds` 是函数名，括号里的两个 `int` 变量叫**参数**。调用 `walk_seconds(12, 3)` 时，第一个收到 12，第二个收到 3。最前面的 `int` 说明返回一个整数；`return` 把计算结果交回调用处。

函数定义放在这里，不代表程序一开始就执行它。程序从 `main` 开始，遇到调用才进入相应函数。函数需要先声明才能调用，本书先把完整定义写在调用之前。

每个参数都写自己的类型：`int steps, int seconds_per_step`，不能简写成 `int steps, seconds_per_step`。调用时数目和顺序要符合约定，类型须匹配或有允许的转换；允许转换也可能损失信息，不能把小数时间随便塞给整数参数。

本函数约定两个输入都在 0 到 1000 之间，乘积放得进 `int`。换了数据范围，还得重新检查这一点。

**停笔 1**　写出程序 A 的输出。若把 `walk_seconds(12, 3)` 改成 `walk_seconds(3, 12)`，这次结果碰巧一样，能说明交换所有函数参数都安全吗？想一个反例。

## 一旦交回答案，这次调用就结束

**函数定义片段：**

```cpp
int remaining_space(int capacity, int used) {
    if (used >= capacity) {
        return 0;
    }
    return capacity - used;
}
```

当第一个 `return` 执行，本次函数调用立即结束，不会再往下执行。这个函数约定 `capacity`、`used` 都是非负数；空间已满或超过容量时，剩余量按零算。

如果函数只做动作、不交回数值，可以把返回类型写成 `void`。**函数定义片段：**

```cpp
void print_separator() {
    std::printf("---\n");
}
```

调用时写 `print_separator();`。函数中可以用不带值的 `return;` 提前结束，也可直接走到末尾。需要返回整数的普通函数，则要让所有可能路径都交回答案，不能漏掉一边。

**停笔 2**　计算 `remaining_space(20, 7)` 和 `remaining_space(20, 25)`。第二次会先返回 0，再继续返回 −5 吗？

## 传进去的通常是一份副本

**完整程序 B：**

```cpp
#include <cstdio>

void add_one(int value) {
    ++value;
    std::printf("inside: %d\n", value);
}

int main() {
    int points = 8;
    add_one(points);
    std::printf("outside: %d\n", points);
    return 0;
}
```

第一行输出 `inside: 9`，第二行却是 `outside: 8`。`value` 是参数自己的副本，改它不会自动改调用者的 `points`。这叫**值传递**。它很有用：一个只需要数值的函数，不应顺手改变外面的数。

若确实要改原变量，就在参数类型后写 `&`，表示**引用**。

**替换函数片段：**

```cpp
void add_one(int& value) {
    ++value;
    std::printf("inside: %d\n", value);
}
```

把程序 B 的函数替换为这一版，两行才分别是 `inside: 9`、`outside: 9`。这里的 `&` 不表示“取地址”，而是参数声明中的“引用”。同一个符号在不同位置，可以有不同用途。

**停笔 3**　把参数中的 `&` 遮住，只看调用 `add_one(points)`，能否断定会改原变量？为什么要看函数的约定，而不是猜名字？

## 引用是别名，不是第二份数据

**片段：**

```cpp
int points = 8;
int& alias = points;
alias = 12;
```

现在 `points` 也变成 12，因为 `alias` 是它的另一个名字。普通引用必须在创建时绑定一个对象，此后不能换成别的对象。写 `alias = other;` 是把 `other` 的值赋给原来的 `points`，不是让 `alias` 改去代表 `other`。

不允许通过这个名字修改时，加 `const`：

```cpp
const int& view = points;
```

这是**片段**。`view` 不能用来赋新值，`points` 自己仍可修改。它是只读访问，不是把原对象永久封住。

有些表达式指向一个已经存在、能识别其位置的对象，例如变量 `points`、元素 `values[0]`，常叫**左值**。普通 `T&` 引用要绑定这类合适的对象。`3`、`points + 1` 这类临时计算结果是常见的右值，不能给 `int&` 当作可改的原变量。

名字容易误导：`const int fixed = 3;` 中的 `fixed` 也是左值，但不能被赋值；不是“凡是能写在等号左边的才是左值”。现阶段会区分“已有对象”和“临时结果”就够用了，不必先学完整的表达式分类。

`const int&` 可以绑定临时结果，例如 `const int& sum = 3 + 4;`；直接这样绑定时，临时对象能活到该局部引用结束。不能据此推断“引用会让所有对象永远活着”。函数结束、返回引用、把引用保存起来时都有额外的寿命问题，第 12 章会说明。

**停笔 4**　`int& a = 5;` 与 `const int& b = 5;` 哪句可行？`alias = other;` 后，引用换主人了吗？

## 大数据不想复制，也不想被修改

一个 `vector<int>` 可能有很多元素。若参数写 `std::vector<int> values`，调用时通常要复制整排数据。只读取时，使用 `const std::vector<int>&`，不复制这排元素，也不能通过参数修改它。

**完整程序 C：**

```cpp
#include <cstdio>
#include <vector>

int count_above(const std::vector<int>& values, int threshold) {
    int count = 0;
    for (std::size_t i = 0; i < values.size(); ++i) {
        if (values[i] > threshold) {
            ++count;
        }
    }
    return count;
}

int main() {
    std::vector<int> values{4, 9, 3, 9};
    std::printf("%d\n", count_above(values, 5));
    return 0;
}
```

本例元素很少，复制也不贵；写法说明的是这个函数没有修改权限。遇到以后真正变大的数据，也不必换一份规则。

| 需要什么 | 小型数据，如 `int` | `vector`、`string` 等可能较大的数据 |
|---|---|---|
| 只要读到值 | 按值 `int x` | 只读引用 `const ...& x` |
| 要修改调用者的对象 | 引用 `int& x` | 可修改引用 `...& x` |

这是本书的常用选择，不是说所有自定义类型都一定很大。指针本身也很小，常按值传递；复制指针不等于复制它指向的内容。

**停笔 5**　程序 C 输出什么？如果把参数改成按值，答案会改变吗？代价会不会改变？若改成非 `const` 引用，函数是否就必须修改原序列？

## 一次得到两个结果

可以用引用参数接收额外结果。**完整程序 D：**把 135 分钟拆成小时和剩余分钟。

```cpp
#include <cstdio>

void split_time(int total_minutes, int& hours, int& minutes) {
    hours = total_minutes / 60;
    minutes = total_minutes % 60;
}

int main() {
    int hours = 0;
    int minutes = 0;
    split_time(135, hours, minutes);
    std::printf("%d %d\n", hours, minutes);
    return 0;
}
```

`total_minutes` 是输入，后两个参数是输出位置。调用者应传两个不同的变量；如果两个引用参数都绑定同一个变量，后一次赋值就会覆盖前一次。本例也约定总分钟数非负。

# 08　用记录表达一件事

打印任务里有名字、每份页数、份数。只用三排互不相干的变量，容易把一项名字和另一项数量配错。让属于同一件事的数据放在一起，能减少这类混乱。

## 一个任务，一份记录

**类型定义片段，需要 `<string>`：**

```cpp
struct PrintJob {
    std::string name;
    int pages;
    int copies;
};
```

`struct` 定义一种结构体类型。`name`、`pages`、`copies` 是它的成员。结尾 `};` 的分号不能漏；这个定义不是立刻执行一个打印任务，而是规定“每个这样的记录有哪些部分”。

**使用片段：**

```cpp
PrintJob map{"map", 3, 5};
map.copies = 6;
```

花括号中的初值依定义顺序对应，分别是名称、页数、份数。点号 `.` 表示访问这个对象的成员。修改 `map.copies` 只改这份记录，不会改其他打印任务。

初学时给每个成员明确的初值。`PrintJob job;` 里的整数成员不会因为旁边的字符串初始为空，就也自动有一个确定数值；`PrintJob job{};` 才会把这里的整数成员初始化为零。

**停笔 1**　`PrintJob card{"card", 2, 7};` 含义是什么？若把 2 和 7 写反，总页数碰巧相同，记录是否仍然正确？

## 把自己的计算放在自己身上

每份页数乘份数，就是任务总页数。与其让每个使用者都重新记住这条规则，可以让记录提供一个动作。

**完整程序 A：**

```cpp
#include <cstdio>
#include <string>

struct PrintJob {
    std::string name;
    int pages;
    int copies;

    int total_pages() const {
        return pages * copies;
    }

    void print_label() const {
        std::printf("%s: %d\n", name.c_str(), total_pages());
    }
};

int main() {
    PrintJob map{"map", 3, 5};
    PrintJob card{"card", 2, 7};
    map.print_label();
    card.print_label();
    PrintJob{"notice", 1, 4}.print_label();
    return 0;
}
```

`total_pages` 和 `print_label` 是成员函数。`map.total_pages()` 算的是 `map` 的页数，不是 `card` 的页数。末尾的 `const` 表示这个成员函数不会通过当前对象的这条访问路径修改其普通成员，因此只读的 `PrintJob` 也可以调用它。

最后一行使用临时对象：创建一份通知任务，调用它的成员函数，这条语句结束后临时对象就不再存在。不要把“能临时创建”误解成“它会一直留在内存里”。

### 成员函数怎样知道“自己”是谁

在普通的非静态成员函数里，`this` 是指向当前对象的指针。`return pages * copies;` 也可写为 `return this->pages * this->copies;`。箭头是通过指针访问成员的符号，第 12 章再完整解释。

现在先知道：同一个函数定义被不同对象调用时，里面用的是相应对象的成员。它不需要把“当前任务”存到一个大家共用的全局变量里。`this->` 在这里可以省略，不必每次都写。

```cpp
#include <cstdio>

struct TimeParts {
    int hours;
    int minutes;
};

TimeParts split_time(int total_minutes) {
    return {total_minutes / 60, total_minutes % 60};
}

int main() {
    TimeParts result = split_time(135);
    std::printf("%d %d\n", result.hours, result.minutes);
    return 0;
}
```

`split_time` 的返回类型现在是 `TimeParts`。调用者得到完整答案，不用先准备两个输出位置。结构体的价值不是“少写几行”，而是把“这两个数共同表示什么”说清楚。

不要为了使用结构体，就把所有变量都塞进一个巨大的记录。只把属于同一个概念的数据和行为放在一起。之后排序、查找时，我们还会为这样的记录提供比较方式。

# 09　把一段数据交给算法

一排借阅编号需要排序、去重，或者把前面几项移到后面。每次都从循环开始写，容易反复犯同一种错。标准库已经准备了这些算法；先告诉它“处理哪一段”，再告诉它必要的规则。

## 先指出这一段的两端

对 `vector`，`begin()` 标记开头，`end()` 标记最后一个元素**后面**的位置。这样的标记叫**迭代器**。

可以把 `[begin, end)` 读作“从 begin 开始，到 end 之前为止”。左端包含，右端不包含，叫**左闭右开区间**或半开区间。`end()` 不是最后一个元素，不能拿来读元素。

**片段：**

```cpp
std::vector<int> values{8, 3, 6};
auto position = values.begin();
int first = *position;
++position;
int second = *position;
```

`*position` 取得它所指的元素，`++position` 移到下一个位置。`auto` 让编译器由右边推导变量类型，不是“这个变量以后什么类型都能变”。这里推导出的类型是相应的迭代器类型。

**停笔 1**　画出三个元素和末尾后的位置。第一次、第二次取出的数是什么？空序列的 `begin()` 和 `end()` 应相同还是不同？

### 不必每次亲自移动标记

下面是**循环片段**：

```cpp
for (auto position = values.begin(); position != values.end(); ++position) {
    std::printf("%d\n", *position);
}
```

只是逐项看，也可以用范围 `for`：

```cpp
for (int value : values) {
    std::printf("%d\n", value);
}
```

这是**等价用途的片段**。`value` 是每项的副本。要直接修改元素，用 `int& value`；大型元素只读取，用 `const auto& value`。这里的 `&` 正是已经学过的引用，不是新的循环专用符号。

`vector` 的迭代器支持加减：`begin() + 2` 指到下标 2；`end() - begin()` 得到元素数量。不能越过合法范围，也不能把不同容器的迭代器相减。原生数组的指针也可以充当这类迭代器：`std::sort(a, a + n)` 处理前 `n` 个元素，条件是这段确实存在。不是所有容器的迭代器都支持 `+ 2`，后面的有序集合就不支持。

**停笔 2**　`for (int value : values) { value = 0; }` 能把原序列清零吗？应该只改哪里？若取前三项，末端应是 `begin() + 2` 还是 `begin() + 3`？

## 排序和去重不是同一件事

**完整程序 A：**把固定的一排编号从小到大排列，并只保留不同编号。

```cpp
#include <algorithm>
#include <cstdio>
#include <vector>

int main() {
    std::vector<int> codes{7, 2, 7, 4, 2};
    std::sort(codes.begin(), codes.end());
    auto new_end = std::unique(codes.begin(), codes.end());
    codes.erase(new_end, codes.end());
    for (int code : codes) {
        std::printf("%d ", code);
    }
    std::printf("\n");
    return 0;
}
```

`sort` 排序。`unique` 只把**相邻**的重复项压到一起处理，把保留的内容放到前部，并返回新的逻辑末端。它没有改变 `vector` 的元素数量；新末端之后的元素值不要拿来当答案，最后用 `erase` 删去那一段。

若不先排序，`2,7,2` 的两个 2 不相邻，`unique` 不会把它们合成一项。先问题目是“合并相邻相同项”还是“只保留不同值”，再决定要不要排序；有时原来的顺序本身就是信息，不能随便打乱。

**停笔 3**　对 `3,3,1,3,1,1`，不排序直接 `unique`，前面保留的逻辑结果是什么？若先排序再去重呢？`unique` 之后马上看 `size()`，是否已经变短？

## 翻转、旋转和找最值

这些函数需要 `<algorithm>`。下面是查阅表，`first`、`last` 代表同一合法区间的两端。

| 工具 | 做什么 |
|---|---|
| `std::min(a, b)`、`std::max(a, b)` | 比较两个值，取小或大；本书先让两边类型一致 |
| `std::reverse(first, last)` | 把这一段前后颠倒 |
| `std::rotate(first, middle, last)` | 把 `[middle,last)` 移到前面，`[first,middle)` 接到后面；各段内部次序不变 |
| `std::min_element(first, last)` | 返回最小元素的位置 |
| `std::max_element(first, last)` | 返回最大元素的位置 |

**完整程序 B：**轮换四个任务的起点，再翻转。

```cpp
#include <algorithm>
#include <cstdio>
#include <vector>

int main() {
    std::vector<int> tasks{10, 20, 30, 40};
    std::rotate(tasks.begin(), tasks.begin() + 2, tasks.end());
    for (int task : tasks) {
        std::printf("%d ", task);
    }
    std::printf("\n");
    std::reverse(tasks.begin(), tasks.end());
    for (int task : tasks) {
        std::printf("%d ", task);
    }
    std::printf("\n");
    auto best = std::max_element(tasks.begin(), tasks.end());
    if (best != tasks.end()) {
        std::printf("max: %d\n", *best);
    }
    return 0;
}
```

在空区间里找最值，返回的就是末端标记，不能解引用；这与“没有数据就没有最大值”相同。翻转与旋转可以处理空区间，但你提供的三个位置本身仍必须合法。

**停笔 4**　写出程序 B 的三行输出。为什么 `rotate` 不是“把每个数都加 2”，也不是把两段各自反转？

## 一件事的“先后”由哪条规则决定

打印任务先处理总页数少的；总页数相同，按名称字典序。可以把规则写成普通函数。

**完整程序 C：**

```cpp
#include <algorithm>
#include <cstdio>
#include <string>
#include <vector>

struct Batch {
    std::string name;
    int sheets;
};

bool comes_before(const Batch& a, const Batch& b) {
    if (a.sheets != b.sheets) {
        return a.sheets < b.sheets;
    }
    return a.name < b.name;
}

int main() {
    std::vector<Batch> batches{{"map", 6}, {"card", 2}, {"badge", 2}};
    std::sort(batches.begin(), batches.end(), comes_before);
    for (const Batch& batch : batches) {
        std::printf("%s %d\n", batch.name.c_str(), batch.sheets);
    }
    return 0;
}
```

比较函数回答的是“`a` 应排在 `b` 前面吗”，不是“这两个是不是差不多”。同一个元素与自己比，必须是假；不能写 `a.sheets <= b.sheets` 来当排序规则。

规则还要前后一致：若 A 在 B 前，B 在 C 前，A 就也应在 C 前；不能又有 A 在 B 前、B 在 A 前。更完整的要求叫**严格弱序**，还要求“互不在对方前面”的等价关系一致。现在先用“先比页数，再比名称”这样的明确规则，不要让比较结果随时间或随机数变化。

另一种方式是为类型定义 `operator<`。下面是**可替换类型定义**：

```cpp
struct Batch {
    std::string name;
    int sheets;

    bool operator<(const Batch& other) const {
        if (sheets != other.sheets) {
            return sheets < other.sheets;
        }
        return name < other.name;
    }
};
```

此时排序调用可改为 `std::sort(batches.begin(), batches.end());`，默认使用 `<`。为某一次排序临时指定规则，则传比较函数更直接；第 13 章还会把这条短规则写在调用旁边。

两种写法是选择，不必同时定义两份相同规则。默认排序也不保证同优先级元素保留输入先后；若先后重要，就明确加一个编号作下一层比较，或选能保持同类先后的算法。

## 把不同排列按字典序走一遍

`next_permutation` 把一段元素改为字典序下一个排列，有下一个就返回真；已经是最后一个时，变回第一个，并返回假。`prev_permutation` 反着走：走到头时回到字典序最大的排列并返回假。

**完整程序 D：**列出三个字母 `AAB` 的不同排列。

```cpp
#include <algorithm>
#include <cstdio>
#include <string>

int main() {
    std::string letters = "AAB";
    std::sort(letters.begin(), letters.end());
    do {
        std::printf("%s\n", letters.c_str());
    } while (std::next_permutation(letters.begin(), letters.end()));
    std::printf("reset: %s\n", letters.c_str());
    return 0;
}
```

先从最小排列开始，再用 `do-while` 输出它，才能把第一个也算进去。重复的 A 不会被当成两个带隐藏编号的不同字母，所以不会输出六种不同文字。

# 10　按访问方式挑容器

图书排在架上，要随时取第几本；排队借书，要先来先办；撤销操作，要先撤销最近的一步。同样是一批数据，拿取方式不同，合适的容器也不同。

先看操作需要什么，不必先背一排英文名。

## 经常按编号取：`vector`

`vector` 连续保存元素，按下标取一项很方便。尾部添加通常很快，偶尔需要换更大的存储空间并搬移全部元素；平均到很多次添加上，代价仍小。中间插入或删除，后面的元素通常要移动。

**完整程序 A：**

```cpp
#include <cstdio>
#include <vector>

int main() {
    std::vector<int> order{10, 30, 40};
    order.insert(order.begin() + 1, 20);
    order.erase(order.begin() + 2);
    for (int value : order) {
        std::printf("%d ", value);
    }
    std::printf("\n");
    std::printf("checked: %d\n", order.at(1));
    return 0;
}
```

`insert(位置, 值)` 在该位置**之前**插入；`erase(位置)` 删除该元素；`erase(起点, 末端)` 删除一段。

`at(i)` 也按下标访问，但会检查范围：越界时抛出异常，若没有处理通常使程序终止。它不会自动扩大序列，也不是“越界就给零”。`[]` 不作这种检查，仍要自己确保范围。

**停笔 1**　逐步写出程序 A 中的序列，最终输出什么？若有三个元素，`at(3)` 能读到第四项吗？

### 提前准备空间，不等于已经有了元素

如果确定有 100 个元素，可以创建 `vector<int> v(100)`，直接得到 100 项，再按下标填。

若只知道“最多可能加 100 个”，可先创建空序列，再 `v.reserve(100)` 预留容量，然后逐项添加。`reserve` 不改变元素数量，`v[0]` 仍不存在。`resize(100)` 才把数量改成 100。

多开一批零元素再不断追加，会把本不想要的零也留在答案里。选择 `resize` 还是 `reserve`，先看你要的是“已有多少项”还是“为以后留多大空间”。

交换两个同类型容器的内容可以用 `a.swap(b)`，也可以用 `<utility>` 的 `std::swap(a,b)`；不必逐项抄到第三个大容器里。本书使用的默认分配方式下，标准容器的这种交换通常不需复制全部元素。

**停笔 2**　空 `vector` 执行 `reserve(100)` 后，`size()` 是多少？再执行一次 `emplace_back(7)` 呢？如果一开始是 `vector<int> v(100)`，再追加 7，有几项？

### 旧位置不一定继续有效

添加元素可能使 `vector` 换存储空间，此前指向元素的迭代器、指针和引用会失效。即使没有换空间，插入或删除位置及其后面的旧标记也可能失效；尾部添加还会改变末端标记。

先修改容器，再重新取得所需位置，比拿着旧标记继续用更安全。第 12 章会解释指针为何会“还记着旧位置”。这不是每次操作都重新扫描全部数据的要求，而是先弄清手里的标记还能不能用。

## 两头都要加减：`deque`

`deque` 可以按下标取元素，也能在头尾快速添加、删除。它不保证全部元素在一段连续内存里，不能按原生连续数组来使用。

**完整程序 B：**

```cpp
#include <cstdio>
#include <deque>

int main() {
    std::deque<int> line{20, 30};
    line.emplace_front(10);
    line.emplace_back(40);
    line.pop_front();
    line.pop_back();
    for (int value : line) {
        std::printf("%d ", value);
    }
    std::printf("\n");
    return 0;
}
```

头部添加用 `emplace_front`，删除用 `pop_front`；尾部名称与 `vector` 类似。中间插入删除并不会因此变得一样便宜。`deque` 修改后的迭代器有效性也有自己的规则，不能以为“没整排搬家就什么标记都安全”。

**停笔 3**　程序 B 输出什么？如果任务总在开头添加，用 `vector.insert(begin(), value)` 与 `deque.emplace_front(value)`，哪个更符合需要？

## 只撤销最近一步：栈

书叠成一摞，新书放在上面，取时也先拿上面的。这种后进先出叫**栈**，英文 stack。

标准库 `stack` 是一个限制访问方式的适配器：只暴露需要的操作，默认由 `deque` 保存数据，但也可使用其他合适的底层容器。它不是 `deque` 的子类，不提供任意下标访问。

**完整程序 C：**

```cpp
#include <cstdio>
#include <stack>

int main() {
    std::stack<int> history;
    history.emplace(2);
    history.emplace(5);
    history.emplace(9);
    while (!history.empty()) {
        std::printf("%d\n", history.top());
        history.pop();
    }
    return 0;
}
```

`emplace` 添一项，`top` 看栈顶，`pop` 删除栈顶但不返回它。要取得后删除，就先取值，再 `pop`。

## 先来先办：队列

队列 `queue` 先进先出：从尾部加入，从头部取走。下面是**完整程序 D**：

```cpp
#include <cstdio>
#include <queue>

int main() {
    std::queue<int> waiting;
    waiting.emplace(2);
    waiting.emplace(5);
    waiting.emplace(9);
    while (!waiting.empty()) {
        std::printf("%d\n", waiting.front());
        waiting.pop();
    }
    return 0;
}
```

队列用 `front()` 看队头，不叫 `top()`。它默认也由 `deque` 保存数据。栈和队列在空的时候，都不能取顶、取头或删除；所以循环先问 `empty()`。

**停笔 4**　栈、队列按相同顺序放入 2、5、9，各按什么顺序取出？哪一个适合排队办事，哪一个适合撤销最近的绘图步骤？

## 不是按先后，而是每次取当前最急的

优先队列 `priority_queue` 每次提供优先级最高的一项。默认对整数来说，是数值最大的一项。它不保证你能随时从头到尾按顺序查看全部元素。

**完整程序 E：**

```cpp
#include <cstdio>
#include <functional>
#include <queue>
#include <vector>

int main() {
    std::priority_queue<int> largest;
    largest.emplace(4);
    largest.emplace(9);
    largest.emplace(6);
    std::printf("%d\n", largest.top());
    largest.pop();
    std::printf("%d\n", largest.top());

    std::priority_queue<int, std::vector<int>, std::greater<int>> smallest;
    smallest.emplace(4);
    smallest.emplace(9);
    smallest.emplace(6);
    std::printf("%d\n", smallest.top());
    return 0;
}
```

第一次得到 9，删掉以后得到 6。第二种写法传入 `std::greater<int>`，让较小值出现在顶端，得到 4。先把这行作为“每次取最小值”的配方查用，模板参数的细节不用一口气记完。

用自定义记录时，默认优先队列会根据 `<` 选最大的；也可以提供比较器。它和排序使用同样严格、一致的比较要求，但“比较规则下的最大者在顶端”，不等于“排序后第一个在顶端”。不要照搬一个反向规则以后还凭名称猜谁先出来。

添加和删除通常只需逐层调整，并不每次重排所有元素；看 `top()` 不会自动删除。已有元素参与比较的值也不应在容器外偷偷改变，否则内部安排可能不再正确。

# 11　给数据一个可查的名字

储物柜的编号是 1 到 30，可以直接用下标。可是书名是文字，设备编号还可能跳到一百万。为了只保存少数几个实际出现的名字，不必先开一百万个格子。

## 不按第几项，而按名字查

**映射**保存“键到值”的对应，例如书名到借阅次数。键是用来找东西的名字，值是对应的数据。单一键映射中，一个键最多有一份值。

`unordered_map` 是无序映射。先看**完整程序 A**：输入 `0 <= n <= 1000`，再输入 `n` 个不含空格的 ASCII 书名编号，最后读一个要查询的编号，输出它出现过几次。

```cpp
#include <iostream>
#include <string>
#include <unordered_map>

int main() {
    int n = 0;
    if (!(std::cin >> n) || n < 0 || n > 1000) {
        return 1;
    }
    std::unordered_map<std::string, int> counts;
    for (int i = 0; i < n; ++i) {
        std::string code;
        if (!(std::cin >> code)) {
            return 1;
        }
        ++counts[code];
    }
    std::string query;
    if (!(std::cin >> query)) {
        return 1;
    }
    auto found = counts.find(query);
    if (found == counts.end()) {
        std::cout << 0 << '\n';
    } else {
        std::cout << found->second << '\n';
    }
    return 0;
}
```

`counts[code]` 有一个重要动作：键不存在时，**先插入**它，对应的 `int` 初始化为 0，再返回这个值。于是 `++counts[code]` 适合统计出现次数。

但只想查询时，这个动作可能不是你要的。程序最后用 `find`：找到就给出位置，没找到就给 `end()`，不新增记录。`found->second` 取这个键对应的值；箭头表示通过位置标记访问成员。

**停笔 1**　依次输入 `MAP CARD MAP`，再查 `POSTER`。程序输出什么？查询前后有几个不同的键？若改用 `counts["POSTER"]`，数量会不会变？

## “新增”和“覆盖”要分开

**完整程序 B：**

```cpp
#include <cstdio>
#include <string>
#include <unordered_map>

int main() {
    std::unordered_map<std::string, int> stock;
    auto first = stock.emplace("tape", 6);
    auto again = stock.emplace("tape", 9);
    std::printf("%d %d %d\n", first.second, again.second, again.first->second);
    stock["tape"] = 12;
    std::printf("%d\n", stock.find("tape")->second);
    stock.erase("tape");
    std::printf("%zu\n", stock.count("tape"));
    return 0;
}
```

`emplace` 对已有键不覆盖。它返回一对结果：`.first` 是现有或新记录的位置，`.second` 表示是否真的插入成功。这里第一次成功，第二次失败，值仍为 6。

`stock["tape"] = 12` 则是“没有就新增，有就覆盖”。`erase(键)` 删除。`count(键)` 查询该键有几条记录，单一键映射里只能是 0 或 1。`size()` 查总记录数，`clear()` 清空，`empty()` 判断是否为空。

若用 `at(键)`，找到时访问值，缺失则抛出异常，不会插入。查找一次后已拿到迭代器，就直接用它，不必再通过同一个键找一遍。

## 看全部记录，但不猜输出顺序

下面是两种**遍历片段**，选择一种即可：

```cpp
for (const auto& entry : stock) {
    std::printf("%s %d\n", entry.first.c_str(), entry.second);
}
```

```cpp
for (auto it = stock.begin(); it != stock.end(); ++it) {
    std::printf("%s %d\n", it->first.c_str(), it->second);
}
```

每项是一对数据，`.first` 是键，`.second` 是值。键不能在原位置随意改成另一个名字，否则容器原来的组织方式就可能不对了。需要改名，应按容器允许的方式删除旧项并插入新项。

“无序”表示不保证按字母、数值或插入顺序遍历；一次运行看起来排好了，下一次仍不必如此。插入造成重新分组时，旧迭代器可能失效；删除记录也会让指向该记录的标记失效。别在遍历时随便增删，再接着用旧位置。

## 只关心出现过没有：集合

不需要给每个键配一份值，只要保存不同元素，用 `unordered_set`。

**完整程序 C：**

```cpp
#include <cstdio>
#include <string>
#include <unordered_set>

int main() {
    std::unordered_set<std::string> visited;
    visited.emplace("north");
    visited.emplace("south");
    visited.emplace("north");
    std::printf("%zu\n", visited.size());
    std::unordered_set<std::string> other{"south", "north"};
    std::printf("%d\n", visited == other);
    return 0;
}
```

重复加入不会多存一份。两个无序集合的 `==` 比较成员是否相同，不受遍历顺序影响；不能用 `<` 要求它按字典序比较整个无序集合。

如果要保留重复键，有 `unordered_multiset` 和 `unordered_multimap`。多重版本没有映射的方括号访问，`count` 可以大于 1，`emplace` 的返回形式也不同于单一键映射，不能直接照用 `.second` 判断插入成败。`erase(键)` 会删除所有匹配项；只想删一条，就先找出相应迭代器，再删该位置。

## 想按大小排好，再找旁边的键

`map` 和 `set` 会按键的比较规则保持有序。遍历得到的是按规则排列的顺序；可以通过迭代器 `++`、`--` 找前后邻居，但不能写迭代器 `+ 3`。

**完整程序 D：**寻找不小于 25 的第一个已有柜号，并查看它前面的一个柜号。

```cpp
#include <cstdio>
#include <set>

int main() {
    std::set<int> lockers{10, 20, 40};
    auto next = lockers.lower_bound(25);
    if (next != lockers.end()) {
        std::printf("next: %d\n", *next);
    }
    if (next != lockers.begin()) {
        auto previous = next;
        --previous;
        std::printf("previous: %d\n", *previous);
    }
    return 0;
}
```

`lower_bound(x)` 找第一个不小于 `x` 的键；没有则返回 `end()`。要读迭代器，先确认不是末端；要往前走，先确认不在开头。空集合两端相同，以上两个分支都不进入。

有序映射 `map` 的 `find`、`emplace`、`[]` 等用法与单一键无序映射相似，但按序遍历。对应的有序多重版本是 `multimap`、`multiset`。

不要把“有序一定更慢”当作定律。无序容器分布良好时，平均查找代价接近固定；分布很差时可能退化成逐项找。有序容器的查找、插入和删除通常只走逐层缩小的一条路径，最坏代价随层数增长。后面的课程会用更准确的记号描述这些代价。现在先按“需要顺序吗、需要邻居吗、键怎样比较”选择。

## 进一层：自己设计的键怎样分组

这一节可以另用一次阅读时间。设备位置由“房间名”和“格号”共同决定。两个位置相同，必须房间和格号都相同，不能只比较格号。

无序容器还需要一个**哈希函数**，把键算成一个整数，再据此分组查找。像先按索引分区，再去相应区域找记录；分到同一区的不一定是同一个键，还要用判等规则核对。

最重要的一条是：**相等的键，哈希值必须相同。不同的键，可以出现相同哈希值。** 后一种叫碰撞，不是自动算错；碰撞过多会影响速度。哈希值不是“保证唯一的编号”，也不应拿来替代真正的键。

**完整程序 E：**

```cpp
#include <cstddef>
#include <cstdio>
#include <functional>
#include <string>
#include <unordered_map>

struct Slot {
    std::string room;
    int number;

    bool operator==(const Slot& other) const {
        return room == other.room && number == other.number;
    }
};

struct SlotRules {
    std::size_t operator()(const Slot& slot) const {
        std::size_t room_hash = std::hash<std::string>{}(slot.room);
        std::size_t number_hash = std::hash<int>{}(slot.number);
        return room_hash ^ (number_hash << 1);
    }

    bool operator()(const Slot& a, const Slot& b) const {
        return a == b;
    }
};

int main() {
    std::unordered_map<Slot, int, SlotRules> visits;
    ++visits[Slot{"blue", 2}];
    ++visits[Slot{"red", 2}];
    ++visits[Slot{"blue", 2}];
    auto found = visits.find(Slot{"blue", 2});
    std::printf("%zu %d\n", visits.size(), found->second);
    return 0;
}
```

`operator==` 给出判等。`SlotRules` 的一个参数版本是哈希工具；写了 `operator()`，对象就能像函数一样被调用。此处 `<< 1` 把无符号整数的位左移一位，`^` 逐位比较两个数，相异的位得到 1，用来混合两个哈希结果。现在不用发明自己的混合公式；这份简单写法能满足相等键哈希相同，但不是对所有数据都最佳的分布方案。

运算先在 `size_t` 这样的无符号类型里进行，避免用带符号 `int` 随意相乘而溢出。固定容器使用期间，同一键的哈希和判等结果要保持一致；不要求不同运行之间的库哈希值永远相同。

示例默认通过 `operator==` 判等。也可把声明改为 `std::unordered_map<Slot, int, SlotRules, SlotRules>`，让同一个规则类型的两个参数版本负责判等。这是两种接法，不必把同一条判等逻辑复制两遍。

如果改成有序 `map` 或 `set`，不需要哈希，也不要求 `operator==`；需要 `<` 或指定的比较器。例如先比房间名，再比格号，形成一致的严格先后关系。有序容器按“彼此都不小于对方”判为同一键。若只比较房间，两个同房间、不同格号就会被当成同一个键，这通常不是你想要的。

# 12　谁在使用这块内存

这一章不要求一次读完。每做完一小节，画出“哪个名字指向哪个对象”，再继续。你已经用过 `vector`，不必先学会手动分配内存，才能保存一排数据。

这次要回答另一个问题：**手里只记着一个位置，那个位置上的对象还在吗？**

## 值和位置是两件事

变量 `level` 保存一个整数。`&level` 取得它所在的地址；能保存这种地址的变量叫**指针**。指向 `int` 的指针类型写成 `int*`。

**完整程序 A：**

```cpp
#include <cstdio>

int main() {
    int level = 4;
    int* position = &level;
    std::printf("%d\n", *position);
    *position = 7;
    std::printf("%d\n", level);
    return 0;
}
```

`position` 保存的是地址，`*position` 访问那个地址上的 `int`，这一步叫**解引用**。因此输出先是 4，再是 7。修改 `*position` 就是在修改 `level`，不是修改一个副本。

这里两种星号各有位置：声明里的 `int*` 说明类型；表达式里的 `*position` 表示访问所指对象。先看它放在哪里，不要只看单个符号猜意思。

**停笔 1**　画一个保存 4 的格子，旁边画出指针到格子的箭头。执行 `*position = 7` 后，改的是格子内容还是箭头指向？若写 `position = &other`，又是哪一个改变？

## 指针能换位置，引用不能换主人

引用在创建时绑定对象，之后对引用赋值是修改对象；指针本身则可以改为保存另一个地址。

**片段：**

```cpp
int left = 2;
int right = 9;
int* chosen = &left;
chosen = &right;
*chosen = 10;
```

最后 `left` 仍为 2，`right` 变成 10。指针也可用 `nullptr` 表示“现在没有指向对象”。不能解引用 `nullptr`。

声明多个变量时还有一个陷阱：`int *a = nullptr, b = 0;` 中，`a` 是指针，`b` 却是整数，不是两个指针。本书一行声明一个指针，少猜一次语法。

旧代码里常用 `NULL` 表示空指针；C++14 写新代码优先用 `nullptr`，意思更明确。

**停笔 2**　给 `chosen` 赋值为 `nullptr` 后，`right` 会消失吗？这时是否可以读 `*chosen`？

## 非空不等于还能用

地址不是一张能让对象永远存在的通行证。局部变量走出自己的范围，就结束了生命；记着它地址的指针仍可能非空，但不能继续访问。

下面是**危险片段，只用于辨认，不要解引用运行**：

```cpp
int* saved = nullptr;
{
    int temporary = 8;
    saved = &temporary;
}
```

走出大括号，`temporary` 已经不在了。`saved` 变成**悬垂指针**，不能因为 `saved != nullptr` 就使用 `*saved`。引用也可能悬垂，它没有自动检查寿命的能力。

函数不能返回指向自己普通局部变量的指针或引用。`vector` 重新分配空间，也会使指向旧元素的指针失效。解引用前要同时知道：不是空；对象仍在；类型正确；位置有效；访问权限允许。

**停笔 3**　朋友的检查是 `if (saved != nullptr)`。它能排除哪一种危险？不能排除哪一种？在纸上划掉上面片段中已经不再存在的对象。

## 数组不是指针，但常能提供起点

**片段：**

```cpp
int values[4] = {3, 6, 9, 12};
int* first = values;
int third = *(first + 2);
```

在这里，数组名转换成了指向首元素的指针。`first + 2` 是往后移两个 `int` 元素的位置，取出 9。它不是“把地址往后移两个字节”。编译器按元素类型处理距离，不要再手动乘 `sizeof(int)`。

`values[2]` 和 `*(values + 2)` 访问同一元素。同一数组内的两个合适指针相减，得到相隔多少个元素，也不必再除以元素大小。

数组本身并不等于指针：`sizeof(values)` 在这里得到整个数组的字节数，`sizeof(first)` 是指针本身的大小；数组还知道固定容量，而单个指针通常不携带长度。

指针运算只在同一数组对象的有效元素位置与末尾后位置之间进行。`values + 4` 可以作为末端标记，但不能解引用；越过这个末端继续加，也不合法。不同数组的指针不能任意相减来“算距离”。

**停笔 4**　`first + 3` 指向哪个数？`(first + 3) - first` 是 3 还是 12？为什么 `first + 4` 可作末端，却不能读它？

## 哪个部分不许改

普通变量加 `const` 表示不能通过它修改该值。指针有两件事可受限制：指向什么，或所指内容是否能通过这条路径修改。

**对照片段：**

```cpp
int a = 2;
int b = 5;
const int* view = &a;
int* const fixed = &a;
```

`view` 是“指向只读内容的指针”：可改成 `view = &b`，不能通过它写 `*view = 7`。原来的 `a` 并没有变成常量，仍可直接赋值。

`fixed` 是“指针本身固定”：不能改成 `fixed = &b`，但这里可以用 `*fixed = 7` 修改 `a`。两个 `const` 也能同时出现：`const int* const p = &a;`，两边都不许通过它改。

**停笔 5**　“指针的地址值不能换”和“不能通过指针修改内容”是同一件事吗？上面哪个指针允许改指向，哪个允许改内容？

## 自己申请，就要自己说清楚何时归还

`new` 在动态存储区创建对象，返回其地址。对象不会因为保存地址的局部指针离开范围就自动删除；需要匹配的释放。

**完整程序 B：**

```cpp
#include <cstdio>

int main() {
    int* value = new int(12);
    std::printf("%d\n", *value);
    delete value;
    value = nullptr;

    int* readings = new int[3]{};
    readings[1] = 5;
    std::printf("%d %d %d\n", readings[0], readings[1], readings[2]);
    delete[] readings;
    readings = nullptr;
    return 0;
}
```

`new int(12)` 创建一个值为 12 的整数，用 `delete` 归还；`new int[3]{}` 创建三个初值为零的整数，用 `delete[]` 归还。这里的 `{}` 有用：`new int[3]` 不会把三个整数都初始化成零。

归还后，不能再使用对象，也不能再次释放同一个对象。`delete nullptr` 是安全的，但这不等于“重复删除任何指针都安全”。`delete` 和 `delete[]` 不能混用，也不能拿来删除普通局部变量的地址。

**停笔 6**　程序 B 输出哪两行？删掉数组创建时的 `{}` 后，未赋值的第 0、2 项还能保证为零吗？若 `other = readings` 保存了同一地址，`readings = nullptr` 是否同时把 `other` 也变空？

### 一件东西只能有一份清楚的释放责任

只申请不归还，失去最后一个可用地址，就造成泄漏。两个指针都以为自己负责归还，又可能重复释放。提前 `return` 或抛出异常，还可能绕过原计划的 `delete`。

因此，本书日常程序仍优先用局部对象、`vector`、`string`：由对象自己在生命周期结束时归还资源。需要单独动态拥有一个对象时，标准库还有 `unique_ptr` 等工具，它们也沿用“明确的单一释放责任”。不必为了练习语法，把所有普通变量都改成 `new`。

这里只在短小、没有中途离开的示例中展示手动配对。写较复杂程序时，不能靠“记住以后加一句 delete”保证每条路径都收尾。

## 通过指针使用一份记录

**完整程序 C：**

```cpp
#include <cstdio>
#include <string>

struct Box {
    std::string label;
    int cards;
};

int main() {
    Box* box = new Box{"blue", 8};
    (*box).cards += 2;
    std::printf("%s %d\n", box->label.c_str(), box->cards);
    delete box;
    box = nullptr;
    return 0;
}
```

`box->cards` 是 `(*box).cards` 的简写：先找到对象，再访问成员。第 08 章的 `this->pages` 就是同样的箭头。普通对象用点，指针用箭头；不要因为看到结构体，就认定必须把它放进动态存储区。

释放结构体对象时，其中的 `string` 成员也会结束生命并处理自己的存储。这不意味着结构体里若保存一个普通裸指针，指向的另一个对象就会自动删除；仍要看谁实际拥有它。

**停笔 7**　程序 C 输出什么？若改用 `Box box{"blue", 8};`，访问成员用点还是箭头？还要手动 `delete` 吗？

## 核对

# 13　把行为当作数据

排序时，我们不只交给工具一排数据，还交给它一条“谁排在前面”的规则。有时这条规则只在这里用一次，写在旁边比起一个远处的函数名更方便。

这一章分三次读也可以：先看短函数，再看捕获，最后看保存行为。

## 一小段可以调用的代码

**完整程序 A：**

```cpp
#include <cstdio>

int main() {
    auto twice = [](int value) -> int {
        return value * 2;
    };
    std::printf("%d\n", twice(7));
    return 0;
}
```

方括号开头的写法叫 **lambda 表达式**。它创建一个能被调用的对象。这里用变量 `twice` 保存，再像调用函数一样写 `twice(7)`。

先把它分成四部分看：`[]` 是捕获表，暂时为空；`(int value)` 是参数；`-> int` 指定返回类型；花括号里是执行内容。末尾分号属于创建变量的语句，不是函数体里多出来的一句。

这里可以省略 `-> int`，编译器能从返回语句推导出来；没有返回值时也可以推导成 `void`。若有多条返回语句，推导要保持类型一致。把返回类型写出来，有时更清楚。

`auto` 只是推导变量类型。每个 lambda 表达式都有编译器生成的类型，类型不是“叫 auto 的万能类型”。这让我们不用先写出那串类型名。

**停笔 1**　`twice(7)` 得多少？创建 `twice` 时是否已经把里面的乘法执行了一遍？若只是想把 7 加倍，用一行普通计算是否也行？什么时候给行为起名字更有用？

## 把短规则放在使用处

第 09 章用普通函数写排序规则，现在把只用一次的规则放到 `sort` 的第三个参数。

**完整程序 B：**按姓名长度从短到长；同长度按字典序。

```cpp
#include <algorithm>
#include <cstdio>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> names{"Zoe", "Al", "Bo", "Mia"};
    std::sort(names.begin(), names.end(),
              [](const std::string& a, const std::string& b) {
                  if (a.size() != b.size()) {
                      return a.size() < b.size();
                  }
                  return a < b;
              });
    for (const std::string& name : names) {
        std::printf("%s\n", name.c_str());
    }
    return 0;
}
```

这个例子的名字限定为 ASCII，所以 `size()` 正好等于字母数。比较规则依然要满足严格、一致的先后关系；lambda 不会替你修复 `<=` 这种不合要求的比较。

把代码写在这里，不意味着 lambda 是一个普通命名函数声明。它是可作为值交给工具的对象；普通函数也可以作为这里的比较参数。选择哪一种，取决于放在哪里更容易读。

**停笔 2**　写出四行输出。如果本节改成中文姓名，按 `size()` 比较的是“字数”还是字节数？

## 想用外面的数，要说明怎样带进去

门票满减的门槛放在变量 `limit` 里，lambda 想用它，就在捕获表里写出名字。

**完整程序 C：**

```cpp
#include <cstdio>

int main() {
    int limit = 10;
    auto snapshot = [limit](int value) {
        return value >= limit;
    };
    auto current = [&limit](int value) {
        return value >= limit;
    };
    limit = 20;
    std::printf("%d %d\n", snapshot(15), current(15));
    return 0;
}
```

`[limit]` **按值捕获**：创建时保留一份 10，之后外面的 `limit` 变成 20，这份仍是 10。`[&limit]` **按引用捕获**：使用外面那个变量，现在看到 20。

`[&]` 表示把函数体中实际用到、需要捕获的外部局部变量按引用捕获；`[=]` 表示这类变量按值捕获。不是把整个程序里的所有变量无条件搬进来。初学时先显式写名字，更容易看出依赖谁。

按值捕获的普通副本默认不能在 lambda 的调用中改；本节只读取它。按引用捕获有修改权限，但仍要遵守原变量是否只读等限制。

**停笔 3**　程序 C 输出什么？如果以后要始终按“创建时的门槛”判断，选哪种捕获？如果希望跟着外面的调整变化，又选哪种？

## 行为还在，借用的变量可能已经不在

下面的**错误函数定义片段**不要运行：

```cpp
std::function<bool(int)> make_bad(int target) {
    return [&target](int value) {
        return value == target;
    };
}
```

参数 `target` 是这次调用的局部对象。函数返回后它结束生命，但交出去的 lambda 仍借用它。下一次调用 lambda，就访问了已经不在的对象。

正确做法是保留需要的值，不是保留一个即将失效的位置。下面是**完整程序 D**：

```cpp
#include <cstdio>
#include <functional>

std::function<bool(int)> make_matcher(int target) {
    return [target](int value) {
        return value == target;
    };
}

int main() {
    auto is_five = make_matcher(5);
    auto is_nine = make_matcher(9);
    std::printf("%d %d %d\n", is_five(5), is_five(9), is_nine(9));
    return 0;
}
```

两个匹配器各自保存自己的目标值，函数返回也不会失去它。这里按值捕获的是一个 `int`，复制就得到独立数值；如果按值捕获的是裸指针，只复制地址，不会自动复制或延长它指向对象的生命。

“只执行一次、就在当前函数内调用”的引用捕获通常容易检查；要返回、保存或稍后执行，就必须重新检查所借用对象能否活得足够久。换个包装类型不会修复悬垂引用。

**停笔 4**　程序 D 输出什么？把 `[target]` 换回 `[&target]`，即使把返回结果放进 `function`，能让局部参数活下来吗？

## 需要同一类盒子保存不同的行为

不同 lambda 有不同的实际类型。`std::function<返回类型(参数类型)>` 可以统一保存符合调用形式的行为，需要 `<functional>`。

**完整程序 E：**把两条规则放进同一个容器，依次用在数值 10 上。

```cpp
#include <cstdio>
#include <functional>
#include <vector>

int main() {
    std::vector<std::function<int(int)>> rules;
    rules.emplace_back([](int value) { return value + 3; });
    rules.emplace_back([](int value) { return value * 2; });
    for (const auto& rule : rules) {
        std::printf("%d\n", rule(10));
    }
    return 0;
}
```

`std::function<int(int)>` 读作“输入一个 `int`，返回一个 `int` 的可调用行为”。`std::function<int(bool, bool)>` 则是接收两个 `bool`，返回一个 `int`。

不必每个 lambda 都先包成 `function`。像程序 A、B 那样直接保存或传给标准算法就够用。`function` 的统一包装可能有额外分配和间接调用开销；只有需要统一存储、明确接口等收益时再用。

默认创建的空 `function` 没有可调用目标，直接调用会抛出异常；不能把“没有规则”当成默认返回零。本书示例都先放入真实行为再调用。

**停笔 5**　程序 E 是先加 3 再乘 2，最终只输出 26 吗？还是两个规则各自作用于 10？如果真要依次接着处理，应由谁保留并更新中间值？

## 核对

1. 结果 14；创建 lambda 没有执行函数体，调用才执行。一次简单运算可直接写；需要复用或交给别的工具时，保存行为更有用。
2. `Al`、`Bo`、`Mia`、`Zoe`。中文 UTF-8 文本按字节数，不自动按人眼看见的字数。
3. `1 0`。创建时的门槛用值捕获，跟随外部变量用引用捕获，后者还要保证外部变量活着。
4. `1 0 1`。包装不会延长被引用的局部参数寿命，错误仍在。
5. 分别输出 13、20。原程序每次都把 10 交给一条规则。若要接着处理，由调用这两条规则的代码维护 `result`，依次写 `result = rule(result)`，最终得到 26。

# 查阅　数学工具

这页像工具箱，不是一节必须背完的课。会用四则运算，可以先读“取整”和“整数乘方”。后半页只是先认名字，等数学课学到相应概念再回来。

数学函数需要正确的输入，也需要正确理解返回类型。工具帮你计算，不替你判断题目想要哪种答案。

## 小数取整有几种不同的方向

“只要有剩余就多开一页”与“取最近的整数”不是同一条规则。负数时差别更明显。

| 工具，需 `<cmath>` | `2.5` 的结果 | `-2.5` 的结果 | 结果类型 |
|---|---|---|---|
| `std::floor(x)`：向较小方向取整 | 2 | −3 | 这里传 `double`，返回 `double` |
| `std::ceil(x)`：向较大方向取整 | 3 | −2 | `double` |
| `std::round(x)`：取最近整数，正好一半时远离零 | 3 | −3 | `double` |
| `std::llround(x)`：同样的舍入方向 | 3 | −3 | `long long` |

`floor` 的结果虽然没有小数部分，类型仍可能是 `double`。强制转换 `static_cast<int>(x)` 是截向 0，并不总等于 `floor(x)`，也不执行四舍五入。转换或 `llround` 前，都要确认结果能装进目标整数类型。

**完整程序 A：**

```cpp
#include <cmath>
#include <cstdio>

int main() {
    double x = -2.5;
    std::printf("%.0f %.0f %.0f %lld\n",
                std::floor(x), std::ceil(x), std::round(x), std::llround(x));
    return 0;
}
```

**停笔 1**　写出输出。对 −2.5，向上取整是更接近零，还是更远离零？“向上”不是“把绝对值加大”。

## 精确整数乘方，不必绕进小数

`3` 的四次方是四个 3 相乘，也写作 $3^4$，结果为 81。注意 C++ 的 `^` **不是**乘方运算符，它是按位异或；不要写 `3 ^ 4` 来求这个答案。

**完整程序 B：**在很小的范围内计算非负整数次方。

```cpp
#include <cstdio>

long long integer_power(int base, int exponent) {
    long long result = 1;
    for (int i = 0; i < exponent; ++i) {
        result *= base;
    }
    return result;
}

int main() {
    std::printf("%lld\n", integer_power(3, 4));
    std::printf("%lld\n", integer_power(7, 0));
    return 0;
}
```

这个函数约定 `1 <= base <= 10`、`0 <= exponent <= 9`，中间结果都放得下。指数为 0 时不做乘法，得到 1。若扩大范围，必须重新检查每一步的乘积；换成 `long long` 并不意味着永不溢出。

`std::pow(base, exponent)` 是 `<cmath>` 中的乘方工具，这里常见用法返回小数近似值，也能处理合适范围的非整数指数。要做精确整数乘方，不要先用它得到近似值再截断回整数。这不是说某个 `pow(10,6)` 在所有机器都会算错；有的整数结果能精确给出，但不能靠这个巧合制定整数算法。

**停笔 2**　程序 B 两行分别是什么？若把 `result` 初值写成 0，为什么任何正指数都无法算对？只把返回类型改大，能自动改变之前每步的计算类型吗？

## 绝对值：离零有多远

`abs(-8)` 为 8，`abs(8)` 也为 8。整数和小数有同名重载：

- `<cstdlib>` 提供 `std::abs(int)`、`std::abs(long long)` 等整数版本。
- `<cmath>` 提供浮点版本，例如 `std::abs(double)`。

调用时让类型正确，包含相应头文件，需要两类就两个都包含。不是“名字叫 abs 就只适合小数”，也不是“把数先转成整数比较保险”。

有符号整数的最小值有特殊风险。例如本环境的 `int` 能表示 −2147483648，却不能表示 +2147483648，因此在 `int` 中取该最小值的绝对值会超范围。可以在**确认较宽类型能表示结果**后，先转换到较宽类型再取绝对值；不能先让窄类型发生溢出再补救。

**停笔 3**　一个测量值为 `-2.75`，误用整数版本得到 2，错在什么地方？为什么“绝对值总是正数，所以一定安全”不成立？

## 以下是以后会用到的名字

没有学过平方根、三角函数和对数时，先知道它们是不同工具，不要求现在做题。

| 工具，均在 `<cmath>` | 做什么 | 使用前提或单位 |
|---|---|---|
| `std::sqrt(x)` | 求平方根，例如 9 的非负平方根为 3 | 普通实数计算要求 `x >= 0` |
| `std::sin(x)`、`std::cos(x)`、`std::tan(x)` | 三角函数 | 输入按弧度，不直接按“度”；正切有不定义的位置 |
| `std::asin(x)`、`std::acos(x)`、`std::atan(x)` | 反三角函数 | 前两者输入范围为 −1 到 1；返回角按弧度 |
| `std::exp(x)` | 以常数 e 为底的指数 | 结果过大可能超出浮点范围 |
| `std::log(x)`、`std::log10(x)` | 自然对数、以 10 为底的对数 | 普通有限实数结果要求 `x > 0` |
| `std::ilogb(x)` | 取浮点表示的指数，本环境以 2 为底 | 这里只考虑正的、有限且非零输入，返回 `int` |

上表中除 `ilogb` 外，传 `double` 时这些函数返回 `double`。例如二进制环境里，`ilogb(8.0)` 为 3，`ilogb(12.0)` 也为 3，因为 12 落在 8 到 16 之间，不含 16。它不是返回一个小数的通用对数函数。

三角函数用到的“弧度”是另一种角度单位，180 度对应圆周率 π 弧度。C++14 不保证有名为 `M_PI` 的标准常量；以后需要时，可以用 `std::acos(-1.0)` 得到 π 的近似值。现在不需要为记住这条而提前学完整套三角函数。

无效输入可能产生非数、无穷大或错误状态，并不是每次都会抛异常或停止程序。普通输入也可能有舍入误差。不要把“函数有返回值”当作“已经得到题目允许的有限答案”。

**停笔 4**　不用计算复杂函数，只分类：输入 −9 求普通实数平方根、输入 0 求有限自然对数、输入 9 求平方根，哪一个符合上表条件？如果题目要求整数，为什么不能一律调用小数函数再截断？

## 核对

1. `-3 -2 -3 -3`。向上是往数轴较大的一边，对负数可以更接近零。
2. `81`、`1`。乘法从零开始会一直是零；返回类型不反过来改变已经完成的计算类型。
3. 先发生了小数到整数的损失，已经不是原测量值的绝对值。类型有范围，绝对值结果也可能超范围，零的绝对值还是零而不是正数。
4. 只有输入 9 求平方根符合这些条件。整数题可能要求精确结果，近似加截断既可能损失信息，也可能超出目标类型范围。

# 查阅　格式文本与文件

不必一次读完。先看自己遇到的情况：读数、读一个字符、读一段有固定格式的文字，或读文件。每个小节都能单独查。

本页的 C 风格输入输出来自 `<cstdio>`。遇到地址与指针的细节，可回到第 12 章；不熟悉时，先用前面章节已经学过的写法。

## 一次读取为什么可能只做了一半

下面是**完整程序 A**，要求输入一组像 `12,7` 这样的两个整数，中间是逗号。

```cpp
#include <cstdio>

int main() {
    int row = 0;
    int column = 0;
    int matched = std::scanf("%d,%d", &row, &column);
    std::printf("read: %d\n", matched);
    if (matched != 2) {
        std::printf("BAD INPUT\n");
        return 1;
    }
    std::printf("%d %d\n", row, column);
    return 0;
}
```

输入 `12,7`，成功写入两个整数，返回 2。输入 `12;7`，先读到 12，随后需要逗号却遇到分号，于是停在这里，返回 1。不是“已经开始读就一定把两个数都读完”。

**停笔 1**　分别输入 `12,7`、`12;7`、`cat`，`read:` 后面是什么？后两种情况下，能否把没读到的变量也当作有效数据？

## 按格式字符串从左向右读

格式里的普通字符要与输入匹配。格式里的空白则很特别：一个空格、多个空格或换行，都表示“跳过任意多个输入空白”，不是必须读到同一种、同样多的空白。

| 格式部分 | 它做什么 | 保存到哪里 |
|---|---|---|
| `%d` | 跳过前导空白，读整数 | `int*`，常写 `&x` |
| `%lld` | 跳过前导空白，读较宽整数 | `long long*` |
| `%lf` | 跳过前导空白，读小数 | `double*` |
| `%c` | 直接读一个字符，不自动跳空白 | `char*` |
| `%15s` | 跳过前导空白，最多读 15 个非空白字节，再补空字符 | 容量至少 16 的字符数组 |
| `%15[ABC]` | 最多读 15 个属于 A、B、C 的字节，再补空字符 | 同上，不自动跳前导空白 |
| `%15[^,]` | 最多读 15 个不是逗号的字节，再补空字符 | 同上，不自动跳前导空白 |
| `%%` | 匹配输入里的一个百分号 | 不接变量 |
| `%n` | 不取新字符，把这次调用已经消耗的字符数写入变量 | 默认接 `int*` |

`%[` 后的集合叫扫描集，不必把它当成一般的正则表达式。取反的 `^` 是说“不在这个集合里”，不是乘方。遇到第一个不匹配的字节就停止该项，它通常留在输入里，等待格式中后续部分处理。

字符串转换至少要读到一个匹配字符才算成功。`%[^,]` 不能自动把空字段识别成一个成功读入的空串；若第一个就是逗号，这一项会匹配失败。

**停笔 2**　有 `char code;`。输入是一个换行后跟 `R`，`scanf("%c", &code)` 会先读什么？改成 `scanf(" %c", &code)` 呢？两者都一定合适吗？

### 为什么别随手在最后加一个空格

`scanf("%d ", &x)` 读到整数后，还会继续跳过输入中的空白，直到遇到非空白或输入结束。交互输入时，你已经按回车，它却可能继续等，看起来像卡住。

不需要后续格式时，读整数直接用 `"%d"`。`" %c"` 则是有意在字符前跳空白：要读一个非空白符号时适合；要研究空格或换行本身时就不合适。

## 返回值在数“成功存入了几项”

一般情况下，返回值是成功赋值的项数。普通字符、格式中的空白、`%n` 以及被抑制的转换都不计入这个数。

先看 `%d%d` 这种读数格式：还没有成功保存第一个数，就遇到输入结束或读取错误，返回宏 `EOF`；如果已经成功读了一项再遇到文件结束，返回 1，而不是 `EOF`。`EOF` 是一个负值，常见为 −1；程序用 `== EOF` 比较，不要把它永远写死成 −1。

本页常见的“全是实际要保存的数据”的格式，检查 `返回值 == 预期项数` 就能判断是否读全。加了 `%n`、跳过项等特殊项时，要按具体格式判断，不能机械地数百分号。

**片段：**

```cpp
int a = 0;
int b = 0;
int matched = std::scanf("%d%d", &a, &b);
```

若输入文件只有一个 `8` 就结束，`matched` 为 1；空文件则是 `EOF`；第一个字符是 `X`，匹配整数失败，返回 0。只有变量被初始化为零，不代表读取成功，不能把缺失的输入偷偷补成零。

还有一个边界：`scanf` 的整数转换不能作为“任意长度数字都能安全处理”的验证器。输入数值必须在目标类型能表示的范围内；超范围的转换没有普通匹配失败那样的安全保证。书中程序因此都说明数值范围。

**停笔 3**　希望读两个整数时，为什么只检查 `matched != EOF` 不够？输入第一个字符就是 `X`，会不会得到 `EOF`？

## 有些字段只想越过，不保存

转换的星号表示抑制赋值：`%*d` 仍读取整数，但不需要对应变量，也不增加返回的赋值项数。

**完整程序 B：**从 `ticket=42,blue,18` 中，跳过编号，读取颜色和数量，再记录消耗的字符数。

```cpp
#include <cstdio>

int main() {
    const char line[] = "ticket=42,blue,18";
    char color[16] = {};
    int amount = 0;
    int consumed = -1;
    int matched = std::sscanf(line, "ticket=%*d,%15[^,],%d%n",
                              color, &amount, &consumed);
    if (matched != 2 || consumed < 0) {
        return 1;
    }
    std::printf("%s %d %d\n", color, amount, consumed);
    return 0;
}
```

`sscanf` 从一个有效的 C 风格字符串读取，不从键盘读取。颜色扫描到逗号之前，后面的普通逗号再把分隔符匹配掉。`%n` 写入已经消耗的 17 个字符，不消耗输入，也不增加返回值；所以成功项数是 2，不是 3。

若输入格式要求完全到此结束，可以再用 `consumed` 检查后面是否还有内容；本例是固定字符串，不需要把这个动作伪装成额外的万能验证。

**停笔 4**　如果删掉格式中的 `%*d` 前的星号，需要增加哪种变量和参数？返回成功项数应从 2 变成几？`%n` 的 17 是颜色长度吗？

## 输出到文字里，也要给容量

`printf` 向标准输出写，`fprintf` 向文件写。向字符缓冲区写文字，优先用有容量参数的 `snprintf`，不是没有容量限制的 `sprintf`。

**完整程序 C：**

```cpp
#include <cstdio>

int main() {
    char label[16] = {};
    int needed = std::snprintf(label, sizeof label, "BOX-%d", 27);
    if (needed < 0 || static_cast<std::size_t>(needed) >= sizeof label) {
        return 1;
    }
    std::printf("%s\n", label);
    return 0;
}
```

成功时，返回本来需要的字符数，不包括末尾空字符。若这个数不小于缓冲区容量，说明内容被截断，不应把它当作完整标签。这里先检查负值，再转换，避免把错误值当成很大的无符号数。

`sprintf(buffer, 格式, 参数...)` 与它用途相近，但不接容量，输出过长时可能越界。要会认旧代码里的名称，不必为了“学全接口”在新代码里使用危险写法。`printf` 若想输出一个百分号，格式中写 `%%`。

**停笔 5**　`BOX-27` 有几个字符？缓冲区至少要几个字节才放得下它和结束标记？若把程序中的容量改为 6，会发生什么？

## 把输入来源换成文件

下面的**完整程序 D**读取 `measurements.txt` 中的两个整数，输出到 `total.txt`。约定两个数的绝对值都不超过 1000000。只把自己可覆盖的结果文件命名为 `total.txt`，因为 `"w"` 模式会清空已有内容。

```cpp
#include <cstdio>

int main() {
    std::FILE* in = std::fopen("measurements.txt", "r");
    if (in == nullptr) {
        std::fprintf(stderr, "Cannot open input.\n");
        return 1;
    }
    int a = 0;
    int b = 0;
    bool read_ok = std::fscanf(in, "%d%d", &a, &b) == 2;
    int input_close = std::fclose(in);
    if (!read_ok || input_close != 0) {
        std::fprintf(stderr, "Cannot read input.\n");
        return 1;
    }

    std::FILE* out = std::fopen("total.txt", "w");
    if (out == nullptr) {
        std::fprintf(stderr, "Cannot open output.\n");
        return 1;
    }
    bool write_ok = std::fprintf(out, "%d\n", a + b) >= 0;
    int output_close = std::fclose(out);
    if (!write_ok || output_close != 0) {
        std::fprintf(stderr, "Cannot finish output.\n");
        return 1;
    }
    return 0;
}
```

这比前三行相加程序长，是因为文件多了真实的失败情况，不是加法变复杂了。

`fopen` 打开文件，失败返回空指针；`"r"` 读已有文件，`"w"` 创建或覆盖文件。相对文件名从程序当前工作目录寻找，不一定是源代码所在目录。`fscanf` 与 `scanf` 的读取规则一致，前面多一个文件参数；`fprintf` 对应输出；`fclose` 关闭。

检查输入成功后才打开输出，避免明明没有有效输入，却先清空旧结果。写入和关闭都要检查：输出可能先缓存在程序里，到关闭时才暴露错误。发生写入失败时，也不能宣称文件一点没改；它可能已有部分内容。

`stderr` 是错误输出通道，提示文字不写进 `total.txt`。在这段短程序里，每条成功打开文件的路径都会关闭它，失败不会被包装成一次成功计算。

**停笔 6**　输入文件不存在时，是否应继续调用 `fscanf`？为什么程序不一上来就打开 `total.txt`？如果写入返回成功但关闭失败，可以对用户说“已经完整写好”吗？

## 核对

1. 分别为 2、1、0；没有读到的变量不算有效输入，程序报告失败。
2. 前者先读换行，后者跳过空白读 `R`。要保留空白本身时不能跳过。
3. 返回 0 或 1 也不是 `EOF`，但都没读全。`X` 是匹配失败，返回 0。
4. 增加一个 `int` 变量，按格式顺序传它的地址；成功项数为 3。17 是整次解析消耗的字符数，不是颜色长度。
5. 六个可见字符，至少七字节。容量为 6 时不能放完整内容和空字符，返回所需长度仍为 6，检查会发现截断并退出。编译器若提前发现这次输出必然放不下，也可能先给出警告；这不是应该忽略的普通提示。
6. 不应对空文件指针读取。推迟打开输出可避免无效输入先毁掉旧结果。关闭失败则没有“完整写好”的证据，必须报告失败。

# 走出本册

## 先不翻书，试着独立做一次

班级收到了几次材料领取申请。一种材料可能被多人领取，你需要分别统计总量，还要记住每种材料第一次出现的顺序。

先用纸笔做，不急着写完整程序。

**输入约定：**第一行 `n`，表示申请条数，`0 <= n <= 100`。随后每条给一个不含空白的 ASCII 材料名和领取数，领取数为 1 到 20。

**输出约定：**按材料第一次出现的顺序，每行输出材料名和总领取数；没有申请就不输出任何材料行。

例如输入：

```text
5
tape 2
card 6
tape 3
pen 4
card 1
```

应输出：

```text
tape 5
card 7
pen 4
```

先回答三个小问题：

1. 只用一个“目前总数”，为什么不够？
2. 只用无序映射能保证上述顺序吗？只用有序映射呢？
3. 该记住哪些数据，每读一条怎样更新？

### 做完再核对

每种材料需要各自的总数，因此用“材料名到数量”的映射。无序映射不承诺遍历顺序；有序映射会按键排序，也不是第一次出现的顺序。再用一个 `vector<string>` 记录首次出现的名称即可。

每读一条，先找名称是否已登记：没有时，把它加入映射并把名称追加到顺序表；有时，只加数量。最后按顺序表依次查询总数输出。数量最多 2000，`int` 足够。若 `n = 0`，顺序表为空，输出循环不执行。

这道题可以完全用第 11 章的工具完成，也可以先用小数组和逐项比较做出来。若选择后者，查找次数会随已有材料种类增多，但在小范围内仍是一份真实、完整的解法。不是必须把所有学过的工具都塞进同一题。

再给自己加三个反例：全部申请同一种材料；每条都是新材料；第一种材料隔很久才再次出现。能解释这些情况，就比“样例刚好对”多了一层把握。

## 下一步学什么

C++ 是表达办法的语言，不等于办法本身。学完这些工具后，可以先练几类问题：有多少种小方案就逐一尝试；处理新数据时维护一份小记录；排序后看邻居；为查找选择键；把重复的处理规则写成函数。

做题时保留一小段记录：我先怎么想；哪个输入推翻它；后来改了什么。这比只抄最终正确代码更容易让下一次真正进步。每次只换一个主要想法，能说出改变为何有效。

不是每道题都要做出来，也不是学完语法就能参加高难度比赛。读不懂题目时先用具体数字演一遍；程序有问题时先缩小输入，保留仍会出错的最小情况。不要为了显得熟练，跳过这些普通但有用的步骤。

## 给家长：把学习、参赛与录取分开

孩子喜欢设计规则、愿意检查自己的错误，是继续学习的好理由。是否报名竞赛、投入多少时间，要结合兴趣、学校学习、休息和家庭条件。没有一个“晚于某年级就不能学”的普遍年龄界线；比赛本身则可能有明确学籍或年龄要求，不能把教材学习与参赛资格混为一谈。

国内常见的信息学活动包括 CSP-J/S、NOIP、省级选拔与 NOI。它们不只是同一场考试的不同难度，也不能当成所有年龄都可依次参加的固定通行证。例如 [CCF 的 NOIP 2026 报名通知](https://www.noi.cn/xw/2026-10-12/938849.shtml)明确，该届参赛资格仅限在籍在校高中生，并需按省级组织流程报名。小学阶段先学基础，不意味着现在就能参加每个环节。

[USACO 官方网站](https://usaco.org/)提供训练资料和在线比赛，2025—2026 赛季保留 bronze、silver、gold、platinum 分级，但赛程、认证安排和选拔结构已有调整。参加在线比赛、取得某级成绩与入选美国集训营或国家队，是不同的事情，不能一概而论。

竞赛成绩可以反映某一方面的学习经历，不能替代大学规定的申请条件。奖牌也不能直接翻译成“必保送”或“必录取”。例如[教育部网站转载的 2024 年保送招生说明](https://dxs.moe.gov.cn/zx/a/jj/231113/1865771.shtml)列的是学科奥赛国家集训队成员等资格，不是任意信息学奖项；这里引用的是该年份说明，未来申请必须重新核对当年政策。强基计划等通道同样要看目标高校当年的简章，不能把培训机构口头承诺当作资格。

考虑上海纽约大学等中外合作办学项目，或香港、新加坡高校时，应逐校核对国籍与学籍要求、课程或高考要求、语言成绩、材料、截止时间、费用和资助。例如[上海纽约大学的中国学生招生流程](https://shanghai.nyu.edu/cn/undergraduate-admissions/admission-process)包含申请、初审、校园日、高考与录取，不是“高考分加一个竞赛成绩就保证录取”。是否需要国际学校背景，也由具体申请路线决定，不能用一句话代替核对。

预算要按目标学校当年的学费、住宿、生活、交通和汇率计算，再扣除确有依据的资助。教材不写死一个四年总价，也不把“海外路径一定更划算”当作结论。现在愿意学、学得明白，与多年后选择哪条升学路径，可以分别作决定。
