# P2　列车追踪（Train Tracking）

## 题目

这是一道**交互题**（提交时不需要 `main`）。

每天早晨，一列有 $N$ 节车厢的火车从农场旁开往大城市，下午再从原路开回来。车厢编号为 $0 \dots N-1$，第 $i$ 节车厢的编号 $c_i$ 写在车身上（$1 \le N \le 10^6$，$0 \le c_i \le 10^9$），上午、下午各能看到一次。Bessie 选定了一个整数 $K$（$1 \le K \le N$），想知道每个长度为 $K$ 的连续车厢段的最小编号，一共 $N+1-K$ 个。

她的笔记本被均分为 $5500$ 格（编号 $0 \dots 5499$），每格只能存一个 $32$ 位有符号整数，初始全为 $0$。两趟观察之间，Bessie 除了笔记本什么都记不住。

交互方式：你只需实现函数

```cpp
void helpBessie(int ID);
```

火车每次经过一节车厢（上午下午各一遍、共 $2N$ 次），评测器就用那节车厢的编号调用它一次。在函数内部可以调用评测器提供的：

- `int get(int index)`：读笔记本第 `index` 格；
- `void set(int index, int value)`：写笔记本第 `index` 格；
- `void shoutMinimum(int output)`：向天空广播一个窗口最小值；
- `int getTrainLength()` / `int getWindowLength()`：返回 $N$ / $K$；
- `int getCurrentCarIndex()`：返回正在经过的车厢编号（$0 \sim N-1$）；
- `int getCurrentPassIndex()`：上午返回 0，下午返回 1。

$N+1-K$ 个最小值必须按窗口顺序广播（先 $0 \sim K-1$ 的最小值，再 $1 \sim K$ 的最小值，依此类推），但可以在任意一次调用里广播任意多个。除笔记本外，**不允许建立任何非常量全局变量或静态变量**，也不允许文件 I/O；每条测试用例上 `set` 调用次数加 `get` 调用次数不得超过 $25 \times 10^6$。

## 输入

本题没有标准输入。评测器从文件读入：第一行两个整数 `N K`，第二行 `N` 个整数 $c_0 \dots c_{N-1}$，然后按上述交互方式调用 `helpBessie`。

## 输出

本题没有标准输出。评测器把你调用 `shoutMinimum` 广播过的数列依次收集起来，就是答案（官方 `.out` 文件中一行一个数）。

## 样例

输入：

```text
10 3
5 7 9 2 0 1 7 4 3 6
```

输出：

```text
5
2
0
0
0
1
3
3
```

解释：窗口 $[0,3)$ 的最小值是 5，$[1,4)$ 是 2，$[2,5)$ 是 0，$[3,6)$ 是 0，$[4,7)$ 是 0，$[5,8)$ 是 1，$[6,9)$ 是 3，$[7,10)$ 是 3。

## 思路

记窗口 $i$ 覆盖车厢 $[i, i+K)$（$i = 0 \dots N-K$），$f(i)$ 表示窗口 $i$ 里最小值所在的车厢编号（有并列取最小下标）。整个算法的地基是：

> **$f$ 单调不减。** 因为窗口 $i+1$ 只比窗口 $i$ 少了最左边一节、多了最右边一节；原最小值若还在窗口里就仍是最小值（并列时下标更小的那个依然在），否则新进入的那一节带来了更小的值、位置也更靠后。

笔记本只有 5500 格，装不下 $N$ 个最小值，但**每隔 $B = 1000$ 个窗口存一个地标 $f(t \cdot B)$ 只占 $(N-K)/B + 1 \approx 1000$ 格**，正好放得下（本解法把它们记在笔记本第 `DIF = 4050` 格起，`4050 + 1000 < 5500`）。

**上午**求出所有地标位置。直接把每个窗口最小值都算出来是 $O(NK)$，太慢；用"分段 + 单调队列"降到线性：

- 以地标窗口的左端点 $t \cdot B$ 和右端点右边一格 $t \cdot B + K$ 为界，把数组切成若干段。同一段里的车厢**要么全在某个地标窗口里、要么全不在**，所以每段只需要一个代表——段内的最小值；
- 扫到每段的段首时，把上一段的代表压入单调队列（队尾所有不小于它的代表都被弹掉，因为新代表更小、离开窗口更晚，永远不会先被用到）；扫到地标窗口的右端点时，把队首弹出窗口的段，此时队首的位置就是 $f(t \cdot B)$，写进笔记本；
- 段数不超过 $2N/B \approx 2000$，队列塞得进第 2 格到第 4049 格。

**下午**逐块广播。块 $b$ 负责窗口 $[(b-1)B, b \cdot B)$，它的地标 $f((b-1)B)$ 上午已经记下。以地标为界，车厢分成两类：

- 位置 $p \le f((b-1)B) + B$ 的：可能只落在本块一部分窗口里，位置必须留住 → 连同编号一起进单调队列（队首弹出窗口外的元素）；
- 更靠后的：因为 $f((b-1)B) \ge (b-1)B$，它们的位置一定大于 $b \cdot B$，也就是落在本块**每个**窗口的左端点之后；只要读到时还没广播，它们就属于所有剩余窗口 → 位置没用了，只把最小值记在一个格子里（"全局最小值"）就够。

于是读到第 $i+K-1$ 节车厢（窗口 $i$ 的右端点）时，把队首（带位置的候选）与全局最小值取较小者广播即可——此刻读到的车厢恰好就是窗口 $i$ 的全部。当读到下一块的地标 $f(b \cdot B)$ 时，由于 $f$ 单调，本块所有还没广播的窗口的最小值位置都不超过 $f(b \cdot B)$、都已经读到，可以一次性补完本块剩余窗口（下一个地标窗口 $b \cdot B$ 也顺便广播掉，因为它的最小值位置正是 $f(b \cdot B)$，其余没读到的车厢只会更大），然后开始下一块。

每个车厢在两趟里各花**均摊常数次** get/set：笔记本第 0、1 格是单调队列的队首、队尾指针；第 2、3 格起按 `(位置, 数值)` 交替存队列；第 `DIF-3`、`DIF-2`、`DIF-1` 格分别存"已广播的窗口个数""当前块的全局最小值""当前块编号"；第 `DIF` 格起存地标位置。

本题在本地怎么验证：写一个 grader，提供上面那七个函数和一个 `main`，把 `P2.cpp` 直接 `#include` 进去（所以 `P2.cpp` 里没有 `main`、也不 include `grader.h`）。`main` 从 `.in` 文件读入 $N$、$K$ 与车厢编号，先把全部车厢按上午（`getCurrentPassIndex()` 返回 0）调一遍 `helpBessie`，再按下午调一遍，笔记本在两趟之间保留、初始为 0；收集 `shoutMinimum` 广播的数列与官方 `.out` 逐行对比，同时统计 set/get 调用次数。本文的 `P2.cpp` 就是这样在官方测试 1～17 上全部对上（`N = 10^6` 的大用例上 set+get 合计在 $1.2\times10^7 \sim 2.4\times10^7$ 之间，均低于 $25\times10^6$）。

## 复杂度

时间：两趟各扫描一遍车厢，每次 `helpBessie` 里每次单调队列的弹出都对应一次先前的入队，所以均摊 $O(1)$ 次 get/set，全程共 $O(N)$ 次笔记本操作（常数约 12～24），满足 $25\times10^6$ 的限制。

空间：全部状态放在笔记本里。本解法只用第 0、1 格、第 2 格起至多约 4004 格的单调队列、3 个状态格和 `DIF = 4050` 起至多 1000 格地标，最多到第 5049 格，在 5500 格之内。
