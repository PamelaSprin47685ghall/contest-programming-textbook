# P1　古戈尔（Googol）

## 题目

奶牛的搜索引擎公司里雇了 $N$ 名员工（$1 \le N \le 10^{100}$），编号为 $1 \dots N$，编号互不相同。公司被组织成一棵二叉树：每名员工管理着两名直接下属，分别叫左下属和右下属。为了平衡管理负担，对每名员工 $E$ 都满足：$E$ 左子树里的员工总数等于或多于右子树里的员工总数整整 $1$ 个（也就是差值只能是 $0$ 或 $1$）。CEO 是树根，编号为 $1$。

奶牛们弄丢了 $N$ 的准确值，请你求出来。

**这是一道交互题**：程序可以不断询问某名员工的两个下属是谁，最后输出答案。查询次数不能超过 $70000$ 次。

## 输入

本题的程序没有常规输入，所有信息都要靠向评测器提问得到。

提问方式：把要询问的员工编号写到标准输出（stdout）上，后面跟一个换行符并刷新输出缓冲（`fflush(stdout)`，否则可能和评测器互相等待）。评测器会回一行两个整数，依次是该员工的左、右下属编号。若某名员工没有下属，对应位置是 `0`；由于平衡条件，不可能出现"有右下属没有左下属"的情况（只可能两个都是 `0`，或只有右编号是 `0`）。

示例交互（来自原题面）：

```text
程序: 1
评测器: 4 3
程序: 4
评测器: 2 0
程序: 3
评测器: 0 0
程序: Answer 4
```

它对应的树是

```text
   1
  4 3
 2
```

注意不需要询问员工 2：由员工 4 没有右下属就能知道 2 也没有下属。

## 输出

最后一行输出 `Answer N`，其中 $N$ 是员工总数。

## 样例

输入（程序发出的提问与评测器回应交错显示，箭头左侧是程序写出的编号）：

```text
1
4 3
4
2 0
3
0 0
```

输出：

```text
Answer 4
```

## 思路

最直接的办法是递归问遍整棵树：对每个员工问出两个下属，再递归统计两棵子树的大小，加起来加一。可惜 $N$ 可以大到 $10^{100}$，树里的节点数本身就是天文数字，"问遍整棵树"必然超时也远超 $70000$ 次查询。

关键是用上平衡条件 $lft - rgt \in \{0, 1\}$：知道了一侧子树的大小，另一侧就只可能是这个数或这个数加一，**不需要重新完整统计**，只要在两种可能里挑出正确的那一个。

于是定义两个函数：

- `countFull(u)`：完整统计以 $u$ 为根的子树大小。先递归求出右子树大小 $rgt = \text{countFull}(b)$，再由平衡条件知道左子树大小 $lft$ 只能是 $rgt$ 或 $rgt + 1$，交给 `countHalf` 判定。
- `countHalf(u, x)`：已知 $u$ 子树的大小是 $x$ 或 $x + 1$，把它定下来。设 $lft + rgt$ 为子树大小减一，即 $x - 1$ 或 $x$，且 $lft$ 是 $rgt$ 或 $rgt + 1$。
    - 若 $x$ 是奇数：$x - 1$ 是偶数，两种情形（$lft = rgt$ 配和 $lft + rgt = x-1$，或 $lft = rgt + 1$ 配 $lft + rgt = x$）都推出 $rgt = \lfloor x/2 \rfloor$，右子树大小被唯一确定，再去判定左子树：它是 $rgt$ 或 $rgt + 1$，即 `countHalf(a, rgt)`。
    - 若 $x$ 是偶数：同理 $lft = x/2$ 被唯一确定，再去判定右子树：它是 $lft - 1$ 或 $lft$，即 `countHalf(b, lft - 1)`。

也就是说，除了最外层沿右链的一次完整统计，`countHalf` 每次只需要向下递归**一条路径**，每层只额外问一个员工。

两个实现细节：

- **查询次数**。树高 $H \le \lg N$，$N \le 10^{100}$ 时 $H \le 332$。`countFull` 沿最右链每层问一次，在高度为 $h$ 的位置挂出的 `countHalf` 每次最多问 $h$ 层，总查询数是 $1 + 2 + \dots + H \approx H^2/2$。本实现实测在 $N = 10^{100}$（最大的树高情形）时用了 $55278$ 次查询，小于上限 $70000$。
- **高精度**。$N$ 可以到 $10^{100}$，员工编号和答案都远超 64 位整数范围。编号只用来原样回问，所以按字符串读入、归一化前导零后原样输出；子树大小要参与加一、减一、除以二和奇偶判断，用 $10^9$ 进制的高精度数组实现（只需要这几种运算，不必写完整的四则运算）。另外注意 $x = 0$ 的收尾：此时子树大小只能是 $0$ 或 $1$，而节点编号非 `0` 说明该员工存在，所以大小一定是 $1$，可以直接返回而不必再问。

**本地验证**：这道题没有官方测试数据文件（`meta.json` 里 zip 为 null），只能自己写交互式评测器验证。评测器按题面平衡条件生成合法树（$n$ 个结点的子树形状唯一：左子树 $n \mathbin{/\!/} 2$ 个、右子树 $(n-1) \mathbin{/\!/} 2$ 个），根固定编号 $1$、其余编号随机打乱，逐条响应查询并统计查询次数。本地验证覆盖了 $N = 1, 2, 3$ 等边界、$20$ 组随机 $N \le 3000$、若干组 $N$ 接近 $10^5$ 以及 $N = 10^{100}$、$N = 2^{332}$（树高最大、查询最费）等超大情形，共 $35$ 组全部通过，最大查询次数 $55278 < 70000$。

## 复杂度

设树高 $H \le \lfloor \log_2 N \rfloor \le 332$：查询次数为 $O(H^2)$，即最坏约 $5.5 \times 10^4$ 次（上限 $70000$）；每次查询附带的高精度运算（加一、减一、除二）与输出编号的代价都是答案位数级别的 $O(100)$。空间 $O(H)$ 递归栈加上高精度常数。
