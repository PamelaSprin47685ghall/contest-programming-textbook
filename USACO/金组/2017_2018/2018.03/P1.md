# P1　失序（Out of Sorts）

## 题目

Bessie 正在学习各种算法，她最喜欢的算法是"冒泡排序"。做实验时她发现：大的元素很快就会被拖到数组末尾，而小的元素却要花很多轮才能慢慢"冒"到前面。

为了缓解这个问题，她把冒泡排序改成了每轮来回扫描的版本：先从左到右扫一遍做相邻交换，再从右到左扫一遍做相邻交换，最后再从左到右检查一次数组是否已经有序；只要还有逆序对，就继续下一轮。每进入一轮主循环，程序就打印一次 `moo`。

给定长度为 $N$ 的数组 $A$，请预测这段修改后的代码一共会打印多少次 `moo`。

```text
sorted = false
while (not sorted):
    sorted = true
    moo
    for i = 0 to N-2:
        if A[i+1] < A[i]: swap A[i], A[i+1]
    for i = N-2 downto 0:
        if A[i+1] < A[i]: swap A[i], A[i+1]
    for i = 0 to N-2:
        if A[i+1] < A[i]: sorted = false
```

## 输入

- 第 1 行：整数 $N$（$1 \le N \le 100\,000$）。
- 接下来 $N$ 行：每行一个整数，依次给出 $A[0] \dots A[N-1]$，取值范围 $0 \ldots 10^9$，元素不保证互不相同。

## 输出

一行一个整数，表示 `moo` 被打印的次数。

## 样例

输入：

```text
5
1
8
5
3
2
```

输出：

```text
2
```

解释：第一轮正向扫描把 8 一路换到末尾附近，反向扫描又把 2 向前带了回来，一轮结束后数组变成 `1 2 5 3 8`，仍存在逆序对 5 > 3，所以打印第二次 `moo`；第二轮把 3 和 5 交换后数组有序，主循环结束。共打印 2 次。

## 思路

把原数组和它排序后的结果上下对齐，在位置 $i$ 与 $i+1$ 之间画一条分界线。设 $M_i$ 为"在原数组中位于分界线左侧、但在排序后的数组中位于分界线右侧"的元素个数（也就是原数组前 $i+1$ 个位置里，本应属于后半段的元素数量）。

- 下界：这 $M_i$ 个元素每个都必须跨过这条分界线，而一轮来回扫描至多只能把其中的一个元素从左侧带到右侧（正向扫描把跨线元素向右推一格，反向扫描再处理相反方向的一个），所以每轮最多消掉一个单位的失衡，$M_i$ 是答案的下界。
- 上界：经过 $\max_i M_i$ 轮后，每条分界线两侧都满足"左侧元素全部不大于右侧元素"，也就是数组在每个位置都已被正确划分；若此时还有逆序对 $A[i] > A[i+1]$，就会与分界线 $i$ 处的性质矛盾，所以数组必然有序。而 Bessie 恰好需要再跑一轮才能发现数组有序，因此总共会打印 $\max\left(1, \max_i M_i\right)$ 次。

求 $M_i$ 只需一个树状数组：把 $(A_i, i)$ 按数值排序（数值相同时按下标排，保证结果确定），依次把排序后第 $1 \dots N-1$ 个元素的原下标插入树状数组；处理到第 $i$ 个元素时，`query(i)` 就是"前 $i$ 小的元素里原下标不超过 $i$ 的个数"，于是 $M_i = i - \text{query}(i)$。答案取所有 $M_i$ 的最大值和 1 的较大者。
