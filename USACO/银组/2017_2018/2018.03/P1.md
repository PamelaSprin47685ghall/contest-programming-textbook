# P1　失序（Out of Sorts）

## 题目

Bessie 正在学习算法，她最喜欢的是「冒泡排序」。给定长度为 $N$ 的数组 $A$，她写的 cow-code 如下：

```text
sorted = false
while (not sorted):
    sorted = true
    moo
    for i = 0 to N-2:
        if A[i+1] < A[i]:
            swap A[i], A[i+1]
            sorted = false
```

其中 `moo` 命令只是打印出一行 "moo"。请预测这段代码对给定的数组会打印多少次 "moo"。

## 输入

第一行一个整数 $N$（$1 \le N \le 100000$）。

接下来 $N$ 行每行一个整数，依次为 $A[0] \dots A[N-1]$，范围 $0 \dots 10^9$。元素不保证互不相同。

## 输出

一个整数：打印 "moo" 的次数。

## 样例

输入：

```text
5
1
5
3
8
2
```

输出：

```text
4
```

数组的排序过程为 $[1,5,3,8,2] \to [1,3,5,2,8] \to [1,3,2,5,8] \to [1,2,3,5,8] \to [1,2,3,5,8]$，前 3 趟让数组变有序，第 4 趟循环里扫描一遍发现已有序才退出，共打印 4 次 "moo"。

## 思路

先「离散化」：把所有元素按「值升序、值相同则原下标升序」排序，得到每个元素的最终排名 $rank_i$（这正好等于稳定排序后它应该待的位置）。

冒泡排序有一个关键性质：**一趟扫描中，任何一个元素最多向左移动一格**。所以下标为 $i$ 的元素要移到位置 $rank_i$，至少要 $i - rank_i$ 趟（若 $i - rank_i < 0$ 则不是限制），于是

$$\text{趟数} \ge \max_i (i - rank_i)$$

反过来，可以证明这个下界恰好达到：设 $D = \max_i (i - rank_i)$。取任意 $i - rank_i > 0$ 的元素，它左边一定存在比它大的元素（否则它的排名会更大），因此这一趟中它**必然**向左移动一格，$i - rank_i$ 减 1；而对于 $i - rank_i = 0$ 的元素，只要它还不在最终位置，它右边就存在更小的元素，但此时它左边也存在比它大的元素（否则无法形成逆序对），于是它要么不动、要么向左移动，绝不会向右移动。所以每趟之后 $D$ 恰好减 1，且 $D = 0$ 时数组已经有序。于是需要的趟数就是 $\max_i (i - rank_i)$。

注意循环在数组有序之后还要再跑一趟（打印一次 "moo"、扫描一遍确认有序）才退出，所以答案要再加 1。$N = 1$ 时答案为 $0 + 1 = 1$，恰好符合。
